# Linggan Intelligence 新一代情报系统：数据底座、采集体系与 Agent 内核战略讨论稿

版本：v1.0\
目的：用于与其他 Agent
深度讨论新项目架构、数据模型、采集策略和长期技术路线。

------------------------------------------------------------------------

# 一、核心背景与战略转向

当前项目已经完成一次关键验证：

旧方向：

    内容工作台
    → 内容采集
    → 内容管理
    → 内容生产

正在升级为：

    Linggan Intelligence
    → 感知世界
    → 理解变化
    → 发现信号
    → 形成情报
    → 指导行动

核心变化：

内容不再是最终产品，而是观察世界的入口。

真正资产：

-   长期领域数据积累
-   用户真实表达
-   时间变化记录
-   领域知识结构
-   情报判断能力

情报定义：

    情报 = 变化 + 证据 + 判断 + 行动价值

------------------------------------------------------------------------

# 二、对"重写新项目"的核心判断

当前考虑重新建设新项目，并不是因为旧系统失败。

真正原因：

旧系统已经承担了多个阶段的历史演进：

-   内容工作台
-   采集系统
-   博主监控
-   深度建档
-   语料库
-   AI 分析

因此产生：

-   多套数据结构
-   多套状态系统
-   多套读取逻辑
-   大量兼容代码

新的机会：

不是简单重写代码，而是重新定义：

"一个情报系统真正需要哪些核心对象"。

------------------------------------------------------------------------

# 三、重要原则：不要为了新而推倒已有资产

当前 V2 最大价值：

不是代码，而是思想。

已经验证：

    External
     ↓
    Evidence
     ↓
    Derived
     ↓
    Canonical
     ↓
    Projection
     ↓
    Product

核心原则：

## Evidence First

所有判断必须有证据。

不能：

AI 先总结，再寻找依据。

必须：

事实 → 理解 → 判断。

------------------------------------------------------------------------

# 四、插件重新审查：是否需要重写？

结论：

不应该简单重写插件。

应该区分：

## 1. 已验证资产（保留）

插件已经具备：

-   工位注册
-   授权
-   心跳
-   任务领取
-   租约
-   本地队列
-   重试
-   死信
-   幂等提交
-   服务端确认
-   页面能力判断

这些是生产验证后的基础设施。

------------------------------------------------------------------------

## 2. 应该升级的部分

真正需要优化的是：

采集能力，而不是运行能力。

插件应该从：

    采集工具

升级为：

    情报观察执行器

------------------------------------------------------------------------

# 五、重新定义插件角色

插件不是爬虫。

插件应该模拟：

一个长期工作的研究员。

错误模式：

    一次打开
    大量抓取
    结束

正确模式：

    建立观察对象

    ↓

    持续观察

    ↓

    发现变化

    ↓

    补充证据

    ↓

    形成长期认知

------------------------------------------------------------------------

# 六、采集系统最大变化：从 Capture Task 到 Observation Plan

传统：

    任务
     ↓
    插件
     ↓
    抓数据

情报系统：

    Observation Target
            ↓
    Observation Plan
            ↓
    Scheduler
            ↓
    Worker Station
            ↓
    Evidence
            ↓
    Observation
            ↓
    Signal
            ↓
    Intelligence

Observation Plan 应描述：

-   为什么观察
-   观察什么对象
-   观察周期
-   数据覆盖要求
-   深度级别
-   停止条件
-   下一次观察时间

------------------------------------------------------------------------

# 七、风控不是限制，而是设计原则

当前：

-   单插件 200 条限制
-   真人浏览行为
-   单账号低频
-   多工位分散

这些不是性能不足。

而是情报系统优势。

原因：

真实情报不是一次性爬取。

而是：

低频、持续、多源、长期观察。

类似：

卫星遥感：

-   大范围低频扫描
-   重点区域高频观察

------------------------------------------------------------------------

# 八、采集模式重新设计

未来采集应该分层。

## 第一层：发现扫描

目标：

发现对象。

采集：

-   ID
-   作者
-   标题
-   时间
-   基础指标
-   来源路径

不深挖。

------------------------------------------------------------------------

## 第二层：变化观察

目标：

发现变化。

采集：

-   新内容
-   指标变化
-   新评论
-   内容修改

------------------------------------------------------------------------

## 第三层：深度采样

参考博主深度建档。

不是全量抓。

而是：

代表性样本：

-   高表现内容
-   最新内容
-   异常内容
-   多样内容

深挖：

-   正文
-   图片
-   视频
-   评论
-   回复
-   用户表达

------------------------------------------------------------------------

## 第四层：长期跟踪

形成时间序列：

    第一次观察

    ↓

    7天后

    ↓

    30天后

重点不是当前状态。

而是变化。

------------------------------------------------------------------------

# 九、评论采集重新设计

评论不是数据。

评论是用户需求传感器。

不能：

    每篇30条评论

应该：

多维采样：

-   高赞评论
-   最新评论
-   作者回复
-   长回复链
-   争议评论
-   随机评论
-   新表达评论

同时保存：

-   排序方式
-   页面可见数量
-   实际采集数量
-   停止原因
-   覆盖率

------------------------------------------------------------------------

# 十、必须建设覆盖与缺失模型

系统必须知道：

没有看到什么。

例如：

    发现100条

    成功采集80条

    失败5条

    不可见15条

不能简单认为：

"没有数据"。

否则 AI 会产生错误判断。

------------------------------------------------------------------------

# 十一、媒体能力是当前最大产品缺口

当前 V2：

已经具备：

-   标题
-   正文
-   原文
-   Evidence
-   Projection

但是：

媒体没有形成完整闭环。

未来需要：

media_inventory：

包括：

-   封面
-   图片
-   视频
-   顺序
-   来源
-   checksum
-   可用状态

插件负责发现。

服务端负责：

-   存储
-   去重
-   转码
-   分析

------------------------------------------------------------------------

# 十二、情报系统真正的数据模型

核心不是 Content 表。

而是：

## 1. Evidence

世界发生了什么。

## 2. Observation

确认了什么事实。

## 3. Feature

AI 可消费特征。

例如：

-   情绪
-   痛点
-   意图
-   用户阶段
-   主题

## 4. Cluster

长期语义群体。

不是一次聚类结果。

需要：

-   版本
-   时间
-   成员变化
-   增长速度

## 5. Signal

变化。

例如：

-   新需求增长
-   新群体出现
-   话题迁移

## 6. Intelligence Event

情报事件：

包含：

-   证据
-   判断
-   反例
-   置信度
-   建议

## 7. Outcome

真实业务结果。

形成：

    判断
     ↓
    行动
     ↓
    结果
     ↓
    校准

------------------------------------------------------------------------

# 十三、聚类算法设计原则

不能只是：

embedding + 聚类。

需要综合：

## 语义

-   embedding
-   topic
-   concept

## 用户表达

-   痛点
-   情绪
-   语言模式

## 行为

-   点赞
-   评论
-   回复

## 时间

-   增长速度
-   新出现
-   消退

## 关系

-   作者
-   用户
-   内容

目标：

发现变化，而不是分类。

------------------------------------------------------------------------

# 十四、Agent 内核设计

Agent 不应该只是聊天机器人。

应该成为分析组织。

需要：

Input：

-   Objective
-   Evidence
-   Memory
-   Context

Reasoning：

-   Hypothesis
-   支撑证据
-   反例
-   不确定性

Output：

-   判断
-   置信度
-   引用
-   行动建议

Audit：

-   模型版本
-   Prompt
-   使用证据
-   成本
-   人工修正

------------------------------------------------------------------------

# 十五、技术路线判断

如果重建：

推荐：

模块化单体。

不要：

-   微服务
-   Kafka
-   复杂事件总线
-   过早 Graph Database

建议：

    Rust Backend

    +

    PostgreSQL

    +

    Object Storage

    +

    React

    +

    Browser Extension

重点不是技术先进。

重点：

领域模型正确。

------------------------------------------------------------------------

# 十六、下一步不要直接开发

必须先做事实调研。

输出：

## 1. 当前插件能力审计

明确：

-   当前采什么
-   怎么采
-   数据质量
-   风险

## 2. 数据字段审计

明确：

-   当前有哪些事实
-   缺哪些事实

## 3. 情报需求映射

明确：

每个情报能力需要什么数据。

## 4. 新 Capture Contract

定义：

-   Observation Plan
-   Evidence
-   Coverage
-   Artifact
-   Observation

## 5. 新数据库设计

基于：

事实 →变化 →判断 →行动

而不是：

页面 →功能 →表。

------------------------------------------------------------------------

# 最终核心判断

未来竞争力不是：

更多内容。

不是：

更强模型。

不是：

更漂亮页面。

而是：

    持续观察世界

    ↓

    保存可信事实

    ↓

    发现变化

    ↓

    形成领域认知

    ↓

    Agent 辅助判断

    ↓

    真实结果反馈

    ↓

    系统越来越懂这个领域

因此，新项目最值得投入的不是 UI，而是：

1.  采集观察体系；
2.  Evidence 数据底座；
3.  时间序列能力；
4.  聚类与变化检测；
5.  情报记忆；
6.  Agent 推理闭环。

插件不是简单采集工具。

它是未来 Linggan Intelligence 的"感知器官"。
