D. F1: Artifact restricted 传播 ✅

问题：artifacts[].restricted === true 但 builder 不自动传播到 capturePackage.restricted，导致组合被工作台 validator 以 invalid_submission 拒绝（§3.3 规则）。

修复：buildCaptureSubmissionBodyV2 自动传播:
const effectiveRestricted = restricted || (artifacts || []).some(a => a.restricted === true);

验证：
- ✅ artifact.restricted=true → capturePackage.restricted=true（自动）
- ✅ 无 restricted artifact + restricted: true → 保留 caller 显式值
- ✅ 无 restricted artifact + 未设 → restricted: false
- ✅ 工作台 cross-repo-verify.ts 6/6 workbench-validator=accepted
- ✅ 六份 fixture hash 全部不变

E. F2: 严格 JSON 值校验 ✅

问题：canonicalJson 依赖 JSON.stringify，对 undefined（静默删除键）、NaN/Infinity（转为 null）、Date/Map/Set（允许通过但产出非法 JSON）不做任何拒绝。

修复：新增 assertJsonValue(value, path) 函数，匹配工作台 assertJsonValue 语义：
- undefined → throw
- NaN → throw
- Infinity → throw
- BigInt → throw
- function → throw
- 非普通对象（Date/Map/Set/类实例）→ throw（检测 Object.getPrototypeOf）
- 合法 JSON 递归校验

sortKeys 改用 isPlainObject 替代 !(value instanceof Date) 条件。
