根因（与验收诊断的精确对齐 + 一个关键修正）

验收诊断"syncingFromUrlRef 阻止回写 effect 的 router.replace"——方向正确，但调试发现一个隐藏前提：

- 回写 effect（baa413a9 :487）if (syncingFromUrlRef.current) return 在 mount 时跳过 replace。
- 真实 Next.js 的 useRouter() 返回稳定单例 → mount 后回写依赖的 state 不变 → 回写只跑这一次（return）→ 不 replace → 地址栏残留（正是验收缺口）。
- 但原测试 mock 的 useRouter: () => ({ push, replace }) 每次渲染返回新对象，router 引用每 render 变 → load/workspace fetch 的 setState 引起 re-render → 回写 effect 反复 re-run（syncingFromUrlRef 已 false）→ 误把 replace 触发了。这个 mock artifact 掩盖了真实问题（首次跑 3 个新测试竟全部通过）。

改前失败 / 改后通过（router.replace 真实断言）

修复了两处：
1. page.tsx：删除 syncingFromUrlRef（声明 / URL 同步 effect 的赋值 / 回写 effect 的 return），回写 effect 改为纯 nextQuery !== searchParamsString 判断——即"当前 URL 已等于规范化 URL 才跳过"，否则 router.replace 一次。
2. page.test.tsx：vi.mock("next/navigation") 改为返回稳定 router 实例（惰性缓存，反映真实 Next.js），让测试能暴露真实缺口。
