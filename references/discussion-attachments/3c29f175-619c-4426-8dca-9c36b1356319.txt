调用链：

caller body.stationId (自报)
  → verifyExecutionStationRequestSignature(stationId: body.stationId)
    → findUnique({ id: body.stationId })
    → if (!signingSecret || !signatureRequiredAt) → return (BYPASS)
    → else → HMAC verify

唯一候选身份：ExecutionStation.id（schema:2869）——这是唯一与签名绑定的身份。但兼容路径下签名被跳过时，body.stationId 即未经验证的 caller 自报字符串。

判决：DECISION_REQUIRED

原因：
- 无 principal 列
- 格式未定义（"station:<id>"？"<id>@<workspace>"？）
- 渐进签名路径使无签名工位的身份不可信

最小候选方案：

关键发现：

所有与 station.workspaceId 相关的比较（#1, #3, #4, #5）均有 if (station.workspaceId) 前置条件。当 station.workspaceId = null 时（schema 允许），比较被跳过。

只有 job.workspaceId !== input.workspaceId（#2）是无条件执行的——因为 ExecutionJob.workspaceId 是 NOT NULL。

input.workspaceId 来源链：

route.ts:64  requirePluginAuthorizationRequest (auth token)
route.ts:68  resolvePluginTaskWorkspaceScope(authorization) → scope.executionWorkspaceId
route.ts:92  handleSyncRequest({ workspaceId: scope.executionWorkspaceId })
sync-service.ts:1026  commitRawSnapshot({ workspaceId: input.workspaceId })
ingest-service.ts:196  station.workspaceId !== input.workspaceId
ingest-service.ts:223  job.workspaceId !== input.workspaceId

input.workspaceId 全程来自 plugin authorization chain，不是 station。

判决：DECISION_REQUIRED

原因：
- station.workspaceId 比较存在（4 处）但都依赖 station.workspaceId !== null
- schema 允许 station.workspaceId = null（String?）
- null workspace 的工位可跳过所有 station 级 workspace 校验
- input.workspaceId 来自 auth chain 而非 station 自身
