## 2026-09-01 · PLUGIN-XHS-FINALIZATION-001 / Issue #128

- 为什么改：0.8.20 真实详情已接纳新一代媒体槽位，当前工位也立即领取了媒体工作，但五分钟
  Lease 内没有创建上传会话、Materialization 或失败回执。平台 CDN、Manifest host permission
  与 `alarms` 均正常；真实状态只停在 `leased`，证明 MV3 Service Worker 的脱离事件异步尾部可被
  Chrome 回收，不能承担长媒体下载与续传。
- 实现：0.8.21 增加最小 offscreen 媒体执行页。Service Worker 仍负责安装身份、服务端领取、精确
  generation 和持久 outbox；offscreen 页只处理已批准候选的下载、20 秒超时、SHA-256、1 MiB 分块
  续传、finalize 与失败回报。服务端仍拥有最多三次尝试，人工选择下载窗口继续保留。
- 真实评论修正：0.8.20 的全回复 Attempt 从头取得 `396 / 713` 后诚实以 `PARTIAL / no_progress`
  接纳，20 条顶层 comments 与 376 条 replies 分别形成 Package。页面当时位于 `.note-scroller`
  当前底部、没有结束标记，也没有剩余回复展开控件；一次受控回拉再下滑使顶层节点立即从 20 增至
  30，证明缺口是小红书无限加载的底部重触发条件。0.8.21 因此增加最多三次的状态驱动底部回拉，
  新数据出现即清零预算，仍保留 1.2 秒冷却、单动作、暂停/停止和风险门闸。
- 能力边界：标准详情继续一次带回详情、媒体槽位和最多 30 条评论；单篇深采与批量评论共用同一
  克制采集器。搜索筛选、下拉联想、作者主页和各页面字段状态继续只登记在
  `docs/platforms/xiaohongshu/capture-capability-registry.md`，插件不进行情报分析。
- 验证：216 项 Linggan/XHS focused tests、TypeScript 合同、Rust workspace、隔离 PostgreSQL 48 项、
  production build、content runtime、运行隔离、release 校验与可复现重建已通过；0.8.21 ZIP SHA-256
  为 `d8c7e3b1469f212922e3a6c4691599ebb075e0d22295b7006f874dbe0d43738a`。0.8.20 真实标准详情已分别
  接纳详情 1、媒体槽位 9、顶层评论 16、回复 14，标准窗口回执为 `30 / 30 COMPLETE`、页面公开数
  713。真实 0.8.21 重载媒体链、底部重触发后的完整评论 Attempt、Evidence UI 与合并后 main 验证
  在本条后续补齐。
