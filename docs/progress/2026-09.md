## 2026-09-01 · DEV-05-XHS-CONTENT-OBSERVATION-001 / Issue #133

- 为什么改：作品详情的“最新整行”语义会在后一次局部观察中遮蔽较早已知的标题、作者或发布时间；互动数只适合显示当前快照，评论/回复 Coverage 也缺少不可跨 Attempt 相加的历史。Evidence Inspector 同时没有一个能明确授权、范围和真实执行状态的复观测入口。
- 实现：`material_query_sql` 与 detail read 改为逐字段/逐指标取最新合格事实，向 Inspector 交付 `detailCurrent`、每指标 current/previous/delta 和带 Package/观察/记录时点的时间线。Current 直接从全部已接纳历史的最新两条合格 Observation 读取，时间线只从最新端有界展示，不能因第 101 条之后的记录而退化。较新的 `SOURCE_TEXT_ONLY` 也不能遮蔽较早的精确 platform epoch。评论与回复新增每个 Package/Receipt 独立的 Coverage history；不设跨 lane 共享截断，因此详情窗口、独立全公开观察和回复历史不做总和、也不互相挤掉。该变化不回填或覆写历史事实。
- 受限动作：仅当前 XHS 作品可沿**作品原先关联的那一份** target-linked active deep-archive authorization 发起一次实际 `Work Order → Lease → server-issued Task → Attempt → Package → Receipt`。固定 lanes 是详情、评论、回复，评论窗口最多 30；`acquire_media=false`，不新建媒体字节、OCR 或 ASR 工作。详情 read 交付 canonical `supported/eligible/reason`，只有 `eligible=true` 才给出 action URL；POST 仍在同一写事务内重查。无关联授权返回 `reobservation_authorization_not_linked`，绝不从作者、标题、URL 或监控目标名称回退；更宽但未关联的 grant 也不能 shadow 原授权。`MERGE` 只在同一 target、授权和完整冻结 policy（作品集合、评论/回复限额、媒体/OCR/ASR）全部相同的活 Lease 下成立；不同 policy 必须形成新 scope。准入、Work Order、过期 lease 收敛、Lease 和 Task 在同一事务内完成，因此并发点击不能留下“已有 Work Order、尚无 Lease”的中间态。为使 no-media 工作不被无关能力挡住，准入容量只在请求媒体时才要求 `media_slots`。
