# 上线路线与质量门

> 状态: 草案
> 最后核对: 2026-11-13
> 适用范围: “高质量上线”的定义、三圈上线的阶段划分、每个阶段的工作与退出条件、并行关系与风险
> 事实来源: 2026-11-13 只读审计；本手册集其余各册；[机会卡实施手册](../opportunity/playbook.md)与其进度记录；[创作流程规格](../product/creation-asset-workflow.md)
> 冲突时以谁为准: Mog 最新明确决定与各模块自己的计划、合同；本文是排序建议，不改变任何已授权工作包的范围

## 1. 什么叫高质量上线

五条，缺一条都不算：

| # | 标准 | 怎么验 |
|---|---|---|
| Q1 | 链路是真的 | 至少一次真实任务从外部作品走到我方成稿，每一步都留下可查的记录 |
| Q2 | 数字是诚实的 | 页面上每个数字都能下钻到对象；未知不显示为零；样本不足不显示比例 |
| Q3 | 发现有等级 | 事实、假设、已检验三者在数据和界面上都分得开 |
| Q4 | 有人在用 | 目标用户用它完成了自己的任务，而不是只做了验收 |
| Q5 | 停得下来、退得回去 | 每项新能力都在开关之后；关闭后现有行为不变；有备份与恢复演练记录 |

Q4 是最容易被跳过的一条。代码合并、测试通过、页面可访问都不能代替它，这与仓库现有的六层完成证据一致。

## 2. 三圈

```text
圈 A 单人可用 ──► 圈 B 团队可用 ──► 圈 C 持续运转
（Mog，本机）     （运营写手登录）    （观察恢复，假设在检验）
```

每一圈都是一次真实的上线，都按第 1 节的五条验收。

## 3. 圈 A：单人可用

目标：Mog 一个人在本机上，用真实数据把整条链走通一次，并能在看板上看到我方内容的结构与效果。

| 工作 | 内容 | 退出条件 |
|---|---|---|
| A1 一次真实穿行 | 选一个真实方向，从主题图谱看材料、选角度、交接到创作、写出一篇成稿。不改代码，只记录每一步卡在哪 | 一份穿行记录：每一步用了多久、哪里不顺、哪里缺材料 |
| A2 L1 收口 | 按[架构手册](03-architecture.md) 2.3 的顺序看清并处理三类失败，然后对就绪的作品放量 | 失败原因有分类统计；处理后失败率的实际数字；覆盖篇数 |
| A3 内容回溯看板阶段 0–2 | 按[实施手册](06-content-lens-playbook.md) | 质量门 G0、G1、G2 |
| A4 文档对齐 | 待裁定事项里标为“圈 A”的各项落定并同步到对应权威文档 | DR-02、DR-03 关闭 |

顺序：A1 最先做，因为它不需要任何开发，而且它的结果会改变后面三项的细节。A2、A3 可以并行。

【判断】A1 是整条路线里投入最小、信息量最大的一步。主题角度交接到创作的功能已经实现，使用次数是 0；它为什么没被用过，只有走一次才知道。

圈 A 的退出：第 1 节五条逐条有证据。其中 Q4 的证据是 A1 的穿行记录和 G2 里“Mog 说出一件此前不知道的事”。

## 4. 圈 B：团队可用

目标：运营写手在这里写稿、登记发布和阅读量；看板的数据是新鲜的。

| 工作 | 内容 | 退出条件 |
|---|---|---|
| B1 成员登录 | 创作规格里的 S0 | 第二个人能登录；非管理员看不到不该看的 |
| B2 原生登记 | 写手在运营台账登记发布与阅读量；稿件的“已发布”与登记挂上 | 连续两周有原生登记；阅读量填写率的实际数字 |
| B3 看板接新数据 | 新登记的笔记进入标注与快照；选题身份从选题框自动得到 | 看板的“数据截至”在一周以内 |
| B4 内容工作台运营模块切换 | 按运营迁移计划 | 不再双处登记 |

【事实】我没有找到运营写手实际工作方式的记录。

【判断】B2 是整条路线里最不确定的一步，因为它要求人改变习惯。建议在 B1 之前，先由 Mog 找一两位写手看一遍创作与登记的流程，听他们说哪里会不愿意用。这件事不需要开发。

## 5. 圈 C：持续运转

目标：系统在持续观察，假设在被检验。

| 工作 | 内容 | 退出条件 |
|---|---|---|
| C1 恢复一个固定面板 | 选一小组关键词与创作者，固定观察条件，按固定节奏复观测 | 面板连续运行四周；每周的覆盖情况有记录 |
| C2 假设台账 | 实施手册阶段 3 | 质量门 G3 |
| C3 第一条假设走完 | 用一题多号检验一条假设 | 结论被记录，不论支持还是推翻 |
| C4 同一套分类照外部作品 | 实施手册阶段 4 的第一项 | 供给、对标两张表并排可看 |

【判断】C1 的面板宁小勿大。它的价值在连续和可比，不在覆盖面。哪些对象进面板、风控边界如何，由 Mog 决定，见待裁定事项 DR-08。

## 6. 与正在进行的工作的关系

| 工作 | 状态 | 与本路线的关系 |
|---|---|---|
| 机会卡 | 按自己的手册推进，2026-11-13 已合入评论提及与问题指标 | 并行，不调整。统计函数与指标定义的做法两边共用 |
| 创作资产版 | 按切片推进 | 圈 A 的 A1 会用到它；圈 B 依赖它的登录与登记 |
| 统一内容理解 | L1 已上线运行 | 圈 A 的 A2 |
| 主题图谱 | 单次研究已部署 | 圈 A 的 A1 |

本路线不要求暂停任何已授权的工作包。它只建议一件事：在开新的工作包之前，先做 A1。

## 7. 每一圈的上线检查表

- [ ] 第 1 节五条各有证据，证据能被打开。
- [ ] 新能力都在开关之后；开关关闭时的回归测试通过。
- [ ] 涉及的迁移在隔离库里按真实顺序跑过；本机库迁移前有加密备份，且做过一次恢复验证。
- [ ] 涉及模型外发的，授权范围写明任务、供应商、材料范围，且与实际发送的内容一致。
- [ ] 涉及真实采集的，目标、频率、停止条件写明。
- [ ] 页面状态清单逐项有截图。
- [ ] 当前状态文档按事实更新，一页以内说清“现在跑的是什么版本、开了哪些开关”。
- [ ] Mog 的业务验收单独记录，不由合并或部署推断。

## 8. 风险

| 风险 | 表现 | 应对 |
|---|---|---|
| 又开一条线 | 看板变成第八十份活跃计划，其他线照旧 | 看板只做阶段 0–2 就停下验收；阶段 3 等圈 B 的数据 |
| 看板被当成结论 | 按效果区的差异直接调整全部产出 | 等级标签、固定说明、假设台账 |
| 运营不来用 | 原生登记一直是 0 | B1 之前先听写手怎么说 |
| 标注换模型后质量下降 | G1 不过 | 停下由 Mog 决定，不硬过 |
| 数据一直是旧的 | 看板停在 2026-10-12 | 质量条明说；圈 B 解决 |
| 我对运营场景的判断是错的 | 整套“选题”建议不贴合实际 | A1 与 B 之前的访谈就是为了尽早发现这一点 |

## 9. 我建议的第一周

1. Mog 读完[待裁定事项](DECISIONS-REQUIRED.md)，先裁 DR-01 至 DR-05。
2. Mog 做 A1：一次真实穿行，留下记录。
3. 执行 agent 做看板的 T0.1 勘察与 T0.2 合成数据。
4. Mog 抽看 30 条 2026-11-13 的标签（私有目录里已有），这是目前唯一缺的人工校验。

这四件事都不需要合并任何功能代码。
