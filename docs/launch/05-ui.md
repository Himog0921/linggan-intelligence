# 界面设计手册

> 状态: 草案
> 最后核对: 2026-11-13
> 适用范围: 情报类界面的信息表达原则、看板的信息骨架、新增表达形式的准入、文案约定与验收清单；不定义任何视觉数值
> 事实来源: [LIDS](../design/lids/README.md) 及其[数据边界四态](../design/lids/data-boundaries.md)；[UI 执行合同](../agents/ui-execution-contract.md)；`apps/web/src/pages/ops/` 的只读走查；[回溯归类报告](../audits/own-notes-retro-labeling-2026-11-13.md)
> 冲突时以谁为准: LIDS、UI 执行合同与页面合同；Mog 最新明确决定；本文只在这些边界内提出信息结构建议

## 1. 范围与诚实声明

- 我没有看过运行中的界面，本文不评价现有页面的视觉效果，只谈信息怎样组织。
- 视觉表达以 LIDS 为唯一标准。本文不引入新的色值、字号、间距或材质。
- 本文提出的三种新表达形式（第 4 节）需要走组件准入，不能在页面里私自实现。

## 2. 六条表达原则

情报界面与普通数据看板的区别，在于它展示的大多是“有条件成立的东西”。六条原则都是为了让条件不被隐藏。

| # | 原则 | 做法 | 反例 |
|---|---|---|---|
| U1 | 先说这份数据能信到什么程度 | 页面最上方是数据质量条：数据截至何时、多少有结果数据、标签一致率、分类体系版本 | 质量信息藏在页脚或提示里 |
| U2 | 每个数字都能回到对象 | 点任何一个格子或一行，都能看到它由哪些笔记构成 | 只有聚合数，无法下钻 |
| U3 | 发现的等级写在明处 | 结构事实、待检验假设、已检验，三种等级用固定的标签区分，同一页面不混排成同一种样式 | 事后归纳出来的模式与事实并列，看不出区别 |
| U4 | 不确定性看得见 | 比例旁边画区间；分母不足时不显示比例，写“样本不足”和实际分母 | 3/7 显示成 42.9% |
| U5 | 未知不是零 | 沿用 LIDS 四态：0 只表示确认为零，未填、未取得用未知表达 | 未填阅读量的笔记被算进分母 |
| U6 | 前端不计算 | 页面只渲染接口给的值和质量标记，不做除法、不比阈值、不推等级 | 前端自己算比例或判断“是否显著” |

## 3. 看板的信息骨架

任何一块“标注加结果”的看板都按五段自上而下组织。运营概览的内容回溯看板是第一个实例，具体内容见[实施手册](06-content-lens-playbook.md)第 8 节。

| 段 | 回答 | 等级 |
|---|---|---|
| ① 数据质量条 | 这份数据能信到什么程度 | — |
| ② 结构 | 我们写了什么，各占多少 | 结构事实 |
| ③ 覆盖 | 哪些格子写得多、哪些是空的 | 结构事实 |
| ④ 效果 | 各类的结果如何，差异有多大把握 | 待检验假设 |
| ⑤ 假设与检验 | 登记了哪些假设，检验到哪一步 | 假设或已检验 |

顺序不能颠倒：先看质量，再看结构，最后才看效果。把效果放在最上面，会让人跳过“这份数据能信多少”。

## 4. 三种新增表达形式

| 形式 | 用途 | 准入前先核对 |
|---|---|---|
| 区间条 | 一个比例加它的区间，多行并排比较 | `apps/web/src/pages/ops/Charts.tsx` 是否已有可复用的条形实现 |
| 覆盖格 | 两个维度交叉的格子，显示篇数，空格与样本不足的格子有明确区别 | 运营概览已有的“运营人 × 账号矩阵”是否可以复用其表格结构 |
| 等级标签 | 结构事实、待检验假设、已检验 | LIDS 现有的状态标签是否已有对应语义 |

准入按 LIDS 的组件晋升规则执行：先查重；在第二个独立页面使用之前，作为页面内实现存在；不提前宣布为标准件。

对区间条的三条信息要求（不涉及视觉数值）：

- 区间与点估计同时可见，区间不能只在悬停时出现。
- 多行比较时共用同一条横轴。
- 样本不足的行不画条，只写实际分母。

对覆盖格的三条信息要求：

- 空格（一篇都没有）与样本不足（有，但太少）必须能区分。
- 定义上不可能有内容的格子，与没写过的格子，不混为一谈；前者不显示为“空白机会”。
- 点格子进入该格的笔记列表。

## 5. 文案约定

| 不用 | 用 | 原因 |
|---|---|---|
| 爆款概率、预测 | 过千率、爆款率（都是已发生的比例） | 系统不预测 |
| 显著、有效 | 差异的把握程度；写出比例、区间与分母 | 避免把统计用语读成业务结论 |
| 规律、结论 | 待检验假设 | 事后归纳 |
| 趋势 | 候选变化 | 与 DEC-05 一致 |
| 机会、蓝海 | 没写过的格子、写得少的格子 | 空格不等于机会 |
| 0（当数据未填时） | 未填 | 未知不是零 |
| AI 判断 | 机器标注；并给出一致率 | 说清楚可信到什么程度 |

每个效果区块下固定一行说明：这些差异来自已发布笔记的回溯，账号、时机和偶然都混在里面，只能当作待检验的假设。

## 6. 状态清单

每个看板页面至少覆盖这些状态，各有明确文案：

| 状态 | 触发 | 页面表现 |
|---|---|---|
| 未启用 | 特性开关关闭 | 导航不显示入口；直接访问显示“未启用” |
| 无数据 | 没有任何标注批次 | 说明需要先完成一次标注；不放示例数据 |
| 标注进行中 | 批次未完成 | 显示已完成的比例；效果区不展示 |
| 一致率不足 | 某维度一致率低于门槛 | 该维度只出现在结构区，效果区写明原因 |
| 数据陈旧 | 最新发布日期早于设定天数 | 质量条明确写出“数据截至”和距今天数 |
| 样本不足 | 分母低于最小分母 | 不显示比例，写实际分母 |
| 读取失败 | 接口错误 | 明确报错并可重试；不显示上一次的数字冒充当前 |

## 7. 对现有页面的三条建议

都是信息结构上的建议，是否采纳、怎样实现由对应页面的合同决定。

- **运营概览**：现有区块回答“做了多少、结果多少”。新增的内容回溯看板作为运营下的独立二级页，不往现有概览里塞，避免一页承担两种读法。
- **主题图谱**：角度交接到创作的入口已有但从未被使用。建议用一次真实任务找出不顺的位置，再决定是否调整，不凭猜测改。
- **研究底稿**：Content Card 的知识单元已经带依据。在任何复用卡片内容的地方（看板的外部对照、创作的材料桌），保持同一种“点单元看依据”的交互，不各做一套。

## 8. 验收清单

一块看板在交付前逐条核对：

- [ ] 页面最上方是数据质量条，四项齐全。
- [ ] 结构、覆盖、效果、假设的顺序正确。
- [ ] 每个聚合数都能下钻到对象列表。
- [ ] 效果区的每个比例都带区间和分母。
- [ ] 分母不足的行不显示比例。
- [ ] 未填与零的表达不同。
- [ ] 三种等级的标签在全页一致。
- [ ] 效果区下有固定的限制说明。
- [ ] 第 6 节的七种状态各有截图。
- [ ] 前端代码里没有除法、阈值比较和等级推导。
- [ ] 没有使用第 5 节左列的任何用语。
- [ ] 新增的表达形式已按 LIDS 查重并登记为页面内实现。
