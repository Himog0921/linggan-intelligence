## 这是什么

一套由 Claude 在一次完整审计之后写给 Mog 的手册。它回答三件事：

1. 这个产品真正的内核是什么，现在缺哪一块。
2. 架构、产品功能、界面、数据各自应当保留什么、调整什么、暂时不做什么。
3. 怎样把“我方笔记回溯归类”这套方法做成运营概览里的一块看板，并让它成为内核能力的第一个实例。

2026-11-14 Mog 已采纳[待裁定事项](DECISIONS-REQUIRED.md)里的全部建议项。据此，内容回溯看板实施手册与任务编排是活跃计划，外部 agent 可以按它们开工；其余各册仍是供对照的参考草案，其中被采纳的部分通过任务编排里的工作包落实。

## 一页结论

- **北极星不变**：垂直领域情报系统。价值有三个属性：新（靠刷内容得不到）、早（在别人之前）、可信（能回到原文核对）。
- **现状**：可信这条腿已经很扎实；新和早还没有产出。系统目前是一份溯源严格的语料快照，加上刚开始运行的 L1 理解。
- **缺的那一块**：把材料变成“可检验的发现”的回路。它由六步组成：归纳分类、盲标、独立复标、关联结果、登记假设、前瞻检验。
- **第一个实例**：运营概览的内容回溯看板。它用你们自己的发布数据，2026-11-13 已经手工跑通一遍，方法和结果见[回溯归类报告](../audits/own-notes-retro-labeling-2026-11-13.md)。
- **做法上的纪律**：一个实例跑通再抽象；标签必须盲标并带一致率；事后归纳只算假设；结果数据必须是工作的副产品而不是填报。

## 三种标记

手册里的重要陈述都带标记，方便对照和推翻：

| 标记 | 含义 |
|---|---|
| 【事实】 | 2026-11-13 从代码、文档或本机库直接核实；附位置或数字 |
| 【判断】 | 我基于事实得出的结论；可以被新事实推翻 |
| 【假设】 | 还没有被检验的想法；采用前应先检验 |

所有数字都是 2026-11-13 的时点值。实施前按[协作协议](../governance/agent-collaboration.md)的事实优先级重新核对。

## 这套手册不做什么

- 不重开已确认的决定。与现有决定有出入的地方，都列在[待裁定事项](DECISIONS-REQUIRED.md)里，由 Mog 决定。
- 不定义视觉数值。界面部分只谈信息结构，视觉表达以 [LIDS](../design/lids/README.md) 为准。
- 不替代[机会卡实施手册](../opportunity/playbook.md)。机会卡按自己的手册推进；本手册集只说明两者的关系。
- 不含任何我方笔记或外部材料的原文。

## 写这套手册时学到的三个教训

这些是同一轮讨论里我被纠正、或自己推翻自己的地方，写在这里以免重犯：

1. **不要把定位收窄成一个下游指标。** 我最初建议把产品收窄为“提高试新命中率”，被 Mog 否定。数据后来也显示，阅读量与加微在现有口径下对不上，那个指标本身没有被验证过。
2. **不要把相关当因果。** “上游反复重做是因为没有下游拉动”“监控关闭说明不是情报系统”都是我从并存的数字里读出来的因果；监控是开发期的有意关闭。
3. **不要把技术指标当业务价值。** 降低失败率、统一定义、补评测集，都只在有人使用产出时才有意义。每项建议都应当能回答“它改变了谁的哪个决定”。
