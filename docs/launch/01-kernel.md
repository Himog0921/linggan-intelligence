## 1. 核心价值

Intelligence 是垂直领域情报系统。它的价值是告诉团队一件事，这件事同时满足三个条件：

| 属性 | 含义 | 现状 |
|---|---|---|
| 新 | 靠人刷内容得不到 | 还没有产出 |
| 早 | 在别人看到之前，或在还来得及行动时 | 还没有产出；持续观察在开发期关闭 |
| 可信 | 每一步都能回到原文核对 | 已经很扎实 |

【事实】原始的《情报价值链优先级评估》把“异常发现”和“情报日报”列为第一优先，理由是“情报与分析工具最大的区别”；证据链列在第二阶段。实际建设顺序相反：前三个月主要投在证据链上。

【判断】这个顺序并不是错的。没有可信的材料，任何发现都站不住。但它意味着产品最核心的价值假设到现在还没有被检验过：**系统能不能说出一条你原本不知道、并且站得住的领域发现。**

## 3. 内核回路

2026-11-13 那次回溯归类，手工走了一遍完整的回路。它就是这个产品缺的那一块。

```text
一批材料（我方笔记 / 外部作品 / 评论）
  │
  ├─ ① 归纳   从材料里归纳分类体系：取值、定义、纳入标准、易混淆的区分办法
  ├─ ② 盲标   逐条标注；标注者拿不到任何结果数据
  ├─ ③ 复标   第二个标注者独立重标一个样本，算一致率
  ├─ ④ 关联   标签与结果关联；比例带区间，维度影响做置换检验，小样本不下结论
  ├─ ⑤ 假设   把看到的模式登记成假设，写明它是事后归纳
  └─ ⑥ 检验   为假设预先写好检验办法，在真实发布里验证，结果回写
```

每一步解决一个具体的失真来源：

| 步骤 | 防的是什么 |
|---|---|
| 归纳 | 套用现成框架，看不见这批材料自己的结构 |
| 盲标 | 知道结果之后再贴标签，标签被结果带着走 |
| 复标 | 定义含糊，换个人标就不一样 |
| 关联时的区间与检验 | 把偶然波动读成规律 |
| 假设登记 | 事后归纳冒充结论 |
| 前瞻检验 | 相关冒充因果 |

【事实】这次的结果：两遍标注的 kappa 为 0.88–0.90；选题维度各自能解释阅读量方差的几个百分点，账号约 20%；讲道理型笔记过千的比例是 2.2%，其余是 10.1%；让人开口的写法评论率是讲道理型的 3–4 倍。

【判断】这套回路之所以是内核，是因为它不依赖某一种材料。换成外部作品，结果变量是点赞；换成评论，结果变量是提及人数。机会卡手册里的 Wilson 区间、质量门、时点一致，是同一套纪律在评论上的应用。

## 4. 七项内核能力

| # | 能力 | 现有实现 | 缺口 | 最小下一步 |
|---|---|---|---|---|
| K1 | 可信材料 | 采集包、回执、逐字段当前值、媒体物化；测试覆盖厚 | 持续观察关闭；复观测很少 | 开发完成后先恢复一个小的固定面板 |
| K2 | 一次理解 | L1 与 Content Card，文字引句逐字核验 | 失败率 28%；只有主题研究一个下游；没有数据化的评测 | 见[架构手册](03-architecture.md)第 2 节 |
| K3 | 归纳与标注 | 无产品实现；2026-11-13 手工跑通 | 全部 | 内容回溯看板 |
| K4 | 关联与护栏 | 机会卡已有 Wilson 区间和指标定义版本 | 置换检验、同账号内比较、小样本护栏未产品化 | 随看板实现，复用机会卡的统计函数 |
| K5 | 假设与检验 | 无 | 全部 | 看板第三阶段：假设台账，绑定一题多号 |
| K6 | 时间面板 | 发布时间为毫秒精度，可按发布周回溯 | 同一批对象的纵向观察几乎没有 | 同 K1 |
| K7 | 领域语言 | 主题定义版本、发布与人工裁定 | 真实数据很少 | 随主题研究放量自然积累 |

K3、K4、K5 是这套手册主张新增的部分，其余是已有能力的收口。

## 5. 设计原则

| # | 原则 | 落到实现上 |
|---|---|---|
| P1 | 每项能力都要说得出它改变了谁的哪个决定 | 任务卡必须写“用户结果”；写不出来的不排期 |
| P2 | 标签必须盲标 | 标注任务的输入里不得出现任何结果字段；用测试断言 |
| P3 | 标签必须带一致率 | 每个标注批次都抽样复标；一致率不达标的维度不出现在看板的效果区 |
| P4 | 发现分三级：结构事实、待检验假设、已检验 | 界面文案与数据字段都区分这三级；事后划分的分组只能是假设 |
| P5 | 小样本不下结论 | 分母低于阈值时比例与区间为空，并给出原因；阈值只来自指标定义 |
| P6 | 未知不是零 | 沿用现有不变量与 LIDS 数据四态 |
| P7 | 结果数据是工作的副产品 | 不新增让运营填写的字段；选题身份从“选题框 → 稿件 → 发布登记”这条链自动得到 |
| P8 | 一个实例跑通再抽象 | 回路先只为运营看板实现；第二种材料接入时再提取公共部分 |
| P9 | AI 层保持薄 | 冻结输入、一次调用、结构校验、程序绑定来源；不为假想的规模建调度 |
| P10 | 时间补不回来 | 观察一旦恢复，优先保证一个小面板的连续性，而不是覆盖面 |

## 6. 反模式

都是这一轮讨论里实际出现过的：

- **用阅读量给判断打分。** 一篇笔记的阅读量由账号、封面标题、时机和分发共同决定，不能用来检验“某个话题在升温”。
- **把监控关闭、数据为零读成缺陷。** 先问是不是有意为之。
- **事后分组后直接下结论。** “讲道理型很少跑出来”是看了数据才划的组，p 值再小也只是假设。
- **用格式通过数代替内容质量。** 内容卡合同文档里已经反复提醒这一点。
- **为了让下游有东西用而放宽上游的证据规则。** 例如“一条引句不符只丢该条”会让一张卡静默缺内容，采用前要先看它丢的是什么。
- **在没有任何运营人员证据的情况下谈运营场景。** 截至本文，我没有看到运营人员实际怎样工作的记录。

## 7. 新思路

以下都是【假设】级别的想法，按我认为的价值排序。每条都写了最小做法，避免一上来就建大东西。

### 7.1 同一套分类，照三种材料

对我方笔记用过的“时刻 × 给什么”，同样可以照外部作品和评论：

| 材料 | 回答 | 结果变量 |
|---|---|---|
| 我方笔记 | 我们写了什么 | 阅读量、评论 |
| 外部作品 | 别人写了什么、什么跑出来了 | 点赞、收藏、评论 |
| 评论 | 家长在问什么、在说什么 | 提及人数、点赞 |

三张表并排，就是“供给、对标、需求”的对照：家长问得多而我们没写的格子、外部跑出来而我们没写的格子、我们写得多而没人接的格子。这比任何单独的机会分都直观，而且每个格子都能下钻到原文。

最小做法：先做我方笔记；外部作品复用已有的 Content Card 字段做映射，不重新调用模型；评论等机会卡的问题数据就绪后再接。

### 7.2 假设台账与一题多号

把看板上看到的模式登记成假设，每条写明：陈述、来源、检验办法、判定规则、状态。检验办法优先用已经定下的一题多号：同一个选题同一周发在 2–3 个账号上，就能把“题目的作用”和“账号与运气的作用”分开。

最小做法：一张表、一个列表页。第一条假设就是“在同一个时刻上，提问或两难的写法比解释的写法评论更多”。

### 7.3 评论区开口率

转化发生在评论区，所以比阅读量更接近业务的结果变量是：我方笔记评论区里，有多少条是目标家长在描述自己的处境或追问。DEC-0009 把“爆款评论区家长占比”列为后续指标；我建议把它提前，因为它可以由插件读取我方笔记的评论区得到，不需要运营填任何东西。这需要一次新的采集授权。

### 7.4 按发布周回看

全部外部作品都有毫秒精度的发布时间，跨度 2022–2026。在监控恢复之前，可以先按发布周看各格子的供给和表现变化。它有幸存者偏差（越早的作品积累互动越久、越容易被搜到），只能给出候选变化，不能叫趋势，这与 DEC-05 的边界一致。

### 7.5 发现档案

每条进入过看板的假设及其检验结果都保留，包括被推翻的。一年后，这份“我们在什么时候、基于什么、相信过什么、后来怎样”的记录，是别人复制不了的东西。

最小做法：假设台账不删除记录，只追加状态。

### 7.6 包装层单独成维度

第一个标注者指出，标题里有一层三个维度都装不下的东西：句式（“为什么”“别再”）、讲述者身份、情绪强度、连载。它们可能比题材更影响点击。

最小做法：先不建模，在看板的备注里保留这条观察；等题材维度稳定后，把句式作为第四个维度做一次同样的归类。
