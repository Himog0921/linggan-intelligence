## 当前登记结论

Mog 指定的 LIDS 已通过 [lids/README.md](lids/README.md) 吸收为项目的**设计表达标准**（2026-08-21 的 v2.0，2026-09-02 由 DESIGN-010 升级为 v7.0），因此不是普通外部参考条目。它的来源校验、可继承范围和不继承范围都在 LIDS 入口中冻结：可继承 Token、Primitive、Pattern、材料语法、壳层区位、状态表达和 Agent 治理；不可继承任何产品事实、模拟数据、V3 原型、技术栈、资产或运行状态。

DESIGN-002 原先的“未来感 + ASCII + 新粗野主义 + 情报系统感”已被 LIDS 收敛为“纯白台面上的精密情报基础设施”（DESIGN-003 换向、DESIGN-010 补齐 70/20/10 材料预算）。ASCII 保留为机器语义，不再是可自由扩散的视觉风格。除 LIDS 外，当前仍没有可供直接实现的外部产品、旧系统、截图或品牌材料条目。

### 两个"V7"不是同一件事

本表存在一处**命名冲突**，登记于此以免后续误读：

| 名称 | 是什么 | 影响 |
|---|---|---|
| `REF-V7-001` | Evidence Library **页面** Gold Master，2026-08-24 登记（见下） | 运行时 CSS 类前缀 `v7-*` 由它而来 |
| 设计系统 **v7.0** | 全项目设计表达标准，2026-09-02 吸收 | LIDS 全部规则文件 |

两者同名纯属巧合，来源、范围与生效时间都不同。迁移 `v7-*` 类名时不要以为是在迁移设计系统 v7.0；反之亦然。

仓库内的 references/ 是历史证据区；现有页面与架构草案是产品/架构候选。两者可以在未来按具体事项被核对，但均不能单独授权 UI 实现。

## 新增参考的登记格式

每一个条目必须至少包含下列信息：

| 字段 | 必填内容 |
|---|---|
| 参考 ID 与名称 | 稳定名称，避免“最新截图”“某个网站”之类的模糊称呼 |
| 来源与核对时间 | 原始出处、可访问位置或受控证据位置，以及何时核对 |
| 参考性质 | 历史产品、视觉灵感、交互样本、品牌材料、低保真原型或其他 |
| 可借鉴范围 | 只说明可观察的表达层面，不上升为产品要求 |
| 明确不继承 | 旧数据口径、旧业务规则、旧权限、旧技术路径或其他禁止迁入的内容 |
| 关联事项 | 哪个 Issue、页面规格或设计决定允许本次参考 |
| 时效与风险 | 是否可能过期、是否受版权/隐私/访问限制、是否需要重新核验 |
| 不构成什么 | 不能授权页面、功能、数据、权限、技术或发布的边界 |

如需保存截图、浏览器导出、录屏或其它生成物，必须先按 docs/governance/generated-artifacts-registry.md 登记固定位置、来源、Git 策略和清理规则；未登记的材料默认不进入仓库。

## 使用限制

- 参考只能帮助提出候选，不可替代用户确认、产品页面、数据合同、当前 SCOPE 或设计规格；
- 历史系统中的页面结构、字段、状态名称和交互，不因视觉上相似而继承；
- 不从截图推断数据来源、权限、执行结果、真实可用性或用户价值；
- 在受限、敏感或版权不明的材料中，不复制原始内容到 Markdown、代码、测试或外部 Agent 上下文；
- 发现参考与权威规则冲突时，保留冲突事实并停止受影响部分，不通过改写历史材料消除冲突。
