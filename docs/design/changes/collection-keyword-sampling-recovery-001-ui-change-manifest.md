## 用户结果与范围

关键词任务的 `scrollRounds` 表示实际下拉动作预算，`maximumQuota` 表示候选卡片上限，`topByLikes` 表示最终保留数（历史字段名）。一次巡查可以接纳少于 20 条的有效材料，不能因未采满就抹掉发现。搜索排序的最终样本遵循已生效的排序口径；读不到互动数时不能编造评论或收藏名次。插件失败码按实际页面阶段上报；未消费详情页许可的普通任务可有界重试，已消费的详情页许可继续执行单次导航保护。

## 表面地图与状态词典

| 表面 | 输入事实 | 输出词义 |
|---|---|---|
| `/collection/targets` 目标行 | 最新合格巡查、最新已接纳但未完成的巡查、当前活跃工单 | `巡查中` 是当前执行；`最近巡查未完成` 是历史部分结果；`受阻` 只给当前确实需要处理的执行阻塞 |
| 目标抽屉巡查状态 | 同一目标的工单与回执 | 未完成的最近巡查保留其已接纳发现，并说明当前是否已排队恢复 |
| `/collection/runtime` 通道判断 | 派发判定及 reason code | `station_busy`、`account_busy`、平台并发满是等容量；资格或控制闸门才是阻塞 |
| 不可变材料台账 | CapturePackage、Receipt、Disposition | 有效部分结果继续入库与详情追采；旧回执不改写 |

`UNKNOWN` 不显示成 0；有效的部分结果不显示为数据无效；历史失败不自动等于当前受阻。新增界面词只用中文，按 LANG-05 处理。

## 依赖地图

冻结 TaskSpec → 页面筛选与下拉 → 候选卡片 → 按排序依据保留样本 → CapturePackage / Receipt / Disposition → 详情追采 → 目标与工位只读投影。失败上报走独立 Task / Lease / WorkOrder 状态链，不修改已经接纳的材料。详情页导航 grant 的消费事实优先于重试便利。

## 验收矩阵

| 场景 | 预期 |
|---|---|
| 3 次下拉、候选上限 200、最终 20 | 未到底且未到 200 时确实执行 3 次下拉；回执能区分动作、候选与保留数 |
| 最多评论、最多收藏、最多点赞、最新 | 评论和收藏数可解析时按对应数值选样，不可解析时维持已生效页面顺序；点赞沿用现有取样规则；最新维持页面顺序 |
| 页面打开或就绪失败 | 普通发现任务报告对应 `tab_unavailable` / `page_timeout`；详情导航不重复 |
| 连续派发失败 | 普通任务在有限次数后结束当前工单并留下明确失败事实；后续定时巡查可以重新建单 |
| 最新巡查部分接纳、无当前活跃任务 | 目标显示最近巡查未完成，已接纳发现不丢失；不误报当前受阻 |
| 三通道因工位忙等待 | 工位显示等待容量，阻塞数不包含这些通道 |
