# UIUX-CONTENT-WORKBENCH-001 · 三页交互原型提案

> 状态: 草案
> 最后核对: 2026-10-14
> 适用范围: 专项阶段二独立原型；不适用于正式运行页面
> 事实来源: Mog 本次派定、专项阶段一审计、LIDS v7 及当前 runtime token 源
> 冲突时以谁为准: Mog 最新确认、专项计划和真实实现；原型不证明真实业务能力

## 1. 目标与视觉主题

白色工作台、冷黑文字、橙红色强调。页面各有一个重心：比较选题、阅读取材、完成作品。大量留白用于区分任务，不靠卡片嵌套或常驻说明组织信息。原型为 LIDS 修订候选，正式规则与运行 token 本轮均不改。

## 2. 调色与 token 来源

沿用 LIDS v7 的白底、`#0b0f12` 主文字、`#30373c` 正文、`#5f6a71` 次要文字、`#c63214` 可读信号、`#f24a23` 非文字标记、`#137557` 成功、`#b52b20` 危险、`#335e72` 焦点；低层背景及细线来自 runtime。所有 UI 值集中在原型 CSS token 块，不回写生产。作品画布的米白、浅橙和淡绿只属于演示图文模板，不是应用主题。

## 3. 字体与排版

中文 Sans 使用 PingFang SC / Noto Sans SC；模拟人的原声使用 Songti SC；序号和尺寸使用 SFMono-Regular。常用字号 12/13/15/17/21/27，正文行高 1.75，字重 400/600/700。选题标题与创作标题可用 27，编辑正文 17。

## 4. 组件与动作矩阵

| 页面 | 任务 / Pattern | 组成与可操作结果 | 事实边界 |
|---|---|---|---|
| 今日选题 | L1，比较 / 选择 | 10 份完整演示方案；搜索、类别筛选、收藏；三种结构切换；方案详情、进入研读 / 创作 | 合成推荐依据，不存在真实每日供给或阅读预测 |
| 材料研读 | L2，原文阅读 / 摘录 | 材料切换、原文段落、摘录加入 / 移除；带上下文进入创作 | 合成材料，不是真实作者、评论或研究证据 |
| 图文创作 | L2，分步编辑 / 预览导出 | 标题正文、演示改写、素材抽屉；封面排版；内页编辑增删排序；逐图预览、正文复制、PNG/ZIP 下载 | 本地画布导出真实运行，AI 与发布无接入 |

按钮、表单、选中态、空态、反馈、弹窗为原型局部责任；不晋升正式共享组件。主操作每区最多一个；正文输入即时保存至本浏览器原型专属键，失败明确提示；可清除本原型草稿。示例改写必须预览并确认采用，不能覆盖用户手稿而无反馈。

## 5. 布局与导航提案

同一个领域上下文贯穿三页，左侧轻导航加当前选题；编辑区有正文、封面、内页、预览导出四步。沉浸模式隐藏全局导航，保留返回与退出。材料与辅助工具按需出现。今日选题结构 A 编辑台（连续列表 + 方案），B 选题墙（按类别分组），C 单篇决策（逐篇查看），通过底部审美比较条切换。

**局部壳层提案**：紧凑侧栏取代现行固定 326/400 页头区位，仅获准用于本独立原型。Mog 验收后再决定是否修订 `shell-zones.md`；当前不是正式壳层例外的推广授权。

## 6. 边界、深度与动效

留白 → 浅底 → 细线；圆角 4/8；无渐变、玻璃或大投影。按钮按压及步骤切换用 140–200ms，系统 reduced-motion 时取消。重音限选中项及主动作。普通文字无假 hover。

## 7. Do / Don't 与数据合同

- 固定展示原型与演示内容标识，详细限制收于「原型说明」；V3 按 §12 移除重复常驻说明。无真实作者、账号、来源链接或效果读数。
- 合成方案含目标读者、角度、依据、提纲和 3 份材料。材料是演示场景，不作为医疗或效果建议。
- 草稿、素材篮、模板与排序按选题隔离；本地恢复是原型体验验证，不等于生产保存合同。
- 导出包含正文、封面、内页和演示说明。默认 1080×1440，仅原型规格假设；过长文案提示并阻止整包导出，禁止无声截断。
- 不出现模拟运行进度、实际模型费用、真实成功通知或不可点击的假动作。
- 无模型、数据库、API、采集、正式业务文件或外部资源访问。

## 8. 响应式与可访问性

桌面 1440/1280 以并排阅读和创作为主，窄屏 390 纵向组织。主要动作点击区至少 40px；V2 密集来源和片段内次级操作采用 28–36px，并保留用途菜单及明确标签；键盘可用、焦点清晰、表单标签明确；弹窗 Escape 可关闭、关闭后恢复焦点。左右键只在未编辑时切换选题布局。

## 9. 后续实现提示与验收

仅普通 HTML + CSS + JavaScript，CSS 为唯一样式策略，无依赖安装和构建。入口：[可交互原型](../pages/content-workbench-prototype/index.html)。从设计源可直接打开，也可启动仅 loopback 的静态服务。共享视觉规则在 Mog 选定方向后才进入正式 LIDS；真实数据 / 保存 / AI / 导出适配由后续模块合同独立实现。

验收必须实际走通选题→原文→摘录→正文→封面→内页排序→整组检查→下载；核对 PNG 尺寸、ZIP 内容和实际编辑是否进入导出。截图、文件核验、未知与用户待验收项登记在[验收记录](../acceptance/uiux-content-workbench-001-prototype-acceptance.md)。

## 10. V2 · 从材料片段到创作画布

本轮用户指出 V1 资料添加不足、研读分散和信息密度低，要求多篇原笔记、用户原声、系统内类似选题及全文，选择片段进入创作画布；同时提供原稿 / 改稿截图与 15.08 秒交互视频。V1 保留供当前体验，V2 在独立子目录和存储键实现，用户已授权该原型范围。

### 参考观察与解释

- 截图：原稿 / 改稿并排；删除与新增有可读差异；作者可决定采用。继承对照关系、差异可见与作者控制，不继承截图中的正文或生成指标。
- 视频：0–5 秒切换人物 / 片段类型；约 8.8 秒点击文字片段，书页中对应文字高亮；11.5 秒换片段后原文位置随之变化。可观察的是分类、片段与上下文互相定位；“片段加入创作画布”是 Mog 在此基础上明确提出的新任务，不声称视频已经展示了创作功能。
- 本地取 scene 关键帧，再补 2.6/6.4/8.8/11.5 秒动作上下文；没有上传视频。未安装本地 Whisper，音频未转写，结论限于可见交互。
- 两个官方模式对照：[mymind](https://mymind.helpscoutdocs.com/article/55-how-to-save-reading-highlights-quotes-in-mymind) 支持阅读时选择文字保存片段；[Heptabase](https://support.heptabase.com/en/articles/10447319-connect-and-sync-readwise) 支持把高亮片段拖入白板组织。本原型据此采用原文选取与画布编排；具体作品结构仍按 Mog 目标设计。

### 入口与职责

DEC-0009 已规定选题池归运营并默认打开。当前源码 `apps/api/src/local_web/shell.rs` 的运营侧栏仅有总览、发布、账号、每日数据、导入导出，不能说创作已上线。提案：运营 → 今日选题 / 我的创作 → 本篇工作区（研读取材、画布、正文、封面、内页、导出）。研读是对象内任务，不另建孤立资料库；原始事实仍归语料 / 主题图谱 / 评论，发布结果仍归运营台账。原型用紧凑“运营”语境演示，正式壳不改。

### 表面、状态、依赖与验收矩阵

|---|---|---|---|
| 研读取材 | 搜索多篇原笔记、原声、类似选题；数量随当前演示结果；无结果有恢复入口 | 合成来源，来源范围与样本数明确；真实系统数量未知 | 原笔记 / 原声 / 类似选题切换、检索、双篇对照、源文回定位 |

### 视觉和动作提案

保持 LIDS 白底与 Sans / 原声 Serif；纯 CSS 为唯一策略。资料区缩短纵向间距，以来源列表、正文、选中片段形成三个稳定区域。画布按文章结构分栏，保留足够的卡片正文，不用大面积装饰填空。改稿对照借用用户截图的浅绿新增、淡红删除，作为 diff 的局部语义色，不能晋升应用主题。选中文字时出现添加动作，添加后反馈数量；拖动改变归组，正文与改稿滚动可联动。

本轮复制 V1 为 `v2/index.html`、`v2/prototype.js`，追加 `v2/research-fixture.js` 与 `v2/workbench.css`；复用上层 fixture 和基础 CSS。浏览器键 `linggan-workbench-prototype-v2`，不读取 / 覆盖 V1 草稿。全部类似数量是可数的合成样本，不代表真实系统检索。


### V2 走查后的设计判断与后续缺口

原资料添加把“看见一篇材料”和“决定使用哪句话”合成了一个动作，缺少回查、比较与自己的推理位置。V2 将其拆成可见链路：材料范围 → 片段 → 原文上下文 → 本篇画布 → 自己的表达 → 正文。画布先按文章结构组织，避免自由白板的空间操作占据主要精力；自由排布、连线和无限缩放留待 Mog 使用后判断。

相似选题显示已有角度、场景、具体正文及差别；合成“我方已写”与“候选选题”分开。原声带父笔记上下文。原文选择保存字符位置，回查精确选文使用局部浅黄标记，浅绿只用于改稿新增文字。画布内的自己的表达和片段备注不会改写原始材料；组装先预览，并保留来源，不能称作自动成稿。

正式实现顺序建议如下，均未派定业务代码：

| 优先级 | 能力缺口 | 达标依据 |
|---|---|---|
| P0 | 当前领域跨原笔记、评论、我方作品与候选选题的真实检索 | 真实范围和数量，完整 / 部分 / 未取得分开，不能用原型的 18 / 4 代替 |
| P0 | 片段身份、来源版本、原图 / OCR 位置与评论上下文 | 选中的精确文本可回查；原文更新或撤回有状态；当前原型只有合成文字 |
| P0 | 本篇工作区与草稿持久化 | 材料、作者表达、正文、图组关联到同一作品；历史和恢复可审计；浏览器存储仅用于本轮体验 |
| P0 | 改稿的作者控制 | 方法 / 提示词 / skill 版本可见；选定材料决定上下文；保留词句、逐段采用和历史比较另行实现 |
| P0 | 正文到图组的内容对应 | 封面、内页能反映当前定稿；生成后仍可改；导出绑定同一版本；当前原型图片内容需单独编辑 |
| P1 | 海量片段检索、对比与编排性能 | 真实规模下的召回质量、延迟、分页和来源完整性；原型只验证有限样本交互 |

Mog 当前验收应首先聚焦：材料能否支撑一次具体写作判断；从摘取到自己表达是否顺手；正文编辑和对照是否足够沉浸；是否需要比结构分栏更自由的画布。统一设计规则的晋升和真实接入继续等待后续派定。


## 11. V3 · 空间材料浏览与作品关联（用户已派定）

2026-10-14，Mog 要求补齐视频中的完整材料浏览：保留空间与翻阅体验，片段筛选、分布索引、原文定位高亮真实联动，片段进入画布后关联正文和指定内页。范围仅独立原型，V1/V2 与已有草稿保留，不改业务代码。

视觉命题：左侧展开的纸页保留原文上下文，右侧以作者分组铺开短纸条；纸条悬停或键盘聚焦时放大阅读。局部纸色、书脊、纸页阴影和翻页动效仅用于此次用户明确参考的材料表面，不改 LIDS，不扩散到其他卡片。功能由原生 HTML/CSS/JS 实现，不用截图伪装可操作界面。

| 表面 | 状态和用户结果 | 依赖 / 数据边界 | 验收 |
|---|---|---|---|
| 片段筛选 | 来源类型、用途、全文检索交集；作者分组、真实结果数、空态恢复 | 同一组合成来源中按句切分，保存精确字符区间 | 分类改变纸条、索引与可定位原文；聚焦放大不遮挡主动作 |
| 原文纸页 | 双页展开、前后翻阅、精确高亮；原声可回父笔记 | 每页固定两个原始段落，片段保持来源与区间 | 点纸条和索引均翻到正确页；翻页同步当前位置 |
| 分布索引 | 来源分栏、用途分行，每个点是真实片段位置 | 从当前筛选结果派生，不手写统计 | 点选双向定位，当前点可辨识，不把过滤掉的点继续显示 |
| 作品画布 | 引用原文与我的表达分开；选正文和指定内页，一次放入 | 内页稳定 ID；保留出处关联；已有文字只追加；重复目标不重复插入 | 正文/内页实际文本一致；页面排序后关联仍指向原页面；可撤销 |
| 创作与导出 | 正文、封面、内页与预览继续可编辑；关联出处可复查 | 本地保存独立键 v3；真实 PNG/ZIP；无模型/业务 API | 完整实走并下载，manifest 保留片段和作品目标；用户改过文字后如实标记 |

V3 的来源文字与原声全部为合成样本；书页为可阅读的合成文字排版，原帖图像/OCR 与海量性能尚未接入。加入作品后作者可自由编辑，来源关联保留；不宣称后续源文变化会自动改写手稿。修改后同步需显式决定，本轮不做后台覆盖。

## 12. V3 方向确认与工作区文案精简（2026-10-14）

Mog 明确认可当前 V3，要求删除截图中的描述性文字，把空间让给操作区。本次确认覆盖 V3 审美与交互方向；不等于授权业务实现、接入真实数据或部署。继续使用原 URL 和本地存储键，不重置已有作品，不新建 V4。沿用 prototype 技能的独立可运行原型方式；已有用户范围优先于技能默认的新增变体、正式代码推广与提交建议。

| 表面 | 本次调整 | 状态 / 依赖 | 验收 |
|---|---|---|---|
| 今日选题 | 移除开场口号、大标题和示例说明块，筛选直接接选题内容 | 功能标题保留给辅助技术；合成标识由顶栏原型入口统一承担 | 首屏可见更多选题，搜索和布局切换仍可用 |
| 材料与画布 | 移除工作区前缀、常驻使用说明、各结构栏的教学句；保留当前选题、来源与操作 | 只改展示，不改片段筛选、引用或目标关联 | 材料定位及画布操作仍有清晰名称，原有片段保持 |
| 图文创作 | 移除重复页名和常态保存说明；步骤与素材/沉浸动作合并成紧凑工具行；删除对照区教学文案 | 保存失败仍明确显示；正文冲突提示、字数、差异和采用动作保留 | 正文/对照获得更多高度，短屏与窄屏不遮挡动作 |

文案原则：常态展示用户当前处理的内容、可执行的动作与有助决策的状态；教学说明按需出现。删除文案时同时收回其布局空间。保留可访问名称、错误状态、来源和数据真实性，不把「简洁」变成动作无名称或异常无反馈。

实施边界：仅 `v3/prototype.js`、`v3/material-browser.css` 与专项文档；共享 V1/V2 源、正式 LIDS token、业务源和数据保持不动。无需新增业务测试；完成语法、治理与实际浏览器版面验证。

| 本轮核实的代码 | 已有基础 | 与 V3 的距离 |

### 关键挑战及验收标准

| 优先级 | 挑战 | 实施要求与用户验收 |
|---|---|---|
| P0 | 材料片段既有用又可定位 | 保留来源版本、精确选区、原图/行位置、原声父笔记及必要对话语境。自动提炼与原话分开；允许重新圈选片段。点击任何作品引用能回到对应版本和上下文；材料不完整时明确显示。 |
| P0 | 一篇作品可靠保存，关联不乱 | 区分原始材料、摘录、我的表达、正文块、图页和导出版本。自动保存、失败恢复、历史版本、冲突保护必须先于 AI 自动改稿。页面排序或改名后关联不漂移；删除/重建与撤销结果明确；作者修改不被后台覆盖。 |
| P0 | AI 稳定提供至少 10 个可制作方案 | 主题方向、作品选题、已发作品去重分别处理。方案含角度、依据、提纲和材料，按账号及领域审查可用性；数量不够如实呈现。方法、提示词、Skill 与输入材料绑定版本，修改可对照采用。持续使用验证，而非一次生成 10 张卡。 |
| P0 | 正文与图组完整成品 | 先完成可编辑模板和确定排版，再接图片生成。正文更新时标出受影响图页，由作者决定带入；导出冻结同一作品版本。长中文、字体缺失、图片加载和内容超出均可处理，预览与实际导出一致，导出后不用另补排版。 |
| P1，真实接入时测量 | 海量材料下仍能聚焦与翻阅 | 当前只有 18 份合成材料、89 个按句片段。真实检索、筛选与分布索引共享同一结果范围；区分全量、筛后与已加载数量。按需读取、虚拟列表和服务端索引保留纸条空间感；以真实材料规模约定延迟预算。 |
| P1 | 统一审美不随迭代回退，效果能复盘 | 将已确认的壳、工具栏、来源呈现、空/部分/失败状态和文案规则纳入唯一 LIDS。作品/导出版本关联既有发布记录和带观察时间的阅读量，不再造第二份运营账本；用采纳、补材料、成稿耗时和阅读表现共同迭代。 |
