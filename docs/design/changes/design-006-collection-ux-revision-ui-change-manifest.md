### 关于「未知不得被吞掉」的红线说明

- 「用 0 冒充未知」= 撒谎 → 本次不碰
- 「不渲染一个尚不存在的量」≠ 隐藏未知 → 阶段计数在调度器接通前不存在这个量，且全局 `SCHEDULER NOT CONNECTED` 仍挂在上下文行，语境完整

## 4. 讨论中被推翻的方向（记录以免重复）

本轮前半程曾推进「**裁决台**」方向：以 Agent 提案为主体，人只做批准/驳回/继续观察。该方向经 Mog 判断后**整体作废**，理由成立且值得固定下来：

> **AI 不该放在采集上游做「值不值得采」的判断。** 在采集这件事上，多采与漏采的代价不对称——多采只是浪费一次请求，漏采是永久缺失（内容会被删除、限流、时效过期，补不回来）。用不可逆的损失去换可逆的浪费，风险收益比为负。
>
> AI 在本产品中的位置是**下游**：判断哪条内容值得写、哪个信号值得关注（即首页五个编队成员正在做的事）。上游应尽量全采，把判断留给后面。

**建议另立 `docs/decisions/` 条目固定此结论**，否则它会被反复重新提出。本清单不代替该决策记录。

同时更正一处此前的引用错误：`HOME-04`「按问题划分不按工序」约束的是 **Agent 编队的组织方式**，不是页面导航划分。不得再用它论证 tab 结构。
