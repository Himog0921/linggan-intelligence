## 结论与证明边界

本次审美审查由实施者单独进行，与功能测试分开记录。实际查看有数据正式页面的像素、布局尺寸、字体与对比度，并修正下表的问题。当前候选的表单、任务列表/抽屉、领域列表/编辑器和工位编辑已达到本报告所列局部视觉要求。不能将浏览器断言、31 张截图的生成成功或这个结论写成全站视觉验收通过。

参考图中的 KEEP 用于字段和操作保留，APPROVED 用于局部视觉，WRONG 用于识别必须纠正的现状。认可表单、领域弹窗的截图已实际打开；原 Demo 的完整交互源码已读，但原 Demo 的 file URL 被浏览器安全策略拒绝，未绕过。因此原 Demo 的实际交互体验、与其渲染页面同屏比较仍是 **NOT VERIFIED**。没有把模拟进度、假数字或演示登录搬入正式产品。

正式截图来自完整 0125 隔离 PostgreSQL 与正式 router，包含 27 条初始用户采集记录、5 篇完整作品/150 条评论、51 篇跨页选择作品、26 个长期观察目标、领域及工位。部分观察目标抽屉是已暂停、无目录/巡查历史的合成状态；这些截图只证明原布局与操作保留，不证明有历史目录/巡查图表的所有视觉状态。

## 上线真实数据追加审查（2026-10-14）

原 PR #406 已合并为 `00d12518950b1e8c1c232d6d38800c1cbb97a560`，0125 已获独立授权并应用。随后在正式 3000 的 1068 条历史用户记录、560 条有成果记录、26 个观察目标和两个旧工位上另行检查实际像素。表单 560px、领域列表 900px、1440 下抽屉 1065.59px、390 下表单 358px；字体/边线/主按钮与隔离候选一致。实际打开领域列表→原编辑器→关闭返回，工位原十列和完整管理面板，观察目标 1920 全字段及原创作者抽屉；没有在正式页面提交采集、规则或管理写操作。

发现两项原隔离小集合没有暴露的问题：历史成果缺少新版 checkpoint 时被写成“等待执行与交付”；任务列表先投影全部命中的 JSON 再分页，560 条成果在只读 EXPLAIN 中执行约 20.031 秒。原分支追加候选仅将旧遍历完成证明显示为未知；列表先选本页身份，再在同一只读快照读原汇总，局部关闭 JIT 编译。正式库只读计划实测约 687.755 毫秒；全部/成果首两页的20条有序 body 与原查询逐页哈希相同。候选在完整隔离 PostgreSQL 实跑14项业务及有数据正式浏览器1项，浏览器新增真实旧 WorkOrder/Lease/Task/Attempt/Package/Receipt 与共享详情回查。候选尚未追加合并/部署，不得把这一查询测量说成上线后的浏览器性能通过。

这次审查也识别发布运行边界错误：恢复后台保留了既有自动策略和旧插件接活，跨日后发生9条有provider token回执的 analyze 调用（6成功/3失败），以及旧队列巡查的新发现。已停止原三服务并核验巡检 worker drained，随后仅将运行目录采集 phase设为recovery，重启3000读口；巡检与媒体 worker保持停止，数据库策略/周期规则未改。原先“没有真实调用”的启动快照不能代表跨日后的状态。本报告不把这些副作用写成授权业务验收。

## 审查发现与已修复项

| 问题 | 修复与重新核对 |
| --- | --- |
| 单次标题及输入值过大/过粗 | 校准为局部 17/13/12px 层级，普通输入常规字重，只有选中来源加深；实际查看桌面/窄屏像素 |
| 已选作品或已有目标仍露出隐藏的来源/排序字段 | 局部 `[hidden]` 规则优先于 flex/display；真实来源切换和 selected 精确集合浏览器验证，已选文案改为“本次作品数量” |
| 任务过滤与工具栏混在一条拥挤行中 | 五筛选单独一行，搜索保留当前 filter；黑色主按钮在搜索右侧；1440/1920/390 查看 |
| 390px 被旧页面 min-width 撑到 1040px | 仅用户任务页取消该 min-width，保留表格自己的横向滚动；页面 documentWidth=390 |
| 长抽屉标题挤窄/换行展开与关闭按钮 | 标题 flex/min-width/两行截断，操作不收缩且不换行；提供“查看完整任务名称” |
| 长名称折叠项干扰诊断绑定 | 执行诊断绑定专属 data 标记；浏览器打开长名称后再打开诊断，确认两层互不混入 |
| 领域弹窗未继承原页面 Token | 挂入真实 `.c-page`，恢复边框、行分隔和按钮；查看 900px/342px 列表及具体编辑器 |
| 领域编辑再进入时标题滚出视口 | 重置容器 scrollTop，聚焦使用 preventScroll；查看窄屏返回/标题/表单 |
| 领域关系表单的 action 字段遮蔽 form.action | 使用属性读取，保留弹窗提交/草稿和原上下文；真实关联→角色→解绑测试 |
| 工位更名输入区与保存按钮侵入相邻列 | 隐藏状态遵守 hidden，flex 收窄输入而不收窄按钮；真实保存 303 成功，再查看最终行 |
| 观察目标右侧表头省略号 | 1440 断点减小状态列右内边距；两类主表重新截图，保留全部表头和值 |
| 结果链接缺少原产品样式 | 黑色下划线链接、结果标题和行分隔，语料返回链接也用原 ink Token；查看桌面/窄屏五篇成果列表及语料返回条 |
| 浅底说明文字对比度不足 | 使用现有 body 色替换本次局部低对比度 subtle 色；六组实际颜色 AA 对比度全部通过 |
| 不同入口沿用旧草稿请求身份，可能显示另一轮成果 | 提交前将领域、来源、顺位/精确 ID、上限与评论模式绑定幂等身份；浏览器保留已接纳旧请求草稿后发起 51 篇深采，核验真实新 POST；原 503 重试仍沿用同一身份 |
| 抽屉关闭后迟到读取重新写入 URL，上下文可能被旧响应改变 | 读取按代次与打开状态生效，控制回执不重开已关闭抽屉；浏览器延迟真实读取回执，关闭后交付响应，核验原 URL 保持 |
| 内部发现原因/失败代码进入主文案 | 列表与抽屉显示业务中文，原发现代码保留在诊断；503 显示服务暂时不可用并保留草稿/请求身份 |
| 集合未冻结时阶段出现 0/0 | 固定作品显示“待确定”，阶段明确“范围待确定”，不渲染假完成比例 |
