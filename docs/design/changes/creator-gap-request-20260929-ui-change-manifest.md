## 用户结果与范围

Mog 确认“补采缺口”指补采未取得完整笔记内容的作品，包括详情、标题、正文、媒体、评论等；缺评论时可重新打开一次详情页，同时采集最多 30 条评论。本候选修复同一作品多条 Domain usage 导致请求回滚的问题，并增加有合格详情但存在**可证实评论缺口**的人工候选。缺详情者冻结详情、最多 30 条评论（含回复）、媒体及 OCR/ASR；仅缺评论者仍打开详情页并冻结最多 30 条评论（含回复），每条主评论最多 2 条回复，但不重复申请媒体下载。结果以实际 Package、Receipt 和材料为准。

评论候选只接受可证实的情形：详情中平台评论数已知且大于零却没有合格评论包或已接纳评论包中没有该作品的主评论材料；最近评论回执为 `partial` 且停止原因为 `comment_area_end`、`no_progress` 或 `collector_stopped_without_target`；或历史回执在平台计数未知时以 `no_progress / 0 / 0` 错报完成。已有被接纳的旧评论包和主评论材料，但缺 `commentCollection` 元数据时，只能保留完整度未知，不能冒充“没有评论包”。风控、人工停止和身份冲突的部分回执不由此按钮立即重开页面。新的插件从详情原始互动值到 batch 执行保留 `null`、空白、布尔、负数和无效文本为未知；只有互动面已有有效数值证明加载完成时，原样空串才是平台的已知零。正文 `UNKNOWN`、标题空值、媒体数 0 本身不证明缺采，不能触发自动重采。其余字段缺口须依来源与实际媒体状态作逐项判定，不能把 40 篇正文 `UNKNOWN` 的作品当成 40 篇缺详情。

巡查自动跟进采用显式开启的创作者规则和另一个精确用途的 `deep_archive` 人工授权；默认关闭，每轮每目标至多 3 篇，只处理**巡查逐条已接纳、且从未作为根建档的已接纳记录出现、没有合格详情**的作品。中断巡查中的已接纳作品仍可参与；未完成扫描不能推进“上次巡查成功”或主页目录基线。目标事务内复核开关，任务冻结规则版本，关闭规则后排队任务不能被领取。自动跟进与根建档共享每目标工位背压，每 tick 为自动跟进保留正数预算。根建档保持完成，不被巡查回写。人工“核查并补采内容缺口”可检查所有已登记的根建档和巡查作品的缺详情/评论候选，至多 200 篇，包括无根建档或扫描中断时的已接纳作品。自动跟进不持续重试评论部分回执。
