## B. 产品是什么：请先理解再画

Linggan Intelligence 是一个**受控的持续观察与证据沉淀系统**。它帮助操作者长期关注创作者和关键词，并把一次次平台侧观察组织成可追溯的证据与材料；它不是营销 BI，也不是爬虫开关面板。

一条实际业务链的顺序如下。请用它决定信息层级，但不要把它画成花哨的无限流程图：

```text
观察目标 / 人工同步作者
  → TaskSpec（冻结的采集说明）
  → 租约任务被执行工位领取
  → Attempt（一次执行尝试）
  → 不可变 CapturePackage（捕获包）
  → Submission Receipt（接纳回执）
  → Evidence / Material（证据与作品材料）
  → Materialization（本地材料物化）
  → Media Processing（OCR / 缩略图 / 音频 / ASR / 视频 OCR）
```

其中「调度」只决定某个已授权工位是否获得可领取的工作；真正的平台读取由 Browser Producer 在受控条件下执行。服务端不会把“安排过”误写成“已经采集成功”。

### 五条不可破坏的产品真相

| 维度 | 这是什么 | 绝不能被 UI 误说成什么 |
|---|---|---|
| 真实性 Truth | 某事实是否被证据支持 | 有目标、有任务、已接纳就等于事实为真 |
| 覆盖度 Coverage | 在已知范围内观察到了多少 | 一次成功或一条材料就等于全部覆盖 |
| 有效性 Validity | 证据是否满足接纳、版本、授权等条件 | 有材料就一定可用于任何结论 |
| 新鲜度 Freshness | 最近一次可靠观察距今多久 | 最近派单就等于最近成功 |
| 运行状态 Operation | 调度、租约、工位、队列、回执的工作状态 | 工位在线、配额有余就等于采集一定成功 |

另外必须一直保持以下区别：

- `UNKNOWN`（未知）不是 `0`，不是「正常」，也不是「没有问题」。
- `PARTIAL`（部分）不等于无效；`ACCEPTED`（已接纳）也不等于事实已被完全证明。
- 租约还在、任务已派出，不等于执行成功；租约过期也不等于现在仍有执行权。
- 创作者目标的入口就是该创作者主页，因此创作者目标名在作品详情作者名缺失时即作为作者显示（2026-09-04 DEC-作者合并）；关键词目标是检索词不是人，永不填补作者。
- 本地拿到了某项媒体，不等于该作品的所有媒体都拿到了，更不等于可公开传播。

## C. 谁用它、在什么时刻用

主用户是产品负责人/运营负责人，不是纯工程师。每天打开这页的主问题不是「有多少任务」，而是：

1. **现在有什么真的需要我判断或处理？**
2. **系统正在观察谁、哪些对象已经到期、下一次会发生什么？**
3. **一个异常到底停在调度、租约、浏览器执行、接纳，还是媒体处理？**
4. **一条证据为什么可以/不可以被使用；它的作者、观察目标、覆盖与材料完整度分别是什么？**

默认页面必须先回答问题 1。不要把首屏做成大 KPI 墙、空泛成功率或流量营销图表。

## E. 信息架构：一个壳、六个工作面

请做一个单页工作台，在浏览器内切换六个视图；不需要真实路由。左侧导轨顺序和中文名称固定如下：

1. `待处理`（默认）——需要人作判断的异常、限制和未知。
2. `观察目标`——长期观察的对象、意图、频率、最近可靠结果和限制。
3. `生产流`——从调度到证据/媒体的阶段化运行态，主要用于定位哪里停住。
4. `执行任务`——单条 TaskSpec 的 Attempt → Package → Receipt 可追溯链。
5. `执行工位`——安装、认领、租约、能力、风险与配额；不是账号健康总览。
6. `证据库`——作品证据、作者、采集来源、覆盖、材料和处理状态。

全局壳层包含：

- 顶部：产品名 `灵感情报`、当前视图标题、时间口径提示、明显但不抢眼的「讨论样例 / 非实时」标识；
- 左侧：上述六个入口、当前视图、极少量状态标记；
- 主区：当前用户任务；
- 可选右侧 Inspector：点选待处理项、目标、任务或证据后展开；支持 Escape 关闭；
- 小屏（约 390px）时，左侧导航收为顶部/抽屉导航，Inspector 改为全宽底部或覆盖层，不能出现横向滚动。

### E1. 待处理：默认首屏

布局建议为「主清单 2/3 + 右侧事实轨 1/3」，而非四张同权卡片。

- 顶部一行显示：`4 项需要判断`、时间口径、`SYNTHETIC · NOT LIVE`。
- 主清单使用四条有充分文字的诊断行。每行要可打开右侧 Inspector；Inspector 分为「事实」「尚未知」「不应推断」「下一步需要什么回执」四段。
- 右侧事实轨只放低频、可解释的运行摘要：目标 3、已认领工位 1、日配额 88/200、当前无 live lease、调度最近一次为部分完成。每一个数字旁要有含义或限制，不做仪表盘。
- 提供演示场景切换：`有待处理（默认）`、`读模型未接入`、`全部需人工复核`。切换必须只改变本地演示数据，且场景名称本身显示在页面上。

### E2. 观察目标

- 用密度合适的表格/列表展示 3 个样例目标；不要做社交平台卡片墙。
- 行点开后在 Inspector 中展示：目标身份、观察意图、目标状态、最后一次派发、最后一次可靠成功、计划/到期、Coverage、权限或风险限制、关联任务摘要。
- 关键词目标必须展示「尚未派发」而不是一串假的零值。
- 可以放「查看需要的回执」按钮；不能放真的「新建目标」「暂停巡检」「马上巡检」可执行按钮。

### E3. 生产流

用六个连续但可单独阅读的阶段表达运行态：

`调度资格 → 租约/领取 → 浏览器执行 → CapturePackage → Receipt/证据接纳 → 媒体物化与处理`

- 每段显示阶段的职责、最小状态、已知数字（若有）、限制/未知。
- 当前页面没有完整的语义阶段读模型，因此不要凭空给六段填满“成功数、成功率、耗时曲线”。对没有可靠投影的阶段，直接显示「读模型尚未接入」或「未知」。
- 深色仪器流可以只用于这一小块，以突出连续过程；不得把整个产品变成黑绿终端。
- 点击阶段应打开解释它与前后阶段的因果关系，例如「租约过期后不再代表当前执行权」。

### E4. 执行任务：可追溯而不是任务清单 KPI

至少放两个可展开样例：

1. **已恢复的作者页超时**：曾发生 `page_timeout`，随后同一冻结任务被恢复并得到可接受回执。表达为「一次失败已被记录，后续步骤成功」；不要把早先失败从历史中擦掉，也不要因此断言根因消失。
2. **租约已过期的任务**：状态为 `EXPIRED`，没有 live lease。必须提示「已无当前执行权」，而不是红色高亮成“正在运行的故障”。

每条任务的时间线固定按：

`TaskSpec（目的/来源/采集 lane） → Lease（所有权/有效期） → Attempt（本次尝试） → CapturePackage（不可变） → Submission Receipt（接纳结果）`

任务表中至少有：来源（人工/定时）、lane、当前任务状态、最近 Attempt、Package、Receipt、失败/恢复说明、时间。状态徽标必须用文字，不只靠颜色。

### E5. 执行工位：产能判定要克制

此视图要回答「此刻是否具备接活条件、欠什么、为什么」，而不是把安装记录误画成员工座位图。

- 顶部结论样例可写「可以接活」，并写清它只基于：1 台已认领工位、插件已报到、配额读数可见、无当前风险暂停。它**不含**账号资格判定。
- `账号不参与判定` 必须作为黄色/中性限制显著出现，文字说明「未纳入判定 ≠ 账号健康」。
- 显示日配额 `88 / 200`、当前 live lease `0`、历史未认领安装 `5`。
- 能力矩阵需单列 `author_profile`：它有成功、也有 12 次 `page_timeout`。请将「能力可用」「一次执行失败」「尚未验证」分开：超时是任务级事实，不能直接标为能力不支持。
- 不需要显示真实浏览器版本、Cookie、账号、主机名或任何敏感信息。

### E6. 证据库：事实、目标、作者和材料不能混为一团

用 1–2 个作品条目和 Inspector 展示成熟的证据阅读体验，而不是瀑布流内容消费页。

- 列表至少有：作品标题/短摘要、来源平台（可写「受控平台来源」而非真实链接）、发现/观察时间、作者（单一字段）、接纳状态、Coverage、材料数与处理状态。观察目标不进列表，只在 Inspector 表达。
- 样例要故意展示一个关键词目标、详情未采到因而「作者：当前未知」的作品，其观察目标只在 Inspector 出现。创作者目标的作品**不应**出现未知作者。
- Inspector 里明确分栏：`作品事实`、`来源与溯源`（含作者与来源监控）、`Coverage`、`CapturePackage / Receipt`、`材料与媒体处理`。
- 可用样例：材料 Coverage `2 / 4 · PARTIAL`；本地媒体已物化或处理完成只表示对应 lane，不能推广为作品完整或可公开。
- 「立即复观测」「补采」如出现，必须是禁用的需求提示，不能让 HTML 假装产生了新的回执。

## F. 必须使用并正确解释的状态字典

状态应以中文说明为主，机器枚举可用 11–12px 等宽字附在后面。不要给状态发明百分比。

| 显示建议 | 枚举 | 用户含义 |
|---|---|---|
| 未知 | `UNKNOWN` | 尚未得到足够事实；不能渲染为 0 或绿色正常 |
| 部分覆盖 | `PARTIAL` | 已得到一部分，但范围尚不完整 |
| 已接纳 | `ACCEPTED` | 接纳合同通过；不证明内容事实或所有 lane 完整 |
| 不适用 | `NOT_APPLICABLE` | 某一步/某材料对该对象不适用，不是失败 |
| 本步骤完成 | `COMPLETED_LIVE_STEP` | 一个现场步骤完成，不外推到整个链路 |
| 待领取 | `PENDING` | 有合格工作，但尚未由工位领取 |
| 进行中 | `IN_PROGRESS` | 仍在有效执行范围内；需要搭配租约判断 |
| 租约失效 | `EXPIRED` | 过去的所有权已结束，不代表现在仍在执行 |
| 终态 | `TERMINAL` | 处理在定义的终态停止；需看原因，不等于全部失败 |
| 未核实 | `NOT_VERIFIED` | 一个身份/字段未获验证；不得用相邻字段填补 |
