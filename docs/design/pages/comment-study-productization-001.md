## 1. 用户表面与保留区

分类：**交互＋状态／语义＋行动的混合变更**，不是普通美化任务。只调整评论研究，不重构作者档案、执行工位、全局导航或首页。

源码现状 `comment_study.html` 有 `study-toolbar`、五个 data-view Tab、`study-run-picker`、`study-tab-result` 和 `study-dialog`；还有独立 inline style 与覆盖概览的 inline IIFE。新实施必须将这两个 inline 块迁入现有页面模块，保留观察图功能；不能把 JS 改成 ES module 后仍保留依赖旧全局函数的 IIFE，造成两个初始化入口或两次绑定。

**保留：**共享 HEADER/SIDE_NAV/shell、白场与信号红、概览上半区读数的布局、`.study-observation` 图表／表格、7/28/56 天切换、覆盖状态提示。读数可纠正口径和跳转，不以“保持外观”为由保留错误计数。当前 `.study-observation` 的 CSS 迁移为同一有效声明，不再用第二层覆盖。

**变更：**导航为 overview/comments/runs/problems 四个 data-view，中文分别概览／用户评论／研究批次／用户问题。移除全局 Run 下拉对所有页面的污染；只在批次页或明确批次过滤中出现 runRef。

## 2. URL 与返回行为

浏览器 URL 仍使用 domain；新增可持久字段 view、q、workRef、runRef、problemRef、commentExternalId、state、cursor、detail、panel。data-view 与 view 均使用 overview/comments/runs/problems。

- 切 Tab：保留 domain，保留各 Tab 自己的筛选，不把上一页 runRef 偷带成全域过滤。
- 评论详情：`view=comments&workRef=...&commentExternalId=...&detail=comment`；抽屉关闭恢复筛选／游标／滚动。
- 批次详情：`view=runs&runRef=...`，panel=targets/signals/requests/method；这些不是第五个一级 Tab。
- 问题详情：`view=problems&problemRef=...`，原声链接可进入评论详情，并提供返回问题。
- 旧书签 targets＋runRef 映射到 runs/targets；pending 映射 problems 的未建档表达区；这是 URL 翻译，不保留旧研究执行路径。

后端 UUID／domain 守卫必须重新验证 URL。返回位置只保存定位信息，不缓存受限正文或旧请求 snapshot。浏览器 Back/Forward 走同一状态解析函数，不能只靠按钮 onclick。

## 3. 概览

### 3.1 上半区

保留已经认可的读数／观察图层次。采集观察与知识研究分开：原材料数量不代表模型理解成功，ObservationSeries 的日期也不等同用户发帖／需求出现日期。

| 区域 | 显示 | 点击落点 |
|---|---|---|
| 用户评论读数 | 当前可检索有效评论；索引未齐标部分 | 用户评论，同 domain |
| 研究覆盖读数 | 不同已研究评论，不是 Target 累加 | 用户评论，studied |
| 用户问题读数 | 当前有可读定义的问题数量，支持不足可区分 | 用户问题 |
| 最近研究状态 | 语义阶段＋归并待办＋执行状态分开 | 对应 Run |
| 观察图／表格 | 原有 7/28/56 日材料观察口径与缺失数据状态 | 日期下钻必须带同一时间口径 |

缺数显示“—／未记录”，不以 0 填充失败请求。新汇总查询失败时，原来成功加载的独立图表可保留并标各自 asOf，不用整页错误替代。

### 3.2 下半区，只展示可回证内容

三个连续信息区，而非三排大卡片：**问题新增依据**（标题＋新增不同评论数＋一条原声）、**办法与经历**（solution/experience Signal 原声＋作品）、**未闭合表达**（来自现有 resolution/pair 的状态计数和入口）。无问题时仍可看办法／经历；不足两条证据的表达不被藏掉，也不被升级为 Problem。

删除把完全相同 proposition 直接分组为“主题洞察”的表现；本轮不引入新的语义聚类。下半区的预览条数只是展示裁切，旁边总数必须来自服务端聚合，查看全部可完整分页。不能从取回前 100 条 Signal 中计算全批次类型占比。

## 4. 用户评论

默认连续表格／列表，不以一屏铺满图片卡片代替检索。工具栏：字面搜索、作品过滤、研究状态、声音角色；批量选中后出现“研究所选评论”，未选时不展示无效批量按钮。

| 列 | 优先级／行为 |
|---|---|
| 选择 | 只允许服务器判断当前可研究者；不能由前端猜身份 |
| 原声 | 第一阅读优先级；列表最多三行，点击完整查看；不因标题长压缩图片 |
| 所属作品 | 一至两行标题＋可见标题来源，点击作品详情，不复制长 OCR |
| 研究状态 | 最新尝试＋当前有效结果有冲突时同时解释，如“本次失败，仍有历史有效结果” |
| 作者／时间 | 作者昵称可空；明确观测时间，不伪称发布时间 |
| 互动 | 有可靠评论点赞才展示；未知为“—”，不推断为0 |

评论详情顺序：原文 → 作品及父评论语境 → 清洗文本和确定性原因（折叠）→ 历史研究记录 → 相关 Signal／用户问题。原声与系统概括使用不同字体角色，绝不把系统概括排成引用。

纯 emoji／纯无语义 @ 直接不进入正常列表；混合语义原文完整保留。身份未知材料可以阅读，但研究按钮说明具体不能研究的原因，不要求用户手工为每条补身份。

## 5. 研究批次

### 5.1 列表与详情

列表核心列：开始时间、研究方法、选中／覆盖作品、目标评论数、语义进度、归并待办、执行状态、来源（手动／未来自动）。内部 UUID／lease／batch ID 不占主要列，放详情。

详情主区域展示准确冻结范围和三项预算；子页签是目标评论／研究结果／调用记录／本次方法。方法页必须读该 Run 的 policy 与 snapshot，不读“当前默认”。停止、暂停与原因靠服务器回执更新；不乐观标为已停止。

### 5.2 发起研究的唯一流程

保留现有 `study-dialog` 作为受控入口，不新开一级“设置”页：

```text
选作品或评论 → 选不可变方法版本 → 设本次三项预算
             → 查看默认排重与当前可用量 → 点击“开始研究”
             → committed receipt → 打开该 Run
```

表格搜索为服务器搜索全部作品，不再叫“筛选已加载作品”。跨页选中使用稳定 workRef/commentKey Set；切换筛选不丢已选对象，但显示“已选 X，当前页 Y”。只能全选当前页，不把“全选全部筛选结果”做成没有范围快照的暗动作。最多100作品限制显示在选择区，不限制浏览页数。

“保存研究策略”从开始的必经操作中移除。用户改本次预算直接随最终命令提交；修改方法说明则另存新版本后返回，清楚区分“方法默认值”和“本次预算”。开始前说明 **确认即授权模型研究；新研究目标只来自所选材料，归并可比较同领域已有问题与合格表达；额度覆盖提取和归并，可能有部分结果**。

回执如 targetCount<预算且存在待索引／并发已处理，展示实际冻结数和原因；不循环重发直到凑满，也不把未入包评论偷偷追加。no_work 显示已无符合此模式的材料；index_pending 显示本地清洗处理中；两者不建立空 Run。

### 5.3 方法可见与可迭代

提供“查看方法／复制并编辑”入口，展示三阶段完整说明、Schema、固定证据规则、cleaner 版本和模型配置。规则和 Schema 只读；用户说明可改。保存产生新版本，新旧可人工并排阅读；本轮不建设自动 A/B 评分平台。

历史未记录的内容按字段显示“未记录”，不把页面空值自动替换为本次系统默认。模型调用失败的原始返回内容不直接放到 HTML；安全错误码、usage 和完整合法请求在受保护详情中有明确位置。

## 6. 用户问题

第一层是长期问题列表，不是每条评论的“问题标题”：展示 title、定义的一句摘要、不同评论／作者／作品数、最近新增依据、支持状态。主要排序固定可翻页，不由前端拼接首屏数据重新排序。

点开问题，顺序为：定义与适用边界 → 纳入／排除条件 → 当前有效原声 → 来源分布与时间 → 当时匹配 revision 和历史记录。每条依据都可回到具体评论和作品；同一评论多条 Signal 在同一原声下呈现，不刷出重复卡片。

原有待归并吸收为本页的“尚未建档表达”，可按 deferred_novel、deferred_ambiguous、deferred_context、retrieval_incomplete 等筛选；不新增“待确认问题”要求人工批准。协议错误和 provider 失败同时链接批次诊断，不把机器错误说成“用户观点矛盾”。

| 情况 | UI 文案原则 |
|---|---|
| 两位作者形成问题定义 | “不同作者的评论支持”，不写“普遍需求已验证” |
| 只有一条新表达 | “尚未建档”，仍可查看原声；不是无价值材料 |
| 后续重研 no_signal 使支持减少 | 支持数诚实减少，问题身份保留；可说明历史依据变化 |
| 非 seed 支持受限 | 对应原声和计数剔除；其他证据继续显示 |
| 定义 seed 受限 | 标“定义依据受限”，隐藏定义／边界，不能用一条旧原声冒充完整证明 |
| 没有问题但有其他 Signal | 页面显示真正空问题态，保留通往办法／经历的路径 |

## 7. 样式、密度、可访问性

运行时 CSS 只消费 `apps/api/src/local_web/lids_tokens.css` 现有 `--lgi-*` 语义 Token；原型中的 `--ink-*`、`--sp-*` 不能另复制一套进业务。沿用当前 LIDS 的中文字体、证据字体、字号阶梯与单一焦点环。白场为主，点阵只用于允许的边缘／状态识别，不大面积填黑。

四 Tab 使用文字＋信号下划线；状态使用文字＋符号＋颜色，不只靠色彩。减少内嵌边框和多重卡片，避免 hover-lift、厚重阴影或新渐变。表格主阅读区不显示无意义的01/02层级编号。

右侧检查器顶边对齐全局 Context Bar 下缘，不遮一级导航；读取共享 shell 真实尺寸，用单一 CSS 变量而不是复制猜测高度。抽屉只影响内容区，Esc 关闭、焦点圈定、关闭返回触发点；页面级模态与 drawer 各自有正确 aria 属性，不能所有面板永久 aria-modal=true。

至少在1440、1024、390宽度与200%缩放下检查。窄屏优先压缩次要列／表格横向滚动，不把长原声截成不可访问文本；保留表头语义。长中英文、空标题、极大数字、真实0、未知值、部分状态均有 fixture。Reduced Motion 下关闭非必要动画。

## 8. 状态词典与验收

| 状态 | 应呈现 | 禁止呈现 |
|---|---|---|
| 目录尚未索引完成 | “已索引部分，另有 X 待处理”或待处理数未知 | “全库没有结果” |
| 请求／数据库失败 | 错误与重试入口 | 空列表＋0条 |
| queued | 排队 | 已调用模型 |
| Run.completed | 提取结束，单列归并待办 | 全部理解完成 |
| no_signal | 已处理，未提取到信号 | 未研究／失败 |
| needs_context | 等待可用语境；不无限重试 | 无用户需求 |
| retrieval_incomplete | 候选检索尚不完整 | 全库无匹配／新问题 |
| budget_stopped／dispatch budget_exhausted | 预算停止＋保留部分结果 | 无待办／已全部完成 |
| source restricted | 原声与派生内容同步降级 | 遮原声但泄漏 frame／prompt |
| legacy_unrecorded | 历史方法未记录，结果仍可查 | 自动套最新方法 |

验证必须点通：总览数→筛选后的评论→作品／父语境→该 Run 的真实方法→Signal→用户问题→返回原位置。每个按钮都要有成功、无工作、失败、部分、受限的真实回执 fixture，不用截图文字证明 API 行为。

固定源码 `apps/api/src/local_web/comment_study.html/js/css` 与 LIDS/UI 执行合同，链接在架构手册来源目录。上传的 Design System v7 规定白场、边缘纹理、显式状态与文字 Tab；示例数值、假运行文字以及所有模拟动作均不继承为产品事实。
