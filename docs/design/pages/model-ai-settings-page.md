## 页面任务

用户在一个页面完成：保存供应商连接、用最小合成 V1 JSON 请求测试模型、选择默认研究模型并设定调用上限、看懂后台执行器是否在线以及近期调用是否成功。页面不提供旧 daily、backfill、trial、自动计划或评论批次操作；真实研究只由评论研究页的「开始研究」发起。

## 实现与组合

- 由 `apps/web` 的 React 应用提供（DEC-0010）。服务器只为 `/settings/models` 返回前端入口，`/settings` 由服务器跳转到这里；读写仍走 `/api/local/model-settings*`。
- 外壳为 React AppShell，与旧页面的 AppShell.tsx 结构一致，样式来自同一份 shell.css；页面样式只消费 --lgi-* Token。
- 普通入口的四个真实视图固定为「AI 能力 → 模型连接 → 运行与用量 → 高级配置」，由共享可折叠左栏承载，URL 仍为 view=capabilities|models|runs|advanced。
- 左栏和面包屑已经说明页面身份，主区不重复渲染 SYSTEM / AI OPERATIONS、可见的「AI 设置」标题、说明或“刷新设置”按钮；正确的无障碍页面名称保留为隐藏 h1。
- 旧 section= 深链接只为兼容历史入口保留，不混入普通四视图；它们继续使用原有数据与动作合同。
- 内容区自己滚动，内容再长也能看到底部的调用记录。

## 动作与请求身份

- 停用/启用连接带修订号提交；保存默认配置带当前配置编号；都在回执后才更新页面。导航切换是纯读取，不写入配置；本页不提供独立“刷新设置”按钮。
- 每个写操作有自己的请求编号：同一内容在「结果未确认」后重试时沿用原编号，内容变了或服务器已明确答复时换新编号。服务器按编号去重，模型测试只计费一次。
- 编辑连接会产生新的连接版本，模型在新版本下重新登记；在同一个对话框里输入不变时再点「保存并测试」，只重试测试，不再建新版本。
- 由其他入口建立、协议不在可选列表里的连接，编辑时如实显示原协议，不悄悄改成列表第一项。
- 未通过 V1 JSON 测试的模型在默认模型下拉框里不可选；服务器仍会再校验一次。

## 数据诚实性

保存设置和测试都不会外发真实评论；测试只发送一条合成 V1 JSON 请求。调用记录是回执，不是新的研究入口，不保存评论正文或模型原始输出。故障详情只显示受控错误码与下一步，不泄漏凭据。


## 图片文字识别的 OCR 模型（2026-10-22 候选增量）

`AI-GEN1-OCR-MANUAL-454` 在“AI 能力”中增加“图片文字识别”，其详情与高级工作配置共享同一个 `ocr_recognition` 配置表单。`OCR 模型` 下拉复用已有连接和模型能力，可选现有 DeepSeek 或统一运输层支持的其他模型，不增加 API Key 表单。本文早期“真实研究只由评论研究页发起”的限定，仅对本项获准的当前作品图片 OCR 局部替代；其他任务不变。

保存配置只影响后续批次，不启动执行器、不改变开关、不发测试图、不回填历史；每图仅一次、失败停，输入/输出/超时沿已有模型配置。每日额度仍可选不设上限，未知用量/费用不填零。文本测试通过只说明既有调用资格，不证明视觉效果；不以数字探针作为业务识别前置。许可绑定具体端点、任务与图片材料，换连接不继承旧地址许可；证据库发起前还需确认本篇冻结清单。

界面、后端与隔离验证范围见 [OCR 手动识别计划](../../plans/active/ocr-manual-recognition-454.md)。此处记录候选合同，不声明已合并或部署。
