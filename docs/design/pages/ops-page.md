## 1. 页面责任

- **用户任务**：Mog 和运营查看我方账号、每一条发布登记及其数据、每人每天的链接打开和加微，找出还没补阅读量的帖子和爆款。
- **三秒答案**：这个月发了多少条、出了几篇爆款、哪些帖子的阅读量还没补。
- **五秒主动作**：切到某个运营人、某个平台或某段日期，看对应的发布记录。
- **非目标**：
  - 本步不做任何写入：新增、编辑、删除、补阅读量、导入、同步数据，随登录（D4）之后接入；
  - 不做总览五块（D3，见 [PAGE-OPS-002](ops-overview-page.md)）；
  - 不做自动发现（D5）；
  - 不做团队执行和管理周报（随选题池）。
- **事实边界**：页面上的数据是内容工作台导出的镜像，只说明「导出那一刻工作台里是这样记的」（OPS-LEDGER-001 §1）。切换（D6）之前，录入仍在工作台。

## 3. 发布记录

### 3.1 发布记录的读数条已移除（2026-10-21）

Mog真实页面批注明确删除运营中账号、本月发布、有效发布、本月加微、本月爆款整条读数，不占位。列表仍保留分页结果数和对应列里的未知/待补状态。统计接口及侧栏数据截至时间继续沿原合同，不用摘要读取故障阻断可读列表。

### 3.2 筛选

- **运营人页签**：「全部」加每个发布人（按工作台写法的发布人名）。工作台另有按负责人编号的页签，那来自人员分组，随 D4 建人员后再加。
- **平台页签**：总数据 / 抖音 / 小红书。功能与工作台相同；外观按当前LIDS改为文字页签，不用方块分段控件。
- **账号搜索**：按账号名包含匹配。工作台这个输入框实际拿输入的文字去精确匹配内部账号编号，输入账号名查不到；Linggan 按它的本意修正。
- **日期范围**（开始、结束、清空、取消、确认）：与工作台相同。日期按北京时间的业务日，含首尾两天。
- **排序**：发布时间从新到旧，同一时间按创建时间从新到旧，与工作台一致。
- **新增「待补阅读量」**：只看小红书、阅读量还没填的帖子。发出满 7 天仍未填的排在前面并标出。
- 筛选条件写进地址栏，刷新或分享链接后保持不变。
- **布局**：运营人页签单独占一行；平台页签、账号搜索、日期范围、待补阅读量和两个灰色写入按钮在下一行。运营人多到一行放不下时换行，不藏起任何人；手机上可横滑。
- 连续切换筛选时，只显示最后一次选择的结果。

## 4. 账号管理

- **页签**：运营人（全部 + 每个负责运营），放不下时换行；右侧计数「总账号 N · 运营中 M」；「新增账号」灰色不可点。
- **列与顺序同工作台**：序号、平台、账号名称（有主页链接时可点开）、设备编号、粉丝、IP 所在地、运营人、账号状态、账号健康、保留、账号备注、操作（灰色不可点）。
- **已删账号**：账号状态显示「已停用」，其余未知字段显示「—」。
- **账号健康**：改为运营手动填写（Mog 2026-10-13）。D2 只读阶段这一列统一显示「未填」；填写入口随录入功能（D4b）开放，选项沿用工作台六档（重点培养、健康、观察、低效、风险、可暂停），到 D4b 时再确认。不再按发布数据自动计算，也不显示分数。
- **排序**：负责运营、平台、账号名依次升序，与工作台一致。
- **范围**：只列在台账的账号（与工作台一致）；已在工作台删除的账号只出现在发布记录的「账号」列，标「已停用」。
- 空值一律显示「—」；粉丝数为 0 时显示 0。

## 5. 每日数据

- **页签**：运营人，放不下时换行；右侧说明「迁入自内容工作台 · 发布数按发布记录自动统计」。
- **列与顺序同工作台**：日期、星期、运营人、执行状态、发布、打开、加微、添加率、爆款、月累计加微、月累计发布、操作（灰色不可点）。
- **发布**：按发布人名和业务日从发布记录重新统计，重复登记只算一次。工作台的旧值可能偏高，例如 9 月旧合计 553，重算 387。
- **添加率**：加微 ÷ 打开；打开为 0 时显示「—」。
- **爆款**：当天发布的小红书帖子中，最新阅读量 ≥ 5000 的篇数。工作台这一列是手填数，不迁。
- **月累计加微、月累计发布**：按北京时间的当月逐日累计。
- **打开、加微**：按工作台原值显示。工作台里这两列默认是 0，0 和「没填」分不开；页面在列头说明里写明这一点，不另作推断。
- **执行状态**：D3 按新口径恢复，四个标签与判断顺序见 [PAGE-OPS-002](ops-overview-page.md) §4。D2 时不显示这一列（Mog 2026-10-13）。
- **范围与排序**：默认显示最近 200 行（与工作台一致），日期从新到旧，同一天按运营人。
- **不分业务**：每日数据按运营人记录，没有按业务区分。选了某个业务时，页面照常显示全部运营人的数据，并在表格上方说明「每日数据不分业务」；读数条里的「本月加微」同样不分业务。

## 7. 共用状态词典

| 状态 | 用户应理解 | 禁止暗示 |
|---|---|---|
| 只读 | 切换前，录入和修改仍在内容工作台；这里只能看 | 按钮坏了、权限不足 |
| 未接入 | 系统还没有这项能力（如有效发布要等自动发现） | 数值为 0、没有有效发布 |
| 未检查 | 系统还没去主页核对过这篇帖子 | 帖子不存在、被删除 |
| 待补 | 小红书阅读量还没人填 | 阅读量为 0、没爆 |
| 选填 | 抖音播放量不要求必填，也不判爆款 | 漏填 |
| 爆款 | 小红书最新阅读量 ≥ 5000 | 外部爆款口径（点赞） |
| 日期存疑 | 工作台里写成了 2024 年 | 日期已核实 |
| 已停用 | 这个账号已在工作台删除，旧状态未知 | 账号被平台封禁 |
| 账号未知 | 工作台里这条记录没有关联账号 | — |
| 封面未迁入 | 这条记录在工作台没有封面，或封面还没拷来 | 帖子没有图片 |
| 「—」 | 没有值或未知 | 0 |
| 读取失败 | 这次没读到，可以重试；页面保留上一次的筛选。提示里写中文原因（如「连不上本机服务」），几处同时失败合成一条，一次重试全部重读 | 没有数据 |
| 没有符合条件的记录 | 当前筛选下为空，可清除筛选 | 系统里没有数据 |

## 8. 依赖与数据

- **数据**：OPS-LEDGER-001 的五张表，只读。只看在最新导出中的记录（`missing_since_batch_ref` 为空）；被合并的记录只在「另有 N 条重复登记」中出现。

- **封面**：新增一张封面表，记录发布记录与本机媒体文件的对应关系（文件哈希、类型、来源路径）。用一次性的导入命令把 Mog 拷来的文件放入 Linggan 本机媒体目录，只认工作台导出里登记过的路径。经只读路由按记录号取图，不能按任意路径读文件。导入规则 `ops-cover.v2`：路径上任何一级是链接的文件都拒绝，单独计数；存储前按预览时的哈希、大小和类型复核，文件被改过就整次停止、不登记。
- **共享文件**：一级导航（`AppShell.tsx`）、`local_web.rs` 的路由注册、领域选择器（复用，不改行为）。
- **不碰**：其他一级页面的内容、领域管理、采集与语料的任何读写。
