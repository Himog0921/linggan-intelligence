## 1. 页面责任

- **用户任务**：Mog 和运营每天打开先看「这段时间加了多少微、离目标还差多少、哪里掉了、今天先处理谁」，再看每个人、每个平台、每个账号的产出。
- **三秒答案**：所选时段的加微与环比、目标进度（没设目标就写「未设定」）、今日必须处理的前几项。
- **五秒主动作**：切换时间段（昨日、本周、本月、自定义）；设或改本周、本月的加微目标。
- **非目标**：
  - 发布记录、账号、每日数据的任何写入（D4b）；
  - 自动发现我方帖子与「有效发布」（D5）；
  - 试新命中率、复用爆款数（DEC-0009 第③项）；
  - 团队执行、管理周报（随选题池重做）。
- **事实边界**：
  - 发布、爆款、待补阅读量来自迁入的发布登记；
  - 链接打开、加微来自迁入的每日数据；
  - 都只说明「导出那一刻工作台里是这样记的」。
  - 每日数据里的链接打开和加微默认填 0，「0」和「没填」分不开，页面在口径说明里写明，不另作推断。

## 2. 壳层与时间段

- 壳层、面包屑、业务选择、约束区与 PAGE-OPS-001 §2 相同。左侧栏「01 总览」从「未开放」变为可点，默认页仍是发布记录。
- 时间段页签：昨日、本周、本月、自定义（选开始和结束日期，含首尾两天，最长 366 天）。默认本周，与工作台相同。日期一律按北京时间的业务日。
- **环比按同样天数比**（Mog 2026-10-13；与工作台不同）：

  | 时间段 | 本期 | 上期 |
  |---|---|---|
  | 昨日 | 昨天 | 前天 |
  | 本周 | 本周一到今天 | 上周一起同样天数 |
  | 本月 | 本月 1 日到今天 | 上月 1 日起同样天数（上月天数不够时到上月最后一天） |
  | 自定义 | 所选日期 | 紧挨在前、同样天数 |

  工作台拿「本周到今天」比「上周整周」、「本月到今天」比「上月整月」，周初、月初几乎都显示下降。
- **业务选择**：
  - 发布、爆款、待补阅读量、平台占比、账号矩阵按所选业务计算；
  - 链接打开、加微、转化率、目标和长趋势里的加微来自每日数据，不分业务。

  选了某个业务时，在受影响的数字旁写「不分业务」。

### 2.1 只算已迁入的完整日子

迁入的数据停在工作台导出的那一刻，导出当天还没过完：那天的每日数据多半还没人填，发布也可能还没登记完。直接按日历算，本周、本月几乎总会显示「比上期下降」。所以：

- **算到哪一天**：只算到最近一次迁入的导出日的前一天（北京时间），时间段一行写「数据截至 10-12 22:43，按 10-11 及以前计算」。
- **本期**：日历上的本期里，只有已迁入的日子参与计算；时间段一行写明「按已迁入的 10-01 ~ 10-11（11 天）计算」。
- **上期**：按已迁入的天数对齐（本月 1～13 日、只迁入到 11 日，就比上月 1～11 日）。
- **一天都没迁入**（如导出后的本周）：数字写「—」，不比上期，不出下降提醒、自动结论和排行；排行、平台占比、账号矩阵均写「这段时间还没有迁入的数据」，不能写成「当期无…」；待补阅读量照常显示，它是全部积压，不随时间段变化。
- **目标**：「本期已完成」「时间进度」都按已迁入的天数算，写「按已迁入 11 天」。
- **图表**：长趋势和每日产出只画到已迁入的最后一天，之后的日子标为「还没迁入」，不画成 0。周、月桶只覆盖一部分时保留这部分累计，在图旁可见说明「按 YYYY-MM-DD 及以前计算」，悬停同样标明；不把部分累计说成整周/整月结果。覆盖判断只看截至今天的日子。
- 只有一天的时间段只写那一天，不写「10-12 ~ 10-12」。
- **适用期**：这条规则以「最近一次迁入」为准，只适用于数据靠迁入的阶段。D4b 起每日数据在 Linggan 里录入，届时要按录入的实际情况重定「算到哪一天」，不能沿用迁入时间。

## 3. 五块

### 3.1 加微与目标（工作台「经营结论区」）

- **主数字**：所选时段的加微（标题随时间段变为「昨日加微 / 本周加微 / 本月加微 / 当期加微」）与环比；上期实际值放在副行。
- **目标**：
  - 本周、昨日看今天所在 ISO 周的本周目标（周一也相同）；本月看今天所在月份的本月目标；自定义时段没有对应目标，写「自定义时段不对应目标」。显示和对话框保存使用同一周期。
  - **未设定**：写「未设定」和「设定目标」按钮。不拿估算值当目标，也不下「有缺口 / 节奏正常」的结论（Mog 2026-10-13；工作台用前 30 天日均 × 1.5 估算）。
  - **已设定**：目标值、本期已完成（目标周期内到今天的加微）、完成率、时间进度、每日还需（剩余差额 ÷ 剩余天数）、预计周期末（按当前日均推到周期末）。完成率 ≥ 100% 写「目标已达成」。
  - 目标旁写最近一次修改：「10-13 15:20 改为 500 · 本机」，可以展开查看修改记录。
- **自动结论**（最多 3 条，都由已显示的数字推出，不新增计算）：
  1. 设了目标时：已达成写「目标已达成（完成 X%）」；时间进度比完成率高出 20 个百分点以上，写「目标有缺口：按当前节奏预计完成 X%」；按当前节奏预计能完成（不低于 100%）写「节奏正常：按当前节奏预计完成 X%」；其余只写「按当前节奏预计完成 X%」，不下「正常」的判断（Mog 2026-10-14；工作台在这种情况下也写「节奏正常」）。没设目标不写这一条。
  2. 发布、链接打开中，环比降到 −20% 以下的取降幅最大的一项：「发布下滑是主因（环比 −X%）」。有效发布在 D5 前不参与。
  3. 今日必须处理里「下降 30% 以上」的运营人，取前两个：「某某、某某需今天复盘」。
- **设定目标**：
  - 对话框选「本周」或「本月」，填正整数。保存后写入一条修改记录，记录何时、改成多少、在哪台机器上改；登录（D4）之后再记到人。
  - 只能在本机设，见 §5。

### 3.2 漏斗与结算指标（工作台「转化漏斗诊断」）

- **漏斗**：发布 → 有效发布 → 链接打开 → 加微。
  - 有效发布在 D5 前写「未接入」，不参与转化率；
  - 环节转化：发布 → 打开 = 链接打开 ÷ 发布；打开 → 加微 = 加微 ÷ 链接打开；分母为 0 时写「—」。
  - 每个环节带环比；环比降到 −20% 以下的环节标「观察中」，都没有时写「各环节转化平稳，无明显掉点」。
- **转化率**：加微 ÷ 链接打开，与工作台相同。
- **爆款数**：所选时段发布的小红书帖子中，最新阅读量 ≥ 5000 的篇数，带环比。工作台是每日手填爆款数之和，7 月起恒为 0。

### 3.3 长趋势、每日产出、今日必须处理

- **长趋势**（「加微 · 爆款长趋势」）：
  - 粒度按日近 90 天、按周近 12 周、按月近 6 月，与工作台相同，不随时间段变化；
  - 加微来自每日数据，爆款按发布日计。
- **每日产出 · 按人按平台**：
  - 所选时段每天的发布量，柱子按小红书、抖音叠加；用运营人页签切换「全部」或某个人。
  - 可切换为加微（按人记，不分平台）。
  - 工作台给每个人一种颜色叠在一起；LIDS 没有分类色板，不能为每个人另造颜色，所以改用页签切换人。
  - 工作台的「点赞」切换不迁：点赞是手填旧值，过半为空，求和会把未知算成 0。
- **今日必须处理**：
  - 先列 5 项，其余折叠为「另有 N 项，展开」，点开在原处显示全部，可以收起（Mog 2026-10-14；工作台只写数量）。先排「高」，再排「中」，「中」里「本期记的都是 0」排在最前。
  - 三类：

    | 类别 | 规则 | 程度 | 建议 |
    |---|---|---|---|
    | 下降 | 运营人的发布、链接打开或加微，比上期下降 30% 以上（上期为 0 不比；本期没有这个人的每日数据，或这一项本期每天都记 0 时，链接打开和加微不算下降） | 高 | 查看排行并复盘下降原因 |
    | 本期记的都是 0 | 运营人本期有每日数据，但链接打开或加微每天都记 0，而上期有数。每日数据默认填 0，分不清没填还是真没有 | 中 | 确认是否漏填（切换前在工作台补） |
    | 待补阅读量 | 运营人名下发出满 7 天、还没填阅读量的小红书帖子（不随时间段变化，是全部积压） | 中 | 补阅读量（切换前在工作台填） |
    | 负责人不一致 | 所选时段的发布登记中，账号负责运营与发布人不同 | 中 | 确认账号负责人和发布负责人 |

  - 工作台的「待同步 / 同步失败」随 D5 再加。「重复链接」不再提醒：迁入时已合并，发布记录里已标出。
  - 没有任何一项时写「各项指标在正常波动范围内」。
  - **「本期记的都是 0」**（Mog 2026-10-14）：工作台把这种情况也算「下降 100%」。共享库副本上 10-01～10-11 有 4 位运营人仍在发帖，链接打开和加微却每天都是 0，其中 2 位 9 月上旬还有数，于是今日必须处理的前 5 项都成了「下降 100%」。现在不算下降，单独列为一项，也不算进「需今天复盘」；排行里照常显示记录的 0。

### 3.4 运营人排行

- **列**：运营人、平台（小红书 / 抖音 / 双平台，按所选时段的发布登记判断）、近 7 天加微趋势（迷你折线）、负责账号数、发布、有效发布（D5 前「未接入」）、链接打开、加微、转化率、爆款、待补阅读量、风险、下一步。
- **风险与下一步**：取自今日必须处理里这个人最严重的一项（含没显示出来的项）。高写「待复盘」，中写「待确认」；下一步写短句并点明哪一项：「复盘发布下降」「复盘链接打开下降」「复盘加微下降」「确认是否漏填」「补阅读量」「确认负责人」，完整建议在今日必须处理里。没有则为空。
- **排序**：加微从多到少，同数按发布从多到少。
- **运营人范围**：所选时段内有发布登记或每日数据的运营人。

### 3.5 平台占比与运营人 × 账号矩阵

- **平台占比**：
  - 所选时段的发布按每条登记的平台统计（小红书 / 抖音），画成一条占比条：小红书用信号色，抖音用墨色；
  - 不显示「加微占比」：加微按人记，分不到平台。
  - 工作台把每个人的发布和加微整体算到他的「主平台」上，两个平台都发的人也只算一个，两个占比都不准。
- **运营人 × 账号矩阵**：
  - 行是所选时段内有发布的账号（按平台、账号名排列），列是运营人；账号比运营人多得多，这样向下滚动就能看全；
  - 格子写发布篇数，有爆款时另标爆款数；颜色深浅只表示篇数多少；
  - 账号名过长时省略，悬停看全名；横向滚动时账号列固定在左边，向下滚动时表头固定在上面；
  - 加微分不到账号，不显示转化率（Mog 2026-10-13）。
  - 工作台这块一直是空的。

## 4. 每日数据的执行状态（PAGE-OPS-001 §5 补充）

D2 隐藏的「执行状态」列按新口径恢复。四个标签按以下顺序判断：

| 标签 | 条件 | 建议 |
|---|---|---|
| 未完成 | 当天没有这个运营人的发布登记 | 安排补发 |
| 可表扬 | 当天有爆款（小红书阅读 ≥ 5000），或当天加微大于 0 | 沉淀有效做法 |
| 待补阅读量 | 当天发的小红书帖子里有满 7 天还没填阅读量的 | 补阅读量 |
| 已完成 | 其余 | 保持节奏 |

工作台的「需复盘」（发了 3 条以上、加微为 0）先不用：加微默认填 0，「真的 0 个」和「没填」分不开。录入能区分后（D4b）再加回。「待同步」「数据异常」随 D5 再定。

## 5. 目标的保存

- **按修改记录保存**：
  - 每次保存追加一条修改记录（周期类型、周期、目标值、上一条记录、请求号、时间、来源），不改不删；
  - 当前目标就是这个周期最新的一条。
- **周期**：
  - 周按 ISO 周（周一开始），写作 `2026-W42`；
  - 月写作 `2026-10`；
  - 都按北京时间。
- **防覆盖**：
  - 保存时带上「我看到的当前记录」。如果别人已经改过，这次保存不生效，提示「目标刚被修改过，已显示最新值」。
  - 同一请求重复提交，只生效一次，并返回第一次的结果。
- **写入范围**：
  - 只接受本机页面的请求（与其他写操作的本机守卫相同）；来源记为「本机」。
  - 登录（D4）之后改为记到人。
- **不迁移**：工作台的目标导不出来；如果工作台里设过，需要在 Linggan 里重新设。

## 6. 共用状态词典（补充 PAGE-OPS-001 §7）

| 状态 | 用户应理解 | 禁止暗示 |
|---|---|---|
| 未设定 | 这个周期还没有设加微目标 | 目标为 0、目标已完成 |
| 自定义时段不对应目标 | 目标按周、按月设，自定义时段对不上 | 没有目标 |
| 不分业务 | 这个数来自每日数据，没有按业务区分 | 已按业务过滤 |
| 待补阅读量 | 小红书帖子发出满 7 天还没人填阅读量 | 阅读量为 0、没爆 |
| 可表扬 | 当天有爆款或有加微 | 绩效评定 |
| 观察中 | 这个环节比上期降了 20% 以上 | 已确认出问题 |
| 本期记的都是 0 | 这段时间每天记的都是 0，可能是没填 | 没有加微、业绩为零 |
