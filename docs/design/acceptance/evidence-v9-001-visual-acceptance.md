### 2026-09-02 主线集成更正：评论正文不进入普通列表

上表“研读行原声”的 `正文 ×2、评论 ×1` 是 V9 分支在 2026-09-01 的历史走查结果，**不再是当前主线的可接受读取边界**。与 Issue #133 合并时，隔离 PostgreSQL 回归证明 `items[].evidenceFragment` 会把“评论命中”带入普通列表响应，直接违反现有“评论正文只经 `LOCAL_AUTHORIZED_RESEARCH` 通道按页读取”的隐私断言。

当前合同因此收紧为：普通列表摘录只可来自作品正文或受控媒体的 OCR / ASR；评论正文、评论外部身份与评论 ID 均不得出现在列表响应中，即使评论是唯一命中或唯一可读文本。评论仍可在 Inspector 的本机授权研究通道中按页读取。该更正的自动与隔离数据库证明在主线集成提交中记录；它不是一次新的浏览器视觉走查，因此上述截图对“评论成为列表原声”的结论标为 **SUPERSEDED**。

## 复查发现并已修的缺陷

首轮验收漏掉了几个界面，二次复查逐个走了一遍，发现并修掉四处：

| 缺陷 | 症状 | 修法 |
|---|---|---|
| 后退/前进不能恢复视图 | `syncUrl()` 一律 `replaceState`，页内状态变化从不产生历史条目，`popstate` 几乎不触发，后退直接离开页面。这条是验收清单明写的要求 | 区分导航与偏好：检索、快捷视图、排版、选中作品 `pushState`；Inspector 宽度、开关、Tab 与翻页仍 `replaceState`，避免把真实导航埋进一堆 30px 宽度变化里 |
| URL 缺参数时不回默认 | `view` / `layout` / `tab` / `panel` 与四个筛选在 URL 里缺席时保持当前值。即使有了历史条目，从 `?view=partial` 后退到无参地址也会留着筛选，而标签条却显示「全部材料」 | `restoreFromUrl` 改为地址权威、缺席即默认。宽度是唯一例外，缺席时回落到存储的偏好而不是常量 |
| Inspector 里的引文被截断 | `.ev-evidence q` 的单行钳制是给列表行写的，Inspector 复用了同一个类。实测 `scrollWidth 1028` vs `clientWidth 564`——在专门用来读证据的面板里只看得到一半摘录 | 面板内覆盖为换行显示；列表行保持一行钳制 |
| 「来源引用」把两件不相干的事并成一行 | 评论片段没有媒体槽位，于是渲染成 `cfa9d955-… NO SLOT`，技术码位置写了个和该 ref 无关的否定 | 拆成 `来源引用 / SOURCE REF` 与独立的 `所在媒体对象 / SLOT KEY`，后者只在真有槽位时出现 |

另外统一了行内与面板的引文渲染（此前面板不高亮命中词），并让禁用态的主按钮不再保留马赛克纹理——带纹理的禁用按钮看上去仍像可点。

复查后 `cargo test --workspace` 仍是 26 个目标全绿，`cargo fmt --check` 干净。后退恢复已实测：连点 快捷视图=撤回或受限 → 排版=表格，后退一次回到研读且保留 restricted，后退两次回到全部材料与 14 行。

## 第三轮复查：点击打不开查看器

Mog 报「点击检查器中的图片无法放大显示」。复现并定位：

- **根因**：媒体轨在 `pointerdown` 就调用 `viewport.setPointerCapture()`。指针捕获生效期间，浏览器会把随后的 `click` 重定向到捕获元素，于是每一次点击都落在轨道容器上，而不是光标下的那张卡片——卡片的 click 处理器从未执行。
- **为什么前两轮没抓到**：我此前是用 `element.click()` 程序化触发验证的，那条路径完全绕过指针事件，所以捕获不生效、点击「看起来」正常。**这是验证方法的漏洞，不是偶发**。此后该组件的验收改用真实可信点击。
- **修法**：指针捕获改为「指针实际移动超过 4px 后」才获取，按下不动不再捕获。没有移动的按压保持为卡片上的普通点击；真正的拖拽仍然接管并在释放时吞掉那一次 click。

复验（全部使用真实可信事件或真实指针事件序列）：

| 检查 | 结果 |
|---|---|
| 真实鼠标点击第 4 张卡片 | 查看器打开在 `04 / 09`，缩放 100% |
| 按下移动 3px（低于阈值） | 不进入拖拽，`data-grabbing` 未置位 |
| 按下移动 20px 后继续到 260px | 进入拖拽，吸附关闭（`scroll-snap-type: none`），`scrollLeft` 实际移动到 261 |
| 拖拽释放 | 未误触发查看器 |

## 未证明 / 未做

- **多图链路只有一个样本**。9 个媒体对象的横滑、进度、GO TO MATCH、Lightbox 全部只在 `ADHD的尽头是成瘾` 上验证；其余 13 个作品走的是空态分支。第二个多图作品出现前，不能宣称该链路已被覆盖。
- **触控滑动未实测**。指针拖拽（鼠标）已验证；`pointerType === 'touch'` 分支交给浏览器原生横向滚动，本轮没有真机触控验证。
- **大数据量性能未验证**。当前库只有 14 条，虚拟化与深翻页在这个量级上不构成压力；游标翻页沿用既有实现未改。摘录读取沿用 `enrich` 既有的按行查询模式，每行最多再加 2 条有界查询；页大小为 50，因此单页上界是 100 条额外查询。这是把新读能力接进既有形状的代价，不是新引入的 N+1 模式，但在真实数据长大后应与 `enrich` 的其余按行查询一起复审。
- **未部署**。`:3000` 仍指向冻结快照 `linggan-intelligence-xhs-media-author-e3f8990`，Mog 刷新 `:3000` 看不到本次改动。
- **既有 clippy / 边界告警未处理**：`crates/contracts` 的 `too_many_lines` 与 13 项文件长度错误在 `origin/main` 上已存在，本次未修、也未伪装为已解决。
- **来源轨迹仍是 140 个裸 UUID 的墙**（7 组 × 20）。V9 spec 把这块叫 `ProvenanceTimeline`，但当前 API 只返回 ref 数组、没有事件时间线，做不成真时间线。本次原样保留既有渲染，没有伪造一条时间线出来。
- **快捷视图「部分取得」在这批数据上没有区分度**：14 篇全部命中，因为几乎每篇都有某条通道是 `PARTIAL`。筛选本身工作正常，是数据分布使然，不是缺陷。
- **干净地址会立刻被写上个人偏好**：`panel` 从 `localStorage` 恢复并写回 URL，所以分享出去的链接会带上自己的检查器宽度。这是「宽度偏好持久化」要求的直接结果。
- **Mog 业务验收未进行**。
