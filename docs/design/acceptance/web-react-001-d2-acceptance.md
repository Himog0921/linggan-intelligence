## 5. 发现与后续

- 协调方裁定并已落实（分册 §4.8）：DR-1 三个失效控件先实测再移除；DR-2 未接通占位删除；DR-3 复观测先确认、回执四分、未确认不自动重发；DR-4 四条接口补来源闸门（列表、详情、立即复观测及其状态查询）（核对过调用方只有同源页面与测试脚本，插件只用 `chrome.tabs.create` 打开页面）；DR-5 侧栏徽标保留；DR-6 采集脚本的证据库一段改为 React 页的写法，跨页链接与交接键形状不变（合并后核对阶段 G 的 React 采集页：运行详情、观察目标作品、领域管理三处链接与交接键读取都与 C 组一致）；DR-7、DR-8 按提议；DR-9 保持原样，不扩大暴露。
- 实施方用真实浏览器证明发现并修复两处：封面排版缺多列栅格（退化成一列通栏）、查看器换图后焦点丢失；两处都有样式契约或组件测试兜底。
- 协调方复核中修正：插件入口证明原先依赖 Playwright 的网络事件，而 Playwright 不为扩展新开的标签页报这类事件，改为记录服务器取请求头、页面自读 HTTP 状态，并等领域对话框出现再判定；评论续读断言原先依赖某一条评论出现在前两页，而评论按稳定来源编号排序、编号每次播种都不同，改为断言两页 40 条互不重复；合并主线时清理两处残留（孤立注释与右括号、重复的 `#[test]`）与一个不再使用的导入；两个文件末尾空行。
- 发现脚本 `scripts/test-local-001-discovery-postgres.sh` 的跳过清单漏登记了 7 个需要专用环境的浏览器证明（设置、创作者、证据库、运营、内容工作台与两个前端预览；其中 6 个在主线上已漏，含协调方自己在阶段 B、D1 加的两个），整脚本因此在主线上就跑不通；它们都在第一行就因缺少专用环境标志而拒绝运行，并不是被测功能失败。已补登记，它们仍在各自的专用脚本里运行；补登记后整脚本重跑通过。另预先登记阶段 F（#441）新增的同类证明。
- 云端首跑发现证明脚本有计时依赖：只等「至少一行」或只等检查器标题，较慢的环境会读到旧列表或空分区。协调方在本机把浏览器 CPU 降速 6 倍、接口加 500ms 延迟复现，修正五处等待（媒体类型筛选、阅读主序、图片计数、视频卡片、复观测不可用），降速下 19 步全部通过；并给每一步加上失败现场截图与对话框文字记录。另在正常速度下观察到一次批量整理弹窗（步骤 9）30 秒内没有全部读到处理范围，约十余次运行中出现一次；带诊断复跑时三篇的处理范围请求 90 次全部返回 200、弹窗正常，原因尚未查明——若在 CI 再现，产物里的失败截图会给出当时每篇的状态。
- 主线既有问题（与本包无关，未改）：`local_web::creator_lifecycle_tests::target_route_never_reflects_an_invalid_selected_work` 请求的 `/collection/targets` 已是 React 页，本机没有构建前端产物时得到 503，于是在 `main@82d48a72` 的干净检出上失败；构建过前端的工作树里通过。是否让该测试不依赖构建产物，由阶段 G 的负责方决定。
- 待 Mog：DR-9（研究底稿的诊断信息与两种导出含平台作者编号，与旧页一致；要不要收紧）；复观测三个新状态词的措辞（「平台页面已不存在（生产方确认）」「详情页已打开但没有读成」「尚未开始」）。
- 不得因此推断：隔离环境通过不等于运行实例已部署；合成数据不代表真实数据量下的读取耗时（D1 上线后实测创作者列表接口单次 7.5–9 秒，证据库列表的真实耗时尚未测）；插件入口证明用的是最小测试扩展，不是正式插件包。
