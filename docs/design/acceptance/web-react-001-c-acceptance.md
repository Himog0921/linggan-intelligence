## 首轮历史审核发现及处置

1. 新材料卡 expressionRevision 初始 0 与服务端最小 1 不符，摘入后无法保存。已改为统一工厂初始 1，增加模型与组件请求负例；真实浏览器直接摘录及保存通过。
2. 共享 API 强制 JSON MIME 后旧设置组件 mock 缺少 Content-Type，使 10 项失败。补齐测试响应头，完整前端回归通过，服务端合同保持不变。
3. 未确认的保存/放入/恢复命令可能被后续操作替换，标签输入可能触发自动重试；已冻结命令身份并锁住会替换整篇的操作，添加未知状态、SPA 切换、标签和恢复回归。
4. AI 未确认时可预览新输入而执行旧冻结请求。已保留原预览与指令、锁定输入、明确核实原请求；新增组件反例。
5. 精确局部选文与自然段范围不相等，导致“已摘录”筛选遗漏。改为同来源身份、版本、字段的范围交集；不同归组按任一匹配摘录判断，新增 emoji 局部范围反例。
6. 完整原声换段或复制到角度、提纲等字段后可能丢来源使用关系。已补来源身份保留、所有可编辑字段实际全文位置传播、读取遮断与 AI 输入核验；PostgreSQL 反例通过。临时关闭旧引用保留后，同一测试在新段落返回受限原声处失败，恢复原代码再跑通过；独立审核核验负控确实进入业务断言，而非编译或环境失败。
7. 删除图页后恢复或撤销回到服务器原稿仍显示未保存。已按实际文档一致性恢复已保存状态，不额外发送保存命令。
8. 保存冲突的409回执丢失后，GET查到合法stale回执仍永久显示未确认。现按同一冲突流程展示双方文字；先核对请求和作品身份，不重复POST，错误身份仍拒绝。组件与API反例通过。
9. 浏览器原笔记身份断言误把work public_ref当作material sourceRef；修复测试使用明确的workRef，同时保留原声sourceRef校验。步骤切换、选纸条和标题确认等待React实际提交后再断言，避免旧DOM竞态；不改变产品身份或减弱内容断言。
10. root 目检发现390截图被横移裁剪，原根文档宽度检查假绿。工作台根main明确可收缩尺寸和滚动边界；增强检查逐一滚动正文输入、图页控件、导出按钮和阅读操作，检查实际左右边界与html/AppShell/main三层滚动。增强检查进一步抓到103片段索引按钮的min-width:auto撑大材料区；修正按钮可收缩和内部指示条上限，不裁切或减少片段。
