# 评论研究 V0 · 页面设计基线

状态：`ACCEPTED FOR P2 READ-ONLY IMPLEMENTATION`
日期：2026-09-13
范围：评论研究的五个视图共享页面壳；当前实现「用户原声」的 V0 只读页面，以及详情抽屉中按 Evidence 异步读取的已采到讨论/作品上下文。该文档不把未取得的数据设计成指标或卡片，也不把局部来源写成完整平台树。

## 1. 视觉主题与氛围

**情报档案室**：它应像一张供研究者标注、追溯和比较的工作台，而不是运营 KPI 仪表盘。暖白纸面承接长时间阅读，近黑文字建立事实重量，朱砂色只表示当前操作位置、不可忽略的失败或需要进一步调查的状态。

页面第一屏回答三件事：当前正在看哪个语料范围、系统已取得哪些事实、下一步能打开哪条原声。没有虚构的趋势、得分、图表或“AI 已理解”的结论。

## 2. 颜色与语义

| Token | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `oklch(0.965 0.008 85)` | 页面底色，略暖的纸面 |
| `--surface` | `oklch(0.992 0.004 85)` | 主工作区与浮层 |
| `--rail` | `oklch(0.925 0.010 85)` | 导航与筛选区域 |
| `--ink` | `oklch(0.19 0.010 60)` | 主文字、数据表标题 |
| `--muted` | `oklch(0.50 0.014 70)` | 辅助文字、未知状态 |
| `--rule` | `oklch(0.80 0.012 80 / 0.72)` | 表格和分区细线 |
| `--signal` | `oklch(0.53 0.18 35)` | 当前视图、主要操作、需要调查 |
| `--safe` | `oklch(0.45 0.10 145)` | 已验证、只读正常态 |
| `--caution` | `oklch(0.64 0.13 75)` | 上下文缺口、未知语义 |

禁止使用紫蓝渐变、玻璃效果、整页大阴影和把红色用于普通文本。

## 3. 排版

- UI 字体：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`；中文系统字体优先，避免下载字体影响本地数据工作台启动。
- 数字与来源 ID：`ui-monospace, "SFMono-Regular", Menlo, monospace`，使用 tabular numerals。
- 页面标题：28px / 650 / 1.15 / `-0.02em`；区块标题：16px / 650；正文：14px / 1.6；元数据：12px / 1.5。
- 评论文本以 15px / 1.65 呈现；多行截断只在表格中发生，详情永远展示完整可读文本。

## 4. 组件样式

- **应用壳**：左侧窄导航是平面 rail，不套卡；主内容最多 1440px，保持充足的横向表格空间。
- **按钮**：4px 固定半径；主要按钮为近黑底暖白字，当前范围/警示用朱砂色；按下只做 `scale(.96)`。
- **输入与筛选**：白底、1px 细线、4px 半径；焦点用朱砂色 2px outline，不以颜色本身传递状态。
- **表格**：不使用每行卡片。行以细线分隔，文本列左对齐、时间和计数列右对齐；hover 只改变背景色，不能改变布局。
- **详情抽屉**：从右侧出现，保留原表上下文；用于证据追溯，不能用弹窗打断原声浏览。
- **状态词**：文字加小圆点，不创造彩色徽章墙；例如「尚未研究」「打开详情后按来源读取」必须说明事实，不只给颜色。

## 5. 布局原则

桌面采用 `216px rail + fluid main`；主区顺序为范围栏、工具栏、结果摘要、表头和可扫描行。原声表以评论文本占主要宽度，来源身份和系统接入时间为次列；任何不存在的字段不得用空列占位。

宽度低于 900px 时，rail 收为顶部菜单，表格改为有标签的纵向行，详情抽屉覆盖全宽。最小点击目标为 40px。

## 6. 层次与动效

采用背景明度层级和很浅的 `0 1px 3px rgb(30 25 18 / .10)` 阴影区分 rail、工作面和详情抽屉；不对每一行加阴影。页面加载仅让范围栏、工具栏、表格各以 opacity/translateY 进入，最大 160ms；`prefers-reduced-motion` 下取消动效。

## 7. 页面守则

1. 一条事实必须能从页面进入来源关系；不把来源 ID 写成看似标题的文案。
2. 未知、不可用、尚未取得分开显示；不能显示为 0、空白或“正常”。
3. 研究状态不混入任务状态；V0 仅可显示「尚未研究」。
4. 不在 V0 的原声表首层设计点赞、作者、发表时间或趋势组件；已采到的回复和作品标题只在详情抽屉内以语境出现。
5. 不用单行 KPI 卡替代原声表；表是本页面的核心工作面。
6. 不用内部英文枚举、指纹、run ID 作为主阅读内容。
7. 无数据时解释缺的是范围、来源还是读取权限，并给出可操作入口。

## 8. 响应式行为

- `>= 1100px`：rail 固定、表格显示评论／来源身份／系统接入／研究状态／上下文五列。
- `900–1099px`：rail 收窄，来源身份和系统接入移入行内元数据。
- `< 900px`：导航改为横向滚动，表格行变为两层阅读卡（仅此断点）；详情为全屏层。
- 所有键盘焦点可见；抽屉使用 Escape 关闭并把焦点还给触发行。

## 9. 实现提示

单一策略：静态 CSS 变量 + 原生 HTML/最小 JS；不要在 API 服务中引入 Tailwind、CSS-in-JS 或另一套组件库。

- 原声表：`--canvas` 背景、`--surface` 工作面、评论 15px、元数据 12px、规则线 `--rule`。
- 当前 tab：`--signal` 文字和 2px 底线；其余 tab 使用 `--muted`。
- 原声表不预判上下文是否存在：`--caution` 圆点 +「打开详情后按来源读取」。
- 抽屉无上下文时明确写「尚未取得与当前原声正文相匹配的完整来源上下文」，禁止写“无内容”或暗示平台不存在讨论。
- 已验证读取：`--safe` 圆点 +「来源已接入」，仅当 API 包含已验证 source relation。
- 详情抽屉顺序固定为当前原声、已采到的相关讨论、作品上下文、研究输入预览、来源证据；宽 480px、`--surface`、右侧 1px `--rule`、仅 opacity/transform 过渡。
- 「研究输入预览」默认收起，经用户点击后才读取。它把当前评论的清洗表达单列为直接证据，并把讨论/作品文本标为语境；必须展示固定字符边界与省略事实，不出现模型名、Token、费用、Prompt 编辑器或开始研究按钮。
