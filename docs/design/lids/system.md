# LIDS-SYS-001 · Linggan Intelligence Design System v2.0

> 状态: 权威当前
> 标准成熟度: PROPOSED
> 最后核对: 2026-08-21
> 适用范围: Linggan Intelligence 中所有获准实施的用户界面、视觉资产、状态呈现、动效、页面/组件规格和 UI Agent 交付
> 事实来源: Mog 明确指定的 LIDS v2.0 来源包、[README.md](README.md)、AGENTS.md、docs/governance/、已确认产品页面、数据/权限/行动合同和当前 SCOPE
> 冲突时以谁为准: 用户最新确认、AGENTS.md、真实运行/代码/合同、ACCEPTED 决策和当前 SCOPE；没有产品或数据依据时停止，不以 LIDS 补全事实

## 1. 设计职责与唯一主题

Linggan Intelligence 不是普通 SaaS 后台、传统 BI 看板或聊天窗口。它的界面职责是帮助用户分清：世界发生了什么、系统实际观察到了什么、哪些是原始事实、哪些经过归一化或推导、判断依赖什么证据、覆盖还缺什么、系统或 Agent 实际在做什么，以及用户下一步需要判断什么。

一句话视觉定义：**暖灰纸面上的精密情报基础设施**。

系统应同时体现真实、精密、可追溯和克制：原声/来源/时间/范围/缺口可见；结构、读数和状态对齐；结论可回到证据；少色、少阴影、少装饰动效。视觉权重为编辑式信息设计约 55%、精密仪器语言约 25%、等距系统语言约 15%、ASCII/终端语言约 5%。ASCII 是稳定编码协议，不是纹理；等距场景表达数据路径，不是科技插图。

未来获得运行时 UI 授权时，唯一主题名为：

```html
<html data-theme="linggan-intelligence">
```

在当前无 Web 运行时阶段，这个名称只是冻结的迁移契约，不能被表述为已存在的应用代码。

## 2. 五层架构和横向约束

```text
Token → Primitive → Component → Pattern → Page
        ↘ Motion / Scene / Data Truth（横向约束） ↗
```

| 层 | 只负责什么 | 不负责什么 |
|---|---|---|
| Token | 色彩、文字、间距、边框、阴影、动效和场景的不可拆分值 | 业务对象、数据含义或操作权限 |
| Primitive | 可复用基础语法：文字、按钮、状态、Surface、Readout、输入、分割和焦点 | 某个 Topic、数据请求或业务结论 |
| Component | 有唯一正式入口、数据契约、状态、可访问性、允许/禁止场景的稳定责任 | 把页面判断或权限偷偷封装起来 |
| Pattern | 页面级组合与信息流顺序 | 具体文案、数据数值或动作授权 |
| Page | 某个页面的单一任务、事实来源、状态、动作、响应式与验收 | 反向发明全局规则或数据合同 |

组件在 Linggan 只有被第二个独立页面证明同一用户可见责任、完成 CMP 规格和验收后才算“正式”。来源包中出现的组件名在没有这些条件前只是**受控候选名称**，不可声称为已实现组件库。

每次变更必须从页面任务/真实数据合同向上追到 Pattern、Component/Primitive 和 Token；不可从截图或想象的视觉效果向下倒推产品。

## 3. 视觉强度：先选 L，再选 Pattern

### L3 · Brand / Observatory

适用于建立整体认知、重大 Topic、情报发布或受批准的品牌级展示。允许完整等距情报装置、坐标刻度、背景大网格、巨型标题、有限环境动效、深色命令坞和 Signal Fingerprint。首屏只有一个视觉核心，必须同时有当前对象、变化、覆盖、原声或证据和系统状态；动画必须有真实状态来源，不能退化为品牌展示。

### L2 · Research / Analysis

适用于 Topic 详情、Evidence Inspector、Signal 分析、Market Insight 和主动研究。阅读、筛选、对比优先；允许局部等距结构、高密度 Evidence/Trace 和一到两个深色关键判断面。局部等距区域不超过主工作区 40%，持续动画只在真实任务运行时出现。

### L1 · Operations / Configuration

适用于 Corpus、评论检索、采集调度、任务列表、设置、规则和映射。以表格、连续列表、分栏和轻分割线为主；不使用品牌级主场景，背景纹理关闭或极弱，动效只用于反馈/进度。

当前 `PAGE-TOPIC-001` 是一个 **L2** 静态合成阅读参考，绝不是 L3 Observatory 或对任何真实 Topic 页的授权。

## 4. 所有页面的基本视觉约束

1. 颜色、字号、间距、圆角、阴影、动效只可引用 [tokens.md](tokens.md)；不写硬编码六位色、任意字号或随机间距。
2. 全局中文阅读使用 Sans；数字、时间、状态、来源、命令和 ASCII 使用 Mono。长中文正文、原声和研究结论禁止使用全局 Mono。
3. 功能文字不得小于 11px；关键正文不小于 14px；长评论/原声为 16px；只有不可交互、非关键的装饰刻度可以为 9px。
4. 采用 4px 间距基数，同层级相邻元素使用同一间距值。页面大区块优先 32/48px，组件内部优先 8/12/16px。
5. 常规容器圆角只允许 0/2/4/8px；不以厚胶囊、12px 以上圆角、渐变或多层阴影制造“AI 感”。
6. 边界优先次序为：留白 → 底色 → 左轨/坐标 → 1px Hairline → 强边框。普通列表、表格和读数默认无阴影。
7. Signal 橙红只表达活跃数据流、选中、情报升级和主动作反馈；不承担 Warning、Danger、Success 或所有增长数字。浅底小号 Signal 文本使用 `signal-ink`。
8. 一个视觉组只有一个外层 Surface，内部以排版、留白、栅格与分割线组织；禁止 `section → card → small card` 三层框套框。
9. 纯读数没有 hover、假按钮、假进度、假网络状态或“待联调”Primary。未完成能力隐藏，或明确 disabled 并说明开放条件。
10. 不使用黑底荧光绿终端、蓝紫霓虹大屏、玻璃拟态、大渐变、满屏圆角卡片、军事雷达、代码雨、常驻大型 3D 或用视觉复杂度掩盖不确定性。

## 5. Data Truth：设计不能篡改事实

有真实合同的页面应分别呈现五类问题：

| 轴 | 允许的标准状态 | 不能与什么混同 |
|---|---|---|
| Truth | `OBSERVED`、`NORMALIZED`、`DERIVED`、`REVIEWED`、`PROMOTED` | 数据完整度或运行进度 |
| Coverage | `COMPLETE`、`PARTIAL`、`INTERRUPTED`、`EMPTY` | 数据有效性 |
| Validity | `VALID`、`DEGRADED`、`INVALID` | Coverage 或错误状态 |
| Freshness | `FRESH`、`AGING`、`STALE`、`UNKNOWN` | 已完成/失败 |
| Operation | `QUEUED`、`RUNNING`、`RETRYING`、`COMPLETED`、`FAILED` | 事实来源、Coverage 或 Validity |

`PARTIAL + VALID` 是一等状态：它表示目标尚未完成但已获得数据可在明确范围内使用；必须显示 `TARGET / OBSERVED / RETAINED / GAP` 和可使用范围。不能显示为 `FAILED`、`0` 或“完整代表性”。

`0` 只表示已确认数值为零；无适用值为 `—`，尚未获得或无法验证为 `UNKNOWN`，不适用为 `N/A`。任何 AI/Agent 结论必须带数据窗口、样本、Coverage、处理步骤、冲突、人工复核和适用边界。原声、来源和上下文优先于 AI 摘要。

对没有真实数据合同的页面，不得假装使用上述真实状态轴。它必须使用清晰的 `SYNTHETIC / NOT LIVE`、`SOURCE_INCOMPLETE`、`DECISION_REQUIRED` 或相应空白/未知边界。合成演示不能把静态文案伪装成 `OBSERVED`、`FRESH`、`VALID` 或 `RUNNING`。

## 6. 动效、场景和可访问性

动画只服务四件事：告知状态变化、建立空间/来源关系、解释数据处理过程、降低内容切换突兀。按下 80–120ms，hover/focus/selected 120–180ms，弹层 160–240ms，内容进入 250–300ms；超过 700ms 的交互动画必须有理由。L3 环境动效最多 1–2 个且 8–14 秒，不能无业务状态循环。

永久禁止：鼠标视差、无状态浮动、永久 Ring Spin、代码雨、大面积扫描线、弹跳、360° 装饰旋转、L1 环境循环以及用动画掩盖加载。`prefers-reduced-motion` 下场景停在可读静态状态、路径改为静态高亮、弹层直接出现、粒子/扫描/呼吸关闭，而进度仍由文本/数字表达。

L3 等距场景只能在另获技术和资产授权时进入实现；静态 Style Frame、灰模、材质/灯光、状态机、真实数据绑定、Poster、移动降级、Reduced Motion、性能记录和等价 HTML 都是前置门。当前不得把来源包 V3 的 JavaScript Prism、模拟数值或持续动画复用到产品。L2 只可使用受控局部 2.5D/Poster；L1 禁止品牌级常驻场景。

每个可交互元素可键盘到达，命中区至少 24×24px，主要按钮建议 36–40px，具有双层 Focus Ring，且没有 `outline: none` 的无替代。状态必须以颜色 + 图标/定位 + 文字双通道表达；Tooltip 永远不是必读信息或唯一错误处置入口；场景热点需有键盘、触屏和等价 HTML 列表/树。

## 7. 页面和组件的不可跳过门

新页面在写任何运行时代码前必须有 PAGE 规格，至少固定：页面任务、3 秒答案、5 秒动作、非目标、用户/频率、真实数据来源与边界、L1/L2/L3、唯一主 Pattern、结构与组件、必需状态、响应式、动效、可访问性、禁止元素和验收。页面级动作不超过三个，单一视口仅一个视觉核心。

新组件先查重，再写 CMP 规格，后实现、预览、测试、迁移记录；组件必须说明唯一职责、不负责什么、适用强度、数据/空值、五轴状态、视觉 Token、交互/动效、可访问性、响应式、性能、测试、Decision Log 和废止策略。现有组件升级前先查全仓影响；不可留一套“临时第二外观”。

任何影响 Token、Primitive、Component、Pattern、Page、Motion、Scene 或 Data Truth 的改动，必须同一事项更新 LIDS 规格、对应预览/参考页、[migration-log.md](migration-log.md)、UI Change Manifest 和验证记录。例外必须显式列出规则、原因、影响、复核条件与回退；跨多页例外进入长期决定，不能埋在 CSS、条件分支或截图中。

## 8. 验收与成熟度

每项 UI 工作至少分开回答：任务是否成立、状态是否诚实、视觉是否符合 LIDS、动作是否有真实回执。截图、编译、HTTP 200、toast 或模型文字不能独自证明其他层。

最低视觉验收尺寸为桌面 `1280×800`、`1440×900`、`1536×960`、`1728×1117`、`1920×1080`、`2560×1440` 和移动 `390×844`、`430×932`。无页面级横向滚动；移动端不是缩小桌面场景，而是保留 Topic、状态、原声和主动作，降级/隐藏不重要的仪器层。

LIDS 从 `PROPOSED` 升至 `STABLE` 的证据门见 [README.md](README.md)。在此之前，任何项目文件只能声称“按 Proposed 标准执行/通过静态参考验证”，不能声称 LIDS 已获得真实运行页、组件、3D、数据或用户验收。
