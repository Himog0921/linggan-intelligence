每一次破例都必须留下记录。**没有记录的破例会在半年后变成"历史原因"，然后变成新的默认。**

本表有两个状态列，必须分开读：

- **规则状态**：这条决定是否已成为本项目的强制约束。DESIGN-010 之后全部为「已采纳」，除非另行注明。
- **运行时状态**：现有代码是否已经符合。**多数为「未迁移」**——规则先行、代码后补是本次事项的明确边界，不是疏漏。把「已采纳」读成「已实现」是本表最容易犯的误读。

## 本项目新增的决定

以下两条不在 v7 原件中，由本次采纳（DESIGN-010）在项目层面确定，用于处理 v7 与本仓库既有状态的冲突。

### `ADR-P01` · 英文技术旁注收窄到 Mono 三类

**决定**：`LIDS-LANG-001` 的「中文主表达 + 英文技术旁注」结构保留，但英文旁注的**适用面收窄**为 v7 Mono 预算的三类（机器事实、系统状态枚举、结构编号）。描述性标签一律只用中文，不再配英文对照。

**理由**：v2.0 时代的规则允许技术键紧邻任何中文，实践中扩散为满屏中英成对出现。v7 明确把「中英对照并列」列为壳层违规，并给出替换样例（`MONITOR TARGET`→监控目标、`BODY / COMMENT / MEDIA / OCR`→正文·评论·媒体·OCR、`SINCE LAST PATROL`→距上次巡逻）。两条规则不冲突——v7 是对同一原则的**执行口径收紧**。

**状态**：规则已采纳，见 [language-policy.md](language-policy.md) 第 2.5 节。运行时未迁移：`shell.rs` 与 `evidence_page.rs` 中现存大量 `v7-tech-key` 描述性对照，属 DESIGN-010 欠账。

### `ADR-P02` · 运行时 Token 保持 `--lgi-*`，v7 三层架构为目标态

**决定**：本次不改运行时 token。`apps/api/src/local_web/lids_tokens.css` 的 127 项 `--lgi-*` 仍是唯一运行时值源与 Rust 校验对象；v7 的 L1/L2/L3 三层架构写入 [tokens.md](tokens.md) 作为**目标态与新工作的选值依据**。

**理由**：Mog 于 2026-09-02 明确将本次范围限定为「只改治理文档 + 记录迁移欠账」。同时改动 token 会连带三个样式表与多个页面模板变色变字号，需要逐屏验收，且会与并行分支抢文件。

**状态**：已采纳。迁移触发条件与分步计划见 [tokens.md](tokens.md) 第 4 节。

## 新增 ADR 的条件

向本表新增条目必须同时满足：

1. 这是一条**结构性**决定——影响 Token、Primitive、Component、Pattern、Page、Motion、Scene 或 Data Truth 中至少一层；
2. 记录了**理由**，且理由可核对（实测对比度、字体实际不存在某字重、真实页面的违规计数等），不是"看起来更好";
3. 明确写出**代价**与**被取代的做法**；
4. 规则状态与运行时状态**分别**填写，不合并；
5. 同一事项内更新 [migration-log.md](migration-log.md) 与对应 UI Change Manifest。

一条决定被推翻时，**旧条目保留并注明替代者**，不删除。删除等于让"历史原因"重新变得不可追溯。
