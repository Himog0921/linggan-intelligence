## 1. 方法与边界

- **被测对象**：main@05b69db0 的 `WorkbenchPage`、`ManuscriptEditor`、`CanvasBoard` 真实代码，不是 Demo，也不是重写的简化版。
- **接口**：浏览器里把 `/ops/api/creation/*` 等请求拦下，用内存里的作品库应答（保存、修订、冲突与现有合同一致）；没有连接任何真实服务、数据库或模型。
- **输入法**：用调试协议（CDP）的 `Input.imeSetComposition` 和 `Input.insertText` 模拟“拼音组合 → 候选 → 提交”。这能复现“组合期间页面会不会打断、会不会丢字”，**不等于苹果拼音、搜狗、微信输入法的真实行为**。
- **性能数字**：来自无界面 Chrome，生产构建（开发构建每个字的处理约慢 6–9 倍，不作为依据）。不代表写手的电脑，更不包含网络和服务器时间，只用于判断做法在量级上够不够。
- **数据**：全部合成，没有读取任何真实笔记、账号或经历。
- **可丢弃**：脚本与小样代码在 `.worktrees/creation-assets-proto-001`（本地分支 `proto/creation-assets-001`，提交 `21620ab1`），不合并、不推送；依赖用仓库锁定文件 `npm ci` 安装，没有新增任何依赖。

## 2. 小样 1：中文输入、按段落替换、撤销

| 项 | 做法 | 结果 | 结论 |
|---|---|---|---|
| T1 组合输入 | 在末段用 n→ni→nih→niha→nihao→“你好”组合，再提交 | 最终文字正确，无丢字、无重复；组合期间（超过 900 毫秒自动保存防抖）**零次保存**，提交后保存一次且与屏幕一致 | 通过 |
| T2 回车 | 组合中按回车；组合结束后按回车 | 组合中不拆段；组合结束后正常拆成两段 | 通过 |
| T3 回执返回 | 前一个字触发自动保存，回执延迟 1.4 秒，回执返回时第二段正在组合 | 组合继续，提交后文字正确，两段都保存成功 | 通过 |
| T4 替换后撤销 | 在对照页“采用这一段”替换第 2 段，回到正文在第 1 段又打 6 个字，然后连续点“撤销” | 共 7 次才回到原稿：前 6 次逐字撤销在第 1 段打的字，第 7 次才撤销“采用”。按钮在对照页叫“撤销上次采用”，实际只撤最后一次击键 | **不通过**：无法只撤销一次采用而保留后来在别段的编辑 |
| T1 撤销部分 | 提交“你好”后连续点“撤销” | 6 次才回到空；第一次撤销显示“nihao”，依次是 niha、nih、ni、n | **不通过**：输入法组合的每次更新都记成一步，会撤出拼音 |
| T5 浏览器自带撤销 | 打 3 个字后按 ⌘Z | 去掉最后一个字，页面状态与保存内容一致 | 通过。它与页面的“撤销”按钮是两套独立的撤销；浏览器撤销引起的文字变化会再作为一次新编辑记入页面的撤销栈（读代码得出，未单独测试） |

**原因**（读代码得出，与现象对得上）：`edit()` 每次都把整篇文档的上一个版本压进撤销栈（`WorkbenchPage.tsx:336-357`），输入法组合的每次更新也触发 `onChange`；“撤销”弹出一个栈顶（`:797-805`）。没有“按段落”“按一次采用”“按一次输入法提交”的粒度。

**文字内部着色**：每段是一个 `<textarea>`（`ManuscriptEditor.tsx:39-100`），无法把命中的字标红标黄。替代做法已验证：用 `setSelectionRange` 选中命中的字，浏览器原生高亮可见（截图见私有目录）；但页面的选区状态由 `onSelect` 事件维护，程序选中不会自动更新它（“改写选段”仍是灰的），实现时要在定位后显式调用选区处理。这是实现细节，不是障碍。没有测试 `contenteditable` 方案：中文输入法在其中更容易出问题，建议第一版不走这条路。

## 3. 小样 2：200 张卡

**现有画布**（五个固定列，`CanvasBoard.tsx`）：

| 指标（生产构建，200 张卡，约 4,400 个页面元素） | 结果 |
|---|---|
| 打开画布 | 约 0.1 秒 |
| 在一张卡里打字，每个字的页面处理 | 中位数约 9 毫秒，最高约 12 毫秒（未超过一帧） |
| 滚动 | 中位数约 17 毫秒（60 帧），90 帧里只有 1 帧超过 33 毫秒（45 毫秒） |
| 文档里有 200 张卡时在正文里打字 | 每个字约 2.5 毫秒（没有卡时约 1.5 毫秒） |

**现有画布没有拖动和缩放**：卡片没有坐标，只能在五列之间用下拉框改分组（`types.rs:73-82`）。材料桌是新建，不是改造。

**无限画布小样**（容器整体 `transform` 平移缩放、单卡改 `left/top` 拖动，与 Demo 相同，纯 DOM，不含 React）：

| 卡数 | 平移 p50 / p95 | 缩放 p50 / p95 | 拖一张卡 p50 / p95 |
|---|---|---|---|
| 200 | 16.9 / 17.9 毫秒 | 16.8 / 18.1 毫秒 | 16.8 / 18.7 毫秒 |
| 400 | 16.8 / 17.8 毫秒 | 16.8 / 18.3 毫秒 | 17.0 / 20.0 毫秒 |
| 200，每卡带一个文本框 | 16.8 / 18.2 毫秒 | 16.9 / 18.0 毫秒 | 16.8 / 18.4 毫秒 |

16.7 毫秒就是 60 帧。每次运行里偶尔有一两帧 30–85 毫秒（多出现在拖卡的起步），不是持续卡顿；两次完整重跑的数字相近，上表取最后一次、与私有目录里保存的原始结果一致。**结论**：到 400 张卡，纯 DOM 做法足够，不需要画布库；条件是实现时平移缩放的状态放在引用里直接改样式，**不能每帧触发整页重新渲染**（现有页面在卡里打字会让 200 张卡全部重渲，量级上还可以，但平移缩放每帧都这么做就不行了）。

## 4. 小样 3：复制格式的真机验证（待人操作）

**需要的人和东西**：一个装了小红书 App 的手机，一个能用的账号；**不发布**，只存草稿，验证后删掉草稿。文字全部用下面的合成样例。

**样例文字**（电脑上复制，一行一行都要带上；第 2、4 行只有一个“ㅤ”）：

```text
这是第一段，用来测试段落之间的空行。
ㅤ
这是第二段，两段之间那一行只有一个空白符号。
ㅤ
这是第三段，后面另起一行放话题。
#ADHD #A娃成长 #放手
```

**要看的三件事**：

1. **只有“ㅤ”的空白行是否保留。** 粘进正文后，段与段之间是否仍隔着一行？存草稿再打开，还在不在？对照：用普通空行（不带“ㅤ”）粘一次，看是否被吃掉。
2. **话题能否被识别。** 最后一行的 `#ADHD` 等是否变成可点的话题（蓝字、可跳转），还是普通文字？是否需要手动选择？
3. **标题字数怎么算。** 依次在标题栏输入：18 个汉字；20 个汉字；21 个汉字；20 个汉字里夹 2 个表情；“A娃 ADHD”这类中英文混排的 20 个字符。读标题栏旁边的计数，记下它显示的数字，以及超出后能不能继续输入。

**记录表**（每行填“是 / 否 / 看不出来”，并附一张截图）：

| 项 | 结果 | 备注 |
|---|---|---|
| 带“ㅤ”的空行粘贴后保留 | | |
| 存草稿重开后仍保留 | | |
| 普通空行粘贴后保留 | | |
| `#话题` 粘贴后被识别 | | |

**结果怎么影响设计**：“ㅤ”保留 → 附录 A.4 的格式定稿；不保留 → 要换分隔办法，并同步改 Mog 的打样习惯。话题不识别 → 复制按钮旁要有“复制话题”，由写手在 App 里手动选话题。标题计数方式不同 → 修改 R-W9 的计数规则。

## 5. 小样 4：样板复刻试做 3 篇（待授权）

**授权前不做任何模型调用，不读真实笔记。** 拿到 Mog 对模型、供应商、材料范围的授权后再做：

1. 从证据库选 3 篇真实笔记，类型尽量不同（清单体、故事体、问答体）；经**研究底稿的唯一读取入口**读取，不批量读原文，不绕过。
2. 每篇用样板复刻技能生成“写法步骤 + 写法提示 + 需要几段经历 + 踩线点”。
3. 逐篇核对：结果里**有没有任何一句原文**（包括开头几个字）；步骤是否对得上原文结构；踩线点（疗效承诺、对所有孩子下结论）是否被标出；同一篇第二次复刻是否提示“已在库里”。
4. 记录：调用次数、输入输出字数、耗时、费用；原始回包只放私有目录，用后按计划处置。

授权前可以做的“纸面核对”：用合成笔记检查样板记录的字段能否装下三种类型的结构，以及“不存原文”能否由字段设计本身保证（例如样板步骤里没有任何自由文本摘录字段，除非是自家稿件且 Mog 另行允许）。

## 6. 对第一版的影响

- **编辑器**：第一版不需要引入编辑器库。“每段一个文本框”输入法表现稳定，可以保留；要改的是撤销——撤销需要按“一次输入法提交”“一次采用”“一次换个说法”为单位记录，采用的撤销只还原被采用的那一段（该段自采用后没有再改时），不能连带撤掉别段后来的编辑。这属于采用的拦截条件改造（审计 C6）的同一块工作，进 S2。
- **检查命中的显示**：第一版用“检查项 + 定位按钮选中命中的字”，不做文字内部着色。如果 Mog 一定要文字内部着色，需要另行评估编辑器方案（`contenteditable` 或叠层），并重做输入法测试。
- **材料桌**：新建；用纯 DOM 容器变换；卡数按 400 以内设计；平移缩放状态不走 React 渲染路径。
- **D10（编辑器/画布何时选型）**：结论是第一版不选库，延后决定仍然成立。
- **仍未证明**：真实输入法（苹果拼音、搜狗、微信输入法）、手机浏览器、长稿（几十段）、网络延迟与服务器保存、多人同时编辑。这些不在本次小样里。
