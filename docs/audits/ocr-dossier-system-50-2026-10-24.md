## 结论

研究底稿 v2 已在主线和本机3000运行，但历史原文、OCR结果与 v2 读本并未全部衔接。功能合同比现有可读数据更完整；不能称为已经可靠处理所有历史笔记的研究资料库。

本轮固定50篇、106张完整图组。33篇全图通过结构校验，17篇停止；65张图生成候选，17张失败，24张未尝试。全部65张成功图均经原图目视对照，其中31张记录了文字、结构、角色或坐标问题，7张有明显内容问题。34张本次未发现重要问题，不能等同于经人工Gold证明准确。未自动采用候选、未伪造人工核验。

本次真实识别使用基线 `93f03a579b954b0850d405a33f1f83a6a5704d26` 的 prompt v4 / cloud v2。修正后的 prompt v5 / cloud v3 仅有代码、离线及隔离测试证据，尚未真实重跑。源码、运行版本、历史结果与质量合格是四个不同结论。

## 产品能力、解决的问题与流程

研究底稿将平台标题、正文、标签、图片文字、可用音视频文字按来源组织成同一篇作品的材料。它解决的是研究人员和后续Agent各自读取不同摘要、丢失原文或无法追溯的问题。正文应连续可读，图片文字能回到原图，疑点和缺口与文字相邻，来源及读本版本可查。

已有能力包括结构化区块（段落、标题、清单、表格、对话、引述、缺口）、原图对照、候选读本的核对与修正、采用/保留/拒绝回执、JSON/Markdown导出及明确范围的读取。合同能表达表格和对话，不代表当前云OCR已稳定恢复它们；当前云解析结果多数仍落成段落和角色提示。

实际链路为：取得平台原文和媒体 → 核对来源与图片完整性 → 显式准备正文或运行识别 → 形成带来源的读本/候选 → 对照原图核对 → 明确采用 → 研究人员和Agent读取同一底稿。刷新是读取动作，不会自动外发图片、重识别或覆盖原文。普通本地处理与手动云候选的采用语义不同，界面必须保留“自动采用/尚未人工核验”等必要状态。

本轮起点共享库3463篇，旧OCR布局10716条，而 v2 unit/reading/selection/command 均为0。最初ADHD列表前50篇接口均无blocks；该只读列表抽查不是本轮分层样本。对固定50篇显式准备平台正文后，48篇生成读本，2篇没有可用正文。候选修正将这2篇计作partial，不再错误计作alreadyCurrent。

## 全系统 OCR 版本核对

| 路径 | 基线实际版本/状态 | 本包处理 |
|---|---|---|
| 普通图片 OCR、视频帧 OCR | 注册版本 `local-v4`；PaddleOCR，本地处理 | 修复普通领取未限制版本的问题，防止新实现误领旧版本积压 |
| 本地视觉识别 | `local-vl-v1`，独立处理与定位用途 | 保留；不是已退役Tesseract代码 |
| 本地布局/分层 | `rules-v3` | 保留，不把规则层等同于原图识别 |
| 手动云 OCR | `cloud-manual-v2`、`cloud-ocr-observation.v2`、`ocr-blind-read.v4` | 候选升至v3/v3/v5；旧v2候选仍可读取 |
| 研究底稿 | `research-dossier.v2`、`dossier-content.v2` | 主线已存在，历史读本需显式准备；本包UI与回执修正未部署 |
| 旧识别内容 | 大量local-v3；另有少量cloud-manual-v1和正式退役Tesseract v1/v2 | 只清理已正式退役且引用核对通过的v1/v2；不将其他版本全部删光 |

结论：不能说整个系统所有历史识别已经是最新版。新任务注册版本已更新，但旧结果不会自动重算；普通领取漏洞也需本包部署后才得到修正。Tesseract执行实现此前已移除，本轮未虚报删除一套不存在的旧代码。ASR、缩略图和音频抽取的版本有各自职责，不按OCR版本统一删除。

## 已实施的候选修正

- 提示词v5列全必需字段、legibility词表、坐标与标题自查，要求保留阅读次序与段落边界；不放宽严格解析、不自动修补原响应。
- 区分坐标、标题一致性、格式、截断、供应商失败；提示词版本写入调用回执和请求指纹。前端显示对应简短原因。
- cloud v3保留unreadable区块中仍存在的字符并标疑点，只有真正空文本才显示缺口；保留旧v2读本资格。角色提示区分界面、背景、字幕、品牌。
- 普通worker只领取当前注册版本与仍支持的local-vl；显式指定版本的受控入口保留。没有自动重排或执行旧队列。
- 原文未取得时批次结果为partial，避免声称已经准备。
- UI删除检查器与底稿重复摘录/标题，压缩材料摘要和间距；问题按key就近去重，未知页码使用独立图片编号，连续相同表达者标签只显示一次，缺口括号不叠加。
- 无当前读本/候选时不显示不能提交的审核表单，来源和技术版本默认折叠；保留实际风险、采用状态和动作后果，删除重复解释性文案。

## UI实看与仍需修正的地方

候选前端3012对接3000真实只读接口，核对标准/宽/专注三种检查器宽度、正文阅读、空核对表单和原图对照。截图保存在本包私有证据位置；用户交付附原图与候选截图。

已有改进：正文前的重复信息减少，阅读区域更集中；空表单收起后行动与状态一致；来源诊断不挤占正文。仍存在：专注模式在1280px窗口会把左侧列表压得过窄；历史封面/正文同图身份未完整合并时可能显示两张已取得，而原作总页数未知。后者不能靠前端伪造页数解决。本轮样本完整性由原始imageList核对证明，不等于生产API的历史inventory缺口已经回填。

复杂表格/对话恢复、密集多栏/竖排阅读次序、清楚文字漏读与不确定性校准仍是阻止“完全可用”的问题。处理顺序应为：修复版本/回执可靠性 → 在重新授权范围内复测修正版 → 对高风险样本人工确认 → 再扩展自动采用。不能用增加标语掩盖这些缺口。
