# Gate 7 合成任务走查：任务启动困难

> 状态: 一次性报告
> 最后核对: 2026-08-20
> 适用范围: 使用合成、非真实用户材料验证今日关注、Topic 工作区、运行中心与外部 Agent CLI 的诚实性和任务效率
> 事实来源: `product-interface-architecture.md`、已确认产品/领域不变量和 Gate 4–6 候选架构
> 冲突时以谁为准: 用户真实原型反馈、已确认产品边界和后端权威合同；本报告中的名称、数字和文案全部是合成测试数据

## 目的与限制

本次不设计视觉风格，不访问小红书，不使用真实评论，也不证明任何 ADHD 结论。它只检验：当数据不完整、版本不一致、替代解释存在时，产品是否仍能帮助 Mog 在 5–10 分钟内做出一个诚实决定。

合成数据不得进入真实 Corpus、Topic、Claim、fixture 合同或将来演示中的“用户原声”。

## 合成测试状态

### Topic


这意味着页面可以展示 v3 定义，但不能把 v2 分类数字伪装成 v3 当前统计。

### 本轮观察

```text
观察入口：合成搜索入口 A
目标：100 篇 content detail
实际尝试：70
合格 Evidence Record：50
失败：20
未尝试：30
停止原因：risk_control
```

### 分析候选

- 50 条合格内容中，18 条出现与“坐下但迟迟不能开始”相似的表达；
- 其中 10 条集中在一篇合成高互动内容的评论上下文；
- 另外 8 条来自 7 篇不同内容；
- 本轮新增了一个更接近“启动不了”的搜索表达，上一轮没有；
- 分类器从 `classifier-v1` 升级为 `classifier-v2`；
- 因此不能把 18 条与上一轮 6 条直接解释成“增长 200%”。

### 合成原声片段

以下为测试用虚构句子，不来自真实用户：

```text
“题会做，但坐下以后要很久才开始。”
“不是不想写，像是第一步怎么也迈不出去。”
“只有有人坐在旁边，才比较容易动起来。”
```

### 当前允许形成的主张

可以说：

> 本轮合格捕获材料中出现了一组与“开始行动困难”相关的相似表达，分布在多篇内容中，值得继续观察。

不能说：

> 任务启动困难最近增长了 200%，正在成为新的巨大用户需求。

### 走查结果

- 用户不需要理解 Capture Package、classifier manifest 或统计术语，仍能知道为何被提醒；
- 集中度、扩采和模型变化在第一屏出现，不藏在“高级详情”；
- 三个动作含义不同：进入 Topic 只是读取；继续观察不改变基线；提出调查形成申请；
- 不提供“确认这是趋势”按钮，因为当前没有资格；
- 当前卡片应来自多个权威来源的 Read Model，不建立万能 Attention 真相对象。

### 失败条件

若卡片标题写成“任务启动困难增长 200%”或只显示“18 条相关内容”，Gate 7 失败。

## 任务 2：进入 Topic 工作区

### 顶部版本栏

```text
任务启动困难
定义：v3 · 已发布
分类与统计：仍为 v2 · 重算尚未完成

[查看 v3 定义] [按 v2 查看现有分析] [查看认知历史]
```

禁止把 v3 名称与 v2 数字无提示拼在一起。用户可以阅读当前定义，但所有现有分析明确标记仍按 v2。

### 快速理解

```text
当前捕获材料里，人们主要在三类场景中描述“很难开始”：

1. 写作业坐下后迟迟不动笔
2. 需要他人在旁才能启动
3. 开始前反复做无关小事

这是一份候选结构整理，不代表 ADHD 家庭总体，也不能证明最近增长。
```

“三类场景”来自合成分析结果，不自动写进正式 Topic 定义。

### 走查结果

- 原声不是词云；
- 身份未知不会被页面补成“家长”；
- 典型样本、边界与反例同屏可达；
- 用户能知道为什么展示、代表什么范围；
- 原文权限和当前脱敏状态可见。

## 任务 4：查看内容叙事

不使用一个“内容角度”字段，而用多维表：

| 合成内容 | 用户问题 | 立场 | 承诺 | 形式 | 方案 | 表现资格 |
|---|---|---|---|---|---|---|
| A | 很难开始 | 不是懒 | 解释原因 | 科普 | 无 | 发布 3 天，指标一次观察 |
| B | 家长催促冲突 | 先降低摩擦 | 给出三步 | 清单 | 环境调整 | 发布 7 天，指标两次观察 |
| C | 需要陪伴才能开始 | 外部支持有价值 | 分享经历 | 故事 | body doubling | 发布 20 天，当前只作历史材料 |

页面不能据此说 B 的方法有效；只能说该叙事在限定内容和观察条件下获得了什么平台表现与评论反馈。

## 任务 5：理解近期观察

### 正确呈现

```text
本轮新观察
· 50 条合格内容详情
· 18 条被当前模型关联到候选表达结构
· 其中 10 条集中于一篇高互动内容

不能比较
· 搜索表达发生变化
· classifier-v1 → classifier-v2
· 本轮 Coverage 50/100

可以继续观察该结构是否跨入口、跨内容持续出现；
当前不能发布增长/下降判断。
```

### 错误呈现

```text

```

任何实现出现错误呈现，Gate 7 失败。

## 任务 6：选择下一步

### 选择 A：进入 Topic

只改变页面位置，不产生 Decision、Work Order 或正式知识。

### 选择 B：继续按当前计划观察

如果现有 Objective/Plan 本来就已批准且仍有效，只记录用户关注/订阅偏好；不偷偷扩大关键词、页数或工位。

### 选择 C：提出有限调查

```text
目的
检查候选结构是否脱离单一爆款仍然存在

建议范围
使用现有已发现内容和现有 Corpus 先分析；
若仍不足，再申请最多两个新 discovery expression，
不自动增加作者监控或评论深采。

预计资源

形成 Research Question / Analysis work，
不是插件 Work Order。
```

该设计证明“主动研究”不等于“立即扩采”。

## 任务 9：外部 Agent 请求扩采

```text
linggan acquisition request \
  --purpose "验证候选表达是否跨来源持续" \
  --proposal-file request.json
```

预期返回：

```text
REQUEST_RECORDED
等待决定，不代表已授权
不会自动产生 Work Order
```

即便人批准，也必须继续显示：

```text
approved → admission pending → work admitted/deferred/denied
→ attempt running → package accepted/partial/rejected
→ evidence/observation processing
```

禁止合并成“批准成功”。

## 5–10 分钟任务测量

低保真目标不是点击越少越好，而是用户在有限时间内正确回答：

1. 为什么系统今天提醒我；
2. 它实际观察到了什么；
3. 哪些解释仍可能是采集/模型变化；
4. 真实用户原声和内容叙事是什么；
5. 当前能判断到哪里、不能证明什么；
6. 继续观察、主动研究和采集申请有什么不同；
7. 做出决定后系统是否真的执行。

建议原型测试完成标准：首要用户无需阅读架构术语，在 10 分钟内正确回答至少 6 项，且不会把候选变化说成正式趋势。

## 对 Gate 7 候选决定的影响

| 决定 | 走查结果 | 当前建议 |
|---|---|---|
| 一级导航 | 该任务只直接需要今日关注、领域探索和运行中心；语料/研究/行动可从 Topic 进入 | 完整导航保留六个主任务面，首切片只实现必要入口 |
| 今日关注数量 | 固定卡片数量没有意义，信息完整度更重要 | 以 5–10 分钟完成判断为门，不先设数字 |
| Topic 首屏 | 快速理解、原声、叙事、近期/历史、依据、动作顺序成立 | 保留当前推荐 |
| Corpus 单位 | 片段需要上下文、选择理由和用途 | Material + Fragment + Selection，不复制池 |
| CLI 首批能力 | `topic explore`、`explain`、`status`、`proposal/request` 足够验证核心 | 先不开正式知识写入和原文批量 |
| MCP | 当前结构化 CLI 已能验证合同 | 首期不引入 MCP server |

这些仍是合成走查结论，不替代用户确认或真实可用性测试。

## 发现的产品风险

1. **今日关注可能仍过密。** 如果每张卡展示全部限制，会变成研究报告；实现时应首屏只显示最关键限制，其余可展开，但“不可比较”类 P0 限制不能折叠隐藏。
2. **Topic 版本栏可能过技术。** 用户需要看“当前定义已经更新，但下面数字还没按新定义重算”，而不是先理解 Release/Run；技术引用放详情。
3. **运行中心容易变工程面板。** 默认必须说清“影响什么、系统接下来会怎样”，技术 attempt/hash 只在诊断层。
4. **CLI 自然语言可能掩盖结构化限制。** JSON 和 human 输出必须由同一个产品结果生成，不能两套逻辑。
5. **内容叙事维度可能过多。** 首屏先呈现当前任务最有用的两三维，完整多维分析按需展开；底层仍不压成一个 angle。

## 结论

当前 Gate 7 方向通过这次合成负面场景走查，没有发现需要改变产品主入口的结构性问题。它证明的是设计逻辑可继续，不证明页面可用、真实数据可展示或 CLI 已实现。

进入正式原型前仍需：

- 用户确认 `USER-DEC-06`；
- SCOPE-001 决定首切片是否包含最小只读页面、CLI 或二者；
- 使用获准脱敏样本进行真实内容密度测试；
- 对页面文案、信息折叠和 10 分钟任务做首要用户走查。
