# 页面地图

> 状态: 草案
> 最后核对: 2026-08-21
> 适用范围: 情报工作流的初步页面映射
> 事实来源: PRD 与目标领域对象
> 冲突时以谁为准: 用户确认的产品流程和更新后的 PRD

页面设计服务于完整领域认知与行动工作流，不以旧工作台导航为模板。语料、Topic Map、市场洞察、情报和选题是领域情报内核的应用能力/视图；Agent/CLI 是受控服务入口。它们都不能成为新的事实源或技术模块，也不是同一种 Projection。Gate 2 只确认用户任务和跨资产探索路径；页面数量、Tab、区块顺序和 P0 优先级必须在 Gate 7 使用真实样本复核。

Gate 7 的工作台导航、Topic 认知路径、Corpus/研究/行动/运行中心、页面 provenance envelope、API 能力边界与外部 Agent CLI 继续进入 [`product-interface-architecture.md`](product-interface-architecture.md)。本文保留总地图，子文档负责可验证的交互与接口候选。

首页/日常入口的具体形态继续进入第三层 [`home-intelligence-surface.md`](home-intelligence-surface.md)：它记录 2026-08-21 用户确认的 `HOME-01`–`HOME-17`，锁定三栏骨架、恒定领域地形与昨夜行动轨迹、常驻 Agent 编队与总编、选题卡回流、就地抽屉下钻、每早钩子与校准回路。该文不新增事实源，也不是实现授权；本文的用户任务面与页面共同规则继续对它生效。

## DEC-02 已确认的每日信息顺序

第一阶段日常入口先呈现少量值得关注并需要判断是否深入的事项；用户理解“为什么现在出现、证据边界和不确定性”后，再进入相关 Topic 查看原声、内容角度、历史、近期观察和 Evidence。该顺序不等于已经确认“情报收件箱”页面名，也不把所有展示事项升级成 Signal 或 Intelligence。

每日入口没有合格事项时必须明确显示“没有形成新的合格事项”；观察未运行、Coverage 不足或分析未完成时显示“观察不完整/无法判断”。首页不能为了保持每日更新而制造趋势、机会或无证据简报。

## Gate 2 已确认的用户任务面（名称与对象待 Gate 3/7）

下表确认的是用户必须能够完成的任务，不是最终导航、页面名称或领域对象清单。`Radar`、`Change Candidate` 和“内容选题候选”等仍是便于讨论的候选称呼；内容选题不得再使用容易与 Domain Topic 混淆的 `Topic Idea`，其最终英文名称与长期身份仍待 Gate 3-C，Gate 7 决定是否独立成页、位于哪里和用户看见什么名称。

| 产品探索面 | 用户要完成的任务 | 读取的主要资产 | 不能变成什么 |
|---|---|---|---|
| ADHD 领域入口 / Topic Map | 找到当前正式发布了哪些 Topic、采用哪个定义版本，以及当前 Map View 如何导航 | Topic Identity、Topic Definition Version、Domain Definition Release、Knowledge Relation、Map View | 固定真理树、采集关键词目录，或把导航位置当成概念定义 |
| Topic 探索 | 理解人们怎样表达、创作者怎样讲、历史如何积累、近期观察到了什么、有哪些候选变化及当前能判断到哪里 | Corpus、主题知识、市场投影、洞察候选、Evidence | 第二份 Topic、Corpus、市场事实或未经资格验证的趋势 |
| 每日关注与决策入口（名称待 Gate 7） | 从已自动去重和初步挑战的材料中找到少量值得关注事项，决定是否继续观察、进入 Topic 或提出行动 | 候选变化、证据缺口、观察异常、反证结果、Coverage、待授权事项 | 未验证变化、机器中间过程队列或自动行动清单 |
| 词表与主题治理 | 查看正式语言版本，提出并决定 Term、Alias、Topic 定义与知识关系变更，理解对分类和统计的影响 | Knowledge Change Proposal、Domain Definition Release、Classification Run、Human Adjudication | 聚类结果自动发布器、全局同义词表或无影响说明的改名按钮 |
| Corpus | 检索、筛选、阅读和引用真实表达与内容材料 | 可复用材料及其 Evidence 来源 | Evidence 替代品或 AI 摘要仓库 |
| 市场洞察 | 查看捕获面中的结构、近期观察、候选变化、反例与限制；后续只在资格通过的范围查看正式趋势 | 合格投影、变化候选、洞察版本、后续合格趋势 Claim | 爆款榜、机会分、把候选写成趋势或无边界市场结论 |
| 选题与行动 | 把原声、Topic、洞察或情报转成可追踪的候选行动，区分实际行动、结果渠道是否可用、取得了什么和如何评价 | 内容选题候选（最终英文名待 Gate 3-C）、Decision、Action、结果可获得性、Outcome Observation、Evaluation | AI 标题垃圾桶、把未接入显示为 0、或用表现证明因果 |
| 外部 Agent/CLI | 在当前委托范围内查询、分析、提交候选或申请有边界动作，并查看申请、授权、执行与结果的不同状态 | 聚合/脱敏视图、受控 Evidence 引用、候选提案、决策与运行回执 | 数据库入口、producer 遥控器、正式知识写入器或“批准即成功”捷径 |

Topic 探索的功能顺序已经确认，但不等于最终页面布局：快速理解当前 Topic → 用户原声 → 内容叙事与代表表现 → 长期历史与近期变化 → 判断依据和资格 → Corpus/Evidence 下钻 → 保存选题、主动研究或观察建议。任何 AI 摘要都必须允许继续回到真实评论、内容和 Evidence。

## 页面共同规则

- 页面展示的确定事实必须带来源。
- ADHD、儿童、家庭、医疗和可反向识别材料默认展示脱敏片段；普通页面不直接暴露账号身份、可搜索原话或组合识别线索。需要查看受限原文时必须经过后续确认的用途与访问边界。
- 未知不能显示为 0、没有或正常。
- Projection 缺失时显示明确不可用，不回退旧字段。
- 所有 AI 文本必须能展开所使用 Evidence、反例与缺失。
- 每日入口的出现只表示“值得用户注意”，不表示事项已经成为正式变化、Signal 或 Intelligence；没有合格事项和观察不完整必须使用不同文案。
- 页面不直接读取原始 Evidence 表，由受控查询服务返回版本化 DTO。
- 来源经过获准隐私处置后，页面、搜索、代表样本、缓存和 Agent 入口必须停止返回失效原文；相关历史判断显示“来源资格已变化/待重新评估”，不能无声消失或继续显示证据完整。
- 页面必须通过 [`../product/domain-invariants.md`](../product/domain-invariants.md) 的相关案例：不把任务未跑显示为“没有”、不把身份推断显示为事实、不把新模型或扩采显示为市场增长、不把高表现显示为因果证明。
- 外部 Agent 请求若会改变正式知识、长期观察、真实采集、敏感传播或现实行动，用户必须看到调用者与委托范围、准备改变什么、资源/风险、支持与反例、批准和不批准的后果；批准界面不能把尚未执行的动作显示成完成。
- 行动与结果页面必须把“未接入”“尚未观察”“观察窗口未结束”“来源不合格”“实际为零”和“评价为失败”分开；人工补充结果要显示提供者与依据，旧 schema 有字段不能让页面声称反馈链已接通。
- 第一阶段页面必须把“近期观察”“候选变化”和“正式趋势”分开。正式趋势能力未开放时，不使用增长/下降百分比、趋势箭头或确定性标题暗示已经可比；候选变化要同时显示可能由观察条件或分析版本造成的解释。
- Topic、词表、分类统计和 Topic 探索页面必须显示或可追溯到所用 Domain Definition Release、Topic Definition Version 与 Classification Run。新定义已发布但重分类/统计尚未就绪时，显示“分析尚未按新定义完成”，或明确保留旧版本结果；不能把新名称和旧统计混成当前答案。
- Map View 的路径和层级只帮助用户找路。页面移动 Topic 时不得暗示定义、知识关系或历史分类同时改变；Topic 拆分/合并后的旧 Claim、统计和分类只有经过明确重算或裁定才能出现在新 Topic 下。
