# 评论研究

> 状态: 权威当前
> 最后核对: 2026-09-06
> 适用范围: COMMENT-RESEARCH-001 交付分支的评论研究二级页
> 事实来源: Mog 当前会话决策、Issue #167、0039 migration 与当前 Rust/API
> 冲突时以谁为准: 用户最新确认、AGENTS.md、真实代码/数据库与验证；本页不证明部署

评论是语料库的基础材料。接纳、去重与当前可读资格成立后，用户直接研究，不需要手动搬运、完成全部采集或等待 AI。当前三个内部视图及查询页已接入代码；模型尚未接入。

| 入口 | 用户动作 | 实际保存/读取 | 限制 |
|---|---|---|---|
| `/corpus/comments?view=voices` 原声浏览 | 跨作品检索，分页，展开来源与父评论/作品上下文 | Evidence Current 和接受时间快照；作品标题、作者、发布时间来自 Work Resource owner | 库内观察样本；父评论缺失不补全；本机受限研究，不是外部模型权限 |
| `?view=groups` 问题分组 | 看相同问题标签的原声样本，继续研读 | 当前源上的最新人工问题标注，或明确同模型/规则版本的候选 | 当前是精确标签归组；未实现语义聚类、代表/边缘样本裁定，也不是正式 Topic |
| `?view=assets` 语料资产 | 将精确表达连同理由收存，可在保存时放入集合 | 源版本 UUID、Unicode 起止范围、源 SHA-256、理由与集合；不复制原文 | 原声变化后历史选择保持；当前源资格失效时停止返回引用及理由 |
| `/corpus/queries` 已存查询 | 保存条件并在以后重跑 | 服务端名称、文字条件、可选作品范围 | 不冻结结果，不触发采集或订阅；当前只承接评论查询 |

资产保存是研究者的选择，不能据此宣布真实、普遍或适合生产。普通研究和计数不会被“是否收存”过滤。当前集合可创建、列出、筛选并在收存时选择；改名、移动旧资产、跨集合复用和导出不在本次已经实现的能力内。

## 来源、上下文和资格

Evidence 的 `comment_research_read` 是跨作品和单源研究入口。最新原声按作品与平台评论身份去重，但 API 只提供内部不透明来源引用，不返回评论用户 ID、名字或平台评论 ID。页面一次最多显示 20 条、每条先显示 350 字符；详情一次至多显示 4,000 字符，长源标明截断。作品上下文仍来自共享 Work Resource，不能用监控目标另造作者事实。

跨页 cursor 保留接受时间及原查询；新来源不混进原页快照，重新查询才更新样本。`total` 是全匹配可读样本数，部分采集并不使已有评论失效。筛选文字是字面子串，`%` 和 `_` 没有 SQL 通配含义。

新增稳定评论身份的研究限制记录，覆盖该评论所有历史和后来再次观察的版本；原有 `/api/local/work-resources/{ref}/comments` 也使用同一可读 view。资产/标注/分析每次读取都核对资格；已有分析引用的父评论受限时，相关结果不再返回。研究限制只收缩用途，不宣称平台删除，也不删除不可变 Evidence。

本机通道增加 Host/Origin/Fetch-Site 校验和 `Cache-Control: no-store`。这是 loopback 内部研究边界，不是多用户角色、账号授权系统或第三方处理许可。查询、集合、资产、人工修订写入使用 JSON、严格类型、幂等 ID 与修订冲突检查。源正文不写入日志、URL 或新资产表。

## 智能化已实现与未实现

`comment_analysis` 有明确规则版本、持久待处理工作、120 秒租约、最多三次尝试、失效租约恢复、精确源/片段/多维输出校验，以及成功无信号与失败分责。输入材料带“不可信数据”合同，不获得采集、数据库或正式发布工具。受控输入保留父评论、作品上下文的确切引用和缺失限制，禁止把材料里的指令当运行命令。

独立 `linggan-comment-worker --queue-only [--once]` 同步新源版本到待分析队列。API GET 不产生分析副作用；阅读不依赖 worker。当前未配置 provider，队列不自动变成结果；真实消费、费用预算、敏感材料许可、语义聚类与语义质量评估仍未完成。合成传输验证只能证明边界，不证明模型理解了评论或能够抵御真实提示注入。

人工七维修订分别是场景、问题、尝试过的方法、评论者自述失败原因、情绪、期望、表达方式；每项区分来源直接表达与研究推断。人工历史追加保存，不被机器运行覆盖。当前界面展示最新人工修订及保留版本数，完整旧修订内容可从受控 API 读取。
