## 1. 产品任务与范围

Intelligence 持续观察内容领域，帮助运营看清主题结构、表现差异、作者与内容供给、用户表达和未被充分理解的问题，并交付可继续追问、比较与导出的情报。人可以亲自探索，也可以把目标交给 Agent。情报交付后，通过新观察和反馈继续更新。

本轮确认范围：独立首页；智能工作台、市场洞察、语料库、采集四个工作区。没有选题库、制作发布、生产排期、转化归因等默认产品流程。雷达作为持续发现能力进入首页和工作台；Pi 支撑执行，其模型、权限和诊断入口放在设置。

| 入口 | 用户带来的意图 | 第一眼必须给出的答案 | 主要停留方式 |
|---|---|---|---|
| 首页 | 今天值得注意什么 | 领域的哪里有值得看的发现、哪里观察不完整、哪些事待决定 | 短时浏览、就地下钻 |
| 智能工作台 | 替我完成一件情报工作 | 正在推进什么、已交付什么、下一步由谁负责 | 交工作、调整工作、接成果 |
| 市场洞察 | 我要亲自比较方向 | 当前主题下有哪些细分方向，各自供给、表现和用户问题怎样 | 排序、对比、展开材料 |
| 语料库 | 我要找、看、引用材料 | 当前取得什么，来源与缺失是什么，怎样精确定位 | 检索、研读、随手记 |
| 采集 | 我要控制对世界的观察 | 看谁、何时看、实际取得什么、为什么停下 | 配置、运营、恢复 |

首页是独立 `/` 入口，不占用智能工作台的默认页。四个工作区拥有具体工作对象；首页只引用它们的事件、发现、成果和待决事项，不另存一套副本。

## 2. 导航总图

以下 URL 是建议路径，不代表现有 API 或路由已存在。生产迁移保留旧深链并按对象映射；原型使用 hash 路由。

```text
首页 /
  └─ 领域地形 / 今日叙事 / 今日语料 / 待决定 / 工作回执（同一页的区域）

智能工作台 /workbench
  ├─ 情报工作 /workbench/jobs                  默认
  │   └─ 工作详情：成果、材料、接续对话、活动记录
  ├─ 持续关注 /workbench/watches
  │   └─ 关注详情：目的、范围、触发、最新变化、暂停
  ├─ 情报成果 /workbench/results
  │   └─ 成果详情：结论、比较、引用、版本、继续分析
  └─ 待我决定 /workbench/decisions
      └─ 补采申请 / 主题语言变更 / 关注范围调整（各自后果）

市场洞察 /insights
  ├─ 主题地图 /insights/topics                默认
  │   ├─ 细分主题比较：表格 / 分布（同一数据集的视图）
  │   ├─ 主题详情：表现 / 内容怎样讲 / 用户在问什么 / 相关情报
  │   └─ 已选主题对比：当前探索中的临时工作面
  ├─ 用户问题 /insights/questions
  │   └─ 问题详情：原声与上下文 / 已有回答 / 问题 × 回答方式
  └─ 跨行业参照 /insights/references
      └─ 从领域外找参照；链接外部语料，保留独立范围

语料库 /corpus
  ├─ 证据库 /corpus/evidence                  默认；沿用现有入口
  │   ├─ 作品 Inspector：正文 / 评论 / 媒体 / 来源
  │   └─ 本领域 / 跨行业范围；外部样本随手记（页内工具）
  ├─ 评论研究 /corpus/comments
  │   └─ 原声浏览 / 问题分组 / 语料资产（含语料集合）；回答对照进入问题详情
  ├─ 创作者 /corpus/creators
  │   └─ 作者目录 / 作品与主题 / 发布节奏 / 讨论与表现
  └─ 已存查询 /corpus/queries
      └─ 保存条件 / 再次执行 / 修改 / 发起持续关注

采集 /collection
  ├─ 待处理 /collection/attention
  ├─ 观察目标 /collection/targets             默认建议
  │   └─ 创作者档案 / 关键词范围；规则按钮 + 弹窗
  ├─ 生产流 /collection/operations
  ├─ 采集任务 /collection/tasks
  │   └─ 工作单 / 实际执行 / 包 / 回执
  └─ 执行工位 /collection/runtime

设置（命令入口进入，不增加业务一级页）
  └─ 模型与 Pi 适配 / 工具与访问 / 指标规则 / 领域语言 / 诊断
```

不将每个详情 Tab 提升为二级导航。OCR、转录是材料属性与处理结果；主题比较是探索状态；工具调用是工作详情里的活动记录。它们有可寻址上下文，但不各自占一页。

2026-09-06，Mog 已确认并派定 MODEL-PI-001：从个人菜单进入「设置 → 模型与 AI」，按当前本机工作空间生效，首版一个功能页包含供应商连接、可用模型、用途默认、额度与运行状态四区。连接测试、模型调用测试与评论分析合格分别呈现。保存配置不启动批量分析；小批试运行后可显式启用新增评论分析，历史补跑单独显示范围和额度。更换模型仅影响新任务，旧任务与结果保留配置版本；Pi 负责调用执行，Linggan 保留材料、预算、持久任务与结果校验。#169 对应 Draft PR #170 的 3cb6135 已完成源码与隔离执行审核，实际官方 Pi SDK 使用合成供应商跑通；[最终审核记录](https://github.com/Himog0921/linggan-intelligence/pull/170#issuecomment-5558907109)的浏览器缺项已在 Mog 解锁后由[同一提交的浏览器验收](https://github.com/Himog0921/linggan-intelligence/pull/170#issuecomment-5559371754)补齐。真实语义质量和部署仍未完成，不将合成响应视作真实模型分析证明。

## 3. 全局交互与对象所有权

### 3.1 壳层

继承 LIDS 中文优先、顶部一级职责入口、页内二级导航。页头承载品牌、五个入口与系统/命令两项；Context Bar 只承载当前范围、必要限制及快照时间，不堆叠长说明。首页正文恢复既有三栏；市场洞察左树中表，右侧分析按需展开。

用户切换一级入口进入职责默认页。返回、浏览器 Back、深链打开和刷新应恢复对象、筛选、排序与滚动上下文。不要让一级入口直接指向最近一个具体工作/主题。可另给“继续上次”显式入口。

### 3.2 共享上下文

从主题勾选后发起工作，携带所选主题、时间、平台、形式、排序、分类/统计版本、实际选择材料和来源页；工作创建前可见且可修改。不是把来源页面整张截图交给模型。

从成果引用进入 Corpus，定位同一作品及获准片段；关闭 Inspector 回到原成果及原位置。从工作提出补采后，工作显示申请与结果引用，具体执行状态由采集负责。采集返回的新材料依旧进入 Corpus，分析不另造正文副本。

### 3.3 同一个事项在三个位置出现

| 对象 | 完整管理位置 | 其他表面的显示 | 操作后的同步 |
|---|---|---|---|
| 值得看的发现 | 工作/成果详情中的相应记录 | 首页今日叙事、相关主题 | 标为已看同步，不等于认可判断 |
| 补采申请 | 工作台待我决定；执行归采集 | 首页右栏、所属工作 | 同一申请版本只能决定一次；首页立刻显示已决定及实际后续状态 |
| 情报成果 | 工作台情报成果 | 主题相关情报、首页精选 | 修改生成后继版本；历史引用不静默变化 |
| 平台/工位故障 | 采集待处理 | 首页观察不完整提示、受影响工作 | 故障恢复后取消当前阻塞；历史事件继续可查 |
| 原始作品/评论/派生材料 | Corpus 的共享资源读面 | 所有引用和对比视图 | 来源受限时所有新读取按当前权限重评估 |

“待我决定”负责有后果的选择；“采集待处理”负责当前运行阻塞。同一个失联工位不会变成一百条情报决定。

## 4. 智能工作台

### 4.1 情报工作：默认页

首屏是工作列表，顶部有“交给系统一件事”。筛选为进行中、需要我、已结束及搜索。每项展示目标、范围、最近进展、已有成果、下一责任与更新时间；工具调用、OCR 和聚类批次不单独变成用户任务卡。

创建面：一段目标描述 + 从来源页带入的范围 + 预期交付类型（方向比较/问题分析/外部参照/自定义）+ 可用材料摘要 + 本次分析限额。默认先用已有材料。只有涉及新的真实访问，才出现具体访问范围；不要求用户配置技术步骤。

工作详情以结果为主：中间为可交互比较表/分析文档/样本对照；范围和材料可折叠；对话用于追加条件、追问局部与修改结果。活动记录只显示实际查询、工具、取得结果、失败和用量，不展示虚构思维链。

动作：开始、追加要求、暂停/取消、从现有结果继续、查看材料、保存成果、提出补充观察。取消后保留已完成部分并显示剩余未完成项；重试先检查输入版本与当前授权。界面上的“已有结果”可以和“等待新材料”同时成立。

### 4.2 持续关注

关注的是情报目标，如“观察几个方向的供给是否出现新的表达角度”，而不是某个关键词的采集频率。列表显示关注对象/目的、范围、触发条件、最近检查、最近有意义的更新、当前状态。

详情配置：相关主题或问题、观察窗口、变化通知条件、分析频率/限额、何时停止、数据依赖。首次设置可复用已有采集；确需增加外部访问时创建独立申请。暂停关注停止未来分析触发，不删除既有成果，也不默认停掉被别的目标使用的采集规则。

同一发现只在有新增依据、解释变化或限制改变时回流，显示“这次新增了什么”。普通重复材料更新底层统计即可。条件调整生成版本，由人确认后生效。

### 4.3 情报成果

按主题、问题、类型、时间、来源工作和阅读状态检索。结果条目显示一句核心判断、适用范围、最后更新时间、材料是否有更新、来源工作。打开后先交付比较和解释，证据/方法折叠但可直接访问。

动作：保存、补充个人判断、继续分析、设为持续关注、导出。导出冻结本次版本、统计口径、材料引用和使用限制；生成一份分析文件不代表对外发布。默认不导出受限评论原文。

新材料进入后，旧成果显示“有新材料，尚未复核”；复核完成后显示变化摘要和新版本。来源撤回与失效单独提示，不将旧成果静默删除或重写。

### 4.4 待我决定

按补采、领域语言、关注范围三类分组，各类复用已有后果模型。每项先说清决定会改变什么、为什么现在需要、已有依据、范围与代价，然后提供同意、缩小范围、延后、拒绝。

补采的同意只形成许可/待执行回执；排队、取得部分材料、完成和分析更新是之后的状态。语言变更显示受影响的主题、旧分类与统计，批准后不立即把旧统计套在新名称下。

只读成员可看获准内容，不能处置、批准或修改任务范围。通知不等于权限。

## 5. 市场洞察

### 5.1 主题地图：默认先比较细分方向

继承截图中左侧主题树与中央统计工作面，右侧 AI 解释收为按需展开。选择父主题后，中央默认展示其直接子主题的比较表，同时保留父主题摘要与面包屑。

常用列：细分主题、下级主题数、作品数、创作者数、爆款数/爆款率、典型表现、代表作品。展开列：产生爆款的作者数、头部作者集中度、内容形式分布、样本与字段缺失。典型表现可切点赞/收藏/评论，再展开中位数及 P90。

用户可搜索主题/别名、选择时间/平台/内容形式、排序、查看列说明、勾选至多三个方向并排比较。这个“至多三个”是原型可读性建议，不是数据规则。选择集合用稳定主题引用保存，切筛选后明确是否仍适用。

“分布”视图用观察供给量与样本爆款率找位置；与比较表使用同一集合、口径、筛选和选择。点不被命名为“蓝海”或“竞争分”。返回表格保留已选项。首页 Three.js 地形不替代表格和这个二维分析图。

主题详情四个 Tab：

| Tab | 可见内容 | 主要操作 |
|---|---|---|
| 表现与供给 | 同口径规模、分位数、爆款分布、作者集中、内容形式；可展开作者分布 | 看普通/高表现样本；移除单一作者后对照；比较相关主题 |
| 内容怎样讲 | 切入角度、回答方式、代表作品、重复与少见结构 | 并排作品、进入原文、把所选样本交给分析 |
| 用户在问什么 | 该范围内的具体问题、涉及作品、代表表达及上下文资格 | 打开问题、查看回答、扩到整个领域 |
| 相关情报 | 当前判断、比较成果、争议、待复核与关注历史 | 继续分析、保存判断、持续关注 |

“值得投入/继续观察/暂时放下”是人的判断与 Agent 建议，显示理由及范围；不强制创建内容生产任务。

### 5.2 指标可用性与爆款率

计算先固定平台、形式、发布时间窗口、观察时点、来源范围、去重规则、分类版本和统一爆款规则。爆款率 = 当前主题中满足该规则的合格作品数 ÷ 同一统计集合内有资格判断的作品数；同时展示总作品与被排除数量及原因。

不能对每个子主题各取自己的前 10% 再比较爆款率，那会让各组接近固定比例。运营比较应采用同一可解释规则，必要时分平台/形式设置基准。最终生产阈值要核对旧系统和真实分布，本稿不替其定值；原型用“合成点赞 ≥ 1,000”的统一演示规则。

按点赞排名采得的样本存在选择偏差，页面应称“当前观察样本爆款率”，显示采样来源，不能声称总体市场概率。按主题去重计数时，一篇作品可属多主题；子主题相加不保证等于父主题。父主题按独立作品重新计算。

供给量、作者覆盖、头部集中度、表达多样性分开显示。不生成一个复合机会分替代这些维度。不同时间窗口不可比时保留集合内指标并说明原因，隐藏跨期增长/下降箭头；新分类发布而重算未完成时保留明确的旧版本，不能混拼。

### 5.3 用户问题

默认列表按具体问题组织，展示表达片段数、涉及作品数、涉及作品作者数、关联主题及代表表达。评论数不等于用户人数。多问题评论可被多个分析关系引用，聚合时说明是否重叠；不推断评论者身份、年龄或诊断。

作品主题与评论问题分别提取和归类。问题可以来自求助、尝试失败、现实限制、分歧等表达，不要求带问号。原文、抽取表达、归类和 Agent 解释保持来源及版本连接。

问题详情分“原声与上下文”“已有回答”“问题 × 回答方式”。必须分开：问题出现在哪些作品下；哪些作品确实讨论了该问题。前者来自关联，后者需要内容分析及可引用片段。没有匹配显示“当前未匹配到回答”，不宣称市场无人回答。

矩阵行是问题，列是回答方式（清单、条件建议、过程复盘等）。格子显示已匹配作品数与判断状态，点击同时查看内容回答、相关表达和不匹配理由。不是将评论所属作品直接视作有效回答。可疑匹配可纠正并记录理由。

### 5.4 跨行业参照

市场洞察提供“带着当前问题看外部”的工作入口；无问题时也能自由探索。领域筛选、样本和随手记的管理仍在 Corpus。此页通过明确引用或跳转消费外部数据，不把外部样本并入 ADHD 统计。

初期：选择外部领域，按已取得样本和笔记检索；查看标题/封面/结构参照，手工记下适用或不同条件；进入外部语料保留筛选与返回上下文。

后续建议：在一个明确的参照任务中并列“外部做法、为什么值得看、本领域的适配假设、不能迁移的条件”。这是表达分析结果，不作为 ADHD 事实依据。#130 首版仍只做采样/浏览/随手记；自动手法归纳按原卡积累门槛另行设计。新增跨页面入口不将整张 #130 自动扩大成自动分析授权。

## 6. 语料库：材料组织、研究与发现的基础工作区

2026-09-06 Mog 进一步明确：保留“证据库、评论研究、创作者、已存查询”四个二级页。上一版“本领域材料/跨行业样本/随手记”分类取代了现有工作面，本节修正该偏移。跨行业仍是独立来源范围；随手记属于样本研读工具，不挤掉评论研究、创作者和已存查询。

语料库从作品、表达、作者、查询四个入口组织同一批已取得材料，让人和 Agent 能直接研究。采集把可用材料持续送入，市场洞察把这里的结构和统计组织成领域比较，智能工作台使用同一材料完成具体情报工作。研究不必等到进入智能工作台才开始。

### 6.1 证据库：从一篇作品读懂材料

沿用共享 Work Resource。顶部搜索、来源范围与可保存条件；研读、宽表、封面是同一结果的布局。显示标题、作者、发布时间资格、互动观测时刻、正文/评论/媒体状态。作者展示遵循现行共享读取合同：详情优先，创作者目标的有限回退由同一 owner 裁定，关键词目标不补作者；展示名称不作为评论者身份或跨作者合并依据。本条随 2026-09-06 实施核对修正此前“任何目标均不能回退”的过时表述。

Inspector 保留正文、评论、媒体、来源。点击“研究这篇作品的评论”带入精确作品范围；点击作者进入同一作者索引。OCR/转录显示来源和质量，评论普通列表使用获准片段，不暴露平台评论者身份。

跨行业样本在来源范围内进入独立读取，继续保存 #130 的领域、关键词、排序、时间、下拉次数与实际取得数；不混入 ADHD 统计。外部样本随手记可检索、编辑、返回来源和导出，仍按原卡范围推进。

### 6.2 评论研究：评论取得后即进入的研究工作面

**默认衔接**：评论/回复被接纳并形成可读材料后，自动进入评论研究的当前材料索引，无需人工搬运、另建研究课题或等全量评论采完。已有材料先开放，新增材料持续补入。这里的“进入”是关联同一来源与使用资格，不复制第二份评论原文。

一篇作品再次被观察时，用稳定评论身份与版本归并；新评论与旧评论的新版本分开，不把多次采集相加成多条用户表达。缺少父评论/回复上下文、采集窗口部分及原文不可用各自可见。采集失败不撤掉此前可用材料。

首屏默认“表达浏览”：搜索词、作品主题、作品作者、表达类型、时间范围、上下文状态；每行显示可用表达片段、来源作品/作者、评论或回复、原文上下文入口、已提取的场景/问题及分析状态。评论发表时间未知时允许按取得时间查新材料，但两种时间不混称“最近讨论”。默认匿名化评论者；作品作者仍保留已确认归属。

页内三种工作视图：

| 视图 | 用户看见什么 | 操作 |
|---|---|---|
| 原声浏览 | 已取得且当前可读的表达、来源、缺失、待分析状态 | 搜索、读上下文、框选材料、存查询、纠正归类、收为语料 |
| 问题分组 | 困扰/限制/失败尝试/求助/不同意见；表达数、涉及作品和独立作品作者 | 看组内典型与边缘样本、合并/拆分候选、继续分析 |
| 语料资产 | 建议保留的表达、已收存语料与语料集合；来源、选择理由和使用关系 | 收存、修改理由、组织集合、引用到情报工作、查看引用影响 |

Mog 随后明确确认：上述语料资产能力属于「语料库 → 评论研究」二级页面内部，不增加平级语料资产入口。「问题与回答」进入问题详情，对照正文、评论及作者回复，区分出现位置与确实回应关系。

评论、表达片段、分析标注、人工选择和语料集合分别记录。语料资产是对原材料的长期选择与研究说明，保存精确来源版本、上下文、保留理由及被哪些情报使用；不复制第二份原文，也不把收存视为真实性或代表性的证明。普通研究无需先逐条人工收存，人工挑选的资产集合不能代替全范围问题统计的分母。分类可描述场景、问题、已尝试方法、评论者自述的失败原因、情绪、期望与表达形式；模型推测另列，不补写原文没有的条件。

已存查询保存查找条件；语料集合保存选择引用；情报工作保存问题、分析与判断。三者互相链接，完整情报工作由智能工作台管理。原型尚未同步本次新增的语料资产工作视图，不把页面蓝图更新当作原型或正式代码已实现。

后台可以在既有使用范围和分析预算内做增量预处理与语义分析。顺序是身份/上下文组织 → 可读可检索 → 表达提取与多标签 → 初步问题归组 → 需要时研究回答关系。分组未完成或分析失败时，原评论仍可读可检索；新取得评论显示“待分析”，不等于没有问题。每条可同时表达求助、尝试失败与现实限制，不强压成正/负情绪。

初期优先交付“已经取得的评论可以跨作品检索、查看上下文、保存范围”；然后完善自动问题分组。市场洞察的“用户问题”消费同一分析版本和来源引用，侧重跨主题分布与机会比较；评论研究侧重材料阅读、提取和纠错，两处不各自重复聚类。

### 6.3 创作者：发现领域内容由谁提供

目录来自**所有合格作品的已确认作者关系**，包括关键词搜索、其他入口取得的作品，以及已观察作者的作品。只要观察到其发布一篇符合当前 ADHD 内容定义的作品，就能以“观察到相关作品”进入目录；不要求先被加入监控。没有作者身份的作品保留待识别，不能造出“未知作者”合并账户。跨平台账号默认分开，不能靠同名合并。

首屏字段：作者/平台、已观察相关作品数、已知时间窗口内的发布分布、最近一篇已观察相关作品的发布时间、主要细分主题、已观察表现、材料覆盖情况、是否已持续观察。支持按主题、已观察相关作品数量、时间范围及观察状态筛选。一次提及、持续参与等分层只有明确规则时才展示，不把关键词命中直接定性为领域专业创作者，也不推断作者本人有 ADHD。

作者详情分“概览、作品与主题、发布节奏、讨论与表现”。作品和评论复用语料读取，时间轴每点可以返回作品。可以比较作者的主题覆盖、表达方式、获得互动的作品分布，以及作品下反复出现的用户问题；不能把评论问题都当成作者的立场。

发布频率必须分两种条件：

- 来源仅为搜索命中/部分采集：显示“近 4 周已观察到 8 篇相关作品、涉及 3 个自然周”等样本描述，以及缺口；不能称作者每周只发两篇。
- 发布日期有资格、统计窗口足够覆盖且领域分类口径明确：才计算对应窗口内的相关内容发布节奏，明确分母为固定观察窗口，而非首篇到末篇的短距离。置顶老作品按发布时间计入原窗口；发现时间不代替发布时间。

“ADHD 内容占比”还要求同窗口取得该作者其他内容，并说明哪些已分类、未分类。只采 ADHD 关键词命中时不显示该占比；没有新命中不等于作者停更。最近发布时间指已观察材料中的最近值，不冒充平台上的最新作品。

点击“加入持续观察”带入已确认作者身份，转到采集的目标与规则设置。语料库回答“这个作者在领域里做什么”，采集回答“怎样继续观察、缺什么、何时巡查”，二者共享作者和作品引用，不重建两份档案。

### 6.4 已存查询：保留可重复使用的观察范围

保存的是条件：查询对象（作品/表达/作者）、搜索词、主题、来源、时间语义、排序、分类/分析版本选择及显示布局。条目显示名称、条件摘要、上次执行时间；数量要附执行时点，过期结果不冒充当前计数。

“重新打开”在当前获准材料上重新执行；“保存结果供分析”另行冻结当次材料集合。相对时间窗口随执行时间滚动，绝对日期窗口固定；固定分类版本与跟随当前版本必须明确选择。查询跨模型/分类版本变化时说明可比性。

可从三类材料入口保存，再从这里打开、重命名、修改条件或删除查询。保存查询不自动启动采集、模型任务或通知；需要持续执行时，可带入工作台建立关注目标。典型查询包括“最近取得但尚未分析的评论”“某主题下用户的执行困难”“近期观察到相关作品且尚未监控的作者”。

## 8. 从一次探索到自动维护

### 8.0 从已有语料形成第一份领域快照

“第一批研究”的具体交付应是第一份可用的领域快照：初始细分主题及边界、同口径的供给与表现统计、代表材料、初步用户问题、明显观察缺口。它让后续变化有参照，也让运营能开始比较。它不要求先穷尽整个领域、标完全部语料或回答一套研究问卷。

初始组织分两条：作品按讨论对象/场景/表达聚类；评论表达按问题/限制/尝试聚类。算法提出候选簇及代表/边缘样本，模型解释命名，人工抽查哪些分组值得保留。聚类结果、命名和正式可导航结构分别有版本；离群材料保留为未归类。聚类数量取决于真实样本的可区分性，不预先规定每类必须拆出多少子类。

市场洞察的页面依次显示“已有材料，结构尚未形成”“部分主题已可比较”“当前有效快照”“新结构候选待检查”。已可比较的区域先开放，其余区域显示观察不足。首页仅用有效结构绘制可导航地形，不用一份模型临时分组每日重排地块。

后续普通作品优先尝试归入已有结构；不同问题、持续离群或边界变得混乱时，才对相关范围重新聚类并提出拆分/合并建议。互动数变化更新统计，新增评论更新问题分析，主题定义变化后再按新版本重算对应统计。初始快照不是循环里的每次必做步骤。

### 8.1 人亲自探索

进入主题地图 → 选择大主题 → 按样本表现/作者分布比较子主题 → 勾选方向 → 看代表作品和用户问题 → 保存判断或交给 Agent 深入比较 → 成果可从主题和工作台两处找回。无需先创建研究课题才能看统计。

### 8.2 Agent 完成情报工作

继承来源上下文 → 先读取合格统计/材料 → 产生可用的部分比较 → 确认关键缺口 → 如有必要申请补采 → 显示实际取得结果 → 更新受影响部分 → 冻结交付版本。用户补一句条件时改对应范围/结果，保留变更说明，不从头生成无关长文。

### 8.3 持续观察驱动更新

| 事件 | 确定性更新 | 需要分析时 | 用户看见什么 |
|---|---|---|---|
| 新作品 | 身份去重、材料和计数 | 有可读内容才做语义提取和归类 | 主题数据更新；新发现过门槛再出现 |
| 新评论/回复 | 去重、窗口和上下文 | 提取新增问题，更新受影响关系 | 问题/回答关系的新版本与缺口 |
| 只有互动数变化 | 更新同一观测序列与合格统计 | 关注条件触发时检查变化 | 新观测时刻；不重读全库正文 |
| OCR/转录后到 | 派生材料及其来源 | 只补受影响作品/问题 | 先前成果提示输入有更新 |
| 新聚类/模型版本 | 保留旧结果及版本 | 对比、抽查、提变更建议 | 候选新结构；不自动重命名正式树 |
| 授权/来源资格变化 | 当前读取资格更新 | 相关成果重新评估 | 受限/待复核；不是数据归零 |
| 用户关注/质疑 | 保存明确理由 | 更新相关工作目的或复核条件 | 后续按条件提醒；不静默调权 |

后台可用规则、统计和受控 Agent 分担。Pi 是候选适配器；当前 Draft #116 的窄 Topic Pack 输入不能被本稿当成全工具工作台已经实现。持久工作、权限、预算、幂等、取消和结果版本由 Linggan 负责；不把 Pi 会话或模型思维当产品事实源。

## 9. 状态词典

| 状态 | 页面必须说清 | 合适的下一步 |
|---|---|---|
| 尚未开始 | 哪一能力/范围还没有数据或配置 | 添加获准来源、浏览已有材料、配置工作 |
| 无命中 | 当前查询及过滤确实没有命中 | 修改筛选；不说现实不存在 |
| 处理中 | 当前固定输入尚未分析完成 | 查看已完成部分、等待或取消 |
| 部分结果 | 已交付什么、仍缺什么及原因 | 先使用有资格部分、选择性补充 |
| 受限 | 哪部分因用途/来源/权限不能读 | 看允许的摘要/范围；申请不等于获准 |
| 中断/失败 | 哪一步实际失败，旧成果是否仍可读 | 恢复或停止；不冒充安静日 |
| 没有合格新发现 | 观察/分析已完成，但没有达到出现条件 | 查看检查回执，继续正常使用 |
| 有更新待复核 | 旧成果仍是旧版本，新输入尚未纳入 | 继续分析；不让旧文案悄悄变脸 |

以上是阅读表达集合，不是把工作、采集、材料、Claim 压成一个统一状态机。具体字段合同在实现前分责确定。
