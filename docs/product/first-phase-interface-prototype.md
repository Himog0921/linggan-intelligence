# 第一阶段用户界面原型规格（候选）

> 状态: 草案
> 原型成熟度: PROVISIONAL
> 最后核对: 2026-08-22
> 适用范围: ARC-001 `p0-surface-prototype` 的首个用户可见工作流走查；只定义 P0 的可见边界、信息分工与诚实状态
> 事实来源: ARC-001 已解决的 `product-shell`、`primary-daily-job`；Issue #10；`pages/page-map.md`、`pages/topic-intelligence-surface.md`；DESIGN-002 合成 Topic Reference Page
> 冲突时以谁为准: Mog 最新确认、`AGENTS.md`、ACCEPTED 决定与当前 SCOPE；本候选不授权 Web、数据、权限、技术选型或行动

## 1. 本原型要回答的一个问题

Linggan 的第一位用户每天进入后，不需要先管理一组页面、任务或 Agent。他需要在 5–10 分钟内完成这条判断路径：

```text
看见少量值得注意的事项
→ 知道系统实际观察到了什么、为什么现在出现、哪里尚不确定
→ 决定暂不处理、继续观察、进入 Topic 深入，或提出行动
```

本规格把这条路径收敛为一个供 Mog 走查的 **P0 候选**。这里的任何文案、状态和案例均为合成/脱敏的走查材料；它们不表示真实数据、真实 Evidence、真实趋势、真实任务执行或已存在的产品功能。

## 2. P0 候选：一个一级入口，一个详情工作区

### 2.1 一级入口：`今日关注`（候选名称）

P0 候选只提供一个默认一级入口：**今日关注**。它不是收件箱、任务队列、Signal 列表或自动行动清单；它只回答：

> 今天是否有少量事项值得我理解并决定是否深入？

页面固定按下列顺序表达，避免把机器中间过程或漂亮摘要伪装成情报：

1. **今日观察状态**：今天能否判断、观察是否不完整、数据/分析处于什么边界；
2. **值得关注事项**：仅显示已通过最低资格检查、且仍值得用户花时间的少量候选；
3. **为什么现在出现**：显示观察窗口、被看到的结构、可能的替代解释与未知，而非先给市场结论；
4. **下一步意图**：进入 Topic、暂不处理、继续观察或提出行动。意图不等于执行回执。

候选事项卡至少持续显示：

| 读者需要知道 | P0 如何表示 | 明确不表示 |
|---|---|---|
| 系统看到了什么 | 受限的“观察到的材料/结构”摘要 | 用户群体事实、诊断或市场总量 |
| 为什么现在出现 | 当前观察窗口、候选变化或待补证原因 | 已确认趋势、机会或因果 |
| 哪里不确定 | Coverage、来源分散性、模型/观察条件限制、反例或缺失 | “暂无”或默认正常 |
| 用户可做什么 | 深入、暂不处理、继续观察、提出行动 | 自动采集、自动发布或已经执行 |

### 2.2 详情工作区：`Topic 深入`（候选名称）

点击事项后进入相应 Topic 的深入工作区。它不是第二个一级导航，也不是固定的“Topic 地图”或“Corpus”独立产品页；P0 中它是为了完成一个具体判断而打开的上下文工作区。

为避免 Tab 过多，候选采用一个连续的阅读工作区，而不是把每一类资产做成一级页：

```text
Topic 现在可知什么
  ↓
用户原声：人在真实场景中怎样表达
  ↓
内容叙事：社交媒体正在怎样讲这个问题
  ↓
近期观察与长期背景：哪些材料可以比较、哪些仍只是候选
```

每段的责任如下：

| 区域 | 用户问题 | P0 显示 | 不可替代为 |
|---|---|---|---|
| 当前判断边界 | 现在最多能判断到哪里？ | 一句限定性摘要、适用范围、未排除解释 | 无来源 AI 结论 |
| 用户原声 | 人们在什么场景怎样说？ | 脱敏片段、场景簇、材料数量/选择范围与“不能证明什么” | 词云、永久用户画像、原文库 |
| 内容叙事 | 创作者如何解释、包装或承诺解决？ | 内容叙事候选、代表材料类型、表现与样本限制 | 用户需求或内容机会结论 |
| 近期/历史 | 最近观察到了什么，与长期材料怎样相关？ | 时间范围、可比性、Coverage、候选变化与替代解释 | 自动趋势箭头、跨口径百分比 |

### 2.3 Tab、抽屉与后台状态的分工

| 位置 | 只负责什么 | 为什么放在这里 | P0 不做什么 |
|---|---|---|---|
| 一级入口 | 每日判断与少量事项的优先顺序 | 用户首先决定是否值得深入 | Topic 管理、全局 Corpus、观察计划、工位或 Agent 管理 |
| Topic 深入工作区 | 对一个具体 Topic 的连续理解 | 让“原声—叙事—观察—限制”保持同一上下文 | 把 Topic 变成趋势、正式 Claim 或行动审批页 |
| 证据与 Coverage 抽屉 | 对当前卡片/段落展开“依据、选择范围、缺口、版本与不能证明什么” | 不打断主判断路径，同时不隐藏限制 | 直接给原始全文、账号身份或未获授权的 Evidence |
| 下一步意图面板 | 记录用户提出的“继续观察 / 提出行动 / 暂不处理”意图 | 清楚区分决定意图与真实执行 | 创建真实采集、变更基线、发布内容或调用外部 Agent |
| 后台状态 | 记录运行、权限、队列、工位、producer、模型等未来运行事实 | 它们是解释页面状态的前提，不是日常用户的主任务 | 在 P0 暴露为运营中心、成功提示或自动行动 |

P0 **不以**“首页 + 雷达 + 主题地图 + 词表 + Corpus + 选题库 + 工位中心”作为并列一级导航。它们可能是未来的应用视图，但本原型不能因为已有名词或旧工作台页面而把它们预置为 P0。

## 3. 三条合成/脱敏走查

以下走查仅验证信息分工与状态诚实。所有人物、原话、数值、窗口和动作均为合成说明，必须在任何未来可视原型首屏和相关材料旁持续标为 `SYNTHETIC / NOT LIVE`；没有真实数据合同前，不得复用为真实 UI 文案或运行状态。

### Walkthrough A：早晨判断——有一项值得深入

**合成情境**：今日关注显示一项“任务启动困难相关表达值得进一步理解”。系统说明：在一个限定的观察窗口中，来自多个内容讨论的表达出现了可继续调查的结构；当前不能排除观察入口、样本构成或分析版本的影响。

| 用户看到什么 | 用户可以做什么 | 系统必须同时说清什么 |
|---|---|---|
| 一张事项卡：观察到的表达结构、为何现在提示、当前限制 | 进入 Topic；暂不处理；提出“继续观察”；提出行动想法 | 这是候选事项，不是趋势/需求/机会结论；来源、Coverage、反例与缺失可展开 |
| 今日状态为“已完成本轮可用观察”（合成） | 阅读为何没有更多事项 | “没有更多合格事项”只描述本轮已完成且有资格的观察面，不描述现实世界没有变化 |

**走查通过条件**：用户能在不读完整报告的情况下回答“我为什么现在看它、现在到底能信到哪里、下一步要不要深入”；页面不能把“候选事项”写成“市场正在增长”。

### Walkthrough B：Topic 深入——从摘要回到材料边界

**合成情境**：用户从上述事项进入「任务启动困难」Topic 深入工作区。

| 连续阅读位置 | 用户看见什么 | 用户可采取的动作 | 必须保持的边界 |
|---|---|---|---|
| 当前判断边界 | “在当前受限材料中可继续研究的结构”与可能替代解释 | 展开依据/限制 | 不称为正式 Insight 或已确认市场需求 |
| 用户原声 | 若干脱敏、合成的场景片段及其选择范围 | 打开证据与 Coverage 抽屉；标记“值得继续观察” | 每条均不证明用户身份、普遍性、诊断或需求规模 |
| 内容叙事 | 内容如何从共情、科普、方法等不同角度讲述该问题 | 对比叙事，提出行动想法 | 高互动/高表现不自动等于有效解决方案或机会 |
| 近期/历史 | 当前窗口与历史材料的不同用途、可比性与未完成处 | 返回今日关注或提出继续观察 | 新模型、扩采或 Coverage 改变不能显示为世界变化 |

**走查通过条件**：用户能够从任何摘要回到“系统具体看到了什么、选择了哪些材料、还有什么没看到”；但 P0 不提供全局原文库、身份检索或真实 Evidence 访问。

### Walkthrough C：采集不完整——不能把未知写成“没有”

**合成情境**：本轮计划观察一批内容，已安全取得其中一部分材料；另有一部分因页面、时间或风险边界未完成。系统尚不能判断是否没有新合格事项。

| 用户看到什么 | 用户可以做什么 | 禁止出现的误导 |
|---|---|---|
| 顶部状态：`观察不完整 / 当前不能判断是否没有新事项` | 打开“范围与缺口”；返回稍后再看；进入已具备独立资格的事项 | “暂无动态”“没有新发现”“全部完成” |
| 范围与缺口抽屉：目标语义、实际取得、未覆盖原因、已取得材料可用于什么/不能用于什么 | 阅读已取得材料；提出继续观察意图 | 用 `目标 - 已取得` 伪造平台剩余对象、完成率或平台总量 |
| 若存在独立合格事项，它与不完整状态并存显示 | 进入该事项 | 因整批不完整而丢弃已合格材料，或反过来把部分材料当完整样本 |

**走查通过条件**：用户能区分“没有形成合格事项”与“不能判断有没有事项”；已安全取得的材料可以被如实呈现，但它的适用范围不能越过 Coverage 边界。

## 4. P0 明确不做清单

本候选只定义首个用户可见判断工作流，因此 P0 不包含：

- 真实 Web、路由、组件、API、数据库、登录、权限系统或前端技术选型；
- 真实小红书/其他平台数据、真实用户原文、账号身份、插件、工位、媒体、转录或下载；
- 真实采集、恢复、调度、基线变更、通知、自动行动或外部 Agent 执行；
- 全局 Topic Map、词表治理、全局 Corpus、市场洞察库、选题库、行动/Outcome 中心、观察计划或运行中心；
- 排行榜、爆款分数、趋势箭头、增长百分比、需求规模、机会评分、诊断、因果或代表性结论；
- 将“暂不处理 / 继续观察 / 提出行动”当作已创建任务、已批准决策、已发布内容或已发生结果；
- 将设计参考页、合成案例或旧内容工作台的页面/字段/导航直接迁入 Linggan。

## 5. 供 Mog 走查的收口问题

本文件不自行把 `p0-surface-prototype` 标记为 resolved。Mog 只需确认或修正以下产品取舍：

1. **已确认（Mog，2026-08-22）**：第一版采用 **一个默认一级入口「今日关注」**，而不是一开始并列铺开 Radar、Topic Map、Corpus、词表、行动与运行中心。进入 Topic 后是否采用任何“深入工作区”及其具体形态，仍属于问题 2，尚未确认；此确认只冻结默认入口，不新增全局 Topic 浏览、运行时页面或实现授权。
2. Topic 深入是否采用 **连续工作区 + 证据/Coverage 抽屉 + 下一步意图面板**，而不是多个独立页面或大量 Tab？
3. 当观察不完整时，是否接受“仍可展示独立合格事项，但必须同时明确不能判断是否没有更多事项”的表达？
4. 第一版是否明确不提供全局 Topic 浏览入口；若需要一个主动进入既有 Topic 的入口，它应由后续 `first-user-visible-scope` 决定，而不能在本候选中悄然加入？

问题 2–4 仍为 **未确认**。它们不能从问题 1 的入口确认、DESIGN-002 静态参考页、旧内容工作台或本候选中的布局建议推断出来。

若这些取舍获得确认，ARC-001 可将本候选作为后续 `first-phase-runtime` 与 `first-user-visible-scope` 的产品输入；仍需分别完成首批 producer Canary、Capture/Media 合同和运行架构收口，才可能授权真实实现。
