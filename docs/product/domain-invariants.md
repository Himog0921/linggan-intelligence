# 领域不变量与对抗性测试基线

> 状态: 权威当前
> 最后核对: 2026-09-23
> 适用范围: DISC-001 后续领域、采集、数据、架构、页面、CLI 与实现验收
> 事实来源: 用户确认的产品目标、Gate 1–7 设计边界、USER-DEC-01–06 与对抗性案例审查
> 冲突时以谁为准: 用户最新确认、ACCEPTED ADR、真实 producer/fixture/测试与运行结果

本文件不是数据库对象清单，也不要求现在实现完整自动化测试。它保存 Linggan Intelligence 在更换数据库、模型、聚类算法、Agent、页面或执行方式后仍必须成立的产品不变量，并把抽象原则转成可以反复攻击设计的案例。

## 核心定义保护

Linggan Intelligence 是面向垂直领域的持续情报研究系统。它通过长期、可追溯地观察现实世界材料，组织领域语言与历史认知，帮助人和 Agent 发现变化、形成有边界的判断并支持内容、产品和商业行动。

语料库、主题词表、主题地图、市场洞察、情报、选题库和 Agent Interface 是这套系统面向不同用户任务的应用能力。深入设计其中任何一个应用，都不能反向把 Linggan 重定义成评论数据库、内容生成工具、市场看板或单一知识图谱。

系统长期积累的是可追溯、可挑战、可修订且带时间的领域认知能力。这里的“领域认知”不授权创建一个万能 `CognitiveModel` 对象；它由观察记录、领域定义、判断、决策、行动和结果之间可解释的关系共同形成。

## 总原则：证据先行，主张受限

所有关于世界变化、需求、机会、风险和行动价值的判断都必须能够回到来源；但同一份来源材料能支持什么，取决于当前判断的范围、用途、观察条件和方法，而不是取决于材料自身一个永久的“可信度”标签。

```text
采集尝试与实际返回
→ 被接纳的来源材料（Evidence）
→ 对来源对象的版本化观察（Observation）
→ 明确标注的分类、关联或解释
→ 当前采用的领域定义与语言
→ 有范围、有依据、有反例和限制的判断（Claim）
→ 决定 / 行动 / 结果观察 / 评价
```

这条链只是语义资格，不是已经确认的物理流水线、数据库表或必须逐层创建的状态机。失败或不合格的采集也不能无痕消失：它必须保留足以说明执行、失败、Coverage 和影响范围的记录，但不得据此生成有效 Observation。

页面、Corpus、Topic Map、市场洞察、报告和 CLI 不是上面链条的“最后一层真相”。它们是跨这些责任组织用户任务的视图、选择或服务接口；其中某些选择与发布记录可以持久化，但不会因此复制新的来源事实。

## 系统必须长期保持的不变量

1. **应用不能改写内核。** 语料、主题地图、市场洞察、情报、选题和 CLI 可以形成不同视图与工作流，但不能分别维护互相冲突的事实。
2. **Evidence 不等于现实真相。** Evidence 证明系统在特定时间、producer 和观察条件下接纳了某份来源材料，不证明材料内容真实、完整、有代表性或适合任意用途。
3. **采集发生不等于有效观察成立。** 原始返回不满足身份、来源或运行时合同时，失败记录仍存在，但不能生成有效领域 Observation。
4. **AI 解释不是来源自带属性。** 分类、聚类、角色推断、Topic 关联和内容角度必须声明定义、模型、规则和版本，不能伪装成原评论或原帖已经证明的事实。
5. **判断资格取决于具体主张。** 一条材料可以证明某种表达存在，却未必能证明表达增长、总体需求、商业机会、方法有效或因果关系。
6. **没有采到不等于现实不存在。** 任务未运行、Coverage 不足、producer 异常、入口无资格或分类能力不足时，数据库中的零不能被解释成市场中的零；每日入口也不能为了显得有内容而把未知或空缺生成成变化事项。
7. **测量、探索、补证和行动反馈保持解释隔离。** 系统不能扩大自己的观察镜头后，再把新增材料当成原现象增长的证明；可比资格未通过时只能形成近期观察或候选变化，不能发布正式趋势。
8. **历史只追加修订，不静默重写。** Topic 定义、分类模型、导航方式和当前解释可以改变，但必须保留当时如何理解，以及现在如何重新解释过去。
9. **代表性必须说明代表范围。** AI 或规则选择的样本最多代表明确捕获面、语义簇或选择目的，不能自动代表平台用户、ADHD 家庭或总体市场。
10. **结果缺失不等于失败，结果也不自动证明原因。** 必须先说明对应 Action 的结果渠道是否接入、是否已观察、观察窗口是否结束和来源是否合格；未知不能记为 0 或失败。实际表现是新的观察，它对原判断提供什么支持或挑战属于后续评价，不能反向修改 Evidence 或伪造因果。
11. **治理围绕后果，委托不产生超级权限。** 只有会改变正式领域语言、观察方法、下游依据、资源消耗、敏感材料传播或现实行动的变化，才需要相应授权；机器内部可重算分析不应制造逐条人工审核。外部 Agent 的读取、分析、建议和申请必须受当前调用者、用途、数据、时间、输出与资源委托约束，申请和批准都不能伪装成执行成功。
12. **隐私处置不是静默覆盖。** 受限原文默认内部受控、工作台脱敏、外部 Agent 不批量读取；有授权的删除、撤回、脱敏或限制访问必须留下不含原始敏感内容的最小处置记录，并使语料选择、全文索引、embedding/feature、摘要、引用、缓存和 Agent 输出知道来源已经变化。历史判断重新评估，不静默消失。
13. **页面、报告与 CLI 不是第二事实源。** 所有摘要、计数、代表样本和判断必须能说明来自哪些记录、定义和分析版本；缓存与投影不得反向成为权威来源。
14. **推算时间不是精确来源事实。** 相对时间和 producer 推算必须保留原始表达、来源、参照时间、解析版本和精度；没有资格时只能表达范围或未知，不能制造精确发布时间与假趋势。
15. **对象去重不删除发现与复观测历史。** 稳定来源对象、每次发现、每次有意复观测和分析使用关系各自回答不同问题；复用一次采集不能倒写采集动机，也不能消灭入口、排名和观察上下文。
16. **观察目的不能复制对象事实。** 持续观察目标和主动研究问题可以共享同一 Observation；意图说明用途与授权，不成为 Source Object、Evidence 或 Observation 的身份组成。
17. **正式语言不等于现实判断。** Topic 和知识性关系表达当前采用的概念口径；共现、趋势、需求、机会或因果仍是需要单独资格的 Derived Analysis 或 Claim。人工确认授予治理资格，不制造真理。
18. **结果通过新判断校准，不直接回写知识。** Action 后的实际结果、环境条件、评价和学习必须分开；任何 Outcome 都不能自动修改 Topic、提升 Claim、改变观察计划或覆盖失败行动。
19. **发现与详情采集不自动连锁。** 搜索或作者页返回一批发现记录，只证明发现面发生了什么；系统必须先区分身份解析、Evidence 复用、详情需求和采集准入，不能把“发现 N 条”自动放大成 N 次详情或评论访问。接口返回与页面实际可见也不能在没有来源对照时互相代替。
20. **采集包接纳与下游解释采用不同失败边界。** Capture Package 必须以包为单位完成真实性、一致性、checksum/canonical、重放/冲突和最低合同接入；接纳后按 Record / Source Object 隔离身份解析与 Observation 生成失败。接入后才发现的单条对象归属问题不能让其他合格记录失效，整包成功也不能掩盖该问题和 Coverage 缺口。
21. **无效交付留下安全记录，但不自动成为 Evidence 或永久原始档案。** 合同失败、目标错误、身份冲突和风险中断必须留下发生、失败、终态、Coverage 与影响范围；完整原始载荷是否隔离、保存多久和谁能访问必须服从明确 producer、隐私和生命周期合同。
22. **缺少稳定身份不能用新对象兜底。** 无法满足来源身份合同的评论文本或片段可以保留为未解析材料或受限 Corpus 候选，但不能凭内容制造 `Expression Object`、Comment、Source Object 或 Observation。
23. **重放、接入冲突、来源差异、复观测和修正必须分开。** 同采集身份同内容是幂等重放；同采集身份不同 hash 是接入冲突；同一对象在不同来源出现不同值是来源差异；较晚时间看到新状态是正常 Observation；解析错误修正产生新版本和血缘。任何一种都不能通过覆盖旧值假装问题不存在。
24. **Source Object 不承担跨责任万能生命周期。** 被发现、身份已解析、被观察、检测到变化、来源删除、本次不可访问和隐私处置分别属于不同记录与资格；不能压成一个线性状态机，再用当前状态解释全部历史。
25. **Observation、解析修订和 Current 是三条不同历史。** Observation 只追加；同一 Evidence 的 parser/结构化修正追加解释版本而不制造新世界事件；Current 是可重算读取结果，不能反向成为 Evidence 或覆盖旧观察。
26. **时间责任不能互相替代。** 执行、观察、接收、接纳、来源事件陈述和派生时间分别回答不同问题；较晚写入不等于世界较晚发生，客户端时间和推算时间也不能未经验证决定 Current 或趋势。
27. **Current 必须带来源并允许未知。** 当前展示值必须能回到合格 Evidence、Observation/来源陈述和选择规则；部分观察不能无来源地拼成完整对象，来源不一致时不得按最大值、平均值或最后写入静默裁定。
28. **正式词表与实验词表必须隔离。** Domain Definition Release 由明确发布决定产生；聚类标签和候选 Topic 只属于固定版本的实验分析或知识变更提案，不能因模型高置信或页面采用而进入正式词表。
29. **定义发布不等于分析已经就绪。** 新 Topic 定义发布后，重分类、统计和页面投影可以仍在准备；系统必须标明使用的定义与分类版本以及就绪状态，不能把新定义和旧结果混成一个当前答案。
30. **词、概念和发现入口不能互相冒充。** Term 只有在指定语言、语境和定义版本下才能成为首选名称或 Alias；同词可多义，Collection Seed 和用户原话不自动获得正式词表资格。
31. **知识关系、数据关系和导航关系必须分责。** 正式 broader/narrower 关系不得在同一发布版本中自引用或形成循环；共现、相似和因果假设属于 Derived Analysis 或 Claim；Map View 只负责找路。
32. **分类与人工裁定都保留版本历史。** Classification Run 必须固定输入集合、词表快照、模型/规则/提示和运行版本；人工裁定追加理由而不删除机器输出，Topic 拆分或合并也不自动迁移旧分类、统计或 Claim。
33. **Claim 的修订不能压成可覆盖分数。** Claim 必须有主张、范围、时间和依据；支持、反例、评估、取代与撤回分别留痕，冲突主张允许并存，普通统计不被强制资产化为 Claim。
34. **持续目标、研究问题、计划与运行不得互相冒充。** 持续观察目标说明长期关注什么；Research Question 说明这次要弄清什么；Collection Plan 说明准备怎样观察；实际 Run/Occurrence 说明本轮发生了什么。改变其中一项不能静默改写另外三项。
35. **Information Need 不是插件命令，也不由任务状态关闭。** 它说明当前判断还缺什么信息；已有 Evidence、分析、人工材料或新采集都可能满足它。任务完成、取得材料、材料适用、信息足够和研究停止必须分别记录。
36. **申请、授权、准入与执行分责。** Acquisition Request 说明为何申请；Authorization 固定允许的版本、范围、期限、资源和风险；Admission 按执行前最新事实判断是否仍值得；Work Order 只给 producer 一个有界步骤。任何前一步都不能被报告为后一步成功。
37. **授权不得自我扩张或互相借用。** 采集授权、材料读取/处理/传播许可和插件设备凭证是三种不同权力；修改计划、排队、持有设备令牌或获准读取既有材料，都不能扩大新的平台访问范围。过期和撤回必须在开始前重检。
38. **执行可以合并，目的与用途资格不能合并。** 多个申请可以共享一次必要访问，但原始动机、字段/Coverage、新鲜度、访问资格、保留要求和每个 Need 的满足评估分别保留；去重不能让一个用途继承另一个用途的许可或结论。
39. **探索必须有限且与测量隔离。** 未知结构可以触发有目的、有预算、有范围和停止条件的受控探索，但不能成为 AI 无限扩采的理由，也不能把探索新增材料放入原比较分母自证增长。
40. **决定固定当时版本与依据。** Decision 可以批准、拒绝、缩小、附条件、延后、要求补证或撤回；它必须指向确切提案/申请/计划及当时依据，后续修改不能借用旧批准，批准也不证明执行或现实结果。
41. **业务行动必须区分建议、计划、尝试与现实成立。** 选题建议、采用的行动计划、排期、发布尝试、发布成功及后续结果是不同事实；采集 Work Order 不是业务 Action，流程完成状态也不能证明外部动作发生。
42. **行动前预期不能事后补写。** Expected Outcome 固定对应的行动计划版本、观察窗口、预期方向和当时依据；结果出现后新增解释只能进入 Evaluation，不能改写成预测。
43. **研究退出必须诚实且可恢复。** 已回答、未获支持或受反证、证据不足、不值得继续、范围改变和暂时中止是不同语义；授权、资源或平台原因造成的中止不等于问题解决、假设为假或永久结束。
44. **Corpus 是用途选择，不是第二份来源真相。** 原始材料只由 Evidence/Observation 链负责；精确片段固定来源版本、范围和 hash，脱敏、翻译、摘要和语义标注分别保留转换血缘，不能互相冒充。
45. **历史选择与当前资格分开。** 材料曾被选择或使用不表示永久可读、可展示、可交给模型或可外传；每次有后果的使用按调用者、目的、受众、隐私状态、传播范围和策略版本重新判断，同时保留真实历史。
46. **检索、固定材料包和实际使用分责。** 零命中、未保存、未采用、Coverage 不完整和权限拦截必须分别表达；只有产生 Agent、Decision、引用或传播后果时才要求冻结足够研究复现链，普通浏览不被强制保存完整候选和正文，但受限材料读取与外部 Agent 调用始终不能绕过安全访问审计。
47. **代表性角色必须限定输入。** 典型、反例、多样性、高表现和边界样本相对于明确捕获面、输入集合与选择规则成立，不能被显示成平台用户或 ADHD 家庭总体代表。
48. **Signal 不因被看见或重复出现而升级。** Signal 保留有边界的分析发现；注意力处理、Claim 资格和市场趋势分别治理。跨运行相似结果必须保留各自输入/版本并检查可比性、来源分散和模型差异，不能累计成一个全局 confidence。
49. **分析发布物组织 Claim，不复制 Claim，也不冒充外部发布行动。** Market Insight 与 Intelligence Brief 的历史版本固定当时 Claim revision、分析、材料选择和正文；当前 Claim 修订或来源失效只能追加影响说明或后继版本，不能静默变脸，也不能用版本不可变阻止隐私处置。分析版本冻结与内容实际发布必须使用不同责任链。
50. **重要新断言不能藏在散文里。** 会扩大范围、因果、确定性、资源选择、对外承诺或行动建议的主张必须引用已有 Claim revision 或先成为待审查 Claim；发布生成成功不等于判断正式、建议获批或行动获准。
51. **Content Idea 不是 Domain Topic 或强制流水线阶段。** 它可以来自人工或系统材料，人工来源无需伪造 Signal/Intelligence；建议、保存版本、采用 Decision、成稿、实际 Action 和 Outcome 分开，多个执行结果不回写一个总分。
52. **生成血缘不替生成内容背书。** Agent、标题、提纲或成稿即使引用合格 Evidence/Corpus，也可能新增无依据事实；输入血缘只能证明参考关系，任何对外事实性主张仍需逐项验证。
53. **Agent 临时回答与长期情报分开。** 一次受控查询不自动形成 Intelligence；只有保存、共享、用于 Decision 或需追踪时才冻结研究复现链，长期保存不扩大原权限。无论是否冻结完整回答，外部 Agent 的身份、委托、受限访问、资源使用和回执仍需安全审计。
54. **Work Order 与 Attempt 不是一对一。** 一个有界 Work Order 可以因失败、过期或重新准入产生多次 Execution Attempt；每次 Attempt 使用新的服务端 Capture Identity。任务 ID、本地 run ID、租约续期和 checkpoint 都不能冒充新的或旧的 Attempt 身份。
55. **第一版一个 Attempt 最多一个终态 Package。** 没有成功交卷时为零个；复杂任务通过有界 Work Order 拆分，不先引入成员可变的多包或流式协议。未来分块若成立，每块必须拥有独立身份并冻结成员。
56. **网络重放与执行重试必须分开。** 同 Attempt、同 Capture Identity、同内容的传输重放保持幂等且不产生新 Observation；同身份不同内容显式冲突；新 Attempt 不得静默继承并改挂旧 Attempt 尚未接纳的本地记录。已接纳 Evidence 的用途复用不等于未接纳材料改挂身份。
57. **checkpoint 只有运行资格。** checkpoint 可以帮助同一 Attempt 恢复进度，但不是 Evidence、Coverage、观察成员清单或平台耗尽证明；checkpoint 变化、缺失或恢复成功都不能改变已接纳历史。
58. **执行权限与 Evidence 写入必须原子衔接。** authority 有效性检查和 Package 接入使用同一事务 fence 或等价原子条件；Package 接入全包原子，接纳后按 Record / Source Object 隔离身份解析与 Observation/派生失败。控制状态完成和 Evidence 已接纳仍是不同事实。
59. **批次缺口不得连坐已安全取得的原料。** Work Order/Attempt 是否达到目标、Package 是否通过最小接入硬门、每个 Record 后续是否能形成 Source Observation、材料是否适合某个用途、以及某个 Claim 是否有资格成立，是五次不同判断。Coverage 限制解释范围，不自动拒绝合格原料，也不自动授予总体、趋势或行动资格。
60. **目标数量、补采和跨批组合必须保留语义。** 只有执行前冻结的已知对象集合才允许记录具体未尝试成员；最大配额、来源穷尽、时间预算、风险预算和探针目的不得用差额制造对象或完成比例。补采形成新的 Attempt、Capture Identity、Package 和 Observation；跨批分析用冻结输入集合或用途化 Material Pack 说明成员、去重、时间、入口和 Coverage，不修改旧包或直接相加记录数。
61. **Domain 是平级研究边界。** ADHD、考研自习、自闭症干预及未来正式 Domain 共享基础采集、详情、评论、媒体和研究能力；Domain 名称不是关键词，不决定写入哪套材料表或 API。Domain 之间的隔离体现在用途和读取范围，不靠复制真实来源身份。
62. **Observation Target 保持真实身份唯一并可跨 Domain 使用。** 同一个 creator 或 keyword Target 可以在多个 Domain 中承担不同 role；新增或解除当前关系不改写已经冻结的历史用途。未分配 Domain 的 Target 不可排活。
63. **primary 与 reference 只改变默认研究用途。** 两种 role 具有相同基础材料能力；primary 默认进入本 Domain 的自动研究和统计，reference 可完整读取并可由人显式选择，但默认不支持本 Domain 的自动结论。role 不能替代 WorkOrder 对媒体、评论、回复、OCR 或 ASR 的具体范围。
64. **一次执行可承载多个相容的已准入用途。** 每个 Request 明确属于一个 Domain 和 role；合并用途分别保留授权、字段、Coverage、新鲜度、保留与风险边界。首次 claim 后用途集合冻结，不能让一个 Domain 借用另一个 Domain 的权限。
65. **Domain 材料资格按用途追溯。** 相同平台 Content 在多个 Domain 仍只有一个 canonical 身份；每个 Domain 的 Corpus 读取必须回到被接纳的发现、明确复用或有标识的历史迁移用途，不能从当前 Target 关系、名称或遗留单值字段推断。
66. **暂停保留历史可读性并关闭新增工作。** paused Domain 不接受新采集 Request、新 WorkOrder claim、新 Comment Study Policy 或 Run；历史材料、Run 与结果继续可读并标明暂停。已 claim 的有界 Attempt 可完成，不能借页面隐藏或状态回落改变事实。
67. **Domain 选择必须显式且失败封闭。** 缺失、错误或不存在的 Domain 不得静默回落 ADHD，也不得跨 Domain 返回材料；读取与写入都必须保留调用者明确选择的研究范围。

这些 Domain 专属不变量由 [DEC-0008](../decisions/0008-peer-domains-and-unified-material-pipeline.md) 冻结；本文其余 Evidence、隐私、来源身份、Coverage、Claim 和行动边界继续适用。

## 同一份材料允许说到哪一步

使用示例表达：

> “孩子每天都要催半小时才肯开始写。”

| 层级 | 系统可以表达什么 | 额外资格 | 禁止偷换成什么 |
|---|---|---|---|
| L0 来源陈述 | 某 producer 在某时间和入口返回了这段文本 | 采集、来源、时间和实际返回可追踪 | 这段话一定真实 |
| L1 对象观察 | 系统把它识别为评论 X，并观察到它当时位于帖子 Y 下 | 对象身份与来源关系通过最低合同 | 评论者一定是 ADHD 家长 |
| L2 语义解释 | 某分类运行认为它可能涉及作业场景、任务启动和家长催促 | 定义、模型、规则、版本和不确定性可见 | 这些 Topic 是原评论自带事实 |
| L3 存在性判断 | 当前捕获材料中存在“反复催促后才开始写作业”的表达 | 可打开相关 Observation，并限定为当前捕获面 | 多数家庭都有这个问题 |
| L4 趋势判断 | 在指定、可比较的观察面中，这类表达在某窗口增加 | 明确单位、分母、时间、Coverage、来源集中、定义与分类版本 | ADHD 家庭总体需求增长 |
| L5 市场或行动判断 | 这类问题可能形成值得补证的内容、产品或服务机会 | 还需供给、不满足、求助/行动意愿、反例、能力匹配和资源后果 | 已证明存在巨大市场或必然有效 |

L0–L5 是判断强度测试尺，不是数据库状态枚举，也不要求每份材料机械经过全部层级。

DEC-05 进一步限定首期承诺：第一阶段可以形成 L0–L3、有范围的近期观察和仍可挑战的候选变化，但不承诺 L4 正式趋势。只有 Gate 4–5 对某个具体观察面完成真实可比性实验和统计资格设计后，该范围内的 L4 才能开放；没有一个全局开关能够让所有历史数据突然具备趋势资格。

## 长期对抗性案例

| 编号 | 案例 | 系统必须做到 | 一旦出现即判定失败 |
|---|---|---|---|
| INV-01 | 一条普通评论被采集 | 分开保存采集、Evidence、对象观察与后续解释；能回到原始来源 | 评论入库后自动成为需求或正式 Topic 事实 |
| INV-02 | 评论者身份不确定 | 保留原话，并把身份标记为已知、自述、推断或未知；推断带依据 | 因内容像家长口吻就宣称“真实家长表示” |
| INV-03 | 聚类产生 Candidate Topic | 保存输入范围、聚类/模型版本、代表与边界样本；保持候选 | 聚类名称直接进入正式词表、Topic Map 或长期统计 |
| INV-04 | 一个旧 Topic 被拆成多个新 Topic | 保留旧定义、拆分时间、血缘和当时分类；支持按旧定义回看和按新定义重算 | 重写全部历史，使系统看起来过去就知道新 Topic |
| INV-05 | 新增关键词或来源后相关内容激增 | 区分观察镜头变化与现实变化；调查材料不直接进入原趋势分母 | 把系统主动扩采制造的增长报告为市场增长 |
| INV-06 | 一个洞察既有支持材料也有强反例 | 同时展示支持、反例、Coverage、无法排除的解释和允许结论范围 | AI 只挑最支持结论的材料并输出确定性结论 |
| INV-07 | 外部 Agent 请求扩大采集、修改 Topic 或采取行动 | 检查调用者、委托范围、用途、数据、输出、资源、风险和期限；只保存带来源的申请并形成决策包。人批准后仍分别经过采集准入/producer/Evidence、知识治理或 Decision/Action/Outcome 链 | Agent 直接增加关键词、作者或深采任务，直接发布正式知识/行动；把申请或批准报告为成功；扩大观察后用新增数据自我证明 |
| INV-08 | 依据情报发布内容，但私信/咨询/销售未接入，公开指标也可能尚未采集 | 保存 Decision、实际 Action 与各结果渠道可获得性；未接入/未观察/窗口未结束保持未知。只有来源合格的系统观察或带提供者/依据的人工陈述才能成为结果输入，评价另行形成 | 将未知写成 0 或行动失败；用旧字段、人工印象或公开互动猜测私信/销售；把高互动自动解释为情报正确或市场需求成立 |
| INV-09 | producer 返回格式正确但对象身份错误 | 分开执行目标错、来源记录内部身份错、采集包身份/hash 冲突和媒体主体错；保留实际返回并按各自合同决定隔离、重试、Evidence 与 Coverage | 用一个笼统冲突码吞并不同后果，或因 JSON 通过类型检查就进入正式事实链 |
| INV-10 | 来源内容被删除、撤回或需隐私处置 | 先区分平台来源消失与获准隐私处置；处置传播到语料选择、全文索引、embedding/feature、摘要、引用、缓存和 Agent 输出，历史判断显示来源资格变化并重新评估 | 原文继续从页面、缓存或外部 Agent 返回；或所有历史关联和处置记录无痕消失 |
| INV-11 | 新模型重新分类同一批历史材料 | 新建分析版本，允许比较“固定数据下解释如何变化”，不覆盖旧运行 | 模型升级被展示成 Topic 或市场突然增长 |
| INV-12 | 每日入口需要展示内容，但最近计数为零且任务没有完成 | 显示“观察不完整/无法判断”，并展示计划、完成、失败和未知；若观察完整但没有合格事项，则明确说“没有形成新的合格事项” | 为填满首页输出“最近没有讨论”“需求下降”“现实不存在”或编造一条变化 |
| INV-13 | 同一 Evidence 被多个用途复用 | 每次使用按具体判断重新评估适用性、访问资格和传播范围 | 一条生动评论无条件从 Corpus 一路继承为趋势、机会和公开事实 |
| INV-14 | 页面只显示“7 天前”，producer 推算出精确发布时间 | 保留原始表达、来源字段/页面、参照观察时间、解析版本、时区和精度；不合格时间不进入精确时间窗统计 | 把 30 天/月等近似推算当成平台精确事实并报告日级增长 |
| INV-15 | 同一笔记被多个关键词、作者页和研究重复发现 | 来源对象只保留一个稳定身份，同时保留每次发现的入口、时间、排名、计划、观察身份与 Coverage；有意复观测另形成历史 | 去重后只剩一个对象，无法解释它如何被发现；或把重复发现当成多篇内容 |
| INV-16 | 同一条评论同时服务“用户痛点研究”和“内容角度研究” | 复用同一 Source Object、Evidence 和合格 Observation，分别保留两个观察目标/研究问题的使用关系与派生分析 | 为每个研究目的复制一条 Observation，产生两个互相漂移的对象状态 |
| INV-17 | AI 发现“任务启动困难”和“亲子冲突”经常共现 | 共现保留为有输入和版本的分析；是否发布为知识性关系、市场判断或研究线索分别治理 | 人点确认后，共现自动变成因果关系、正式 Topic 层级或普遍事实 |
| INV-18 | 某选题取得来源合格的好结果，团队希望提高相关 Topic 权重 | 记录 Action、Outcome Observation、结果来源/观察条件与 Evaluation，通过新 Claim 或有记录的定义修订影响后续；同时保留结果缺失、失败和未执行案例 | Outcome 直接改写 Topic、Claim 置信度或长期观察范围，并只保留成功案例 |
| INV-19 | 搜索接口返回 50 条、页面实际可见 35 条，系统只批准其中 5 条详情采集 | 分开保存接口返回与页面可见的来源陈述；身份充分的卡片只建立或复用最小 Source Object；保留全部合格发现记录和 Coverage；仅为经过复用、去重与准入的 5 条创建有界详情工作 | 宣称“页面展示 50 条”；把 50 条都当成完整笔记 Observation；或插件因发现结果自动打开 50 篇详情并采评论 |
| INV-20 | 一个包整体通过最低合同，15 条评论可解析到对象，另 2 条在下游对象归属时发现来源关系冲突 | 包接入原子保存已接纳 Evidence 与接入回执；后续 15 条按对象继续，2 条按 Record 隔离并计入 Coverage/失败 | 因 2 条下游对象问题丢弃 15 条合格记录；或用整包成功让 2 条冲突记录进入 Observation |
| INV-21 | producer 提交的包无法通过权限、目标、checksum 或最低合同 | 保存安全发生/失败记录和 Coverage 影响，不生成 Accepted Evidence/Observation；完整原始载荷只按已确认隔离与保留策略处理 | 无效包无痕消失；或为了“可追溯”永久保存全部敏感原始载荷并允许下游使用 |
| INV-22 | 同一个 `captureId` 被再次提交，随后同一笔记在三天后指标变化 | 相同 hash 只作幂等重放；不同 hash 作为采集身份冲突隔离；三天后的合格新采集形成正常新 Observation | 把正常复观测当冲突丢弃，或用新指标覆盖旧 Observation，或把同 ID 不同内容当正常重试 |
| INV-23 | API 与页面在同一时间给出不同点赞数，之后 parser 修复 | 两个来源陈述并存并标明来源差异，Current 可未知；parser 修复产生可追溯更正版，旧解析不消失 | 任取较大值当真相；页面值静默覆盖 API 值；parser 更新后历史看起来从未出错 |
| INV-24 | 本次无法打开一篇过去存在的笔记，另一个对象有合格来源明确显示已删除 | 前者只记录本次不可访问和 Coverage 影响；后者可形成带来源的删除状态；隐私撤回另走有授权的传播处置 | 两者都把 Source Object 状态改成 deleted；或把平台删除当成隐私处置并无痕清除血缘 |
| INV-25 | 8 月 1 日观察到的包在 8 月 4 日才接纳，但对象已有 8 月 3 日合格 Observation | 分别保留 8 月 1 日观察时间与 8 月 4 日接收/接纳时间；材料进入历史但不把 Current 倒退。若包含更合格的某字段来源陈述，只重新裁定该责任并保留理由 | 按入库时间把它当成 8 月 4 日新状态；覆盖 8 月 3 日 Current；或为了防倒退丢掉迟到 Evidence |
| INV-26 | 第一次详情观察有标题/正文，第二次较新观察只取得指标 | Current 中每个采用值都保留自己的 Observation/Evidence 来源；缺失字段保持既有合格来源或未知，并明确选择规则，物理实现留给 Gate 5 | 用第二条部分 Observation 清空标题；或无来源地拼接字段并伪装成一次完整快照 |
| INV-27 | 插件电脑时钟偏差，页面只显示“1 个月前”，服务端稍后收到包 | 分开执行、观察、接收/接纳、来源原文和解析时间；保留客户端时间资格、原始表达、参照时间、解析版本与精度，未经 Gate 4 验证不进入日级趋势 | 用插件时间或“减 30 天”的毫秒值决定发布顺序、Current 或趋势，并把服务端接收时间当成来源事件时间 |
| INV-28 | 新 Topic 定义已经正式发布，但历史重分类和页面统计尚未完成 | 页面和查询固定并显示定义、分类与统计版本；明确标为尚未就绪，或继续显示并标注旧版本结果 | 用新定义标题展示旧分类统计，使用户误以为数据已按新口径重算 |
| INV-29 | 聚类产生“外部监督依赖”临时标签，模型置信度很高 | 标签保留在固定输入和实验词表快照的 Analysis Run；需要长期治理时转为 Knowledge Change Proposal，由人决定是否发布 | 自动创建正式 Topic、Alias、Topic Map 节点或长期统计口径 |
| INV-30 | “启动困难”在不同语境指向不同概念，且同时是一个采集词 | 分别保存采集入口、原始表达和按语言/语境/定义版本建立的词表关系；允许歧义与多义 | 建立全局同义关系，把搜索命中自动分类到一个正式 Topic |
| INV-31 | 页面把 Topic 从“执行功能”路径移动到“家庭干预”，定义未改变 | 只发布新的 Map View；Topic Identity、Definition Version、分类和历史统计保持不变 | 因导航移动改写知识关系、创建新 Topic 或触发全量重分类 |
| INV-32 | 一个旧 Topic 拆成两个新 Topic，旧 Topic 上已有 Claim、人工分类和统计 | 新身份与旧身份通过拆分血缘关联；旧材料和判断继续指向当时版本，新结果只有经过明确重算/裁定后才属于新 Topic | 新 Topic 自动继承旧 Claim、分类和统计，或历史页面看起来过去一直使用新概念 |
| INV-33 | 人工认为某条评论被模型错分并作出裁定 | 追加 Human Adjudication、理由和依据，保留原模型运行；后续读取明确采用哪一层结果 | 直接覆盖机器输出，使模型错误率、重跑差异和裁定历史无法追踪 |
| INV-34 | 新反例挑战一条当前 Claim，另一条冲突 Claim 同时有支持材料 | 保存支持、反例、评估和治理结果的历史；允许冲突 Claim 并存并分别限定范围 | 原地改写一个 confidence 分数，或把“当前不采用”显示成已证明为假 |
| INV-35 | 一个 Research Question 从“最近 30 天任务启动表达”扩大到“过去三年全部家庭干预需求” | 新建或明确关联新的问题范围，保留原问题、依据和已完成部分 | 原地改写问题，使旧授权、旧结论和旧停止条件看起来覆盖扩大后的研究 |
| INV-36 | 昨天的详情 Evidence 已满足正文需求，今天另一研究需要最新评论 | 分别评估两个 Information Need；复用正文 Evidence，只为仍缺少且有资格的评论信息申请访问 | 因对象相同重复采全部详情；或因旧正文存在就把评论 Need 标成已满足 |
| INV-37 | 两个研究请求同一笔记详情，但用途、Coverage 和原文传播权限不同 | 可以合并一次必要平台访问，同时保留两份动机、用途资格、Coverage 和满足评估 | 合并任务后让第二个用途自动继承第一个用途的原文权限或结论资格 |
| INV-38 | 采集申请已批准并排队，开始前已有新 Evidence 足够回答，或授权已过期 | 在开始前重评估 Need、已有 Evidence、等价在途工作、时间价值、授权、工位、账号和风险；复用、过期或取消时返回明确原因 | 因任务已经排队或曾获批准就必然占用工位并访问平台 |
| INV-39 | AI 发现未知表达簇，但尚无正式 Claim 或明确补证字段 | 只有在独立、有限、已授权探索预算内，说明降低哪类未知、范围、成本和停止条件后才可申请；结果与比较性观察隔离 | AI 以“可能有价值”为由无限扩词、扩作者、深采，并用新增材料证明该簇增长 |
| INV-40 | 人批准一版 20 篇详情计划，随后系统把计划改成 200 篇加完整评论 | 保留旧决定所固定的计划版本；扩大范围必须形成新申请和新决定 | 修改当前计划后继续复用旧授权，或把插件凭证当成业务采集许可 |
| INV-41 | 内容计划获批，点击发布但平台返回失败 | 分开保存 Decision、Action Plan、Expected Outcome 与失败的 Action Attempt；只有合格来源证明外部发布成立后才进入对应结果观察 | 把“获批”“已排期”“任务完成”或“点击发布”任一状态写成已发布 |
| INV-42 | 内容表现很好后，团队补写“我们本来就预期高收藏” | 保留实际结果；事后解释进入 Evaluation，并标明是在结果出现后形成 | 回填或覆盖 Expected Outcome，制造系统预测准确的历史 |
| INV-43 | 研究因账号风险暂停，期间出现了新 Evidence，数日后恢复 | 保留中止原因；恢复前重新检查问题范围、材料时效、授权、资源和新 Evidence，再决定复用、继续或结束 | 把暂停记为 Need 已满足/研究失败；或从旧 checkpoint 无条件继续扩采 |
| INV-44 | 一条已选 Corpus 片段的来源评论后来被编辑 | 旧片段固定旧来源版本、范围和 hash；新文字形成新的来源观察/片段候选，当前使用资格重新评估 | 旧引用自动指向新文字，或覆盖历史使用过的原声 |
| INV-45 | 历史 Brief 引用的原声后来必须撤回原文 | 停止当前原文访问并传播失效；历史发布记录追加影响说明，必要时形成脱敏/受限后继版本和最小审计 | 以版本不可变为由继续展示原文，或无痕改写历史 Brief |
| INV-46 | Corpus 检索零命中，但 Coverage 不完整或材料被权限拦截 | 分开返回候选数、Coverage、资格过滤和未知；只对本次合格输入解释结果 | 从 resultCount=0 推断用户没有这种表达，或把权限过滤写成现实不存在 |
| INV-47 | 两次不同模型运行发现标题相似的异常 | 两次运行和输入分别保留；另行检查可比性、来源集中与模型差异，再形成复现/持续候选 | 按标题/hash 合并并累加 confidence，或把模型重复输出当市场增长 |
| INV-48 | 一个 Signal 进入每日入口后自动消退 | 保留原分析发现与注意力处理历史；结束只表示暂不继续投入注意力 | 删除原分析、把进入首页当正式趋势，或把消退写成现实不存在 |
| INV-49 | Market Insight 中一条 Claim 后来被推翻 | 历史版本固定旧 Claim revision；当前阅读提示受影响并可发布修订版 | 整份报告静默更新、整体删除，或继续把旧 Claim 当当前依据 |
| INV-50 | AI 使用合格 Corpus 写出材料没有提到的诊断或效果承诺 | 保留输入和生成版本；新增事实性主张逐项验证、删除或明确标为无依据草稿 | 因输入有 Evidence 血缘就把整篇输出标成有证据并直接发布 |
| INV-51 | Content Idea 来自 Mog 的经验而非系统 Evidence | 如实记录人工来源、假设和预期；允许进入内容工作区 | 伪造一个 Signal/Intelligence 上游，或把人工经验包装成系统事实 |
| INV-52 | 同一个 Content Idea 在多个账号和形式被执行多次 | 每次 Publication/Action 分别保留环境和结果；另行形成有范围的 Idea Evaluation | 将全部结果写回 Idea 的一个总分，覆盖失败和环境差异 |
| INV-53 | 一次 Agent 回答被保存并用于 Decision | 固定调用者委托、请求、输入、资格、输出和引用版本；继续遵守原传播与行动权限 | 保存即自动变成正式 Intelligence，或因成为长期资产而扩大 Agent 权限 |
| INV-54 | 外部 Agent 查询受限语料但回答未被长期保存 | 保留必要的调用者、委托、访问策略、资源和回执审计；不强制保存完整候选、原文上下文和回答正文 | 因“不保存回答”而完全不记受限访问，或为了审计反而永久复制全部敏感上下文 |
| INV-55 | Intelligence Brief 已冻结，随后准备把内容发布到小红书 | 分别形成分析发布版本与外部内容 Action；后者只有合格平台来源才能证明发布成立 | 用同一个 Publication 状态把 Brief 发布等同于小红书发布，或用外部发布成功证明 Brief 判断正确 |
| INV-56 | 同一 Work Order 的 Attempt 失效后重新准入，插件本地仍有旧 run 与未接纳记录 | 创建新 Attempt 和新 Capture Identity；旧未接纳材料不改挂，确需挽救时走独立 recovery/import 并保留原来源 | 复用任务 ID、本地 run 或 checkpoint，把旧材料包装成新 Attempt 的本轮观察 |
| INV-57 | 同一 Attempt 的终态 Package 因网络超时被再次发送 | 相同 Capture Identity 与相同内容只作幂等 replay；不同内容显式冲突并停止接纳 | 每次重传都创建新 Observation，或用同一身份接受变化后的成员与 hash |
| INV-58 | 一个复杂任务希望先交一半、稍后再向同一包追加其余记录 | 第一版拆成多个有界 Work Order；一个 Attempt 最多一个冻结成员的终态 Package | 为了方便恢复而让同一 Capture Identity 对应可变成员、多次终态或 outbox 批次 |
| INV-59 | 插件从 checkpoint 恢复后发现的目标集合与暂停前不同 | checkpoint 只帮助运行恢复；实际发现、Coverage、停止和成员变化重新按本轮来源记录，必要时结束旧 Attempt 并重新准入 | 用 checkpoint 推断来源已经耗尽、观察集合未变或暂停前后天然可比较 |
| INV-60 | authority 检查通过后、Package 写入前，租约或授权刚好失效 | authority 有效性与 Evidence 写入在同一事务 fence 或等价原子条件下失败关闭；控制完成状态另行推进 | 先查后写产生越权 Evidence，或因任务状态未完成回滚已经合法接纳的 Evidence |
| INV-61 | 已知 3 个内容目标，风险停止前只取得其中 2 个合格详情 | 两个合格 Record 接入并分别处理；第三个已知成员记录为未尝试；Attempt 如实结束且不显示完整成功 | 因 2/3 丢弃两个合格原料；或为空缺成员生成 Source Identity、Observation、零值或不存在结论 |
| INV-62 | 最大配额 100，风险停止时取得 50 个合格详情，平台剩余范围未知 | 保存 50 个合格原料、实际 Coverage 与停止原因；明确“配额上限 100、剩余范围未知”，不计算 50% 完成 | 生成 50 个虚构未尝试对象、宣称平台共有 100 个、任务完成 50% 或因未达配额丢弃已取得材料 |
| INV-63 | 一个已接纳 Package 有 6 个可重放 Record envelope，其中 4 个形成新 Observation、1 个复用既有 Source Identity、1 个身份 unresolved | Package、6 个 Evidence Record、Coverage、receipt 与处理工作原子接入；逐 Record 结果随后独立追加，复用、unresolved 与网络 replay 分责 | 等全部 Record 处理成功才接入 Package；一个 unresolved 撤销其他成员；或把对象复用记成网络 replay/重复计数 |

## 决策包的最低可见内容

当系统准备造成有后果的改变时，用户确认的不是机器中间过程，而是一份可以判断的决策包。它至少应说明：

- 系统准备改变什么；
- 用户正在决定哪一个确切版本的提案、申请或行动计划；
- 为什么现在提出；
- 支持材料与最强反例；
- 当前仍然不知道什么；
- 批准后会消耗哪些工位、账号、时间或其他资源；
- 是否改变正式 Topic、历史解释、比较性观察或对外传播；
- 请求来自哪个调用者和 Agent，处于什么委托范围，授权是否只适用于当前目的与期限；
- 不批准时会发生什么；
- 是否可以撤回，以及撤回会影响什么。
- 当前可作出的决定是批准、拒绝、缩小、附条件、延后还是要求补证；批准后仍需经过哪一责任链。

具体页面、审核频率和权限状态留到 Gate 7；本节不授权建立全系统审批引擎。

## 跨关口使用方式

- **Gate 2-6A：** 用一条评论、一篇帖子、一次失败采集和一个趋势判断跑通语义资格，确认什么是来源记录、Evidence、Observation、派生分析、领域定义、判断、决定/行动/结果/评价与应用接口。
- **Gate 3：** 每个候选领域对象和状态都必须说明覆盖哪些 INV 案例；不因页面名、身份缺口或通用生命周期创建万能对象。
- **Gate 4：** 用真实 producer fixture 证明身份、来源、时间、实际结果、失败和 Coverage，并区分四类身份失败；对搜索发现至少验证接口返回与页面可见差异、身份解析、顺序/终止、风险中断以及“发现不自动深采”；对详情/评论包验证权限、目标、canonical/checksum、重放/冲突、Artifact、包级原子接入与 Record/Object 级下游隔离；来源不足标记 `SOURCE_INCOMPLETE`。
- **Gate 5：** 用 INV-04、05、10–63 攻击版本、关系、统计单位、时间、发现历史、意图复用、接入/详情分责、更正/差异、迟到材料、Current 来源、正式/实验词表、定义与分析就绪、分类裁定、Claim 修订、Information Need、申请/授权/准入/执行、Decision/Action/Expected Outcome、研究退出、Corpus 选择与使用、Signal/注意力、分析发布物与外部发布分责、Content Idea/Action、Agent 输出与访问审计、结果校准、删除传播以及 Work Order/Attempt/Package/checkpoint/authority/部分结果关系设计；将 DEC-01 落成保留、隔离、脱敏、访问和派生失效合同，此关仍不创建物理表。
- **Gate 6：** 用正常路径、攻击性负例、重放、并发和部分失败检查模块边界，不以编译通过代替不变量证明。
- **Gate 7：** 验证页面和 CLI 不会把未知显示成零、把候选显示成事实、把捕获面显示成总体，且用户能下钻到来源和解释边界。
- **实现阶段：** 逐步把可执行部分变成脱敏 fixture、领域测试、PostgreSQL 集成测试和端到端验收；不得把真实未脱敏评论提交到 Git。

## 通过与失败标准

任何后续设计或实现都必须说明：哪些案例已经有证据覆盖，哪些仍是 `SOURCE_INCOMPLETE`、`DECISION_REQUIRED` 或尚未实现。只要某个方案重新允许下列任一行为，即使页面完整、报告漂亮、类型正确或测试全绿，也判定架构未通过：

- 任务没跑却宣称现实没有；
- 一条评论被外推成总体需求；
- 新模型或新关键词制造假趋势；
- 页面或 Agent 无法回到真实来源；
- 无效采集被当作 Evidence，或身份缺失文本被制造成来源对象；
- 重放、冲突、来源差异、复观测和修正通过覆盖旧值被混成一种更新；
- 迟到材料按入库时间伪装成新世界状态，或 Current 由最后写入、最大值、无来源拼接决定；
- 行动表现被伪装成因果证明；
- 外部 Agent 越过授权改变观察世界的方式；
- 新解释、隐私处置或来源失效让历史无声消失；
- 实验标签进入正式词表，或新定义与旧分类统计被混成同一当前结果；
- Topic 拆分、合并或导航移动静默继承或改写旧 Claim、分类和统计。
