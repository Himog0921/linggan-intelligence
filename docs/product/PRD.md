## 产品定义

Linggan Intelligence 是一个面向垂直领域的持续情报研究系统。它长期、可追溯地观察现实世界材料，组织领域语言和历史认知，帮助人和 Agent 发现变化、形成有证据边界的判断，并支持内容、产品和商业行动。

内容和评论不是最终产品，而是系统观察现实世界的重要来源材料。系统的长期价值也不是单纯积累数据量或报告数量，而是不断提高对一个领域的可追溯、可挑战、可修订认知能力。

“Evidence → Observation → Change → Signal → Intelligence → Outcome”是产品最复杂的长期判断引擎，但不是完整产品，也不表示第一阶段已经拥有所有 Outcome 数据来源。语料库、主题词表、主题地图、市场洞察、选题库和对外 Agent 能力都属于正式产品范围；它们是共同内核面向不同用户任务的应用能力，不是彼此平级的事实源，也不能因其中一个应用被深入设计而重新定义 Linggan 的内核。

### 核心与应用层边界（已确认）

| 层次 | 产品责任 | 当前边界 |
|---|---|---|
| 情报研究内核 | 保存可追溯观察，组织领域定义，形成有支持、反例、限制和版本的判断 | 不是单一报告生成器，也不预设一个万能“领域认知模型”对象 |
| 领域入口与 Topic 探索 | 在 ADHD Domain 内导航主题、历史、原声、市场观察和下一步动作 | 是组合视图，不拥有第二份 Topic、Corpus 或市场事实 |
| Voice of Customer / 语料应用 | 选择、组织、检索、分类、聚类和受控引用用户原声与内容表达 | 不是评论数据库，不把评论自动解释为真实身份、需求或市场结论 |
| Market Intelligence | 展示观察面中的结构、变化、反例和有边界解释 | 不把库存增长、爆款或调查扩采自动解释为市场增长 |
| Content Intelligence / 选题行动 | 把原声、Topic、判断和自身能力组织成可验证的内容或研究提案 | 不是标题仓库，表现结果不能自动证明原判断正确 |
| Agent Interface | 让获准 Agent 查询、研究、建议或申请有边界动作 | 不直连数据库，不绕过证据、权限、资源和解释边界 |

这些是产品能力分层，不是最终页面、Rust crate、微服务或 PostgreSQL 表。DEC-02 已确认每日先处理值得关注事项、再进入 Topic 深入研究的信息顺序；具体页面名称、布局、卡片数量和交互仍留到 Gate 7 结合真实使用场景验证。

## 第一阶段首要用户（已确认）

第一阶段只服务产品负责人本人及其小团队。他们长期围绕 ADHD 完成市场研究、内容判断和选题决策，需要把分散、易失、难以复查的信息沉淀为可信且可持续演进的领域资产。

外部客户、商业化账户体系和多租户产品能力不进入第一阶段范围。架构可以避免把未来演进彻底封死，但不得以“以后可能需要”为理由提前增加多租户模型、管理页面或复杂权限系统。

## 第一阶段每日主任务（DEC-02 已确认）

用户每天进入 Linggan 后，首先看到的不是完整 Topic 目录、评论数据库或指标大盘，而是少量值得关注并需要判断是否深入的事项。用户应当能够快速回答：为什么现在提醒我、系统观察到了什么、哪些解释仍不确定，以及我是否需要继续观察、进入 Topic 研究或提出行动。

```text
持续观察 / 正在进行的研究 / 既有判断状态
→ 形成少量值得关注事项
→ 用户理解理由、证据边界、反例/缺失和决定后果
→ 暂不处理 / 继续观察 / 进入 Topic 深入研究 / 提出行动
→ Topic 工作区查看真实原声、内容叙事、历史、近期观察和 Evidence
```

进入每日入口不改变事项本身的资格。候选变化仍是候选，证据缺口仍是缺口，观察异常也不能包装成市场变化；它们不能因为被展示就统一升级成 Signal 或 Intelligence。每日入口也不是机器中间过程队列，系统必须先自动去重、合并、检查持续性和排除明显由采集/模型变化造成的假象，只把少量可能影响认知、资源或行动的事项交给用户。

如果当天没有合格事项，系统应显示“今天没有形成新的合格事项”，而不是生成一份空洞简报。若观察计划未运行、Coverage 不足或分析尚未完成，则必须显示“当前观察不完整/无法判断”，不能表达为现实平静、需求下降或没有变化。

本决定确认每日任务和深入顺序，不冻结首页名称、Tab、卡片数量、排序评分、通知频率、按钮状态或物理 `Inbox`/`DailyBrief` 对象。具体界面及五到十分钟内完成一次日常判断的验收方式进入 Gate 7。

## 第一阶段产品发动方式与主循环（Gate 1 已确认）

产品有两种进入同一认知底座的发动方式：

```text
持续观察（默认日常主循环）
既有关键词、博主和高价值对象计划持续运行
→ 形成新的 Evidence、Observation、Coverage 和可复用资产
→ 发现值得继续观察或深入验证的候选变化

主动研究（按问题启动）
人提出 ADHD 研究问题，或人确认某个候选变化值得深入
→ 调取已有资产并识别证据缺口
→ 必要时建立新的采集计划补证
```

两种发动方式都可以进入下面的产品循环：

```text
持续观察目标 / 主动研究问题
→ 保存 Evidence，并明确实际 Coverage、遗漏、受限和失败
→ 沉淀可复用语料与持续演进的主题知识
→ 识别市场变化，形成可引用的洞察与情报
→ 形成有依据的候选选题
→ 用户确认、修改、否决或要求补证
→ 执行后记录真实 Outcome
→ 用结果校准后续判断
```

“全部相关笔记和评论”表达用户的采集目标，不自动证明平台实际已经完整返回。系统只有在真实运行结果和 Coverage 共同证明时，才能声称已完成目标范围；无法访问、平台限制、采集失败和未观察必须分别展示。

持续观察负责发现，主动研究负责补证，是当前产品原则，不是两个互相隔离的数据系统。具体哪些计划持续运行、什么变化可以提醒用户、哪些补采需要人工批准，以及各步骤可以停在哪一层，进入 Gate 2 逐项确认。

## 受控渐进式采集（Gate 2 子决定已确认）

Linggan Intelligence 不把“AI 认为还需要数据”直接等同于“插件立即无限采集”。已确认的责任链是：

```text
研究问题或候选变化
→ AI 提出证据缺口与候选获取方案
→ 人批准目标、观察边界、成本、风险和允许策略
→ 服务端在授权范围内拆解、调度、恢复有界任务
→ 当前可用 producer 执行一个有界工作单元
→ Evidence 接入验证真实结果、失败和分层 Coverage
→ 根据新增信息价值决定停止、继续观察或申请加深
```

| 责任方 | 可以做什么 | 不可以做什么 |
|---|---|---|
| AI 与分析能力 | 识别证据缺口，提出候选来源、候选查询和补证建议 | 绕过授权直接指挥插件；把建议、预测或未取得的数据写成事实 |
| 人与治理规则 | 批准目标、范围、成本、风险、期限和允许的深化策略；决定正式意义、资源和现实行动 | 被迫逐条点击每个机械工作单元，或用一次宽泛确认授权无限扩张 |
| 服务端编排 | 在已批准范围内拆分有边界的工作、控制顺序和预算、保留进度，并处理暂停、重试、恢复和提前停止 | 擅自扩大研究问题、来源范围、成本上限或风险边界 |
| producer | 执行当前工作单元，返回实际取得的结果、失败、终止状态和可证明的 Coverage | 自行决定业务目标、长期监控对象或下一阶段深采范围 |
| Evidence 与合同接入 | 运行时验证、保存不可静默覆盖的事实，并区分各层实际覆盖与缺失 | 根据期望数量补齐现实，或把“任务结束”解释为“世界已完整观察” |

人的批准采用“授权范围”，而不是每生成一个插件任务都要求人工确认。在目标、来源类型、时间范围、成本、风险、期限和允许策略没有越界时，服务端可以自动完成机械拆解和恢复；任何超出授权范围的扩张都必须重新申请。这既保留自动化价值，也避免人工确认沦为无意义的连续点击。

采集遵循渐进深化和可提前停止：先发现候选，再用较低成本验证来源与相关性，必要时获取索引或范围，再选择少量对象取得详情、评论、回复或持续观察。这个顺序只是决策模式，不是已经冻结的六层任务类型。每一阶段都要根据新增信息价值、证据充分性、成本和风险判断是否继续。

Candidate Source 必须来自可追溯的真实发现路径，不能由 AI 凭空生成。发现一篇相关内容，也不等于该作者值得长期监控；系统应选择当前问题所需的最小观察对象，例如只保存一次内容、短期复看讨论串、轻量了解作者，或经批准后持续观察。作者不是默认采集单位，候选来源也不会自动触发深度建档。

当前第一阶段的现实 producer 主要是浏览器插件，因为社交平台没有提供能够覆盖现有需求的稳定开放接口；产品责任按照“能力边界”定义，不把领域模型永久绑定到插件。未来如果出现真实可用的官方接口或其他适配器，可以在同一合同边界内并存。

风控是停止与恢复规则，不是绕过平台限制的技巧。遇到登录失效、验证、访问受限、账号状态异常、预算耗尽或已达到授权边界时，producer 必须停止或暂停，并如实返回终止状态。ADHD、儿童和家庭相关公开内容也不等于可以不受限制地再利用；DEC-01 已确认原始 Evidence 默认内部受限保存、工作台默认脱敏、外部 Agent 不批量读取原文，以及获准隐私处置必须传播到派生物和缓存。具体期限、算法、权限和法律适用性由 Gate 5–7 继续收敛。

Coverage 必须按阶段分别说明，例如作者作品索引、内容详情、评论页和回复各自有自己的已观察、失败、受限与未知范围，不能把不同层级的数字相加后宣称“完整”。“全部作品”只能表示当次可访问条件和停止规则下实际观察到的范围。

Gate 3-B 已进一步确认：持续观察目标、Research Question、Collection Plan 与实际 Run 分责；Information Need 表达知识缺口；Acquisition Request、人的 Acquisition Authorization、执行前 Acquisition Admission 与 producer Work Order 分责。采集授权、材料使用许可与插件设备凭证不能互相替代，任务完成也不自动代表信息需要已满足。

这些确认仍只是产品责任和权力边界，不授权创建万能 DAG/工作流引擎、固定任务枚举、具体批量大小、数据库表或业务接口。具体关系基数、状态、调度策略、producer 工作类型和安全停止机制由 Gate 4–6 根据真实合同继续设计。

## 有限资源下的采集准入与执行边界（Gate 2 子决定已确认）

采集工位、平台账号、可安全访问时间和人工注意力都是有限资源。Linggan Intelligence 不假设所有进入队列的任务最终都能完成，也不把优化目标收窄为“让插件跑得更快”。系统首先要减少本来不需要发生的真实平台访问，再把剩余访问分配给延迟后信息损失最大的需求。

已确认的责任顺序是：

```text
持续观察 / 主动研究 / AI / 人工
→ 提出还缺什么证据、为什么需要
→ 采集准入：复用 / 合并等待 / 延后 / 过期 / 准入
→ 在授权范围内拆成有边界、可停止、可恢复的工作
→ 执行协调：匹配工位与账号，处理领取、租约、恢复、重试和安全停止
→ producer 执行当前工作单元并报告真实结果、失败和终止原因
→ Evidence 接入独立验证合同、身份、来源和分层 Coverage
→ 判断原证据需求已经满足、仍有缺口，或需要重新申请范围
```

真实平台访问进入队列前至少回答：

1. 已有 Evidence 是否已满足本次所需字段、Coverage、时间窗口和可接受新鲜度。
2. 是否已有等价需求或在途工作可以合并等待。
3. 这是无意义重复，还是为了时间比较而进行的有意复观测。
4. 任务当前是否仍在有价值的时间窗口内；延后会损失多少信息。
5. 是否仍在已批准的目标、来源、成本、风险、期限和允许策略内。
6. 是否存在具备相应平台能力的健康工位和账号，以及当前风险与冷却是否允许访问。

安全、授权、账号健康、平台冷却和能力匹配是硬门槛，通过后才能比较时间价值和优先级。调度主要决定下一个空闲资源执行什么，不默认强行抢占已经在浏览器中运行的工作。基础持续观察、运行恢复和结果提交需要保留资源，AI 提出的调查不能无限占满全部工位；具体 lane、容量和公平策略留到 Gate 4–6。

同一对象经多个关键词、研究问题或候选变化发现，可以由一次合格采集满足多个需求，但必须同时保留：原始采集动机、每条发现路径、授权来源，以及后来对 Evidence 的复用关系。后来的需求不得倒写为最初的采集原因。一次采集也不预设只产生一条 Evidence；producer 可以返回包含多条记录的 Capture Package，最终以 Evidence 接入实际接受的内容为准。

平台生命周期规律必须版本化。“7 天”等经验可以影响特定目的下的资源策略，但不得变成来源对象的永久 `stale` 属性：一篇旧笔记对流量变化监控可能价值很低，对历史语料、作者档案或长期搜索占位研究仍可能有价值。`publishedAt`、各次发现时间、实际观察时间和系统接收时间不得互相替代；发现时间可能因发现路径不同而有多条记录。`publishedAt` 还必须说明是平台绝对时间、原始相对表达、producer 推算、时间范围还是未知，并保留来源、参照观察时间、解析版本和精度；推算值不能未经资格检查进入日级趋势。

市场变化分析也不能直接读取一个不分边界的“全部历史”或只读取 Current。它必须使用由历史 Observation 形成的版本化可比样本，明确时间范围、发现路径/计划、对象年龄、Coverage、平台策略和方法版本。

### 可证伪验收标准

- 五个等价需求命中同一对象和同一证据要求时，最多发生一次真实平台访问，同时保留五条需求/发现关系。
- 已过价值窗口的排队工作在领取前重新评估；不再值得访问时，不向 producer 下发任务，并记录明确原因。
- 合法的定时复观测形成新的 Observation，不会被对象去重或请求幂等误删。
- 工位离线、能力不匹配、账号受限、风险冷却或预算不足时，返回结构化的延后/不可执行原因，不表现成“现实没有内容”。
- producer 报告完成但提交包不满足合同或无法证明结果时，不生成 Evidence 或 Observation，也不把原需求标记为已满足。
- producer 丢失本地运行状态后，可以根据服务端有效租约恢复同一工作；过期或旧租约不能推进状态。
- 已有 Evidence 只缺评论等局部 Coverage 时，只形成所需的补充工作，不默认重跑完整采集。

本次确认的是统一责任边界，不确认一个名为 `Collection Control Plane` 的万能模块或微服务，也不授权固定优先级公式、通用工作流引擎、任务表、数据库唯一键、抢占策略或具体批量参数。术语留给 Gate 3，producer 与 Coverage 合同留给 Gate 4，时间/身份/版本和 PostgreSQL 表达留给 Gate 5，Rust 物理模块与部署留给 Gate 6。

## 持续观察：尺子与放大镜（Gate 2 子决定已确认）

持续观察的根本矛盾不是怎样产生更多任务，而是怎样同时做到：允许系统主动探索未知，又不让系统通过改变观察方式制造一个支持自身判断的数据世界。

因此，Gate 2 确认两种不同的证据用途：

```text
比较性观察：尺子
→ 使用足以解释前后差异的相近观察条件
→ 负责判断世界是否发生变化

探索与调查观察：放大镜
→ 在授权和有限预算内弹性扩大镜头
→ 负责发现未知、理解现象和补齐证据
```

两者共享同一 Evidence、来源对象、语料与主题知识底座，但探索/调查材料不能未经明确可比性处理直接进入趋势基线。这是解释纪律，不是两套数据库、两个服务或两个固定执行队列。

### 已确认的七条规则

1. 比较世界之前，必须确认前后观察条件足以用同一种解释比较；不满足时不得直接宣称趋势。
2. 影响解释的观察方法变化，与某一轮没有完整执行必须分开：前者改变比较条件，后者通过本轮 Coverage 表达。
3. 新的平台访问只能因为三类持续价值发生：补齐已批准的信息缺口、完成有时间窗口的已批准观察、使用受控探索预算发现未知。时间敏感只提高紧迫性，不能单独创造采集目的。
4. 所有访问先复用已有 Evidence、检查在途工作和无意义重复；为了时间比较进行的有意复观测不能被去重消除。
5. 普通采集采用最低充分治理，复杂市场判断采用完整证据治理；复杂度随结论风险增加，不把 Intelligence 级流程强加给每次普通字段采集。
6. 系统没有持续价值或有效观察承诺时，默认不新增平台访问；已经批准的稳定观察按计划运行，不要求每一轮重新申请，但计划本身需要定期复核。
7. 系统可以评估观察入口的效率并提出调整建议，但 AI 不能静默修改比较性观察，再用新增数据证明自己的判断。

### 所有 Evidence 共同的最低底线

“普通采集可以简单”不等于可以省略可信来源。任何被接受的 Evidence 至少必须能够说明：

- 观察的是哪个真实平台对象，通过什么入口发现；
- 由哪个 producer、版本和获准执行身份取得；
- 何时实际观察，取得了哪些原始结果；
- 哪些字段、页面或范围缺失、失败、受限或无法证明；
- 跨边界结果是否通过运行时合同验证。

当系统进一步形成市场变化、Signal、Intelligence 或行动建议时，才额外要求：版本化可比样本、支持证据、反例、缺口、不确定性、方法/模型版本和适用时间。

### 持续观察中的深化与停止

搜索或发现入口实际返回的对象先形成带入口、时间、排序和 Coverage 的发现事实。它不是市场普查，也不能证明平台全部相关内容。AI 与规则只能决定哪些对象值得继续访问详情、评论、回复、作者或新的时间状态，不能让没有被深化的发现事实从历史中消失。

新内容不自动进入完整深采。继续访问必须能够说明是补缺口、抢已批准的时间窗口，还是使用受控探索预算；否则停止。已有信息足够、时间价值已经过去、继续获取的信息增量低于资源与风险成本，或现实条件无法继续时，系统停止新增访问并保留原因。

候选变化也不能立即打扰用户。系统先检查观察条件变化、Coverage、来源集中、内容年龄、平台入口、规则/模型版本和反例；能够解释的内部结束，证据不足的继续观察，只有需要扩大授权、改变比较性观察、启动主动研究、确认正式意义或采取现实行动时，才进入用户决策队列。

本轮不确认 `Observation Opportunity` 正式对象、复杂 Evidence Sufficiency 合同、固定优先级顺序、资源百分比、统一信息价值评分、全系统 Event Sourcing 或观察策略学习引擎。现役 V2 的监控 lane 只能证明执行分类存在，不能证明比较性观察与探索/调查证据已经实现认知隔离。

## 主动研究：问题驱动的有限闭环（Gate 2 子决定已确认）

主动研究不是“提出问题后让 AI 无限搜索并生成报告”，也不默认产生新的平台访问。它从一个有边界、服务于具体判断或行动的问题开始，先使用系统已经拥有的世界事实、语料、主题知识和历史认知，再决定仍然缺少什么，以及新增获取是否值得占用有限资源。

```text
人的问题或经人确认的候选变化
→ 明确本次研究要支持什么判断或行动
→ 检查并复用已有资产
→ 形成初步回答、反例、限制和未知项
→ 识别仍会影响当前判断的证据缺口
→ 无需新增访问：继续分析或诚实结束
→ 需要新增访问：进入已确认的采集准入
→ 有限补证并通过 Evidence 接入验收
→ 更新判断，形成候选产出并结束
```

已确认的主动研究规则：

1. 主动研究从有边界的问题开始，不从采集任务开始；问题应说明当前用途，避免没有停止条件的泛泛探索。
2. 必须先复用已有资产。完全不新增平台访问、仅凭已有材料得到足以支持当前决定的回答，也属于成功研究。
3. 新增采集只能来自会影响当前判断的证据缺口，或受到明确预算约束的探索分支，并统一进入采集准入；研究能力不能直接指挥插件。
4. AI 可以修改假设、提出反例和建议新的研究方向，但扩大问题、来源、成本、风险或稳定观察范围必须重新取得授权。
5. 研究同时保存支持材料、反例、来源限制、未知项和判断变化；完整报告、评分或 AI 文字本身不能证明研究成立。
6. 研究只能以“对当前决定已足够”“当前假设未获支持或受到反证”“证据不足暂时无法判断”“继续研究的价值低于成本而停止”等诚实语义结束。结束不等于获得永久真理。
7. 研究产出默认先形成候选。Evidence 只有通过接入合同才能成为事实；正式 Topic、关系、市场洞察、Intelligence、比较性观察调整和现实行动继续受各自治理，不由一次研究自动写入或发布。
8. 保存可审计的结构化研究血缘和版本，包括问题与用途、使用的 Evidence、关键反例、证据缺口、补证理由、判断变化、结论限制和停止原因；不要求保存模型的完整内部推理或把每次研究固化为一套庞大工作流。

主动研究与持续观察共享同一资产底座，但承担不同责任：持续观察提供稳定发现与比较入口，主动研究围绕具体问题组织已有材料、挑战假设并有限补证。主动研究获得的新材料可以帮助理解结构，但不能仅因为研究扩大了入口，就用来证明市场增长。

以下高风险原则已经作为后续设计的强制输入，但本轮不把它们提前实现为字段、评分、权限等级或模块：证据是否适合支持某个判断取决于该判断的用途；平台搜索结果是带排序和 Coverage 的可见表面而不是总体市场；统计单位必须区分发现次数、唯一来源对象和可证明的观察主体；现实变化、观察方式变化、分析解释变化和未知因素可以同时存在；比较基线需要稳定且允许有记录地演进；重新分析历史必须形成新版本，不能静默覆盖旧判断。

上述内容分别在 Gate 3 统一术语和状态，Gate 4 审计 producer 能证明的观察上下文，Gate 5 设计判断适用性、统计单位、时间和分析版本，Gate 6 再决定 Rust 模块与运行边界。当前不确认 `Research Project` 物理模型、Evidence Gap 表、统一充分性分数、四级权限、自动问题拆解、通用 DAG、六个研究微服务或完整研究工作区页面。

## Topic 中心的资产探索与市场理解（Gate 2-5 已确认）

Gate 2-5 不把语料库、主题词表、主题地图、市场洞察、情报和选题库设计成彼此割裂的页面，也不把它们串成一条所有材料都必须经过的生产线。同一份可信事实可以按不同目的进入多条可追溯路径：

```text
Accepted Evidence / Observation
├─ 选择与整理 → 语料候选 → 可复用的用户原声与内容材料
├─ 语义发现 → 表达簇 / Topic / 关系候选 → 经治理的主题知识
├─ 合格统计 → Topic 库内概况与带时间的市场观察
├─ 可比变化 + 反证 → 市场洞察候选 → 情报判断
└─ 原声 / Topic / 洞察 / 情报 → 选题候选或主动研究

行动后的 Outcome 只能校准后续判断，不能反向改写 Evidence、当时的主题版本或历史结论。
```

Topic 是这些能力最重要的共同探索入口之一，但 Topic 详情不是新的事实资产，也不是把其他模块复制一份。它是在当前已发布 Topic 定义下，组合语料、主题知识、市场观察、历史判断和 Evidence 的受控视图。用户进入一个 Topic 后，核心任务是逐步回答：

1. **人们正在经历和表达什么？** 从正文、评论和回复中按真实场景、具体行为、情绪/冲突、尝试过的方法和结果组织可读原声，并能继续打开原始材料。系统只能称其为“已观察到的表达”；身份或角色无法证明时，不把评论者自动宣称为家长、患者或真实消费者。
2. **社交媒体正在怎样讲这个问题？** 展示内容角度、叙事方式、内容形式、创作者结构和代表作品。内容角度是可版本化、允许多标签的分析结果，不是正式 Topic，也不能由标题关键词直接决定。
3. **长期以来积累了什么？** 展示库内收录范围、代表性原声与内容、历史高表现作品、Topic 关系以及系统对该 Topic 的认识过程。库内累计量表示资产厚度，不表示平台市场规模。
4. **最近有什么变化？** 只在明确观察表面、时间窗口、统计单位、Coverage 和可比条件下展示表达、内容供给、作者结构、互动或 Topic 关系的变化；不能用数据库自然增长替代市场增长。
5. **系统为什么这样判断、目前有资格判断到哪里？** 展开支持材料、反例、Coverage、分类/模型版本、无法排除的其他解释和不能证明的内容，并能一路回到 Corpus 与 Evidence。
6. **接下来可以做什么？** 查看或保存语料、形成选题候选、启动主动研究、提出观察调整建议、查看相关 Topic，或在证据不足时停止。任何动作继续遵守其自身的候选、授权和发布规则。

### Topic 探索必须保持的分离

- **树形导航不等于知识真相。** 前台可以用一级、二级、三级帮助浏览，但底层的 Topic、Term/Expression 与采集关键词不得混为一物；Topic 还可以具有跨层和多对多关系。树负责找路，关系负责表达当前知识。
- **主题知识不等于市场表现。** Topic Map 表达已发布的概念和关系；带时间的 Market Overlay 表达在特定观察面中看到的供给、表达、互动和变化。市场共现增强不能自动改写成正式父子关系。
- **用户原声不等于内容叙事。** 前者回答“材料中的人怎样描述经历”，后者回答“创作者怎样解释、包装或提供方案”。两者的差异可以形成值得调查的候选错位，但当前不计算统一机会分，也不直接宣称蓝海。
- **爆款不等于需求。** 高点赞、高评论、高收藏或高传播只能证明特定平台、时间和样本中的内容表现；它可以帮助理解哪些表达曾获得平台响应，不能单独证明用户需求、市场规模或商业机会。
- **库内历史不等于市场趋势。** 必须区分累计收录、某时间窗口新增以及可比较观察面中的占比；具体名称、分母和计算方式留到 Gate 5，不把 `Stock / Flow / Share` 提前冻结成数据库对象。
- **市场历史不等于系统认知历史。** 一条时间线记录系统当时观察到的市场材料与变化，另一条记录 Topic 何时被提出、确认、拆分、合并或重新解释。产品长期需要同时支持“按当时定义回看”和“用当前定义重新研究”，但后者不能覆盖前者。

### AI 在 Topic 探索中的职责

AI 的价值是把大量材料组织成较短的理解路径：聚合、对比、寻找异常、选择代表样本、寻找反例并提出有边界的解释。任何聚类名称、内容角度、变化解释或机会判断默认是候选；用户必须能够看到选择依据和样本边界，并从摘要继续下钻到表达簇、真实评论/内容和原始 Evidence。

目标体验可以概括为：**AI 缩短理解路径，但不阻断返回真实世界。** 本轮只确认上述探索任务和资产边界，不冻结 Tab 数量、区块顺序、7/30/90 天窗口、固定内容角度词表、机会象限、评分公式或完整 Topic 页面；具体交互留到 Gate 7 用真实“任务启动困难”样本验证。

### 市场洞察的产品边界

市场洞察继续作为正式产品能力，但不再等同于“主题指标看板 + AI 总结”。它负责在明确观察表面中发现变化、主动检查数据生成条件和反例、进行授权内的有限验证，并给出有适用边界的解释；它不负责替用户决定行动，也不能修改正式 Topic、比较性观察或长期采集范围后再用新数据证明自己。

市场事实与结构、变化候选、市场洞察和行动机会是不同认知强度，但本轮不据此创建四张表、四个 Agent 或统一状态机。描述性且可复算的合格投影可以自动刷新；聚类命名、叙事归纳、变化解释、市场洞察和机会判断默认先成为候选。Gate 2-6A 已确认发生记录、Evidence、Source Object/Observation、Derived Analysis、Domain Definition、Claim、Decision/Action/Outcome Observation/Evaluation 的责任边界，再按实际后果决定确认、发布和 Agent 权限。

### Gate 2-6A 真相与派生责任边界（已确认）

- 持续观察目标和主动研究问题都能解释“为什么关注”，但具有不同生命周期和产品责任，不建立统一 `Research Intent` 父对象或状态机。二者都不进入 Source Object、Evidence 或 Observation 身份；同一次 Observation 可以通过使用关系服务多个目标、问题和 Information Need。
- Observation 只表达 Evidence 直接支持的来源对象状态；Topic 分类、角色推断、趋势和市场含义属于 Derived Analysis 或 Claim。
- Topic 定义当前采用的领域语言，不证明对应现象普遍存在；Claim 对存在、关联、变化、需求、机会或行动价值提出可争论主张。
- 人工确认允许某个定义或 Claim 成为当前正式口径/依据，但不把它变成不可挑战真理；自动分析按是否改变正式认知、观察方法、资源、敏感传播或现实行动决定治理强度。
- Corpus 可以保存用途、选择规则和成员历史但不复制原文真相；Topic Map 是导航视图；CLI/Agent Interface 是受控服务入口，仍可在隐私和用途授权下返回真实原声与 Evidence 引用。
- Decision、Action、Outcome Observation 和 Evaluation 分开；结果通过新的判断或有记录修订校准系统，不直接回写 Topic、Claim 或长期观察。
- 当前 Domain 仍为 ADHD；家庭干预是 Topic/研究范围。`Knowledge Layer First`、`Domain Seed`、跨 Domain Graph、固定核心对象数和 `Gate 3-A` 均不成为首期产品合同。

### Gate 3-4 正式领域语言与历史解释边界（已确认）

- Topic 由长期 Topic Identity 与不可静默覆盖的 Topic Definition Version 共同表达。改名、可解释的边界修订可以保持身份并发布新版本；拆分和合并通常产生新身份并保留血缘；页面导航移动只改变 Map View。
- Domain Definition Release 是明确发布决定所采用的 Topic 定义、首选名称、Alias 和 Knowledge Relation 逻辑清单。最后写入、最大版本、模型置信度或页面采用都不能自动成为当前正式语言。
- Term、用户原话和 Collection Seed 分责。Term 只有在指定语言、语境和定义版本中才成为首选名称或 Alias；同词可以多义，搜索命中不能自动形成 Topic 分类或全局同义关系。
- 正式词表与实验分析词表隔离。Classification Run 固定输入集合、正式发布或实验词表快照、模型/规则/提示和运行版本；Human Adjudication 追加理由而不覆盖机器输出。
- Knowledge Relation 与数据共现、语义相似、市场关联、因果假设及页面导航分开。正式层级关系不得在同一发布版本中自引用或成环；分析发现仍属于 Derived Analysis 或 Claim。
- 定义发布不等于历史重分类、统计和页面投影已经就绪。产品必须显示使用的定义与分类版本；新定义发布但分析未完成时显示未就绪或明确继续使用旧结果，禁止混合口径。
- Candidate Topic 是 Knowledge Change Proposal，不是半正式 Topic。语义性变更由人决定，并展示影响的分类、统计、页面、重算与撤回范围；拆分/合并不自动继承旧 Claim、分类和统计。
- Claim 是有主张、范围、时间和当前依据的重要可争论判断，不是所有统计的万能容器。支持、反例、评估、取代与撤回保留历史，冲突 Claim 可以并存；人工确认只授予当前使用资格。

本决定只冻结产品语义与权限后果，不确认 PostgreSQL 表、状态枚举、知识图谱、分类算法、重算调度或页面布局；这些分别进入 Gate 5–7。

### Gate 3-C 应用资产与发布边界（已确认）

- Corpus 是同一来源材料上的用途化选择，不是第二份评论库。精确片段、脱敏/翻译/摘要等转换、语义标注、历史选择和当前使用资格分别留痕；材料曾被选择不代表永久可读、可展示或可外传。
- 检索运行、为某目的固定的材料包和材料实际进入 Agent/报告/成稿的使用记录是三种事实。零命中、未采用、Coverage 不足和权限过滤必须分开，不能从一次检索为空推断现实不存在。
- Signal 保存值得注意的有边界分析发现；是否进入每日入口、继续观察或停止关注属于注意力处理。人工查看或跨运行重复出现不会把它升级成正式趋势、需求或机会。
- Market Insight 与 Intelligence Brief 是组织 Claim、分析、反例、限制与行动选择的版本化发布物，不是第二套 Claim。历史版本固定当时依据；后续判断修订、来源失效和隐私处置通过影响说明或后继版本处理，不静默改写。
- Content Idea 是内容工作资产，不是 Domain Topic 或强制流水线阶段。它可以如实来自人工经验；机器建议、保存版本、采用 Decision、成稿、Publication/Action、材料实际使用和 Outcome 分开。
- Agent 临时回答不自动形成 Intelligence。保存、共享或用作 Decision 时才冻结委托、输入、输出和引用版本；输入有 Evidence 血缘不能证明生成内容新增的事实、诊断、承诺或因果正确。

本确认不要求为每个产品名词建立独立表、服务、状态机或 Agent。哪些责任需要稳定身份、如何持久化、怎样检索和发布，分别由 Gate 5–7 根据真实关系、隐私传播和用户任务证明。

### DEC-01 真实材料隐私与传播边界（已确认）

- 公开可见只说明来源当时可访问，不授予无限期留存、逐字展示、批量导出、训练模型或外部传播资格。
- 受限原始 Evidence 可以按明确用途在内部受控区长期保存，但不承诺永久；普通工作台默认展示脱敏片段，脱敏必须考虑直接身份和原话/组合线索反向识别。
- 外部 Agent 默认只读取聚合结果、脱敏片段和受控 Evidence 引用，不得批量读取原文。第三方模型处理合同未确认前，不发送原文；真实材料实验仍需限定最小样本、目的、访问、输出和结束处置。
- 获准删除、撤回、脱敏或访问限制后，Corpus 选择、全文索引、embedding/feature、摘要、引用、缓存和 Agent 输出必须失效、重建或停止返回。已有 Claim/Intelligence 显示来源资格变化并重新评估，而不是静默消失。
- 平台来源消失与隐私撤回请求分开记录；仅保留不含原始敏感内容的最小处置审计痕迹。具体保存期限、脱敏算法、加密、角色、审计和法律适用性留给 Gate 5–7 与专业审查。

本决定不开放原文 CLI、不授权扩大真实材料采集，也不据此创建固定隐私表、权限等级或审批引擎。

### DEC-04 第一阶段 Outcome 最低边界（已确认）

第一阶段不在收藏、深度评论、私信/咨询、销售、访谈或产品使用中提前选择一个“主 Outcome”，因为系统当前没有资格稳定取得其中多数数据。产品最低承诺是：Decision 与 Action 可追溯；用户能知道每种结果渠道当前是否接通、是否已观察和来源是否合格；系统只保存实际取得且来源明确的 Outcome Observation；Evaluation 另行解释其有限意义。

结果按来源资格分为三类：

1. **系统观察：** 由真实 producer、行动对象身份和运行时合同共同支持。公开点赞、收藏、评论数、分享和浏览等指标也必须先证明与我们的 Action/真实平台对象稳定关联，保留观察时间、缺失和 Coverage；旧 schema 字段或任务完成不是证明。
2. **人工或外部陈述：** 由明确提供者在明确时间提交，并说明依据与精度，例如手工记录“收到若干咨询”。它首先证明有人作出这项陈述；没有额外来源时，不能冒充平台、CRM、销售或用户行为事实。
3. **当前不可观察：** 渠道未接入、尚未观察、观察窗口未结束、来源不合格或无法关联 Action。必须显示未知，不得写成 0、没有结果或行动失败。

现阶段没有已证明的深度评论、私信、咨询、报名、销售、访谈或产品行为自动链。旧 schema 中存在 `OperationPublication`、公开指标或 `leadCount` 等字段，只能作为来源与依赖审计；V2 指标 Raw Record/同源合同仍未完成，不能把历史字段移植成新项目能力声明。

长期仍保留“判断 → 决策 → 行动 → 结果 → 评价 → 校准”目标，但第一阶段不承诺完整自动反馈闭环。本决定不冻结成功指标、结果渠道枚举、人工补录页面、归因算法、同步频率、指标 producer、数据库表或反馈 Agent；这些必须由 Gate 3–7 的真实来源审计和设计决定。

### DEC-05 第一阶段趋势承诺边界（已确认）

第一阶段不承诺“市场正在增长/下降”的正式趋势判断。产品先提供两类诚实能力：

1. **近期观察：** 描述明确时间范围和实际捕获面中看到了什么，同时展示入口/对象范围、Coverage、分析版本和已知缺失；它不主张前后可比，也不外推平台或 ADHD 家庭总体。
2. **候选变化：** 当前后出现差异但可比性尚未完全成立，系统保留账号、工位、入口、Coverage、内容生命周期、平台排序、Topic/模型版本和分析输入变化等替代解释，并可建议继续观察、主动研究或让用户决定；它不能以“趋势”发布。

正式趋势是一类更强 Claim，必须等待 Gate 4 通过真实 producer、跨时间/账号/入口可比性实验，并由 Gate 5 明确单位、分母、时间资格、Coverage、来源集中、定义/分类/分析版本与反例规则。资格只对被实验和设计证明的具体范围生效；即使成立，也不自动证明总体需求增长、市场机会或因果关系。

本决定保留 Linggan 长期发现趋势的目标，但不冻结 7/30/90 天窗口、基线词表、阈值、评分、算法、数据库对象、趋势页面或 Agent，也不授权当前实现趋势计算。

## 五类长期积累视角（已确认的产品价值分类）

| 资产类别 | 主要保存内容 | 长期价值 |
|---|---|---|
| 世界事实积累 | 采集记录、Evidence、来源对象、Observation、Coverage 和历史状态 | 说明系统在什么条件下实际收到、接纳和观察到了什么；不把来源材料等同于现实真相 |
| 语料与表达积累 | 对正文、评论、回复、转录、用户原话和创作者表达的用途明确选择与组织 | 保存值得人和 Agent 反复研究与引用的语言材料，同时保留来源、选择、转换和访问边界 |
| 领域知识积累 | Topic、Term、Alias、定义、分类和关系版本 | 形成并持续修正对 ADHD 领域的共同语言；Topic Map 只是导航视图 |
| 市场与情报认知积累 | 候选变化、判断、反例、市场洞察和 Intelligence 组织 | 保存当时基于什么范围、方法和证据形成了什么判断，以及什么仍不能证明 |
| 行动与学习积累 | 提案、决定、人工修改、行动、发布、结果观察、评价和复盘 | 分开记录决定、行动、结果与解释，用于校准以后判断而不伪造因果 |

这五类是产品长期价值的盘点视角，不等于五张数据库表、五个万能对象、五个应用模块或五个技术模块。语料库、主题地图、市场洞察页面、Radar、情报简报、选题库和 CLI 也不因此成为新的事实来源。它们之间的关系不要求所有材料经过同一条单向流水线，而要求重要结论可以向下追溯、真实结果可以向上校准：

- 世界事实积累必须追溯到采集、被接纳的来源材料、观察时间和实际 Coverage；Evidence 只能证明系统接纳了什么材料。
- 语料与表达积累必须保留来源、选择用途、转换过程、版本、质量和必要的脱敏/访问边界；不复制第二份来源真相。
- 领域知识积累必须区分定义、数据观察、模型分类和产品导航，并保留变更版本。
- 市场洞察与情报必须声明时间窗口、观察面、单位、方法、支持、反例、不确定性、允许解释范围和版本。
- 行动与学习必须保留当时的输入、人工修改、决定、实际行动、结果观察和后续评价；未执行、失败和结果缺失也需要进入学习记录。

Outcome 只能校准未来判断，不能覆盖过去的 Evidence、Observation 或当时判断，也不能仅凭“行动后出现结果”就伪造因果关系。

## 完整产品能力地图（Gate 1 范围已确认，Gate 2 待细化）

| 能力域 | 面向用户的结果 | 与其他能力的边界 |
|---|---|---|
| 观察与证据基础 | 知道观察了什么、何时观察、覆盖多少、哪里失败，并能打开原始证据 | 保存事实，不把“未采集到”解释为“不存在” |
| 语料库 | 得到可检索、可筛选、可引用、可复用的内容、评论、转录等研究材料 | 语料可整理和标注，但不能覆盖或伪装原始 Evidence |
| 主题词表 | 维护概念、术语、别名、分类和版本，使人、系统与 Agent 使用同一语言 | 词表负责定义，不负责宣称现实关系永远成立 |
| 主题地图 | 展示主题、需求、人群、内容、观点和关系如何连接及随时间变化 | 地图是带时间和证据来源的认知视图，不是静态真理，也不预设图数据库 |
| 市场洞察 | 回答供给、需求、竞争、叙事和机会正在怎样变化 | 洞察必须声明证据范围、反例、缺口、方法和有效时间 |
| 情报核心 | 识别变化与信号，形成可引用、有不确定性和行动价值的判断 | 判断不能脱离证据，也不能替用户静默作最终业务决定 |
| 选题库与行动 | 把证据和洞察转成可管理的选题、角度、假设、优先级、状态与结果 | 不是标题仓库；选题需能追溯依据并由结果反向校准 |
| 对外访问 | 人通过工作台使用，外部 Agent 通过稳定 CLI 查询数据和发起获准任务 | CLI 不直连数据库，不另造一套业务逻辑或事实口径 |

产品已确认以一级 Domain 作为长期认知主线，当前 Domain 是 ADHD。用户进入 ADHD 后，在同一份证据与主题知识基础上使用语料库、主题词表、主题地图、市场洞察、情报和选题库，而不是进入若干彼此割裂的工具。

`ADHD 数学`、`家庭干预`、`作业拖延`、`执行功能`等属于 ADHD 内部不断演进的 Topic；专题研究和采集计划也发生在 ADHD 内，不会创建新的平级 Domain。“领域工作空间”可以描述这种统一体验，但当前不把 Workspace 确认为超级业务对象或数据库归属规则。共同语言见 [`../context/domain-language.md`](../context/domain-language.md)。

```text
来源与 producer
  → 采集记录 / Evidence / Observation
      ├─ 用途明确的选择与组织 → Corpus / 用户语料应用
      ├─ 定义与版本治理 → 主题词表 / Topic 知识
      ├─ 有范围的判断与组合 → 市场洞察 / 情报
      └─ 提案与决定 → 选题 / 行动 → 结果观察与评价

主题地图、工作台页面与外部 Agent CLI 通过同一套受版本控制的产品合同组织和访问这些能力，不另造事实。
```

## 领域不变量验收基线（已确认）

后续领域、producer、数据、架构、页面和 CLI 设计必须持续通过 [`domain-invariants.md`](domain-invariants.md) 中持续扩展的对抗性案例。该测试集重点攻击：身份不确定原声、Candidate Topic、Topic 拆分、扩采制造假趋势、强反例、Agent 越权、Outcome 伪因果、不同身份失败被吞并、隐私处置、新模型重分类、任务未完成却计数为零、同一 Evidence 被跨用途误用、相对时间伪装成精确事实、对象去重造成发现历史丢失、发现自动放大成详情访问、观察目的复制事实、关系偷换和结果直改知识。

测试基线冻结的是“系统不能怎样说谎和越权”，不是字段、状态枚举、算法、阈值或物理表。后续即使实现测试全部通过，只要页面或 Agent 仍能从“任务没跑”输出“现实没有”，产品就不算验收成功。

## 对外 Agent 与 CLI 原则（DEC-01、DEC-03 已确认）

CLI 是正式产品入口，不是只给开发人员排错的脚本。它至少应支持：

- 发现当前可用能力、数据结构和版本。
- 查询语料、主题词表、主题地图、市场洞察、情报、选题及其证据引用。
- 在明确委托范围内运行不改变正式知识、观察方法、真实采集或现实行动的分析，并返回输入范围、方法版本、限制和结果。
- 提交带来源的候选建议，或申请有边界的观察、采集、知识修订与行动；申请进入待决定状态，不直接执行。
- 查询申请、授权、执行和结果的不同状态，不能把“已提交”“已批准”或“任务结束”当成 Evidence、正式知识或业务成功。
- 以稳定、可验证的结构化结果供 Agent 使用，明确分页、错误、权限、幂等和版本语义。

第一阶段的外部 Agent 不是一种统一身份或超级用户。每次调用必须处在可追溯的委托范围内，至少能够回答：代表谁、为了什么目的、在哪个 Domain、允许读取什么、允许提交什么、期限和资源边界是什么、结果可以传播到哪里。同一个 Agent 在不同调用者或目的下不自动继承权限。

委托范围内允许自动发生的是读取聚合结果、脱敏片段和受控 Evidence 引用，以及可撤回、可重算、不改变正式世界的分析。外部 Agent 可以提交候选 Topic/Claim、研究建议、采集补证申请或行动提案，但这些只是有来源的候选或请求，不自动改变正式领域语言、长期观察基线、资源分配或现实行动。

下列后果第一阶段必须由人明确授权：改变正式 Topic/Claim 或当前解释；改变长期观察方法；产生新的真实平台访问或扩大采集范围；传播受限材料；触发发布、产品、销售或其他现实行动。即使获准，后续也必须进入原有责任链：真实采集经过 Evidence 复用、采集准入、工位/账号调度、producer 与 Evidence 接入；正式知识经过定义/判断治理；现实行动经过 Decision、Action、Outcome Observation 与 Evaluation。授权只说明“允许尝试”，不证明已经执行成功。

第一阶段外部 Agent 默认只能取得聚合结果、脱敏片段和受控 Evidence 引用，不得批量读取原始评论或其他受限原文；不得直连 PostgreSQL、直接创建插件工作单元、绕过采集准入，或先扩大观察再用新增数据证明自己的建议正确。

CLI 应是 Rust 产品合同的轻量入口，与工作台使用同一套业务规则。DEC-03 不冻结固定角色表、权限等级、授权字段、预算公式、命令名称、审批页面、认证方案或 MCP 协议；这些必须在 Gate 3–7 根据真实调用方、资源合同和对抗测试设计。本阶段不得因为确认产品权力边界就开始实现 CLI、权限系统或审批引擎。

## 用户价值

用户最终需要回答：

- 今天有哪些事项值得我关注，为什么现在出现？
- 哪些只是候选、证据缺口或观察异常，哪些有资格表达为变化？
- 证据是什么，有哪些反例和缺口？
- 这可能意味着什么？
- 下一步应观察、验证或行动什么？
- 之前的判断最终是否有效？

## 产品成功与失败标准（Gate 1 已确认）

Linggan Intelligence 的成功，是随着持续使用，不断提高团队说明观察边界、积累可复用资产、保持历史可比、发现未知结构、形成可追溯且可推翻的判断，并从真实行动结果中学习的能力。

成功分为四层，不要求每次使用都机械走完整个循环：

| 成功层级 | 可证伪标准 |
|---|---|
| 观察成功 | 能说明计划观察什么、实际看到什么、没有看到什么、哪里受限或失败，以及不同时间段能在哪些维度比较 |
| 资产成功 | 本次工作留下可检索、可引用、可追溯、可继续演进的资产；即使没有发现显著变化，也能形成可信基线 |
| 认知成功 | 重要判断能够追溯到证据、时间窗口、方法、反例、缺口和版本，并允许被后续证据推翻或修正 |
| 决策与学习成功 | 涉及行动时，保留当时判断、人工决定、行动环境和真实 Outcome，使结果校准以后判断而不改写历史 |

语料检索可以停在资产层，主题知识维护可以停在知识层，市场研究可以停在认知层；只有进入真实行动的工作流，才要求继续记录 Outcome。任何任务完成提示、数据量增长、聚类结果、漂亮报告、评分或 AI 输出，都不能单独证明产品成功。

以下情况必须明确判定为失败：

- 不知道采集遗漏和观察边界，却宣称看到了全貌。
- 把关键词、博主范围、平台返回、采集能力或模型变化误判成现实变化。
- 保存了大量材料，但以后无法检索、引用、追溯或重建。
- 把 Cluster、AI 命名或 Candidate Topic 静默升级为正式领域知识。
- 换用规则、模型或算法后，无法解释旧结论是怎样形成的。
- 判断没有可打开的证据、反例、缺口、不确定性或适用时间。
- 行动产生结果后，没有连接回当时判断，或把先后发生伪装成因果证明。

证据不足却表现得高度确定，属于核心质量事故，而不是普通分析误差。
