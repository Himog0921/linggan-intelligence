## 1. 用户和场景

**谁用**：机构的运营写手，约 10 人，每人每天约 10 篇小红书图文；Mog 先用它打样。前台只有一个界面，不区分 Mog 和写手，也不做单独的“打样台”（3.1）。

**读者与目的**：读者是 A娃（ADHD 孩子）的家长。笔记要被目标家长读到，最终带来「3V1 ADHD 干预陪跑营」的咨询。

**最费力的一步**：在素人口吻的笔记里，用一句话自然地带出机构的产品。

**这一步怎么做才不越线**（3.3，不重开）：

- 只有账号简介写明了和机构的关系（陪跑营学员家长、陪跑老师），正文才可以有一句如实的衔接。
- 身份没确认，或者简介没写明，就不放衔接句；和机构无关系的号不提产品；每篇都可以选“这篇不植入”。
- 衔接句按身份分组，从库里选，不由 AI 现编；讲效果的说法给提醒；有疗效承诺必须改。
- 不做“让读者察觉不到是推销”的设计。原因：广告必须能被识别；平台有规则；ADHD 孩子的家长容易受影响。

**时间预算（待测假设）**：试用期先按每篇 30 分钟估，其中取材、正文、衔接、封面、检查各占多少没有实测，不写进规格。耗时基线见试用方案。

## 2. 四条使用路径

| 路径 | 步骤 | 入口 | 第一版 |
|---|---|---|---|
| 每天的快路径 | 今日成品包 → 改稿 → 复制发出 → 回收 | 写稿区队列 | 前半段（改稿、复制、回收）进第一版；“今日成品包”依赖选题池，见 §4 |
| 自己找选题 | 材料桌找材料 → 拖进选题框、写思路 → 开稿（可一题多号）→ 改稿 → 发出 | 材料桌 | 进第一版 |
| 看到好笔记 | 插件采集 / 证据库 → 复刻成样板 → 样板库审核 → 以后起稿按它写 | 证据库检查器、资产库·样板库 | 进第一版；“粘贴链接”入口不进（见 §4） |
| 回收反哺 | 发布 → 7 天阅读 → 爆款 → 存为样板、进复用候选 → 下一轮选题 | 写稿区·已发布稿 | “存为样板”进第一版；“进复用候选”依赖选题池 |

## 3. 对象和状态

对象与字段细节见附录 B。这里只列用户看得到的状态。

| 对象 | 状态 | 说明 |
|---|---|---|
| 稿件 | 草稿中 → 已复制 → 已发布 | “已复制”只表示写手把文字带走了；“已发布”必须在运营发布记录里登记（有链接），不能只点一下按钮（INV-41） |
| 稿件的检查 | 必改 / 提醒 / 提示 | 不存为稿件状态，随正文实时计算；有必改不能复制 |
| 账号身份 | 未确认 → 已确认；简介：未写明 → 已写明 | 已确认且简介已写明，才出现衔接句 |
| 衔接句 | 待审 → 可用 → 停用（另有“待改”） | 新增和改写存回库的句子先待审 |
| 样板 | 待审 → 可用 → 停用；每个样板有编码和版本 | 稿件记住用的是哪一版 |
| 经历 | 待本人确认 → 已确认 | 本人确认后才能进稿件 |
| 人设事实 | 已确认 / 推断待确认 / 缺 / 新补充 | 新旧冲突时让人选“保留原来的”或“以新的为准” |
| 产品事实卡 | 待机构确认 → 已确认 | 检查规则读取“当前已确认”的版本 |
| 选题框 | 选题中（还没开稿）→ 已开稿 | 每篇稿件挂在一个选题框上，可互相跳转 |

## 4. 第一版范围与明确不做

**第一版做**（切片见[实施计划](../plans/active/creation-assets-001.md)）：

- 前提（S0）：创作接入成员登录，入口对所有成员开放（审计 C2、C3）。
- 资产与检查（S1a、S1b）：账号身份、产品事实卡、衔接句库（含审核）、三级检查、复制到小红书（S1a）；人设事实、经历库（S1b，需要 S0 与合规意见）。手写稿就能用。
- 选题框与开稿（S2）：材料用途与思路、“AI 会看到的内容”、开稿与一题多号、按段落换个说法并采用。
- 样板库（S3）：编码、版本、状态、检索、防撞车、存为样板、从证据库复刻。
- 标题与回收（S4）：封面大字换一批、右栏标题页、发布后回收。

**第一版明确不做**：

- 不做“让读者察觉不到是推销”的任何设计；不让 AI 现编衔接句；不让 AI 替人编亲身经历。
- 不放行疗效承诺；不自动采用 AI 建议；不自动发布。
- 不做多人实时协作、团队认领排班。
- 不做抖音；不做评论区种草；不做单篇咨询归因。
- 不做语义检索或向量召回（材料查找沿用现有字词检索，如实标明有界）。
- 不在这一版里选定编辑器库或画布库（小样结果见[小样报告](../audits/creation-assets-prototype-2026-10-27.md)）。
- 不做“粘贴链接 → 采单篇”的样板导入入口（现在没有这个能力，见审计 C13）。
- 不做跨领域高赞标题采集，除非 Mog 另行授权采集（审计 C11）；没有数据时标题页只有“我方爆款”和“标题 skill 入口”。
- 不做每晚自动备料（成品包）；它依赖选题池（审计 C9），单独排期。
- 不做 AI 作图；封面是否 AI 作图只作为一条提示（R-I1）。
- Demo 里的“使用路径弹窗”“体验清单”不是产品功能。

## 5. 验收场景

以 Demo 的 8 步体验清单为底稿，改写成真实任务。**自动化测试一律用合成数据**；真人与真实账号只在试用和可用性测试里出现。每个场景的“切片”是它首次可测的切片。

| # | 切片 | 真实任务 | 通过标准 |
|---|---|---|---|
| V1 | S1 | 写手拿到一篇要发的稿，所属账号身份未确认。去确认身份，在账号简介里写明关系，回来勾选“简介已写明” | 确认前稿件有必改“账号身份还没确认”，且不能复制；确认并勾选后，自动从该身份分组里挑第一句“可用”的衔接句放进稿件；改选“这篇不植入”后该必改消失、正文不含产品叫法 |
| V2 | S1 | 一篇稿件有疗效承诺、没选衔接句、经历位还空着。逐条处理到必改清零，再复制 | 每条必改都能点到出问题的位置；处理后“复制到小红书”可点；复制出的文字符合附录 A.4 的格式；真机粘贴结果由小样第 3 项另验 |
| V3 | S2 | 从一篇稿件跳到它的选题框，在画布上看到系统选了哪些材料，再从选题框里的“已开稿”回到稿件 | 两边都能一步到达；手写稿可“补一个选题框”，补出的框里放着这篇用到的经历 |
| V4 | S2 | 在材料桌点一张材料卡，写一句思路，展开“AI 会看到的内容” | 展示的内容与实际将发给模型的内容逐字一致（附录 A.5 的分节）；“只做参考”“反例”的材料不进正文 |
| V5 | S2 | 同一个选题给两个账号各开一篇 | 一次生成两篇；两篇开头不同；一个账号的经历不出现在另一个账号的稿里，对应位置留经历位；背后没有真人的号没有第一人称经历 |
| V6 | S4 | 在封面大字下“换一批”，用一个候选；在右栏标题页看“我方爆款” | 换出的候选不超过 10 个字；含疗效承诺的标题不能用；“我方爆款”只显示真实数据，数据缺失显示“未填”而不是 0 |
| V7 | S3 | 从证据库的一篇作品点“复刻成样板”，在样板库审核后入库，再用它起一篇稿 | 样板只含结构和写法提示，不含任何原句；同一篇笔记第二次复刻提示“已在库里”；审核通过前不能被成品包或开稿选用 |
| V8 | S1 | 为一个背后有真人的账号采集一条新经历，本人确认 | 确认前不能插入稿件；确认后可插入，且记录“本人同意”；稿件里这段标明来自经历库 |

## 6. 规则摘要

规则全表（触发条件、级别、用户怎么改）见附录 A。要点：

- **三级**：必改（挡住复制）、提醒（不挡复制）、提示（只告知）。
- **稿件能否复制**：有必改就不能复制；只有提醒可以复制；都没有也可以复制。
- **关键词是起点，不是定稿**：疗效承诺、效果说法、群体结论的词表要用真实发布记录校准，不准的规则降级或改写（见试用与校准计划）。校准需要 Mog 授权读取我方笔记正文。

## 7. 试用门槛

按 3.8 的设计：3 名写手、两周、盲测对照。

| 门槛 | 口径 |
|---|---|
| 写一篇的中位耗时下降 20% | 与试用前一到两周的自记耗时基线比；没有基线不能比 |
| 衔接句可用率达到 80% | 盲评：只看衔接句，不告知来源；“可用”和“小改可用”算可用；出现虚构亲历、疗效承诺、错账号的一律不算；口径细节待 Mog 确认 |
| 至少 2/3 的写手愿意继续用 | 试用结束时每人自己表态，不以被要求使用代替 |

两周看不出爆款率有没有变化，不拿它当门槛，也不在试用结论里提“提高爆款率”。允许“不植入产品”，选择不植入的稿件不计入衔接句可用率的分母。

## 附录 A · 规则全表

“触发”写判定条件；“怎么改”写用户能点的修改动作。关键词是校准起点。`R-` 编号用于后续测试和校准记录。

### A.1 衔接句状态

| 编号 | 情况 | 处理 |
|---|---|---|
| S-1 | 账号与机构无关系 | 不提产品；衔接位显示“不植入”，无检查项 |
| S-2 | 本篇选了“这篇不植入” | 不放衔接句；可“恢复衔接” |
| S-3 | 身份未确认 | 见 R-M1 |
| S-4 | 身份已确认，简介没写明 | 见 R-M2 |
| S-5 | 简介已写明 | 自动从该身份分组里挑第一句状态为“可用”的衔接句；写手可“换一句”或在本篇里改写 |
| S-6 | 选中的句子与身份对不上 | 见 R-M3 |
| S-7 | 还没选衔接句 | 见 R-M4 |

本篇里改写过的衔接句不再跟库同步，可“存回衔接句库（待审）”或“用回库里的”。

### A.2 检查

**必改**（挡住复制）

| 编号 | 触发 | 怎么改 |
|---|---|---|
| R-M1 | 账号身份未确认且衔接位没选“不植入” | 去确认身份；或“这篇不植入” |
| R-M2 | 身份已确认、简介没写明且没选“不植入” | 复制建议简介去改，回来点“我已改好简介”；或“这篇不植入” |
| R-M3 | 选中的衔接句属于另一个身份分组 | “换成对应的一句” |
| R-M4 | 身份与简介都已确认但没选衔接句 | “自动选一句”；或“这篇不植入” |
| R-M5 | 正文或衔接句里有疗效承诺（起点词：治好、治愈、根治、痊愈、保证能好/改、彻底改掉、不用吃药、停药） | “删掉这几个字”，或手改 |
| R-M6 | 封面大字或笔记标题里有疗效承诺 | “换一个标题”（跳到封面区） |
| R-M7 | 某段写成了亲身经历，但经历库里没有对应的一段（AI 不替人编经历） | “从经历库换一段”；或“留给本人补” |
| R-M8 | 经历位还空着 | “从经历库选”；或“发问题给本人” |

**提醒**（不挡复制）

| 编号 | 触发 | 怎么改 |
|---|---|---|
| R-W1 | 讲效果的说法（起点词：把行为掰过来、掰过来、基本不拖了、改掉了、变好了、进步很大、效果明显、见效、改善了） | “改成只讲学到了什么/做了什么”（有对应改写时）；或手改 |
| R-W2 | 对所有 A娃下结论（起点：“A娃都……”“所有的A娃……”“ADHD孩子都……”） | “改成只说自己孩子”（背后有真人的号）；或“有的孩子” |
| R-W3 | 产品叫法不在产品事实卡的可用叫法里（用了禁用叫法） | “统一叫法” |
| R-W4 | 和人设事实矛盾（Demo 只做了年级：“现在/今年/已经 + 一至六年级”与账号年级事实不符） | 手改，或先去更新人设事实；其他事实类型待定 |
| R-W5 | 这段经历已在别的稿子里讲过 | “换一段经历”；或换角度和说法 |
| R-W6 | “A 娃”“a娃”“adhd”写法不统一（话题标签不改） | “一键统一”为“A娃”“ADHD” |
| R-W7 | 话题重复 | “删掉重复的”（复制时也自动去重） |
| R-W8 | 封面大字超过 10 个字 | “看看备选” |
| R-W9 | 笔记标题超过 20 个字（计数方式待小样第 3 项真机核对） | 手改 |

**提示**（只告知）

| 编号 | 触发 | 内容 |
|---|---|---|
| R-I1 | 封面是 AI 作图 | 发布时勾选平台的 AI 声明 |
| R-I2 | 正文提到了产品 | 简介已写明身份；发布前确认简介还在 |

### A.3 衔接句入库检查

新增或改写存回的衔接句，入库前先过下面几条，结果显示在句子旁。**有疗效承诺（R-L1）的不能加入；其余只提示或提醒，不阻止入库。** 入库后的状态一律是“待审”，审核通过才会出现在写稿里。

| 编号 | 级别 | 触发 |
|---|---|---|
| R-L1 | 必改（挡住加入） | 疗效承诺（同 R-M5 词表） |
| R-L2 | 提醒 | 讲效果的说法（同 R-W1） |
| R-L3 | 提醒 | 对所有 A娃下结论（同 R-W2） |
| R-L4 | 提醒 | 叫法不在产品事实卡里（同 R-W3） |
| R-L5 | 提示 | 没提到产品名（可以，但读者可能不知道在说什么） |
| R-L6 | 提醒 | 像官方或招揽口吻（起点词：我们机构、我们的课、报名、咨询、私信我、扫码） |
| R-L7 | 提醒 | 字数过长（Demo 起点 70 字，数字待定） |

R-L1–R-L7 来自 Demo 的衔接句库页，任务书附录 A 没有列；是否保留请 Mog 在审核规则里确认。

### A.4 复制到小红书的格式

- 正文各段之间隔一行，这一行只有一个“ㅤ”（U+3164）。
- 正文结束后另起一行放话题；重复的话题自动去掉。
- 标题单独复制，不并入正文。
- 衔接位在“不植入”、身份未确认或简介未写明时不输出任何内容；经历位不输出。
- 这个格式取自 Mog 的真实稿子；小红书 App 里是否保留“ㅤ”、话题能否识别、标题字数怎么算，由小样第 3 项真机验证后定稿。

### A.5 开稿与“AI 会看到的内容”

开稿规则：

| 编号 | 规则 |
|---|---|
| R-D1 | 材料按用途进稿；材料的思路里写了样板某一步的名字，这段放到那一步 |
| R-D2 | 用途为“只做参考”“反例”的材料只给 AI 看，不进正文 |
| R-D3 | 别的账号的经历不挪用，留一个经历位等本人来补 |
| R-D4 | 背后没有真人的号不写第一人称经历，改写成知识型段落 |
| R-D5 | 同一选题给几个号写时，各号的开头不一样 |
| R-D6 | 起稿引用评论时不使用“家长”“老师”等身份称呼，除非评论者身份已知（INV-02）。Demo 的开头模板写了“有位家长说”，实现时改掉 |

“AI 会看到的内容”按原样展示，分节：选题；这篇想说什么；账号（身份、简介状态、人设事实）；样板步骤；材料（用途和思路）；只做参考的材料；别这样写（反例、产品事实卡里不能说的话、不编经历）；衔接规则；风格。**这个展示就是将要外发的内容**；外发范围与供应商由 Mog 另行授权（见开工评审材料）。

## 附录 B · 领域对象与数据草案

本节只是草案，不是迁移或合同。**不创建 data-contracts 文档，等 Mog 确认后再建。**

### B.1 通用约定

- **编码**：`<类型前缀>-<流水号>`，由服务端分配，不复用已删除的编号；有版本的资产加 `v<序号>`。Demo 的 YB/JL/XJ/FG/XT 是拼音首字母，写手不一定认得；第一版沿用（3.4 要求按编码检索），是否改成中文前缀待 Mog 看一次实际界面再定。
- **版本**：被稿件引用的资产（样板、衔接句、产品事实卡、风格、账号身份）都追加式修订，稿件记住用的修订；改动不回写旧稿。
- **角色**：沿用运营成员的三种角色 admin / lead / operator（OPS-AUTH-001）。下文“谁审核”的建议默认值待 Mog 在开工评审时确认。
- **敏感等级**：高 = 涉及未成年人、健康、真人与账号对应关系；中 = 对外话术与合规相关；低 = 只含结构或内部业务信息。
- **保留期限**：全部 `待定`，由合规审阅与 Mog 决定；在此之前默认“随账号或稿件存续，本人撤回时删除并沿引用传播（INV-10、INV-45）”。

### B.2 对象

**账号身份**（新表，按账号追加式修订）

- 身份：`accountRef`（指向运营账号）；不单独编码。
- 字段：背后真人的角色（如“妈妈”“老师”，不写真名）、与机构关系（陪跑营学员家长 / 陪跑老师 / 无关系 / 未确认）、简介是否写明（含核对时间和核对人）、能否每周提供经历。
- 状态：未确认 → 已确认；简介：未写明 → 已写明。
- 审核：账号负责运营提出，lead 或 admin 确认（建议）。
- 现有表关系：只引用运营账号表，不改它（审计 C7）。
- 敏感：高。可见：admin、lead、该账号负责运营。
- 永不入库：真人真名、孩子姓名、学校、联系方式。

**人设事实**

- 身份：`accountRef` + 事实键（如“年级”）；每条一行，追加式。
- 字段：文字、来源（稿子、口述等）、状态（已确认 / 推断待确认 / 缺 / 新补充）、用过次数（统计得出）。
- 审核：背后真人确认；系统或 AI 提取的一律先“推断待确认”。
- 现有表关系：新建。
- 敏感：高（未成年人与健康信息）。**会进入“AI 会看到的内容”，属外发材料，需外发授权**。
- 永不入库：孩子真实姓名、学校班级、就诊与诊断细节、照片。
- 冲突：新旧事实不一致时由人选择，两条都保留历史。

**经历**（编码 JL-）

- 字段：账号、标题、本人口述整理的正文、标签、来源（口述 / 稿子 / 去标识的陪跑记录）、状态（待本人确认 / 已确认 / 停用）、**本人同意记录**（谁、何时、同意用于什么）、讲过几次（统计得出，来自稿件引用）。
- 审核：提供经历的真人本人确认；运营可以协助采集，不能代为确认。
- 现有表关系：新建；稿件段落通过引用（经历编码 + 修订）使用，不复制到别处。
- 敏感：高。可见：该账号负责运营、lead、admin。
- 永不入库：学校、就诊细节、第三方真名、未成年人真名；“陪跑记录”必须先去标识。
- 一个账号的经历不能用于别的账号的稿件（R-D3）。

**产品事实卡**（编码 CP-，版本化）

- 字段：规范名称、可用叫法、禁用叫法、是什么、适合谁、能讲的、不能讲的、必带提示、状态（待机构确认 / 已确认）。
- 审核：机构确认（由谁确认待 Mog 定）。
- 现有表关系：新建。检查规则读取“当前已确认”的修订；稿件记录检查时用的修订。
- 敏感：中。

**衔接句**（编码 XJ-，版本化）

- 字段：身份分组（陪跑营学员家长 / 陪跑老师）、文字、状态（待审 / 可用 / 停用 / 待改）、来源（人工新增 / 稿件里改写后存回）、用过次数（统计得出）、入库检查结果（见 A.3）。
- 审核：lead 或 admin（建议）；新增和存回的一律待审。
- 现有表关系：新建。稿件记录用的句子与修订，或本篇改写的文本。
- 敏感：中（对外话术，合规相关）。

**样板**（编码 YB-，版本化）

- 字段：名称、状态（待审 / 可用 / 停用）、来源类型（打样稿 / 插件采集 / 证据库 / 博主蒸馏）、来源指向（证据库作品编号与复刻时间）、写法步骤（每步：名称、写法提示、是否需要真实经历）、标签、需要几段经历、防撞车上限（同一周最多 N 个账号，N 待定）、版本历史、停用原因。统计（用过几次、平均阅读、爆款数）由稿件和回收数据算出，**未回收显示“未回收”，不记 0**（INV-08）。
- 审核：lead 或 admin（建议）；复刻出的样板一律待审。
- 现有表关系：新建；来源通过研究底稿读取（DEC-0011：研究底稿是 AI 读取笔记的唯一入口）。
- 敏感：低，但**只存结构和写法提示，不存别人的原文**，包括开头几个字。同一篇笔记不重复入库。
- 自家稿件存为样板时是否保留短例句：待定，默认不保留。
- 来源作品被撤回或受限时，样板里不应残留可还原的原文（INV-45）。

**风格**（编码 FG-）

- 字段：名称、来源（博主蒸馏 / 账号自己的稿子）、结构、节奏、用词、不学（带效果承诺的写法不收录）、用在哪些账号。
- 审核：lead 或 admin（建议）。
- 现有表关系：新建；博主蒸馏技能不在库里，第一版只接收它的产出。
- 敏感：低。只学结构、节奏、用词，不搬别人的经历和原句。

**选题框**（编码 XT-，内容工作资产）

- 字段：选题名、“这篇想说什么”、给哪些账号写（可多个）、用哪个样板（编码与版本）、材料卡、来源（人工 / 成品包 / 复用）、创建人。
- 状态：选题中（还没开稿）→ 已开稿；每篇稿件挂在一个选题框上。
- 现有表关系：新建；**不是**主题图谱的 Topic（安全约束：Content Idea 不是 Domain Topic），作品里已有的 `topicRef` 仍只指向 Topic。
- 可见范围：待定（谁能看谁的选题框与稿件）。
- 来源如实记录：人工来源不伪造系统证据上游（INV-51）。

**材料卡**

- 字段：种类（笔记 / 评论 / 历史爆款 / 跨行业标题 / 经历 / 便签）、指向的来源（沿用现有来源引用：来源、版本、范围、哈希）、**用途**（开头 / 共鸣 / 经历 / 观点 / 标题参考 / 只做参考 / 反例，七选一）、**思路**（一句话，写给 AI）、在桌面上的位置。
- 默认用途：便签→观点、经历→经历、评论→共鸣、历史爆款与跨行业标题→标题参考。
- 现有表关系：取代现有“画布卡”（审计 C4：以用途取代五种分组，加坐标）。
- 只存引用和用户选定的片段，受限时遮断（沿用 CONTENT-WORKBENCH-001）。

**稿件**（现有作品的扩展）

- 在现有作品文档上增加：选题框、样板（编码与版本）、衔接状态（自动/不植入、所选衔接句与修订或本篇改写文本）、段落的步骤标签与来源标记（经历库 / 材料 / AI 起稿）、稿件状态（草稿中 / 已复制 / 已发布）、种类（复用 / 试新）。
- “AI 起稿”标记只说明来源，不是事实背书（INV-50）。
- 检查结果不存；复制时留一条回执：稿件修订、规则集版本、产品事实卡修订、提醒与提示的编号，便于事后核对。

**稿件—发布关联**

- 字段：稿件修订 → 运营发布记录（`publicationRef`）、登记人、时间。
- 阅读量取自运营的阅读量报告，不复制；判定爆款沿用运营规则（小红书最新有效值 ≥ 5000）。
- “存为样板”“进复用候选”是命令，结果分别是一个待审样板和一个复用候选记录，不改写阅读量。

### B.3 生命周期与审核人汇总

| 资产 | 谁提出 | 谁审核（建议） | 状态流转 | 撤回/停用 |
|---|---|---|---|---|
| 账号身份 | 账号负责运营 | lead / admin | 未确认 → 已确认；简介未写明 → 已写明 | 更正追加新修订 |
| 人设事实 | 运营 / 系统提取 | 背后真人 | 推断待确认 → 已确认 | 真人撤回即删，并沿引用传播 |
| 经历 | 运营协助采集 | 提供经历的本人 | 待本人确认 → 已确认 → 停用 | 同上 |
| 产品事实卡 | admin | 机构 | 待机构确认 → 已确认 | 追加新修订 |
| 衔接句 | 运营 / 稿件存回 | lead / admin | 待审 → 可用 → 停用 | 停用后稿件里已用的保留当时文本 |
| 样板 | 运营复刻 / 稿件存回 | lead / admin | 待审 → 可用 → 停用 | 停用后不进新稿，旧稿保留引用 |
| 风格 | 运营 | lead / admin | 待审 → 可用 → 停用 | 同上 |
| 选题框 | 任何成员 | 无需审核 | 选题中 → 已开稿 | 删除前先解除稿件关系 |
