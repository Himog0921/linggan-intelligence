## 使用规则

这是小红书采集能力的唯一当前登记入口。后续平台变化、探针刷新或插件升级必须更新本页，而不是新增另一份“字段清单”。

- 只记录字段名称、字段来源类别、存在性、数量、状态、探针版本、观察时间与缺口原因；禁止写入笔记正文、评论原文、作者可识别资料、Cookie、令牌、完整 URL 参数、媒体字节或原始响应。
- `VERIFIED` 只表示在注明的页面状态和观察条件下真实看到；不表示平台所有账号、地区、时间或排序下都稳定可得。
- `NOT_AVAILABLE` 表示该页面状态下平台未公开展示或已明确不采；`NOT_IMPLEMENTED` 表示平台可见但当前 Linggan 插件没有交付路径；`SOURCE_INCOMPLETE` 表示本次条件不足；`UNKNOWN` 不得改写成空值、零或成功。
- “目标数量”与“实际获得数量”必须分开。对上限任务，不得从 `limit - actual` 推断未观察对象或平台总量。

## 状态枚举

| 状态 | 含义 |
|---|---|
| `VERIFIED` | 当前探针已在注明条件下实测并由代码路径交付或明确验证 |
| `PARTIAL` | 部分字段、页面状态或覆盖已实测，仍有已知缺口 |
| `NOT_IMPLEMENTED` | 平台页面可见，但 Linggan 当前没有受审查的交付路径 |
| `NOT_AVAILABLE` | 当前页面状态下平台未展示，或现行合同明确不采 |
| `SOURCE_INCOMPLETE` | 登录、验证码、限流、页面状态、隐私最小化或其他来源条件不足 |
| `UNKNOWN` | 尚未核实；不是空值、零、失败或成功 |

## Issue #80 已完成代码与自动验证：双使用者入口、页面加载滚动与详情回执

- **Intelligence 详情入口**：`采集当前笔记到 Linggan` 只读取并交付详情、媒体槽位观察与默认最多 30 条评论；自动测试已证明它不会打开人工媒体选择窗口，也不会触发下载。
- **人工媒体入口**：`人工采集并下载媒体` 保留原有选择窗口和本地下载服务；自动测试已证明选择后会继续进入该人工下载路径。它与 Linggan 的媒体槽位观察、详情接纳和后续理解是不同事实，不能互相替代。
- **详情接纳回执**：笔记详情、媒体观察、评论与回复三条 lane 逐条显示为“已接纳 / 待本机交付 / 未接纳 / 状态未知”；任一条未接纳时，不把整体写成已接纳。
- **页面加载过程**：搜索/主页发现以稳定内容标识、目标数、可见数量、页面高度、到底状态和有限轮次作为事实；新增 `scrollTrace` 只保留这些匿名化过程数据，并进入 package 页面检查点。每轮只执行一个按容器高度计算的有限加载动作。`no_progress` 表示连续无新增但未证明页面到底，不是平台自然结束。评论采集同样将“无新增且无结束标记”报告为 `no_progress`。
- **风险停止**：搜索、主页、评论 API、评论 DOM 与评论图片循环遇到安全验证或访问受限时均立即写 `risk_control` 并停止本次 Attempt；不绕过、不随机伪装行为、不在同一 Attempt 继续。
- **尚未证明**：本事项的真实页面复测尚未进行，尤其是新 Intelligence 入口“不弹窗”、人工入口“仍可下载”、不同筛选与非空评论/楼中楼的实际页面行为。此前最小真实详情样本仅证明一条当前笔记记录已进入 Linggan 的当前投影；它不证明三条 lane 各自接纳，也不替代本事项的重新安装/真实回归。

本表的当前结论：Issue #76 的字段/标准详情升级已经进入代码，Issue #78 继续把它收口为**目标驱动的主动采集执行**。重点仍不是分析功能，而是按指定目标主动加载、分别保全标准 30 条窗口与深采评论、逐目标恢复，以及把目标/实际/停止原因交付给 Linggan。

## 漂移处理

当平台页面字段、筛选项、排序、评论层级或加载方式变化时：

1. 先将受影响行改为 `SOURCE_INCOMPLETE` 或 `UNKNOWN`，不使用旧字段补齐；
2. 记录受影响的页面状态、发现时间和失败/变化类型；
3. 更新对应探针和 focused test；
4. 只有新的真实页面结果与自动检查都通过，才把该行恢复为 `VERIFIED` 或 `PARTIAL`；
5. 若变化需要改变采集合同、权限或真实数据处置，另开事项，不在本登记册内暗中扩展。
