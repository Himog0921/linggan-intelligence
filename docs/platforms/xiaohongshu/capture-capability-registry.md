## 使用规则

这是小红书采集能力的唯一当前登记入口。后续平台变化、探针刷新或插件升级必须更新本页，而不是新增另一份“字段清单”。

- 只记录字段名称、字段来源类别、存在性、数量、状态、探针版本、观察时间与缺口原因；禁止写入笔记正文、评论原文、作者可识别资料、Cookie、令牌、完整 URL 参数、媒体字节或原始响应。
- `VERIFIED` 只表示在注明的页面状态和观察条件下真实看到；不表示平台所有账号、地区、时间或排序下都稳定可得。
- `NOT_AVAILABLE` 表示该页面状态下平台未公开展示或已明确不采；`NOT_IMPLEMENTED` 表示平台可见但当前 Linggan 插件没有交付路径；`SOURCE_INCOMPLETE` 表示本次条件不足；`UNKNOWN` 不得改写成空值、零或成功。
- “目标数量”与“实际获得数量”必须分开。对上限任务，不得从 `limit - actual` 推断未观察对象或平台总量。

## 状态枚举

| 状态 | 含义 |
|---|---|
| `VERIFIED` | 当前探针已在注明条件下实测并由代码路径交付或明确验证 |
| `PARTIAL` | 部分字段、页面状态或覆盖已实测，仍有已知缺口 |
| `NOT_IMPLEMENTED` | 平台页面可见，但 Linggan 当前没有受审查的交付路径 |
| `NOT_AVAILABLE` | 当前页面状态下平台未展示，或现行合同明确不采 |
| `SOURCE_INCOMPLETE` | 登录、验证码、限流、页面状态、隐私最小化或其他来源条件不足 |
| `UNKNOWN` | 尚未核实；不是空值、零、失败或成功 |

## 当前插件能力裁定与升级门

| 采集能力 | 当前实测与代码事实 | 裁定 | 升级要求 |
|---|---|---|---|
| 搜索筛选与列表发现 | 当前搜索面仍命中 `.feeds-container`、`section a.cover`、`.footer span`、`.like-wrapper .count`；筛选项比“综合前 20 条”更丰富 | **基础能力可用，但合同不完整** | TaskSpec/回执必须显式携带实际筛选状态、请求上限、已加载数量和停止原因；不得把 20 当作永久列表边界 |
| 搜索下拉联想 | 当前页面确有下拉，但使用 `sug-container` / `sug-item`；现行插件没有已证明的联想词交付合同 | **需要新增能力** | 新增只读 Search Context lane：输入前缀、候选顺序、可见候选数量、页面状态和缺口；是否使用候选词由 Linggan 决定，插件不分析或推荐 |
| 笔记详情字段 | 当前详情页有 `.note-detail-mask`、`.note-container`、`.note-content` 与媒体槽位，但当前 `collectNote()` 只依赖 `noteDetailMap`，本次页面未提供该状态 | **必须升级后才能称为当前平台详情可采** | 为当前详情 DOM 增加受审查的字段读取回退与字段来源标记；保留原始时间表达和精度，不把相对时间推为平台精确时间 |
| 详情媒体 | 当前样本存在 3 个图片槽位；本次未见视频/Live Photo，不代表平台没有 | **部分具备，媒体类型覆盖未完成** | 详情 DOM 读取升级时同步验证图片、视频、Live Photo 的槽位、顺序和缺失状态；本事项不授权下载字节 |
| 详情附带最多 30 条评论 | 当前详情的空评论状态可由 `.comments-el / .no-comments` 看见；正向评论记录、排序、回复和“达到 30”尚无受限实测 | **硬性升级验收项，尚未通过** | 一次逻辑详情任务必须回执 `commentCap=30`、公开评论数（若可见）、目标数、实际数、排序/层级、空状态和停止原因；不足 30 不得称完整 |
| 作者资料与作品列表 | 当前 DOM 基础资料选择器与作品流选择器仍命中；本页 `userPageData` 缺失 | **基础资料可用，结构化统计部分缺口** | 保留 DOM 回退；粉丝/关注/获赞等只能在有合格来源时交付，否则明确未知，不用 0 或旧缓存补齐 |

本表是本次“是否升级”的当前结论：插件需要一次**以当前真实页面字段和回执为中心的采集能力升级**，重点不是增加分析功能，而是补齐搜索上下文、详情 DOM 回退和“详情 + 最多 30 条评论”的可验证交付合同。

## 漂移处理

当平台页面字段、筛选项、排序、评论层级或加载方式变化时：

1. 先将受影响行改为 `SOURCE_INCOMPLETE` 或 `UNKNOWN`，不使用旧字段补齐；
2. 记录受影响的页面状态、发现时间和失败/变化类型；
3. 更新对应探针和 focused test；
4. 只有新的真实页面结果与自动检查都通过，才把该行恢复为 `VERIFIED` 或 `PARTIAL`；
5. 若变化需要改变采集合同、权限或真实数据处置，另开事项，不在本登记册内暗中扩展。
