## 1. 已确认的用户结果

主要使用者为 Mog，个人高频使用；现有运营团队能力继续保留。首批完整产品交付的主产出为图文笔记，效果重点为我方发布后的阅读量。

核心路径：**每日选题 → 研究与取材 → 正文创作 → 封面与内页制作 → 成品预览与导出 → 发布后复盘**。

- 每日进入 Intelligence，至少获得 10 个可进入制作的完整选题方案：角度、依据、提纲和素材。相同角度仅换标题不重复计数；供给不足如实展示并定位缺口。
- 正文、封面与全部内页图片在 Intelligence 内完成；导出后即可发布，无需再到其他工具补排版。
- 创作过程沉浸、简洁、美观；有明确编辑中心，辅助信息按需展开，保存、恢复与版本可靠。
- 较低频完成下周选题规划，研究领域变化、新发现作者、高表现作品和用户讨论，并转为可用的内容思考。
- 上线前，采集、语料、主题图谱必须流畅、严密且路径清楚；每日 AI 分析、归并和自动化需持续产出有用结果。
- 核心方法、提示词和 Skill 可视化、可迭代，有输入输出、版本、比较和回退记录。
- 视觉、导航和工作流程允许重新梳理；在代表页面验证新方向后统一修订现有 LIDS，不另建并行设计标准。

### 10.6 正文、封面、内页与导出的具体制作规则

- **正文**：标题、提纲和连续正文是编辑中心；原文出处按需展开。引用原话与自己的表达保留不同身份；来源标记默认属于工作区，是否以引号/引文进入成稿由作者决定。支持中文输入法、粘贴、撤销/重做、选段改写；禁止以固定字符切片或粗暴整篇覆盖实现采用。
- **封面**：标题/副标题、模板、配色、主图、裁切和对齐可编辑；从正文标题带入有预览/撤销，不强制长期同步。预览展示完整画幅和实际字形，不能静默缩字到不可读或裁掉文案。
- **内页**：最小模板家族覆盖观点、原声、步骤，内容与版式分开。画布和正文可选择文字块及目标页，一次送入并带上内部出处；支持新建、排序、删除恢复。超长内容提示拆页建议并由作者确认。正文后续修改只提示相关页，不自动覆盖。
- **图片资产**：本机自有图片上传后登记作品资产、哈希、尺寸和用途，支持裁切/替换；阅读原图和作品图片分别登记用途。现有媒体可作为受控读取基础，作品资产存储与原始采集事实分责。AI 图片生成明确在后续扩展，不影响本包站内做完封面与内页。
- **渲染建议**：沿现有 Rust/Axum + 原生 JS/CSS 页面，使用一个正式模板渲染模块服务预览与导出，以目标像素尺寸绘制，预览仅缩放。首包可沿 Canvas 方案重写；固定字体资源、资源加载完成再渲染、逐页排版测量和版本记录。无需新增前端框架、通用设计器或新服务。
- **导出流程**：先等待服务端保存回执并冻结快照，再渲染该快照；生成页按页 ID/哈希登记到导出记录，服务端核对数量、尺寸与完整性后打包。中断任务可重试，已有正文和图页不回滚。成功包可再次下载；内容改动产生新版本，不覆盖已导出的旧文件。
- **交付文件建议**：默认发布包为 `正文.txt`（标题/正文/作者确认的标签）、`01-封面.png`、按顺序命名的内页 PNG。来源清单、原声及模型上下文留在内部作品记录；另行选择才能生成归档包，不混进默认发布文件。仅对用户实际点选的图页导出，不带未采用候选。

| A01 真实方案 | 一篇方案的角度/依据/提纲/素材齐全，能从运营进入并继续 | 真实对象 ID、范围及来源版本；原型合成条目不计数，零结果如实显示 |
| A02 原笔记与原声 | 多篇正文/图片可读，原声有父笔记和确知父评论语境 | 两篇笔记、两条原声及一条回复情景；截断/缺失/未知有区别；隐去身份的接口不被 UI 绕过 |
| A03 精确联动 | 同一个片段在筛选结果、分布索引、原文高亮中一致 | 原笔记文字、原声、OCR 原图各一个；中文/emoji/换行及跨句选文测试；空结果和分页不制造全量数量 |
| A04 画布到作品 | 选中片段一次进入正文与指定内页，来源完整 | 实际插入位置和引用 ID；重复提交不重复写；内页重排后目标不变；原始选文不被个人表达改写 |
| A05 保存与恢复 | 关闭重开仍保留正文、封面、内页、画布和关联 | 隔离 PostgreSQL 与浏览器实走；失败/断连/双标签冲突不丢未提交内容，恢复旧版产生新版本 |
| A06 AI 与作者控制 | 起草/选段改写有真实回执，建议可比较并选择采用 | 一次真实起草、一次真实改写；输入来源、方法和模型版本、用量与采用记录可查；失败/取消/新编辑防覆盖测试；没有真实调用则标为未验收 |
| A07 封面 | 做出与账号和正文一致、可读且可编辑的封面 | 标题带入、替换图片和裁切、换模板、撤销/重开；Mog 看实际 PNG 验收审美，不只看截图 |
| A08 内页 | 四张内页完成不同内容结构，能逐页编辑和调整顺序 | 至少一页原声、一页步骤、一页自有图片；文字和出处目标正确；超出区域有提示与解决入口 |
| A09 修改传递 | 正文改动后知道哪些图页受影响，可选择带入 | 一处关联段落更新，相关页提示；选择更新其中一页，另一页原有手工文字保持；关系不明确时提示复核 |
| A10 成品导出 | 下载文件与冻结版本的正文及图组一致 | 检查 ZIP CRC、文件数/命名/顺序、五张 PNG 尺寸、实际图像中文字与图片；无截断/缺字/占位图；默认包不附内部材料；导出后新编辑产生新版本提示 |
| A11 异常完整性 | 资源缺失、来源变化、受限、保存和导出失败可解释且能恢复 | 隔离负例 + 浏览器状态；受限来源按当前资格停止展示/新使用，已存在作品需标记并按合同处理，不能复制旧原文绕过限制；已完整成品与失败任务分别记录 |
| A12 密度与可用性 | V3 空间浏览和沉浸编辑在真实内容上成立 | 1440/1280 桌面、1280×720 短屏、390 窄屏；无页面横向溢出；画布局部横向浏览允许；键盘、中文输入和 reduced motion 可用；截图+Mog 实际创作验收 |
| A13 性能 | 筛选、定位、编辑与保存能支持高频写作 | 在 S0 记录真实材料规模与机器条件；建议首屏 ≤2s、筛选/定位 ≤500ms、输入后保存回执 ≤2s（均按热态 P95、固定场景至少 30 次记录）；冷态单独报告，全部为待确认预算而非已有成绩；不含模型耗时 |

技术验证采用现有模块定向测试、隔离 PostgreSQL、真实页面和实际下载，避免只测纯函数或制造镜像实现测试。导出与渲染必须包含中文长文、资源缺失和内容溢出的反例。现有运营、语料、主题图谱入口做适度回归；不能因新增创作页破坏原来的阅读和导航。

最终验收以一篇可发布成品为中心。演示脚本：选方案 → 研读至少两篇原笔记及原声 → 精确摘录至少四段 → 画布归组并写自己的表达 → 用于正文和指定内页 → 修改/采用正文建议 → 做封面与四内页 → 离开重开 → 改一段并选择更新相关页 → 整组预览 → 下载检查 → Mog 签收。
