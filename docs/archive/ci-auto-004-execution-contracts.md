## P0 · 接纳与恢复

### 输出接纳顺序

1. 保留受限原始返回，记录完整终止、用量和规范化方式；诊断内容仍按24小时与当前来源资格读取。
2. 文本为裸JSON，或去首尾空白后全文恰好一个完整 `json` fenced block，进入同一个严格解析入口。后端 parser 与 diagnostics 共用函数。
3. 不修复缺括号、不截取多个块之一、不补字段、不把前后解释当合法输出；拒绝重复JSON key、未知根字段、未知commentRef与重复身份等歧义。
4. 依输入ID逐条检查。缺少某个ID只产生该成员 `missing_comment`。身份之外的字段错误按独立性处理；坏problem不保留它已暂存的任何evidence/span。
5. 正确语义字段可保留，超长辅助说明记录具体拒绝路径而不截断猜意；若outcome本身冲突或uncertain缺少必要原因则不冒充可解释/no_signal。
6. 所有语义字段被拒绝不能写“无研究信号”；真正no_signal必须通过该分支合同。结果、字段诊断、成员状态和可追溯回执在同一事务接纳。

补跑范围按成员/字段的实际失败记录计算，不对已接纳成员重发。字段局部补齐如果需要再次模型调用，生成有明确字段目的的有限任务，不能覆盖旧结果或重复累计成功语义。

### Provider诊断

`PiResponse` 增加可选版本化安全诊断；旧适配器兼容字段缺失但标unknown。字段：`stage`枚举、`httpStatus`可空、`responseStarted`、`terminalReceived`、`receivedBytes`、白名单`finishReason`、`elapsedMs`、`usageKnown`、`sdkErrorType`白名单、`retryClass`。未知必须可空，不能因没有记录写false/0。

数据路径：固定SDK实际响应/网络边界 → Node响应 → Rust DTO → invocation.result + request trace → API检查器。日志不记录密钥、请求头、完整URL、上游原始errorMessage或非必要正文；trace正文另走既有脱敏与资格边界。HTTP失败、200后断流、未收到终止、输出上限、程序schema拒绝分别呈现。

### 重试、记账与部署

- 重试有冷却、累计尝试次数、调用前预算预留、调用后实际用量或未知预留；跨批/跨日不重置同一失败的尝试次数。
- `missing_comment` 有界补跑；格式/字段失败不能无限直到“通过”。已知可重试供应商错误采用分类策略；不可恢复的配置/身份/权限问题等待相应条件变化。
- 未知费用恢复由研究设置一次配置次数和Token风险上限；默认不额外自动重发未知调用。用户无需逐条审核；可一次选择允许有限恢复，原未知预留不抹零。
- 已接纳但记账前崩溃：重放持久接纳回执，不再次调用供应商。未取得终态且是否收费不明：保留未知与旧attempt，不伪造失败零用量。
- worker持有任务句柄与shutdown信号，先禁止reserve，再等待当前受限调用及落账；grace上限必须覆盖冻结timeout+收尾余量，耗尽则保存中断原因。启动恢复依据租约及终态，不凭进程退出推断没收费。
- `apps/worker`、`model_runner`、runtime install/sync/stop入口和runbook共同改造；原先直接kill的路径必须显式进入drain。测试只停止自己的隔离进程。
- 旧失败如有未过期完整trace，可本地重新执行规范化+证据资格校验，追加恢复回执；不SQL改failed为success，不在实现时擅自重放生产任务。

## P1 · 自动资格、状态与时间

### 一份资格判定

自动调度、定向prepare和真正reserve调用同一资格服务：来源可读→清洗→有效输入→当前适用结果→是否有执行所有者→有限恢复/过期/首次研究。UI不独立计算是否可调用。

结果DTO：`resultState = unstudied | studied | no_signal | outdated`；独立`executionState = idle | queued | running | failed | waiting_recovery`。`lastAcceptedAnalysisRef`、`currentAttemptRef`与`reasonCode`分开。旧有效分析 + 新失败应显示“已有结果，本次更新未完成”。仅有无效/过期结果不能算当前覆盖；过期历史仍可按资格查看。

清洗剔除是派生资格，不是执行失败。短语同问/蹲/求分享保留；不同人相同文本是独立原声；同一来源评论反复采到是观察更新。

### 复用键与版本

- 内部语义键由稳定来源身份、原文/清洗映射、实际必要上下文及其依据身份、有效规则/Schema/selector组成；排除点赞、凭据、连接版本、额度、排队时间。
- 模型/参数/供应商是执行provenance；切默认模型只影响未来待执行任务。明确要求重研时采用独立generation键，普通重选不会创建它。
- 正文变更、实际选用上下文实质修订、重要缺失上下文补齐、有效规则升级标记outdated候选。仅不相关作品长文改变不自动重算。必须覆盖“之前没声明缺失，但后来关键上下文更新”的情况。
- 新规则的历史重算政策在设置中明确；新版本只负责未来默认，不自动重算整个历史库。历史补齐只选未研究，历史重算单独有额度。
- 旧指纹不原地改写。通过旧结果的真实输入快照/哈希及规则证明兼容后创建复用映射；信息不足保持历史可读，不猜造兼容。映射生成不调用模型。

### 调度和预算

- 保存设置不开关则不执行；启用一次持续研究才授予后续范围内自动运行。读设置、读页面、预检都不外发。
- 默认Asia/Shanghai每日23:00冻结 `[start,cutoff)`；23:00整及之后进入下一窗口。停机跨日逐窗口补齐水位，不从“现在”跳过漏掉的窗口。
- 按首次进入系统的时间区分新增，发布时间只用于明确可比分析。今天分析旧内容不表示今天新需求。
- 设置分别包括新增持续研究、历史未研究补齐及历史边界、过期结果更新政策；首次启用必须能统计启用前真正的未研究库，不仅旧batch积压。
- 当前daily source_limit最高3000保持保护边界，超限持久排队而不丢；优先级 `new_intake → recovery → historical`，过期更新是带原因的recovery候选。同优先级按首次观察时间及稳定身份确定顺序。
- 预算分配前选择优先级，然后按作品和token切包；不能为了按作品拼包颠倒优先级。Token若无模型精确tokenizer则标保守估算并预留安全量，不冒充精确计费。
- 当日新增、恢复、历史共享明确日额度。执行预算归属与原batch出处分开；跨日接续原成员只保留一个当前owner，旧账不改写。新增持续占满时显示历史积压暂未推进，不承诺固定完成时间。
- 与既有定向研究/向量/关系调用统一核算，不允许shadow或聚类复核绕过总额度。累计失败不因转日/换批规避上限。

### 定向预检

互斥主分类加总等于选择总数：可复用、进行中、首次研究、过期可更新、已有失败待恢复、已剔除、上下文待补、异常/受限。再给实际拟外发评论数、作品数、预计调用数/输入输出Token及计算方法。

勾选重研、改模型/规则/上下文/范围后立即重新预检，等待期间禁用确认；30分钟过期或来源资格变化阻止旧确认并说明。取消零新调用，重复提交幂等。自动调度不依赖用户点击这个弹窗。

## P2 · 规则、提示词和原子接口

### 版本规则

建立不可变规则revision与独立有效指针；记录父版本、目的、字段定义、正/反例、schema/validator/selector版本、canonical hash、创建来源。Schema与校验器是程序发行版本，用户不能通过任意JSON编辑关闭证据/身份保护。

用户可在研究设置编辑研究方向与受限语义定义/例子。规范化后内容未变不产生重跑；保存草稿不外发；提交候选触发已配置的shadow任务。过自动检查按预先设置的升级政策用于后续新任务；失败/证据不足保留旧有效版并解释差异，不要求逐条质检。业务方向变更仍由用户定义。

Prompt builder唯一输出：固定安全原则 + 研究目的/字段定义 + 合成正反例 + 带来源标记的作品/父评论片段 + 目标评论 + 输出要求与Schema。生产、预检指纹和shadow调用相同builder；来源内容一律数据，无法授予工具/改写系统合同。P0协议兼容修复不擅自变更语义合同；新增原子定义发行v5而非覆盖v4。

### 字段最小语义

| 类型 | 提取要求 | 必须留空/拒绝的边界 |
|---|---|---|
| problem | 评论者遇到的具体困难；简短名称、含义、场景可空、精确依据 | 不由领域标签/负面情绪/作品内容代造困难 |
| need | 用户希望得到的帮助、信息或结果，保留请求对象 | 收藏/纯认同不直接算需求；不能把全部问句视为需求 |
| solution | 用户提出或尝试的方法；效果只在明确表达时记录 | 作品列出的方法不算评论者尝试；先后发生不自动成因果 |
| stance | 对明确对象/命题的支持、反对、担忧或混合态度 | 担忧不等于反对，语气强烈不等于冲突 |
| story | 自述经历、具体场景及有限时间/事件关系 | 不补不存在的身份、诊断、经历或因果 |
| quote | 有原文依据的典型表达候选 | 不改写成漂亮金句，不由点赞替代语义 |
| emotion | 对象明确的表达情绪，可不确定 | 不推断人格或心理/医学诊断，不单凭感叹号赋值 |
| conflict | 同一目标上至少两种不相容立场的派生关系 | 不是单条评论提取标签；需引用双方stance和原声，跨目标不算对立 |
| context_missing / uncertainty | 缺什么、无法确定什么；不确定字段与确定字段分开 | 无法理解不强塞no_signal；上下文仅消解指代不冒充评论原话 |

原子候选有 `kind, meaning, context(可空), basis, evidence[], contextEvidence[]`；同类多项各有ordinal。保存为版本化机器理解，模型JSON只作候选，经程序接纳才进正式analysis及派生atoms。旧label只有类别没有meaning时不能靠程序猜出需求名称。

## P3 · 自动回归与采用

- 持久sample_set保存来源引用/版本哈希、选择规则/seed、分层：短/长、父回复、依赖上下文、多意图、历史无信号/字段拒绝、多作品。按作品限制集中度；代表性仅针对所选样本，不代表平台。
- baseline/candidate固定同一份可读输入与规则/模型/上下文快照。来源或上下文失效，两侧一起退出比较；报告冻结数、可用配对数、双方完成数与退出原因。
- 两侧各用自己的冻结builder/validator/schema；共同字段才做跨版本对比。v4的need/solution标签没有meaning，不能猜出atom与v5比较。新增维度显示不可直接比较，并单列candidate内重复稳定性。旧builder/validator不可执行时标baseline unavailable，不用当前实现冒充旧版。
- 同一sample_set/run的成员不可追加或替换。新样本生成新sample_set revision及新run，旧run保留不足结论；只有双方输入hash、规则及模型完全一致才复用配对结果。排队超出trace TTL或上下文修订后，从冻结source/context refs重建并校验hash；重建失败成对退出，不用最新正文替代。来源引用无法长期读取时，不承诺该样本永远可重放。
- shadow有独立run/item/result域，复用invocation/trace/accounting但不写正式analysis/atom/problem/member/projectioncursor。持久幂等键含样本集+baseline+candidate+重复序号；同一候选重复保存不重复计费。
- 默认候选回归样本上限120条、至少30个完成配对且覆盖5作品；另取最多20条作重复稳定性检查。这些是初始工程预算，未校准，需设置快照与可调上限；库不足时显示证据不足，不能造样本。
- 在一次授权的回归子预算内自动执行；总日额度扣除、新增研究优先。未启用真实外发时任务保持待执行，读取对比不启动调用。
- 硬门：字段/身份/引用接纳不变量无违规、无生产副作用、无来源越权、配对覆盖≥90%。统计门初值：candidate结构失败≤5%且不高于baseline+2pp；无信号比例变动≤15pp；平均Token≤1.5倍、延迟≤2倍。样本分母及unknown用量显式标出；未知成本不能通过成本门。
- 重复一致性按规范化原子集合和证据的匹配方法计算，阈值/版本记录；语义等价不能用字符串一致直接证明。字段分布漂移和不同结论通过有预算的LLM差异解释补充，不把评审模型的评价叫真实准确率。
- 检查输出 `pass | degraded | insufficient_evidence`。自动采用仅针对已选择自动升级政策的候选；退化保留旧版，继续新增研究；不足自动等新样本/额度后续跑，不向用户生成一堆逐条待审。
- 初始阈值明确为待校准工程默认；调整阈值留版本记录，不能为了让某版通过静默降低门槛。候选采用后异常回退只改未来默认指针，已有结果历史保留。

## P4 · 原子语义、聚类与自动组织

### 数据与计算

- atom唯一键 `(analysis_ref,kind,ordinal,atom_contract_version)`；关联canonical评论身份、work、依据片段、rule、input hash。时间/点赞/作者通过来源关系读取，不复制新的事实列作为真相。
- problem/need/solution分别聚；conflict由经校验stance关系派生后独立组织；story/quote/emotion可作为研究维度，不能跨类型混入问题簇。
- atom→problem/cluster的版本化membership是真正依据；现有comment级member降为可重建去重投影。一条评论不同原子可属不同问题，同一原子不能因重复分析被累计多次。
- 当前atom集合按canonical身份+当前来源/必要上下文+有效规则/generation选择适用的已接纳版本。旧atom保留历史，但不能与新版本一同进入当前聚类/统计。新版本未完成时旧结果是否仍适用服从P1资格判定；字段补齐追加补充版本，替换对应字段集合，不把新旧字段简单union。A16同时验“先成功→明确重研→部分补齐”后当前成员和计数不翻倍。
- embedding缓存键包含atom定义hash+模型实际版本/维度/归一化方法，不混向量空间。批量接口放宽必须仍按供应商/字节/Token限额分块、校验每个index/维度/有限值/非零范数；已有成功向量不重复调用。
- 本地计算进程只接固定snapshot的原子ID、float32向量、参数，返回近邻/assignment/质量值；无数据库凭据和网络。Rust拥有资格、持久化、状态、预算。路径/数量/输出严格校验，输出不能直接授予正式Topic定义。
- 计算候选使用实际依赖实现（如Python受控环境的HDBSCAN、Faiss HNSW、igraph/leidenalg）；开始安装前核对ARM64与固定依赖，记录版本/锁文件。不是新增常驻Agent框架。

### 双路线与自动质量

A：Embedding→HDBSCAN；B：Embedding→KNN稀疏图→Leiden。同一冻结分层集合对比，记录seed、参数、噪声率、簇规模、覆盖、时间/内存。HDBSCAN在高维可能失效；降维若采用必须版本化，另外测原空间近邻保持率。Leiden图社区不自动等于业务层级。

记录簇内一致性、邻簇分离度、同seed复现、seed扰动稳定性、算法agreement、第二embedding空间稳定性；缺少第二模型就标未测，不凭空算通过。资源和统计通过不等于语义正确。

P4写代码前由root冻结一份`cluster-policy`版本，至少包含下表公式、参数、必要性及采用顺序。下列为本包初始工程政策，不是已校准的中文语义阈值；如真实小样本实验否定它，形成新政策版本及明确差异，不能在同一run里调到通过。

| 指标 | 固定计算与初始门槛 | 作用 |
|---|---|---|
| 输入守恒/类型/来源 | 每个输入恰好一个assignment或noise，ID和空间合法，当前资格有效 | 硬门；失败不可采用 |
| ANN召回 | 固定seed最多1000查询，对精确cosine的recall@20≥0.95；不足20取min(20,N-1) | 硬门；小集可精确检索并注明 |
| 同seed复现 | 同一输入/实现版本/参数两次分区在标签置换下等价，noise身份一致 | 硬门；不足或不确定标insufficient |
| 扰动稳定性 | 3个固定seed；共同非noise成员的adjusted Rand index均值≥0.80；另报共同核心覆盖率，核心少于30时insufficient | 组织稳定性门，不是正确率 |
| 簇内一致性 | 归一化向量与簇中心cosine均值，按簇等权和按成员加权分别报 | 诊断；不跨embedding空间直接比数值 |
| 簇间分离 | 固定分层最多1000成员，在原始向量空间计算silhouette抽样估计及邻簇中心差；少于2簇时不可计算 | 诊断；不能用降维后漂亮值替代 |
| 算法一致 | 同一输入共同非noise成员的ARI，另报共同覆盖率/噪声差异 | 诊断；不同算法不一致不等于其中一定错 |
| 第二向量稳定 | 对相同atom比较核心成员配对同簇关系和覆盖变化，记录模型与维度 | 有已配置对照才执行；缺失不算通过也不阻塞主空间受限使用 |

自动选择顺序：先资源/输入/召回硬门，再同seed与扰动稳定性门，再逐簇有界语义复核；失败保留旧可用组织或独立表达。若A/B均合格，先选通过语义复核的当前核心成员覆盖更高者，再比较扰动稳定性，仍相同选耗时低者；保存两侧报告和选择原因。不符合最小稳定性样本规模的初期表达仍按已有same/related路径保守组织，不能假装完成了全局聚类质量证明。

每簇单次复核最多12条原子（核心5、边界4、邻簇3，缺类如实记录），input最多8000/output最多2000 Token；每次组织修订最多2次模型尝试、冷却至少24小时，新增实质证据可产生新修订但仍受日额度。每轮最多60个语义复核/命名调用，使用研究设置中明确的语义组织子预算并受总日预算约束；未完成簇保留待接续。名称与边界可在同一结构化响应中给出，避免无意义的额外调用。

每个待接纳簇用少量核心、边界及邻簇代表表达作LLM复核/命名，严格回到对应atom和原声。`same`才能合并；不确定保持独立，有限复核次数/冷却或新证据触发再次比较。超过次数显示“暂时保持独立”，不产生必经人工任务。

复核、新名字/定义、代表成员都版本化。rename保留ID；split/merge追加父子血缘与变更理由，旧成员/判断不盲目继承。用户主动纠正是可选低频操作，不是自动系统通行证。旧人工决定历史保留，不能改写成系统判断。

新原子先增量embedding/近邻归并；未能归并者进入独立候选，并由规模/时间/变化触发有界重聚类。HDBSCAN approximate_predict不能发现新簇，故不单独承担新问题发现。

### 10万规模门

单域/单类型/同空间100,000 atoms经生产计算路径；固定seed合成向量用于容量，不证明中文语义。float32分块/mmap，禁止N²矩阵；100k×1536原始向量约614MB只是基线，索引和进程开销另测。

初始保护预算：最多4计算线程、子进程峰值RSS≤6GiB、单次最长30分钟，超限安全终止并保存阶段记录。已取得固定合成输入五场景容量回执；真实语料负载仍未验证。ANN以固定1000查询精确对照，recall@20目标≥0.95；这是召回指标，不是研究准确率。

两路线先在同一分层样本实跑并比较，生产候选必须实际跑完100k；HDBSCAN若不能在预算内完成该规模，记录失败原因与适用上限，由实测选择Leiden路线，不能只保留strategy枚举宣称两算法完成。连续验证100k→新增1k→来源撤回→进程中断恢复→embedding版本变化。索引撤回采用资格过滤并重建，不留不可读成员在代表表达中。

官方实现依据：[HDBSCAN FAQ](https://hdbscan.readthedocs.io/en/latest/faq.html)、[预测边界](https://hdbscan.readthedocs.io/en/latest/prediction_tutorial.html)、[Leiden参数](https://leidenalg.readthedocs.io/en/stable/reference.html)、[Leiden固定节点/分辨率](https://leidenalg.readthedocs.io/en/stable/advanced.html)、[Faiss索引](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)。这些说明算法边界，不证明本机已经安装/跑通。

## P5 · 结果、变化和完整用户路径

概览：先自动研究状态与覆盖，后已有问题/六类视角/热词；研究失败统计基于实际执行的去重成员，调用失败率另列，不能混分母。

覆盖率：当前有效已研究（含有效no_signal）÷当前可研究原声；同时单列no_signal、过期、待研究、处理中、需要恢复、剔除/异常口径。正在处理可与有旧结果交叉，不能把两轴相加冒充总数。

“今日新增”按首次入库；“今日完成”按接纳时间；“问题增长”只能来自可比发表/观察窗口及版本。问题详情显示定义、原子表达、来源作品/作者覆盖、点赞事实、邻近问题和来源，不从一条评论推出高冲突或市场普遍需求。

`comment-change.v2`复用当前统计比较规则，并增加当前group修订/向量空间/聚类政策签名、14日自动rename/split/merge记录与两期问题组织覆盖。每期组织覆盖至少80%、差不超过10个百分点；缺失一期原子组织分母不能当作零问题。旧comment级组织两期均无原子时沿用旧门槛且不声称测过原子覆盖。来源受限由当前资格视图剔除。现有每窗30、覆盖80%、差10pp、5完整观察日只是已有门槛；新质量机制不能用开关绕过它们，也不能把回归通过直接等同趋势资格。历史补分析、采集范围变大、规则升级、合并拆分分别解释，不画成需求上涨。

Topic关联以现有Topic ID/定义版本及派生关联回执可查询，关联失败只影响该lane；未发布的评论簇不自动变成正式领域定义。没有可靠变化时提供已有原声和具体限制，不能只有空白。
