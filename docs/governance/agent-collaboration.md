# Agent 协作与文档维护协议

> 状态: 权威当前
> 最后核对: 2026-10-23
> 适用范围: 工作包、协作委托、风险分级、审阅、验证与文档维护
> 事实来源: Mog 2026-10-23 确认的开发协作改革；当前仓库与 CI
> 冲突时以谁为准: 用户最新明确授权；事实以真实运行/代码/合同为准；本文是交付流程唯一规范

## 一个用户结果，一个工作包

用户授权实施后，当前执行 Agent 默认担任包内协调者。已授权目标、限制和决定在该包持续有效；技术拆分、定向验证、修 CI、修审阅发现和包内集成无需逐次确认。只读调查不创建工作包。

工作包摘要可直接放在 PR 正文或已存在的 Issue/计划中，只维护一个权威版本，其他位置引用它：

- 用户结果、验收方式及明确不可接受的结果；
- 风险级别、授权来源、真实副作用与成本边界；
- 涉及模块/表面、关键状态、共享依赖与文件所有权；
- 验证选择及其覆盖理由；
- 协调者、协作者、审阅状态与未决事项。

小改动可用几句话说明；复杂 UI 用表面、状态、依赖、验收矩阵表达，复用现有规格，不强制新增四份文档。默认一个可审阅 PR；兼容迁移、可独立验收的步骤或不可合理审阅的大 diff 可以分 PR，共享同一包摘要和授权。内部修正不重新立项。

## 风险分级

| 通道 | 判定 | 最低流程 |
|---|---|---|
| 只读 | 读取代码、记录、运行身份，无写回或外部动作 | 直接调查与报告 |
| 快车道 | 局部 UI/文案、测试、单模块重构、内部工具；不改变数据语义、公开合同、权限或外部副作用 | 工作包摘要 → 独立分支/必要 worktree → 相关验证 → 一份 PR；免预建 Issue/Claim/active plan |
| 保护车道 | schema/migration、跨模块契约、数据语义、权限、安全、插件发布、部署、真实敏感材料或外部调用、不可逆操作；以及改变治理门禁的 CI/规则 | 工作包 → 关联 Issue 或已确认交付包标识 → Claim → 独立 branch/worktree → 必要真实链路验证 → 独立审阅 → PR |

按最高实际影响判定，不按扩展名或行数。未知依赖先调查，仍不清楚时采用较高验证级别。用户已授权的小型纯文档维护且工作区干净、无并行冲突，可直接有界更新；代码不在共享 main 实施。单人已有独立 checkout 可用分支隔离，保护车道和共享/并行环境使用仓库 `.worktrees/`。

当前对话确认的交付包本身就是实施授权，不为形式重新请求一次授权。Issue 只记录和协调；创建额外外部任务或对外发消息仍须用户要求或已有明确授权，不从技术拆分自动推导。

## 协作委托与升级

协调者负责实现顺序、包内子任务、验证选择和最终集成。允许调用一个独立审阅子代理；只有存在可独立验证、文件互斥的子任务时才安排实现子代理。默认同时写代码的实现者最多两名（含协调者），平台或用户更低上限优先；审阅者只读。每个角色保留独立上下文、必要背景和明确输入/输出，不自动继承全部讨论，不擅自覆盖用户指定的模型。

共享文件由协调者独占集成。执行者发现完成原目标所需的直接依赖时，先核对活跃修改，更新范围记录，再在无冲突且不改变产品/权限边界时实施。其他工作包的所有权冲突、需要改变其排期或吸收未授权成果时，暂停冲突部分并向用户说明；包内普通 Git 冲突由协调者根据双方既定合同解决和验证。

以下事项回到 Mog 决定：

1. 改变已确认用户结果、业务语义、正式领域语言，或出现现有合同无法裁定的用户体验选择；
2. 扩大真实采集、模型外发、敏感材料访问、权限、成本预算或不可逆处置；
3. 需要跨包重排责任或解决相互冲突的授权；
4. 尚未获得授权的合并、部署、真实环境变更。

用户可明确限制角色、并发或要求逐步验收；此时按其指令。普通实现、可逆修复、测试命令选择和已批准设计不转嫁给用户决定。

## 审阅与合并

- 可执行代码、CI/门禁和治理权限变化，在候选完成后安排一次独立审阅；纯文档勘误、格式与状态同步可自查。无需每个中间提交都审。
- 先自查并跑相关测试，再送最终候选。审阅者记录 base、被审提交或工作区 diff 身份、具体发现及证据，不修改实现。
- 成立的发现由执行者在包内修复；不成立的写明理由。涉及行为、合同、权限、验证覆盖的后续变更，复核受影响增量；仅排版/记录修正不重做全仓审阅，但记录最终 head 与差异。
- 提交最终候选后，审阅记录必须关联实际提交；旧 head 的 CI 或审阅不能冒充新 head 已通过。
- Ready for review 表示实现和声明验证已准备好，不要求先有人认领审阅，避免互相等待。
- 合并遵循工作包已记录授权；没有合并授权时，准备具体 head、检查与审阅回执交给 Mog。保护车道的授权针对最终 head，新 head 不自动继承旧授权。
- 不以 Draft、SKIPPED、MERGEABLE、CLEAN 或本地测试代替最终提交所需 CI。CI 缺失时如需例外，明确证据缺口并由 Mog 决定。
- 合并后核对 main 与实际副作用；部署和 Mog 业务验收分别报告，不由合并推断。

## 按影响选择验证

提交前执行 `bash scripts/ci-preflight.sh origin/main`。预检用于格式、文档结构、链接、治理和 CI 路由自身回归；昂贵验证等预检成功再启动。

| 改动 | 必要证据 |
|---|---|
| 文档/导航/模板 | 差异、状态/链接、规则一致性 |
| 局部展示/交互 | 类型/lint、相关组件或浏览器场景；不改变合同的展示不强制真实 PG |
| 业务逻辑/契约/数据/权限 | 相关正常路径与负例，涉及持久化/事务时必须隔离真实 PG；用户动作涉及后端时补真实应用链 |
| CI/验证选择器 | 路由正反例、未知路径保守覆盖、失败/取消/跳过的门禁语义，以及远端实际运行 |
| 部署/真实外部动作 | 另按明确授权、对应 runbook 与真实回执验证 |

本次相关的关键验证必须在合并前完成，不能移到夜间后声称已验证。全仓审计/夜间全检属于补充；未实际建立的定时任务不能声称运行。CI 的实际触发与命令以 `.github/workflows/` 和选择器为准，新增共享依赖必须同步路由测试。

初始反馈目标：预检 2 分钟、常规相关检查 10 分钟；这是待度量目标，不是已达到 SLA。Draft 可优先轻量验证；如延后必要检查，最终汇总必须明确未具备合并资格，转 Ready 时重新触发。不得把必需但未执行的检查显示为全绿。

## 按事实变化维护文档

| 事实变化 | 更新位置 |
|---|---|
| 产品/数据/架构合同改变 | 对应权威文档；长期决定进入现有 ADR |
| 新增/移动/替代文档 | 最近索引及 `docs/README.md` 条目 |
| 运行版本、跨包依赖或阻塞改变 | `docs/current-state.md`；保留原证据核对日期 |
| 重要决定、迁移、发布或包级里程碑 | 当月 progress，引用完整回执 |
| 普通实现、小修复、测试细节 | PR 交付记录；无 PR 的直接维护用会话回执或 commit |

不要求每次代码提交同时改计划、索引、current-state 和月报。只有跨会话复杂依赖或分阶段验收确有需要时建立 active plan；内部补丁引用原计划。现存历史记录保留，不在流程改革中重写过去事实。

## 读取与冲突

从 AGENTS 的任务路由进入合同；索引用于查找，current-state 仅用于当前状态/跨包集成，历史材料仅用于特定来源核查。流程只由本文定义；Issue 指南和模板说明操作，模块合同保留领域/界面语义。

事实优先级：真实运行/数据库副作用/可复现测试 → 当前代码/migration/版本合同/producer fixture → ACCEPTED ADR → 权威当前文档 → 计划与报告 → references。优先级用于说明当前事实，不授予更改业务决定的权力。

事实漂移按证据修正文档；未决产品选择标记 DECISION_REQUIRED；来源不足标记 SOURCE_INCOMPLETE，仅暂停依赖部分。references 原件不改写。无法在包内解决的跨包阻塞记入 current-state。

## 交付与度量

回执写清用户结果、影响、验证、未验证边界及当前需要的决定；分别报告工作树、提交/推送、main、运行/部署、Mog 验收。临时日志和测试产物按生成物登记规则存放。

每个试点包记录授权时间、首个可验收版本、最终提交、CI 完成、Ready、合并时间及用户介入次数。比较 Ready→Merge 与 CI 关键路径，不把 Draft 等待计为纯合并耗时；同时观察取消率、合并后回归/回滚/跟进修复。指标尚未采集时标记未测量，不用目标数字代替结果。
