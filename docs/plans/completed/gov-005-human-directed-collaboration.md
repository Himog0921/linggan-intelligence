# GOV-005 · Mog 直接控制协作

> 状态: 已完成计划
> 最后核对: 2026-09-02
> 适用范围: Linggan Intelligence 的 Agent 协作、Issue 派单、UI 执行与合并授权
> 事实来源: 用户 2026-08-26 确认、`AGENTS.md`、协作协议、Issue 追踪规则与 Issue #72
> 冲突时以谁为准: 用户最新确认、`AGENTS.md`、真实代码/运行证据、ACCEPTED 决定

## 目标与用户可见结果

将协作调度权交由 Mog：谁派单、允许多少并行、何时审查、何时以及对哪个 exact head 合并，都由 Mog 明确控制。执行 Agent 只在已派定范围内工作，不得自行启动额外 Agent、创建衍生任务、提高并行或推进合并。

## 范围与非目标

**范围**：修改 `AGENTS.md`、协作协议、Issue 追踪规则和 UI 执行合同；补充本计划、索引与月度记录。

**非目标**：不删除 Issue/Claim/PR 留痕，不弱化 Evidence、Unknown、Coverage、隐私、权限、敏感数据或 SCOPE；不改变产品、页面、数据库、插件、运行时或真实采集。

## 已确认决策

- GOV-004 的“Harness 自主编排”不符合 Mog 当前偏好的协作模式，必须被本计划明确修订。
- Mog 不是被动验收者，而是默认的协作调度者与合并授权者。
- 执行 Agent 仍对已分配 Work Package 内的技术实现、排查和验证负责；不得将该责任回推给 Mog。

## 执行与验收

1. 在最高合同中明确 Mog 的派单、并发、审查和 merge 权力。
   - 验收：Agent 无法将自行编排表述为默认权力。
2. 在协作协议中改写交付包、升级和共享依赖规则。
   - 验收：跨任务、并发、审查、集成和合并都必须报告并由 Mog 决定。
3. 在 Issue/UI 合同中落实该权力边界。
   - 验收：执行 Agent 只有明确分配后才能 Claim；UI Agent 不会自行派单或整合共享依赖。
4. 运行治理和文本一致性检查。
   - 验收：`git diff --check`、`./scripts/check-project-governance.sh` 通过；关键禁止项可检索。

## 风险、停止与回退

**风险**：将协作调度权交回 Mog 可能降低自动并行速度。该成本是本项明确接受的交换：宁可由 Mog 有意识地决定何时并行，也不让 Agent 自行扩大工作面。

**停止条件**：任何需要削弱事实、权限、隐私、Unknown、Coverage 或 SCOPE 的条款一律停止并单列决策。

**回退**：本事项只改变治理文本；未合并前可丢弃分支。若合并后实践表明阻塞过多，由 Mog 另行定义有限委托的例外，不自动恢复 Harness 自主派单。
