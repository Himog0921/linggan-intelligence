## 当时为什么不能提前进入 SCOPE-001

第一条垂直切片只能从完整产品和系统设计中裁切，不能反过来替代产品定义。当前 PRD、页面地图、目标架构和 Rust 迁移地图仍含 Bootstrap 阶段的建议，尚未共同证明它们能支持同一个真实用户工作流。

## 工作方式

- 一次只讨论一道关口，不让用户同时承担大量技术选择。
- Agent 负责提出结构、备选方案、影响和推荐；用户负责确认产品意图与最终边界。
- 每道关口都记录：已确认、已否决、待决定、证据来源、反例、影响文档。
- 需要事实时只读核对真实源码、fixture、测试和历史证据；`references/` 不自动成为现行要求。
- 来源不足标记 `SOURCE_INCOMPLETE`；需要用户裁决标记 `DECISION_REQUIRED`。
- 后续发现冲突可以回到前一关修订，不用错误决定强推后续设计。

## 七道设计关口

### Gate 1：产品基础（已确认）

回答：为谁服务、解决什么高价值问题、帮助用户积累什么长期资产、做什么决定、为什么值得持续使用；围绕已确认的 ADHD Domain 说明完整产品体验。

产出：产品定义、首要用户、真实场景、完整产品能力地图、核心价值、成功与失败标准、明确非目标。

退出条件：用户能用一个真实领域说明“系统持续积累什么，如何形成语料、主题知识、市场洞察和情报，最终如何进入选题与行动”。

### Gate 2：工作流与功能地图（已确认）

回答：持续观察和主动研究如何分别发动、如何汇入同一资产底座、何时提醒或补证、每条工作流可以在哪一层结束；AI 如何提出证据缺口、人如何批准授权范围、服务端如何在范围内编排、producer 如何执行有界工作、Evidence 如何验收真实结果；用户从观察意图到语料、主题知识、市场洞察、情报、选题、行动和结果的完整过程是什么；共同内核与应用能力怎样保持边界；外部 Agent 通过 CLI 可以读取和发起什么。

产出：端到端工作流、核心与应用边界、能力地图、功能优先级、人机责任、CLI 能力边界、异常与恢复路径，以及跨 Gate 的领域不变量测试基线。

退出条件：每项功能都能追溯到真实用户问题，不保留无场景支撑的“大而全”能力。

### Gate 3：领域模型与共同语言（已确认）

回答：持续观察目标、Research Question、Information Need、采集申请/授权/准入/Work Order、发现执行、发现面 Evidence、发现记录、来源身份解析、来源对象与稳定身份、详情采集、采集发生记录、Capture Package、Evidence 接入/接受、Observation、正常复观测/来源差异/解析修正、来源时间陈述、Coverage 来源事实与用途评估、分析输入集合、分类/聚类/解释、领域定义、Candidate Topic、正式 Topic、可争论判断、决定、Action Plan/Occurrence、Expected Outcome、Outcome Observation 与评价分别是什么、不是什么；候选解释如何被确认、拒绝或修正。这里不以“概念数量少”作为正确标准，也不因产品页面名或身份缺口创建同名对象。

产出：共同语言、对象责任、状态机、不变量、聚合与边界候选。

退出条件：同一词只有一个现行含义；“未采集到”不会被解释为“现实不存在”。

### Gate 4：采集与证据链（已确认）

回答：观察计划如何变成插件任务，Attempt/重试/分块/checkpoint 与 Capture Package 如何关联，真实 producer 产生哪些 Record、Artifact、Coverage 与终态，如何区分持续观察、探索发现、主动调查和补采等不同观察目的，如何记录观察上下文、失败、租约、幂等、媒体和不可变 Evidence；发现执行、接口返回、页面实际可见、发现记录、来源身份解析、来源对象、详情/评论采集、原始时间表达和解析依据分别来自哪里；包级原子接入与 Record/Object 下游隔离怎样同时成立；执行目标错、来源记录内部身份错、采集包身份/hash 冲突和媒体主体错如何产生不同后果；哪些观察能在哪些维度比较。

产出：采集时序、来源合同清单、状态与错误语义、Evidence 接入边界、需要只读审计的事实，以及搜索发现面 API/页面对账与发现—详情分责的 producer 探查报告。

退出条件：正常路径、失败路径和缺失事实都能说明来源；不凭旧 Prisma 字段猜合同。

当前执行顺序：

1. **固定来源证明矩阵：** 以 V2 固定源码、六类合同、fixture 和实际可运行测试为底稿，逐 lane 标记“已证明 / 源码暗示 / `SOURCE_INCOMPLETE`”，不把历史 schema 或未加载测试当成合同证据。
2. **交付与接入关系（已确认）：** Work Order 1:N Attempt、Attempt 独立 Capture Identity、第一版 Attempt 0..1 终态 Package、网络重放与执行重试分责、checkpoint 只属运行状态、新 Attempt 不改挂旧未接纳材料、Package 原子接入、接纳后 Record/Object 隔离及 authority/Evidence 原子 fence 已进入共同语言和不变量。
3. **producer lane（只读审计已完成，约束待整体确认）：** 已分别核对搜索发现、作者资料/作品索引、笔记详情、评论/回复、指标、媒体、Coverage/终态、风险暂停/恢复和时间语义。已发现合成评论 ID、未知值默认、发现路径覆盖、原料截断、Coverage 单位混用、启发式停止冒充来源耗尽及 run 完成时间冒充逐条观察时间等 P0 风险。
4. **真实实验包（设计已完成，未授权执行）：** 只有源码、fixture 与测试无法证明的事实才进入最小真实 producer 实验。每个实验已经写明目的、样本、账号/工位、访问上限、敏感数据处理、停止条件、可证伪结果和结束后处置；需要真实平台资源时仍须另行取得用户授权。
5. **可比性结论：** 只按实验真正证明的账号、入口、时间、Coverage 和 producer 范围开放比较资格；其余保持单次观察或未知。统计单位、分母和正式趋势资格继续进入 Gate 5。

Gate 4 不访问真实平台、不升级插件、不创建数据库或业务代码。固定 V2 producer 能力矩阵、Attempt/恢复/Package 关系、逐 lane 字段来源对账和五份最小实验单均已登记；用户已整体确认七条 producer 约束及实验/冻结政策。该确认关闭设计关口，但不是执行真实实验或访问平台的授权。

第二项关系和第三项的七条约束均已由用户确认并进入共同语言与对抗性不变量；它们仍不预设最终表、字段、队列或服务拆分。约束包括：身份必须证明来源而不只非空、未知不补业务默认、对象去重与发现事件并存、Coverage 先固定单位、启发式停止不冒充来源耗尽、原始材料可重放、真实工位访问统一准入。

#### Gate 4 最小真实 producer 实验包（只设计，未授权执行）

所有实验共享以下边界：

1. 只观察用户已授权的公开页面，不访问私信、咨询、后台、Cookie 内容或其他非公开数据，不下载媒体文件。
2. 每个实验使用独立 Attempt 身份和独立目录 `artifacts/private/gate-4-xhs/<experiment-id>/<attempt-id>/`；该目录已被生成物治理登记为私有运行证据位置并由 Git 忽略。不得写入 `references/`、`docs/` 原文、数据库 dump 或临时自创目录。
3. 原始响应/页面材料只保存在私有目录；提交到 `docs/` 的报告只包含字段来源、计数、hash、脱敏片段和结论。原件保留期限、删除或长期加密保存必须在执行前单独确认，不默认永久保存。
4. 发现验证码、登录失效、账号/平台风险提示、页面目标错、结构明显异常、单次超过 30 分钟或达到访问上限时，立即结束当前 Attempt 并报告实际终态；不为了完成实验自动验证、切号、重试或扩大访问。
5. 不主动制造高频访问来“测风控阈值”。风险实验只记录正常最小访问中自然出现的限制，不能把一次未触发验证码解释为安全频率已证明。
6. 每次页面访问、接口响应、发现卡片、详情、评论页和媒体地址分别计数；所有计数写清单位。空结果只在目标、入口、响应、Coverage 和解析器均有资格时报告“本轮发出 0 条”。
7. 实验只证明该账号、工位、时间、入口和当前 producer 版本下的行为；不能自动外推小红书全平台、其他账号或未来版本。

#### 未执行真实实验时的继续规则

Gate 4 不把真实平台访问变成整个项目的无限阻塞。若当前不执行、资源不足或实验被风险中断：

1. 搜索可比性、平台完整 Coverage、正式趋势、7 天衰减参数、评论全量、评论/作者媒体和安全访问频率继续标为 `SOURCE_INCOMPLETE`。
2. 可以继续 Gate 5–7 的平台无关设计：Capture/Attempt/Package/Evidence/Observation、稳定来源身份失败关闭、unknown 语义、Discovery Event、页级 Coverage、受控访问和 fixture 驱动的首个垂直切片。
3. 不得开始声称真实小红书 producer 合同已验收，不得升级插件为正式新项目执行器，也不得把脱敏 fixture 成功当成真实页面成功。
4. 第一个代码切片可以使用经过明确标注的合成/脱敏 fixture 证明事务与数据库副作用，但上线前仍须以真实 producer 结果补齐对应来源 Gate。

实验执行前仍需用户参与的只有三项现实授权：允许使用哪些已登录账号/工位；允许使用哪个公开作者和哪些公开笔记；私有原件保留多久以及到期删除还是转入长期加密保存。其余技术取样、字段对账、错误判断和结果验证由 Agent 负责，不交给用户排查。

### Gate 5：数据与数据库设计

回答：哪些是原始事实、版本事实、当前视图、推断结果和运行记录；如何追加、更正、关联、保留和授权访问；如何保存稳定来源身份、每次发现、有意复观测、原始/推算时间与精度、Coverage 来源事实及用途评估；模型、规则、算法和输入变化后，如何保留可重建的分析输入集合、版本与语义演进关系；删除、撤回、脱敏和访问限制如何传播到选择、引用、向量/特征、摘要、缓存和外部返回。

产出：概念数据模型、关系与生命周期、版本/身份/时间语义、事务边界、角色权限、数据库验收原则。

退出条件：概念模型通过跨时间、并发、重放、部分失败和更正场景审查。此关只确认设计，不创建物理表。

在 Gate 4 真实实验尚未执行时，Gate 5 允许按冻结规则推进平台无关候选设计，但不得把 `SOURCE_INCOMPLETE` 的平台字段、完整 Coverage、正式趋势或 7 天策略写进数据库合同。原则入口维护在 [`../../architecture/data-architecture.md`](../../architecture/data-architecture.md)，关系与基数进入 [`../../architecture/data-relations.md`](../../architecture/data-relations.md)，事务、并发和 PostgreSQL 验收进入 [`../../architecture/data-consistency.md`](../../architecture/data-consistency.md)，按以下顺序收口：

1. 真相分类、最小 Source Identity Registry 与类型化 Observation；
2. 不可变历史、Interpretation Revision、字段级 Current Resolution 与类型化投影；
3. Topic/Claim 的 Identity、Revision、Release、Run 与双历史；
4. Corpus 使用血缘、隐私保留和处置传播；
5. 统计资格、输入集合、单位、分母和版本；
6. Package、Observation、Current、Definition Release、Decision、Privacy 的事务/并发边界；
7. 用 `INV-01` 至 `INV-63` 完成压力测试和用户确认，确认后才有资格产生候选表簇，仍不直接创建 migration。

### Gate 6：系统架构

回答：Rust 模块、API、worker、浏览器插件、PostgreSQL、对象存储和 Agent 如何分工；合同、事务、安全、可观测性如何闭环；AI Agent 的输入/输出、工具权限、版本、评测、成本、停止和失败降级如何形成可证伪合同；插件升级如何在真实 producer 合同、身份/时间/Coverage 语义和 fixture 兼容测试之后发生；是否需要 pgvector、Python 分析进程或具体聚类算法，必须由前五关合同和真实 benchmark 决定。

产出：系统上下文、模块边界、关键时序、部署单元、错误传播和安全模型。

退出条件：架构能承载前五关，不引入没有真实需求的微服务、Kafka 或图数据库。

## 需要与用户逐项收口的决定

只把产品权力和现实后果交给用户决定；字段、表、错误码、crate 与算法由 Agent 在相应 Gate 提出推荐并负责验证。一次只讨论一个决定。

### DEC-01 · 真实材料的隐私与传播边界

- **Status:** confirmed（2026-08-19）
- **Type:** Product boundary
- **Blocked by:** none
- **Question:** ADHD、儿童、家庭与医疗相关原文，哪些可以长期保存、内部阅读、脱敏展示、供外部 Agent 使用；删除/撤回时哪些派生物必须失效？
- **Answer:** 原始 Evidence 可以按明确用途在内部受限区长期保存，但不承诺永久；普通工作台默认展示脱敏片段；外部 Agent 默认只取得聚合结果、脱敏片段和受控 Evidence 引用，不得批量读取原文。ADHD、儿童、家庭、医疗和可反向识别材料提高访问等级，真实材料实验必须先说明最小样本、用途、访问、输出和处置计划，第三方模型合同未确认前不发送原文。
- **Propagation:** 获准删除、撤回、脱敏或限制访问后，Corpus 选择、全文索引、embedding/feature、摘要、引用、缓存和 Agent 输出必须失效、重建或停止返回；历史 Claim/Intelligence 标记来源资格变化并重新评估，不静默消失。保留不含敏感内容的最小处置审计痕迹。
- **Clarification:** 平台来源消失与隐私撤回请求不是同一事件；具体保留期限、脱敏算法、加密、角色、审计和法律适用性留给 Gate 5–7 与专业审查。本决定不开放原文 CLI，也不自动授权扩大真实材料采集。

### DEC-02 · 第一阶段每天最重要的用户任务

- **Status:** confirmed（2026-08-19）
- **Type:** Product workflow
- **Blocked by:** none
- **Question:** 用户每天打开 Linggan 后，首先要完成的是“查看值得关注的变化并决定下一步”，还是“进入某个 Topic 研究原声/内容角度并形成选题”，或另一项更核心任务？
- **Answer:** 每日第一主任务是看到少量值得关注的事项，理解为什么现在出现，并决定是否继续观察、进入 Topic 深入研究或提出行动；Topic 原声、内容角度、历史与 Evidence 是点击后的核心深入工作区。
- **Qualification:** 每日入口可以包含候选变化、证据缺口、观察异常、待授权事项或已有判断状态变化，但不能因为进入入口就统一成为 Signal/Intelligence。没有合格事项时显示“没有形成新的合格事项”；观察不完整时显示未知，不得制造趋势填满首页。
- **Gate 7 boundary:** 本决定确认任务顺序，不冻结首页名称、导航、卡片数量、排序分数、按钮和页面布局。SCOPE-001 仍需在七道 Gate 完成后另行选择首个可证伪切片。

### DEC-03 · 外部 Agent 的委托深度

- **Status:** confirmed（2026-08-19）
- **Type:** Product authority boundary
- **Blocked by:** none for product direction；实现细节等待 Gate 3 判断/决定边界、Gate 4 资源合同、Gate 5 数据权限和 Gate 6–7 接口设计
- **Question:** 第一阶段外部 Agent 只是读取聚合结果和提交建议，还是可以在预授权预算内发起真实采集与回写行动？
- **Answer:** 第一阶段采用“可读、可分析、可建议、可申请，但未经人明确授权不得直接执行有后果动作”。范围内可以读取聚合结果、脱敏片段和受控 Evidence 引用，运行不改变正式世界的分析，提交候选建议，并申请有边界的采集、知识修订或行动；不能直连数据库、批量读取受限原文、直接指挥 producer、发布正式 Topic/Claim、改变长期观察方法或触发现实行动。
- **Delegation scope:** 每次调用必须能够回到已知调用者、代表关系、目的、Domain、允许数据、允许动作、期限、资源边界和输出传播范围；不能给“外部 Agent”共享一套永久超级权限。
- **Execution boundary:** 申请只创建待决定请求，批准也只授予后续尝试边界。真实采集仍经过 Evidence 复用、采集准入、工位/账号调度、producer 和 Evidence 接入；正式知识仍经过定义/判断治理；现实行动仍经过 Decision/Action/Outcome。任何一步失败都不得由授权或请求状态伪装成完整成功。

### DEC-04 · 第一阶段 Outcome 的主价值

- **Status:** confirmed（2026-08-19）
- **Type:** Product evidence boundary
- **Blocked by:** none for product direction；自动公开指标等待 Gate 4 producer/行动身份审计，数据关系与实现等待 Gate 3、5–7
- **Question:** 第一阶段最值得记录并用于学习的是内容收藏/深度评论、私信/咨询、销售转化、用户访谈，还是产品使用结果？
- **Answer:** 第一阶段不选择一个当前拿不到的指标作为主 Outcome，也不承诺私信、咨询、销售等自动反馈闭环。最低承诺是 Decision/Action 可追溯、每个结果渠道的可获得性可见，并只记录实际取得且来源明确的结果；未接入、未观察、窗口未结束或来源不合格保持未知。
- **Result qualification:** 结果分为真实 producer/合同支持的系统观察、带提供者/时间/依据/精度的人工或外部陈述，以及当前不可观察。人工陈述不能伪装成外部事实；旧 schema 字段、发布记录存在或任务完成不能证明指标链已打通。
- **Current source boundary:** 深度评论、私信、咨询、报名、销售、访谈和产品行为没有已证明的完整自动来源；公开平台指标也只有历史模型/路径，V2 指标来源仍未证明。是否把公开指标作为首期自动 Outcome，必须等待真实发布对象关联和 producer 审计。
- **Non-goal:** 不冻结主成功指标、渠道枚举、人工补录流程、指标同步频率、归因算法、Outcome 表或反馈 Agent；Outcome Observation 与 Evaluation 继续分开，结果不直接证明原因或改写旧知识。

### DEC-05 · 第一阶段是否承诺“趋势判断”

- **Status:** confirmed（2026-08-19）
- **Type:** Product claim boundary
- **Blocked by:** none for first-stage product promise；正式趋势能力等待 Gate 4 搜索/producer 可比性实验和 Gate 5 统计资格设计
- **Question:** 首个切片必须输出可比较的“近期趋势”，还是先只承诺可追溯的观察、语料/Topic 探索和存在性候选，把趋势作为实验通过后的下一阶段能力？
- **Answer:** 第一阶段不承诺“市场正在增长/下降”的正式趋势，只提供有时间范围、实际捕获面、Coverage 和分析版本边界的近期观察，以及明确保留替代解释、反例和缺口的候选变化。候选变化可以触发继续观察、主动研究或用户决策，但不能作为趋势发布。
- **Upgrade gate:** 正式趋势必须等待 Gate 4 真实跨时间/账号/入口/producer 可比性实验，以及 Gate 5 对单位、分母、合格时间、Coverage、来源集中和定义/分析版本的资格设计通过；通过范围外仍保持候选或未知。
- **Non-goal:** 不冻结固定时间窗口、趋势阈值、基线词表、评分、算法、数据库对象、页面文案或趋势 Agent；本决定不删除长期趋势能力。

49. 每日入口只改变注意力和信息顺序，不改变事项本身的证据资格。没有合格事项或观察未完成时必须诚实显示，不得制造变化、Signal 或 Intelligence 填满首页。

52. Evidence 接入以包为原子事务，区分同 identity/hash 的幂等重放和同 identity/不同 hash 的冲突隔离；包被接纳后按 Record/Source Object 隔离身份与 Observation 失败，不能整包下游连坐或整包成功掩盖坏记录。
53. 无效交付必须留下安全发生/失败记录、终态、Coverage 与影响范围，但不自动形成 Accepted Evidence，也不授权永久保存全部原始敏感载荷；隔离范围和期限由 Gate 4–5 决定。
54. 缺少稳定来源身份的文本不创建 `Expression Object`、Comment、Source Object 或 Observation 兜底；只能保持有来源位置和用途限制的未解析材料或受限 Corpus 片段候选。
55. 来源字段解析/格式转换与 AI 语义解释分开。表达簇、作者方向变化、Topic 关联、趋势和市场含义属于 Derived Analysis/Claim，不进入 Observation。
56. 正常复观测、来源陈述差异、parser 更正、来源删除、本次不可访问和隐私处置不是同一更新；不采用统一 upsert、万能冲突码或 Source Object 线性生命周期覆盖历史。
57. Evidence 没有跨用途全局可信度分数；其对 Claim 的适用性随用途、观察条件、Coverage 和判断强度重新评估。

上述决定完成 Gate 2，允许进入 Gate 3 领域模型与共同语言设计；不授权业务代码、数据库表、migration 或大规模移植。

### Gate 2 采集准入与执行边界的后续验收输入

后续 Gate 3–6 的设计至少必须能够推导并最终证明：等价需求只发生一次必要访问且保留全部来源关系；过期任务领取前重评估；有意复观测不被去重；无可用资源返回结构化原因；producer 完成但合同不成立时不生成 Evidence；插件可从服务端租约恢复；局部 Coverage 缺口只产生局部补采。任何物理设计不能削弱这些可证伪标准。

Gate 2-3 进一步要求最终证明：观察方法变化不会被伪装成单轮失败，单轮 Coverage 不足不会静默改写计划；探索/调查材料不会未经明确可比性处理直接制造趋势；有限探索不会吞掉比较性观察承诺；普通采集仍满足最低 Evidence 合同；搜索发现面不会被宣称为市场全量。

Gate 2-4 进一步要求最终证明：研究开始前能够复用已有资产；无需新增访问也可以正常结束；任何新增访问都经过统一采集准入；AI 修改假设不会静默扩大授权；研究可以以证据不足或停止结束；候选产出不会自动污染正式知识、比较性观察或现实行动；重新解释历史不会静默覆盖当时判断。

Gate 2-5 进一步要求最终证明：Topic 摘要可以下钻到可读原声、代表内容和原始 Evidence；库存增长不会被显示成市场增长；树形导航不会改写 Topic 关系；用户表达与创作者叙事不会混为同一统计单位；爆款不会自动升级为需求或机会；AI 重新分类不会覆盖历史 Topic 版本或制造趋势；Topic 详情、地图、雷达和 Corpus 不会形成互相冲突的第二份事实。

### Gate 2-6A 真相与派生边界（已确认）

Gate 2-6A 不先设计 Corpus、Topic、Insight、Intelligence、选题和 Outcome 各自的状态。经“普通评论、同一材料服务多个研究目的、合同/身份失败、假趋势、Topic 共现、选题表现”压力测试后，确认以下责任模型：

1. **发生记录：** 保存系统尝试了什么、实际返回了什么、哪里失败；不合格返回不消失，但不自动生成 Evidence/Observation。
2. **Evidence：** 保存系统在特定 producer、时间和观察条件下接纳的来源材料；它不是现实真相，也没有跨用途永久适用资格。
3. **Source Object / Observation：** 稳定来源对象独立于研究问题；Observation 只表达 Evidence 直接支持的对象状态，同一次观察可以被多个观察意图复用。
4. **Derived Analysis：** 归一化、分类、聚类、embedding、统计和 Agent 分析必须记录输入集合与方法版本；其输出默认是可重算分析或候选解释。
5. **Domain Definition：** Topic、Term、Alias 和知识性关系是当前采用的领域语言；定义发布与数据共现、市场变化、因果主张和页面导航分开治理。
6. **Claim：** 对存在、关联、变化、需求、机会或行动价值提出可争论主张；资格随强度增加，人工确认只是当前使用/发布决定。
7. **Decision / Action / Outcome Observation / Evaluation：** 选择、实际行动、结果事实和结果解释分开保存；结果不直接改写知识。
8. **应用层：** Corpus 保存可追溯选择，Topic Map/页面组织视图，CLI/Agent Interface 提供受控服务；它们跨越前七项，但不是第八套真相。

横向始终受 Identity、Time、Coverage、Version、Governance 与 Privacy 约束。这里是责任模型，不是线性流水线、数据库对象清单或“七层架构”。

对话讨论中的 `Research Intent` 被收敛为观察目的责任，不作为 Observation 身份或万能父对象；`Raw Evidence / Normalized Evidence` 不确认为两类平级 Evidence；`Topic 描述存在、Claim 描述发生` 被修正为“Topic 定义语言，Claim 提出可争论主张”；`Knowledge Layer First` 不取代已确认的领域情报研究系统定义；`Gate 3-A` 不新增为第八道 Gate，采集现实压力测试进入 Gate 4 producer 审计。外部对话的 `DEC-01`–`DEC-15` 只保留为讨论顺序，不进入项目决定编号。

退出结论：[`../../product/domain-invariants.md`](../../product/domain-invariants.md) 中的长期案例能够分别指出当前设计允许说什么、禁止说什么、后续由哪个 Gate 提供证明；用户已要求在逻辑审查后收口进入项目。物理对象、字段、关系基数、错误码和权限状态仍留给 Gate 3–6。本关未创建业务代码、数据库模型、统一 Claim 表、审批引擎或完整权限系统。

### Gate 3 前三项收口（已确认）

第一项已经把搜索/作者页等低成本发现与逐篇详情/评论采集拆开：API 返回与页面可见分别保留来源陈述，发现记录与 Source Object 去重并存，发现 N 条不自动产生 N 次深采。

第二项已经把采集发生记录、Capture Package、Evidence 接入/接受、下游身份解析、Source Object/Observation 和 Derived Analysis 拆开。V2 源码与针对性测试支持包内 Record/Artifact、canonical/hash、重放/冲突和原子接入等参考，但不证明无效原始包已持久保存、metric RawRecord、新项目评论/媒体合同或下游整包失败语义应被照搬。Attempt/Package 最小关系后来已在 Gate 4 单独审计并确认，物理实现继续进入 Gate 5–6。

第三项已经把正常复观测、迟到材料、parser/结构化修正、API/页面来源差异、Current Resolution、来源明确删除、本次不可访问和隐私处置拆开。Observation 只追加；Current 是带来源与规则的可重算读取责任而非最大时间/最后写入；执行、观察、接收、接纳、来源事件陈述和派生时间保持不同资格。V2 只证明按 `observedAt` 防倒退和同时间歧义 fail closed，不证明客户端时间、来源优先或整条 Current 指针适合新项目。

Gate 3 后三组设计均已形成、完成阶段性压力测试并于 2026-08-20 得到用户逐项确认。A 负责 Domain Definition、Topic/Term/Alias、知识关系、分类运行与 Claim；B 负责研究问题、Information Need、采集申请/授权/准入、Decision、Action 与 Outcome；C 负责 Corpus Selection、Signal、Market Insight、Intelligence Brief、Content Idea 与 Agent Answer。全部确认版本的全链压力测试已经完成，并于 2026-08-20 获用户整体确认，Gate 3 正式退出。确认快照见 [`../../audits/gate-3-domain-model-audit-2026-08-20.md`](../../audits/gate-3-domain-model-audit-2026-08-20.md)。Gate 4 现在用真实 producer/fixture 确认包头、Record、Artifact、评论身份、指标/媒体、Coverage、终态、时间和分块/重试；Gate 5 决定持久关系、Current、隔离期限和事务/修订传播。Gate 3 通过本身不授权业务代码、数据库模型、知识图谱、万能 Claim、AI Agent 或插件升级。

### Gate 2-4 分流到后续关口的强制输入

- Gate 3：统一问题、假设、判断、证据缺口、候选和正式知识的词义与状态，不把讨论用语直接变成表。
- Gate 4：只保存真实 producer 能证明的计划、执行和单条记录上下文；搜索发现必须分别核对 API 返回与页面可见，验证稳定身份、重复/冲突、顺序/终止、Coverage、风险中断和发现不自动深采；同时审计原始时间表达/来源/解析参照，区分四类身份失败。上下文不足可以限制判断，但不能抹除通过真实性合同的原始 Evidence。
- Gate 5：判断形成时决定 Evidence 是否适用于当前用途；明确观察表面、统计单位、时间精度、比较条件、Coverage 用途评估和分析输入/版本；现实、观察、解释与未知因素不强制三选一；历史重分析追加版本而不覆盖旧判断；隐私处置传播不得遗漏派生物。
- Gate 6：根据前五关合同决定 Rust 模块和运行边界，单独验收 AI Agent 和插件升级合同；不提前建立六个研究服务、通用工作流引擎或固定权限等级。
- Gate 7：根据已确认工作流设计最小研究入口和用户决策界面，不提前冻结完整研究工作区。

### Gate 2-5 分流到后续关口的强制输入

- Gate 3：先统一 Record、Evidence、Observation、Definition、分类/解释、判断、提案/决定和应用视图的词义与责任，再确定 Corpus、Term/Expression、Topic、Topic Relation、市场洞察、Intelligence Brief、Content Idea 与 Outcome 是否需要独立领域身份和状态，避免名词资产化与万能 Claim。
- Gate 4：核对评论者/作者身份、内容指标、发现入口和代表样本的真实 producer 来源；不能证明的用户角色保持未知。
- Gate 5：设计累计库存、窗口新增、可比占比、观察表面、统计单位、Topic/分析版本，以及“历史原貌”和“当前重解释”两种历史视角。
- Gate 6：决定 Topic 探索需要哪些可复算投影和查询边界，不创建 Market Atlas 微服务或让页面直接拼接数据库真相。
- Gate 7：用“任务启动困难”真实样本验证 Topic 探索顺序、可读代表材料、判断资格和动作入口，不按讨论稿直接堆叠全部模块。
