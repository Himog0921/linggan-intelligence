> 冲突时以谁为准: 用户最新确认、真实页面结果与当前运行时代码/合同

## 目标与边界

插件只执行页面事实采集、字段来源标记、数量/停止原因回执。它不分析内容、不生成关键词、不判断趋势，也不替 Linggan 决定采集对象。

本事项将“笔记详情 + 页面媒体观察 + 当前至多 30 条评论”定义为一个逻辑详情包。`30` 是该详情包的上限，不是平台总量、全量评论承诺或搜索结果上限。少于目标时必须保留实际数量和停止原因；未观察到不写成 0。

## 实施步骤

1. 固化详情包与搜索页面读取的测试合同。
   - 验证: 旧注入数据源缺失时可生成带来源标记的详情页面读取结果；空评论、少于 30、评论关系与停止原因可区分。
2. 实现详情 DOM 读取兜底和统一详情包回执。
   - 验证: 详情、媒体槽位与评论覆盖读数汇入一个逻辑结果；不得伪造 30 条完成。
3. 让任务入口使用详情包，并补齐搜索上下文回执与选择器健康检查。
   - 验证: 任务请求限制、实际已加载数量、筛选快照、下拉建议词观察和停止原因独立存在；不再把当前可见 20 条当永久规则。
4. 同步权威登记、状态和进度记录，执行回归与治理检查。
   - 验证: 相关自动测试、全插件回归、构建/治理检查分层记录；真实页面、发布、接收与业务验收不由代码检查替代。

## 明确不做

- 本次实施期间不下载媒体原件、不运行 OCR/ASR，也不实际发起 Linggan 交付或采集真实页面数据；插件在未来执行获授权任务时仍沿用既有本地暂存与交付通道。
- 不新增调度、账号管理、分析、推荐或 UI 产品能力。
- 不修复既有发布 ZIP 与构建产物漂移。
- 本次不扩大真实页面探针；非空评论页面的真实回归另行受控执行。
