# GOV-001 项目文件治理基线

> 状态: 已完成计划
> 最后核对: 2026-08-15
> 适用范围: 首次建立项目文件管理与 Agent 协作规则
> 事实来源: 用户确认的治理要求与本轮实际文件变更
> 冲突时以谁为准: `AGENTS.md` 和当前治理协议

## 目标

建立一套能长期执行的文件治理系统，使 Agent 能找到正确入口、识别文档权威性、按事项推进、处理新旧冲突，并对代码和说明变更留下可追踪记录。

## 范围

- 把文件治理写入最高约束。
- 建立文档总索引与当前状态入口。
- 定义文件分类、命名、状态、生成物、移动和归档规则。
- 定义 Agent 渐进式披露、事项状态、冲突裁定和变更同步流程。
- 建立按月变更记录和自动治理检查。

## 非目标

- 不安装 Rust 或 PostgreSQL 工具。
- 不决定本机 PostgreSQL 与容器方案。
- 不创建业务数据库模型或 migration。
- 不开始 TypeScript 到 Rust 的业务移植。
- 不改写 `references/` 中的历史材料。

## 可证伪验收

1. 任一重要文档未被总索引引用时，治理检查失败。
2. 任一重要文档缺少状态头时，治理检查失败。
3. 根目录出现未许可 Markdown 或提交危险生成目录时，治理检查失败。
4. 发生重要文件变更但没有月度变更记录时，治理检查失败。
5. 本地 Markdown 链接失效、Bootstrap 来源 checksum 变化或 Shell 语法错误时，验证失败。

## 实际交付

- `AGENTS.md`：新增最高文件治理约束和更精确的事实优先级。
- `docs/README.md`、`docs/current-state.md`：建立导航层。
- `docs/governance/`：建立文件、生成物和 Agent 协作协议。
- `docs/progress/`：建立月度变更记录。
- `scripts/check-project-governance.sh`：把关键规则变成可运行检查。

## 验证与边界

验证结果记录在 [`../../progress/2026-08.md`](../../progress/2026-08.md)。自动检查只能发现结构性漂移，不能证明文档内容真实；事实仍需代码、fixture、测试、数据库副作用和用户验收共同证明。

本地检查已通过，用户于 2026-08-15 确认方案；本计划随治理提交进入 `origin/main` 后完成团队收口。
