## 用户结果

当用户确认“准备本轮研究”后，系统应能将已冻结、可读的用户原声交给已通过校验的模型，稳定接纳结构化研究结果，并且只在没有未解决研究失败时发布可阅读的研究版本。

用户不需要理解 JSON wrapper、模型响应格式或问题归并协议。运行记录保留失败阶段和可追溯调用，研究主页面只读取已发布结果。

## 已确认事实

- 开发期 Comment Research 派生层已重置；原始评论、作品上下文、模型配置、向量配置和调用账本均被保留。
- 20 条受控首批结束为 `completed_with_failures`，未发布结果版本。
- 失败集中在模型文本和严格结构化合同之间：语义提取 3 次不可解析、1 次合同拒绝；问题归并 2 次结构不合格。
- DeepSeek Responses 在当前 Pi adapter 的官方 endpoint / 已列模型组合下已请求 `json_schema`；服务端仍是最终结构校验者。

## 实施决定

1. 研究合同升级为 `semantic.v2`，让研究指纹随着输出合同变化而改变；旧结果不会被误复用。
2. 服务端只接纳两种传输形态：完整单个 JSON，或唯一的完整 `json` fenced block。不得从说明文字、多个片段或混合回答中截取 JSON。
3. 语义提取明确要求：有信号时 `atoms` 必须非空；无信号必须显式 `no_signal`；证据坐标必须指向研究正文。
4. 问题归并明确要求：`same_problem` 只能引用模型实际收到的候选；其他情况必须返回 `new_problem`。
5. 发布门槛不变：任何不可恢复的语义或归并失败都不能形成 ResultRevision。
6. 部署后再次进行最多 20 条的受控运行。只有运行完成、无失败、结果发布且五个读视图可读取时，才讨论扩大到全量。

## 非目标

- 不删除或改写原始评论。
- 不放宽失败即不发布的结果门槛。
- 不恢复旧批次或将旧运行视作成功。
- 不开启连续自动研究，也不扩大真实模型调用规模。

## 验收

- Rust 单元测试：直接 JSON、单个完整 `json` fence、带解释 / 多包装文本的拒绝边界。
- Node adapter 测试：V2 对已合格 DeepSeek Responses 与 OpenAI Responses 仍会带结构化输出请求。
- 隔离 PostgreSQL：新的研究合同指纹不会复用 V1 结论。
- 本机运行：受控批次的真实数据库与 API 回执分开证明运行、发布和读页面；失败仍必须保持未发布。

## 停止点

若 20 条受控批次仍有合同型失败，停止全量研究，保留失败调用证据，继续只修复实际失败的合同边界；不得通过降低验证或把失败结果发布来绕过。
