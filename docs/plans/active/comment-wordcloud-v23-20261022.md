## 用户结果与不可接受的结果

- 与已认可的 V2.3 保持一致：左侧累计指标，右侧同轴评论黑柱/信号向下淡出曲线、紧凑的词云/Top10，桌面不再显示冗长的图表标题；默认近 56 天，7/28/56 和图表/表格切换保留。
- 词云来自当前领域符合原研究来源资格的真实评论，每个短语每条稳定评论仅计一次，关联来源对象可回查。原声只在现有评论详情查看；不向浏览器批量发送原文。
- 未观察、未索引、权限限制与失败不能显示为确认的 0，也不得用假高频数据补满词云；新词与类别都只是候选语言，不升级为“用户问题”或医学判断。
- 不新建数据库真相，不新增 AI 调用、自动批次、采集或外部处理；历史研究保留。

## 一份交付包、四个直接表面

1. 评论概览：累计数据、图表与词云在同一紧凑区域；在窄屏容许自然垂直展开。
2. 日期统计：两个计数序列仍拥有独立尺度，研究信号的折线及淡出填充全部位于横轴上方。
3. 高频语言：领域+首次观察时间窗+来源资格；清洗缓存只读；词语短语候选不做未经确认的同义归并。前端 Top10 与词云共用一个接口响应。
4. 评论原声：点击词语只返回最多三项稳定 commentKey，由现有详情检查身份、资格、父语境与受限状态。

## 范围、依赖与限制

- Rust 直接复用 comment_study_catalog::facts_sql() 与 CLEANER_VERSION，沿原 gate 过滤；最多处理 20,000 条，超过时 explicitly 标记 sampled，不能称完整领域统计。每条截取清洗后的前 800 个字符以限制内存和文本处理成本。
- 词云算法 v1 采用确定性的精确短语词表 + 保守汉字长度候选与最小频数，不依赖新云模型或新增 Cargo.lock 包。分类只在词表命中时给出，其余 unclassified；后续 jieba-rs 优化需独立质量评价，不能直接默认所有切词正确。
- CSS 仅沿用 LIDS Token；面包屑、四视图、评论和运行 API 仍按 React 主线；旧双轨观察图不再并行。
- 可见数值都是合格评论的本地窗口频次，不代表市场普遍性；信号时间与首次观察时间不能推断转化。
- 返回值使用现有 JSON 读取合同，同源、只读、受现有 Host/Origin 保护；缓存更新和模型调用不由 GET 隐含触发。

## 验收矩阵

- 前端：56 天默认、7/28/56 切换与真实 GET，table/plot 等高内部滚动，正文无巨大标题；选词与 Top10 联动、来源详情可回查、空/失败/部分状态。
- 后端：不同评论去重、同评论重复词不重复计数、creator 作者评论和失效来源排除、跨作品数、窗口过滤、超过上限明确标记。
- 工程：TS strict、Lint、Vitest、LIDS sync/verify；Rust compile/unit；隔离 PostgreSQL；GitHub exact-head CI 与浏览器证明。生产部署、敏感原声真实样本及用户审美签收独立验收，未获自动授权。
- 停止点：SQL 门槛与真实来源不一致、后端超时或 UI 计数被误当“需求强度”时不得合并/宣称上线。
