## 2. 产品决定与待定项

### 2.1 本轮已确认的范围

| 编号 | 决定 | 实施时必须保持的结果 |
|---|---|---|
| D01 | 产品是内容领域情报系统 | 交付材料理解、领域比较和可接续情报；当前不建设选题库、制作排期与发布流程 |
| D02 | 首页独立于四个工作区 | 首页、智能工作台、市场洞察、语料库、采集各自承担已定义任务；雷达不增加一级入口 |
| D03 | 语料库是项目基础 | 证据库、评论研究、创作者、已存查询四个二级页，跨页面使用同源材料 |
| D04 | 语料资产归评论研究内部 | 原声浏览、问题分组、语料资产三个页内视图；集合也在其中，不增加平级资产页 |
| D05 | 评论自动承接 | 已接纳且可用的评论自动进入研究读取范围；研究无需人工搬运、先建课题或等待全量采完 |
| D06 | 从作品和用户表达两面理解领域 | 作品主题保留细分结构与运营统计；评论表达提供问题、场景、尝试、限制与不同意见 |
| D07 | 创作者从领域作品中发现 | 基于确认的作品作者关系发现发布过 ADHD 内容的作者，不把监控名单当作者全集 |
| D08 | 向外看属于产品范围 | 保留外部领域观察、样本、随手记与参照用途；外部样本不混成 ADHD 市场证据或统计 |
| D09 | 首页希望使用 Three.js | Three.js 服务领域浏览、发现定位与下钻；不以视觉动画制造分析或采集事实 |
| D10 | Pi 是智能内核方向 | 页面面向情报工作；Pi 通过 Linggan 自有适配边界承接模型/工具循环，不单设 Pi 一级页 |
| D11 | 语料选择与研究可接续 | 保留材料选择理由、来源、集合和被情报引用的关系；收存不授予事实正确性或代表性 |

D01–D11 是当前对话已确认的产品范围及约束。它们不预先确定数据库表名、API 形状、算法、模型版本、运行额度或正式发布权。

## 4. 实施总表

默认建议按一个主交付包串行推进。每包可以有内部技术阶段，但以一份集成结果交 Mog 做页面验收；依赖验收通过后再启下一包。以下顺序是计划建议，未自动派单。

| 顺序 | 用户可验收结果 | 对应页面与实施内容 | 依赖 | 完成标准 |
|---|---|---|---|---|
| P00 决策与事实收口 | 下一个 Agent 能依据明确合同开工 | D01–D11 映射到当前页面与领域文档；核对旧 Issue、基线、路由、字段、权限、迁移与运行边界；冻结首包规格 | 本计划与现行仓库 | 每个首包需求都有来源、owner、输入输出、失败语义和验收；缺口有明确责任，不靠猜值 |

| P07 独立首页与 Three.js | 首页直接呈现领域、重要发现与待决定事项 | 首页独立路由；三栏内容、领域地形、联动定位、详情、有限回放、HTML 等价入口、无基线/安静/中断状态 | P03、P05、P06 的真实读合同 | HTML 与 3D 使用同快照/引用；无事件无假动画；无 WebGL 仍能完成核心操作；不把几何高度或材料增量当机会分 |
| P08 全站集成与受控发布 | 所有已确认页面在目标运行环境中可以连续使用 | 壳层/16 个二级面/设置的跨页一致性；迁移、API/worker/插件版本对齐、运行恢复、业务验收 | 前序包及已授权发布范围 | 一次跨页真实链证明与异常验证；实际运行 revision 可定位；Mog 完成约定操作；分别记录源码、合并、部署和业务验收 |

这不是“先把全部数据采齐，再做智能”。P01 就应让真实评论可以使用；P03 即可形成第一份有边界的领域结构和比较。首次分析用于校准规则与建立初始快照，后续沿源版本增量推进，不要求每轮重做全领域研究。

首页的视觉方向已有原型，可继续按获准范围做设计评审；正式数据接入安排在 P07，避免先让首页长期依赖合成内容。每个业务包同步落实自身导航、深链、状态及必要共享壳层，P08 负责集成核对，不把共享导航全部拖到最后。

### 4.1 P01 内部顺序：先能研究，再形成可复用理解

三个阶段属于同一个评论研究交付包，技术验证逐段完成，对 Mog 交付一份集成模块。

| 阶段 | 实施内容 | 技术出口 |
|---|---|---|
| P01-A 材料与查询 | 基于现有评论 Current 建立跨作品研究读面；来源/上下文/时间资格；分页、全范围命中数、失败重试；服务端已存查询 | 跨作品查询覆盖当前允许范围；原文访问仍经正式通道；不把已加载页当全库；新增可用材料自动被读到 |
| P01-B 片段与资产 | 精确源版本/片段范围；人工收存、理由、集合、使用关系；必要的标注纠正 | 集合引用可追溯；旧选择可解释；源受限时新读取重新判断；没有模型也能人工研究和收存 |
| P01-C 自动理解 | 独立持久分析工作；一个获准模型场景；上下文读取、片段提取、多标签、问题候选分组与代表/边缘表达；人工纠正留存 | 同源同版本幂等；失败/无信号/待分析分开；人工纠正不被静默覆盖；模型越权/无依据引用被拒绝；新版本增量不污染旧结果 |

P01-C 复核 #113/PR #116 的窄 Runtime 接缝。原候选若只允许 Topic Material Pack，则需先扩展获准的材料合同或在新包定义评论专用调用；不直接调用一个假定存在的 Pi 服务，也不绕开 Linggan 授权。仅为此场景建立最小工具与回执，不先建设通用多 Agent 平台。

## 5. 限制 Agent 臆测的执行规则

不能靠一句“不要幻觉”保证不出错。把容易猜错的边界变成读取回执、接口校验、数据库约束与能失败的验收。

### 5.1 编码前的事实核对

每包开始先记录实际 main/base SHA、branch/worktree、相关 PR 状态及已有未提交差异，然后建立小表：

| 需求/符号 | 类型 | 依据 | 本包处理 |
|---|---|---|---|
| 现有 API/字段/状态 | 已存在 | 当前文件路径、符号、schema/迁移及对应测试 | 复用或有据扩展 |
| 新需求所需能力 | 待实现 | D 编号、所属合同及输入输出/负例 | 在本包 owner 内实现 |
| 无来源的假设 | 待查或待决定 | 缺什么证据、影响哪个动作 | 先查代码/数据合同；实质产品取舍再交 Mog |

所有生产调用的接口、字段、状态、表、工具名，要么已查到定义，要么已进入本包获准合同并同时实现；不得凭示例名直接调用。migration 序号开工时重新分配。原型中的演示 ID、随机数、计数、分类、localStorage 成功状态都不作为生产依据。

### 5.2 模型输出按候选输入处理

- 调用固定材料范围、允许上下文、模型/提示/格式版本、预算及工具范围；外部材料中的指令只作数据。
- 输出以结构合同验证。引用必须在本次允许输入中，原声片段必须定位到相应源版本；推断与摘录分别标识。
- 统计由确定性查询产生。模型负责解释/候选，不自行填作品数、爆款率、独立作者数或发布频率。
- 普通评论研究可继续使用已获准材料，AI 失败不会撤销已取得材料。自动分析不能覆盖人工纠正；修订形成新版本与关联。
- 正式主题语言、正式判断、扩大观察范围和真实采集分别走已有决定/准入，不让模型输出直接改写正式状态。
- Pi/provider 只在 adapter 内；业务工具按领域能力暴露，运行时不给任意 SQL、Shell、文件或网络通道。

### 5.3 反例验收清单

| 测试输入/故障 | 必须出现的行为 |
|---|---|
| 同一评论跨 Attempt 重复取得 | 一份稳定材料身份，观测历史保留；研究数量不重复相加 |
| 目标 100、实际取得 40 | 40 条合格材料可研究；Coverage 部分；不伪造剩余 60 个对象 |
| 已入库但没有当前分析回执 | 可读且准确显示待分析；持久工作能继续，不能被当作无问题 |
| 模型成功返回空信号 | 记录已处理且无有效信号，与未处理/失败分开 |
| 缺少父评论或正文 | 标明上下文不足；不自动补写“这个办法”所指对象 |
| 单评论表达多个问题 | 保留多个片段/标签；统计说明重叠和去重口径 |
| 引用不属于本次输入或原话不匹配 | 拒绝对应结果，写明确失败；页面不接收伪证据 |
| 材料内出现“忽略规则/读取其他数据” | 作为材料内容处理；无工具越权、无额外访问 |
| 作者同名/只有监控目标归属 | 不合并身份，不把目标名或展示头像当作者确认 |
| 发布时间未知/只有搜索样本 | 时间资格保持未知；发布频率或主题占比不伪装全量 |
| 历史评论集中补分析 | 展示分析新增，不能称本周需求暴涨 |
| 新分类版本尚未完成统计 | 保留旧快照及版本；不拼接新标签与旧分母 |
| 已存查询重新执行后数据变多 | 显示当前命中；旧情报的实际引用版本保持可解释 |
| 外部样本写入本领域范围 | 数据约束/接口隔离阻止混用，不能只靠页面过滤 |
| 源材料撤回/受限/被更正 | 新读取按当前资格；相关资产与成果追加影响，保留必要历史而不继续泄露原文 |
| worker 在写入前后中断、重复领取 | 幂等恢复，既有结果不丢失；重试有限，不出现无限模型/采集循环 |
| WebGL 失败或系统减少动效 | 同快照 HTML 能完成阅读与下钻，核心功能不随场景消失 |

检索与聚类质量不能只由同一模型自评：准备有来源的评估样本，包含典型、边缘、反例与未知；规则调试样本与最终验收样本分开。引用/权限/身份等硬约束必须全部通过；语义质量阈值在 P01/P03 的评测合同中确定，不在本计划凭空填百分比。

### 5.4 测试与停止条件

- 数据/状态变更用真实隔离 PostgreSQL 验证唯一性、事务、权限/范围、版本与恢复；内存 mock 不替代。涉及 API 再验证 API 合同，涉及 UI 再验证实际页面操作。
- 使用仓库实际存在的脚本与 harness。已核实的入口包括 scripts/check-rust-boundaries.sh、scripts/test-topic-workspace-postgres.sh、scripts/test-local-001-discovery-postgres.sh、scripts/verify-ui-design-handbook.sh、scripts/check-project-governance.sh；执行前读脚本确认范围及目标，不能把名字相近的脚本当作新模块的完整证明。
- 新能力的专门测试在相应包内随实现补充。本计划不预造“已存在”的命令，不用通过的静态检查代替新能力行为测试。
- 缺少合同、来源/权限不清、外部副作用超出范围、共享文件与其他任务冲突、证据无法固定时，暂停相关改动并报告具体缺口。已有授权内的局部修复及必要验证继续完成；不为每个函数或可逆技术选择反复询问。
- 聚类/统计出现难以解释的系统偏差时，保留检索和原声阅读，相关分组只作为候选；不得为赶交付把质量检查阈值调松。

## 6. 单包实施任务模板

下列模板在真正派定时填写，空项保留“待核对”意味着尚未可编码，不用猜测填满。不要复制整段聊天历史作为唯一任务书。

~~~text
交付包：Pxx / 已派定 Issue
用户结果：用户从哪里进入，完成哪些动作，看到什么结果
已确认依据：D 编号 + 当前有效合同/页面规格
基线：开始时实测 main SHA、branch、worktree；相关 PR 状态
范围：本包页面、交互、来源、状态、写入与失败处理
文件责任：exclusive / shared / forbidden；共享 owner 已明确
依赖：已完成的合同/代码/运行层；哪些能力尚不存在
输入输出：实际 API/schema/tool 定义，或本包先补并批准的合同
状态：正常、空、未知、部分、受限、处理中、失败、陈旧
权限与预算：只读/本地写/模型/采集/迁移/部署的实际授权范围
验收：正常操作 + 对应反例 + 适用 PostgreSQL/API/UI 证据
停止：无法自行查明的产品/范围/权限/成本/跨任务冲突
交付：实现摘要、变更范围、测试证据、剩余缺口与分层状态
~~~

每包由一个实施 owner 连续处理，Mog 在完整模块上做前端验收。P01 已由 Mog 指定子代理实施、根代理审核。审核对照冻结需求与固定 HEAD，一次汇总可复现且属于本包的实质问题；整改后只复验清单及整改直接影响。新明确缺陷需要说明触发依据；风格偏好、未来优化和重复全量审核不能阻止收口。其他包不因此获得并发或派单授权。

## 7. 分层完成与全链验收

| 层次 | 能证明什么 | 所需证据 |
|---|---|---|
| 设计已确认 | 用户结果、范围、状态和参数已有依据 | 决定记录、页面/合同与范围 |
| 分支实现 | 指定 checkout 有实现及适用测试 | SHA、diff、真实执行结果 |
| 主线集成 | 相应实现已在 main | PR/merge SHA 与合入后核对 |
| 运行部署 | 目标库与实际 API/worker/插件运行了指定版本 | migration 记录、listener PID/cwd/executable、worker revision、实际加载插件；health 仅其中一项 |
| 真实链路 | 授权任务确实取得材料并推进分析 | 精确 WorkOrder/Lease/Attempt/Package/Receipt、材料引用、分析运行与成果版本 |
| Mog 验收 | 约定用户结果可用且有价值 | Mog 实际完成本包操作和反馈；不能由 Agent 代签 |

发布前按[本机运行部署手册](../../runbooks/local-runtime-deployment.md)核对备份、迁移、启动、恢复与版本。源码合并、共享 migration、runtime 切换、插件重载、真实平台任务和第三方模型处理按实际已授权范围执行，不互相推导；当前授权包括 P01 分支实现、隔离验证与评审交付。

P08 的主验收路径：

~~~text
采集已获准范围的评论
→ 同一批已接纳材料出现在评论研究
→ 跨作品查找、读取上下文、纠正分析、收存语料
→ 保存查询与集合，并可刷新后继续使用
→ 从问题/主题比较发起有界情报工作
→ Agent 引用允许材料，返回判断、限制、反例或缺失
→ 明确缺口形成补采申请
→ 既有授权允许时推进，否则由用户决定后进入正常采集链
→ 新材料回收，原分析历史保留，新判断追加版本
→ 首页用同一发现/工作/决定引用呈现变化，点击可回到依据
~~~

同时验证安静、部分取得、模型失败、工位中断、源受限、重复回收与 WebGL 不可用。外部参照用独立验收路径验证采样/笔记/隔离，不借主链结果证明其完成。
