## 1. 本手册的目标与状态

用户应能从已入库材料看到有依据、边界清楚的主题方向，查看作者内容和读者讨论，理解场景及旅程覆盖，形成具体选题并交给运营、创作。

2026-11-11 Mog 已授权推进代码、功能与上线实施，目标为高质量自动化主题图谱。优先实现真实链路，不增设人工日常审批、过度防御或前端描述性内容；不确定接点优先由 subagent 取证。实际模型用量与运行环境按现有配置和具体发布范围执行。已确认规则写入本手册；第 4 节记录 D01 的用户决定及理由。

当前实施手册已纳入 D01=B，作为后续开发依据；计划定稿不代表业务代码已经实现或部署。

**与上一份审查的关键调整：** 接入路线应优先复用统一理解的 Core，不再把“先启用旧四阶段、重读一批原材料”作为默认第一步。旧四阶段的执行器、任务与来源能力可以复用；其输入与方法是否继续适用，必须按新的消费合同适配，不能复制另一套基础理解。PR #572 的 L2 不需要成为所有主题材料的前置条件。

## 3. 目标分工：谁理解，谁归并，谁经营

```text
原生文字 / 图片 / 已有视频文字
          ↓ L0 就绪
     L1 Core + 来源证据 ─────→ 原研究底稿 / Content Card
          ↓                         ↑
          │                 按人工问题追加 L2 Deep
          ↓
主题消费适配 → 自动跨篇归并与方向发现 → 可直接浏览的主题图谱
                                         ↓
                                   场景、旅程、内容格局
                                         ↓
                                   具体选题 → 运营 → 创作
                                         ↑
语料库评论研究 → 评论原声 / 需求 / 反馈（独立来源）
              └→ 挂靠已有主题；未匹配保留，不创建方向
```

### 已确定，不需重复选择

1. L1 不按热度准入，评论和互动量不写入作者内容事实。作者、被引用者与评论者不能混为同一说话人。
2. Core 的 `mainTopicUnitId` 是这篇的主要议题，`candidateLabels` 是候选标签；二者都不直接变成正式主题。
3. 主题负责可经营的方向，具体标题选题归运营；保留全域概览、内容格局、来源、我方对照与五阶段旅程。不能以新主任务为由删除已确认功能。
4. 初始方向、新方向发现和日常材料归属由系统自动完成，结果直接可用，不设置逐条人工确认。约 20–40 个仅为历史规模参考，不是数量目标。人工用于纠偏及主动调整方向；大范围合并、拆分已有主题结构另行明确影响，不阻断日常归并。
5. 一篇可支持多个方向，但每个归属要有具体单元或原声支持。跨主题材料数可重叠，全领域作品数按作品去重。
6. 不要求每篇做 L2 才能进入图谱。人工问题相关的 Deep 可用于深入比较，不能把一次单篇发现推广成整个领域结论。
7. 基础理解有缺口时，原材料继续可读；没有合格 Core 的材料不能伪装成已理解或从总体悄悄消失。
8. 沿用中立概括、默认 high、保留来源与关键条件的既有决定。不新增真实性审计、泛化机器警告或每段原件入口；可定位依据沿现有阅读路径按需查看。
9. 互动表现用于找参考，不能证明方法有效或因果；我方阅读量和外部点赞分开。新增研究不自动授予无限模型调用。

## 4. 已确认的产品决定

### D01：只有评论提出的问题，能否独立成为新方向候选？

**状态：CONFIRMED_B。确认日期：2026-11-11。**

Mog 明确回复：“B，因为语料库的评论研究在做用户评论的研究”。

**决定：** 首版主题目录由作者内容建立。用户评论的需求、问题和反馈研究由语料库评论研究负责；主题图谱复用已有结果，不另建独立的评论需求发现通道。评论可以挂靠已有方向、保留阅读与具体选题用途；未匹配评论继续保留，不独立提出一级或子级主题候选。

此次决定明确了两个模块的职责边界，选择依据是语料库已有评论研究职责。以下方案对比保留为决策背景，A 未采用。

| 方案 | 用户会得到什么 | 代价与限制 |
|---|---|---|
| A：作者内容和评论都可提出候选，分别标明来源（未采用） | 同时看见“已有内容在讲什么”与“读者还在问什么”；尚无笔记回应的需求也可被发现 | 首版需要评论需求召回、父笔记上下文、去重和独立计数；主题质量验收范围更大 |
| B（已确认）：首版由作者内容建立方向，评论只挂靠已有方向 | 更快验证 Core 到稳定目录；评论阅读、已有研究和具体选题来源仍保留 | 评论中的新需求不能独立推动目录，未匹配评论需保留，不得强塞到已有方向 |

A/B 仅比较主题来源，不决定审批流程。按用户最新决定，B 下的主题发现与归并自动生效；不新增全量评论采集，不把评论条数当人数。

**实施约束：** 候选方向必须有作者内容的 Core 单元依据；仅评论支持的需求不能进入新方向候选，也不能经评论摘要、标签或研究结论间接进入候选。评论变化只影响评论研究、已有方向的评论挂靠与选题材料，不触发新方向创建或作者内容归属重判。不删除评论能力，不承诺后续自动改为 A。

其他尚未知但不应转嫁给用户的技术问题：当前库的 L0/Core 覆盖、批量读成本、旧主题结果兼容方式、存量索引与事务影响。由 Agent 调查或做最小隔离实验后提出实现；不要让 Mog 选择数据库表或消息队列。

## 5. 主题消费合同：先读已有理解，再做跨篇判断

以下是最小责任要求，具体 DTO、表结构和 API 命名在 owning code 中确定，不在本手册虚构已经存在的接口。

### 5.1 输入和引用

| 输入 | 用途 | 必须保留的限制 |
|---|---|---|
| Core 的摘要、主要议题、知识单元 | 召回相近材料、比较共同问题与差异 | 引用至少绑定作品、Core 版本、单元 ID；单元 ID 仅在本卡内有效 |
| 受众、处境、供给价值与候选标签 | 帮助细分方向、筛选材料 | 候选标签是提示；不凭受众标签推断作者身份或诊断 |
| Core evidence | 支持具体主题归属和判断 | 文字引句与图片观察保留不同来源性质，不跨篇串用局部 ID |
| Deep（有且相关时） | 支持具体研究问题的深入比较 | 保留原问题、Core、Deep 版本及领域；不是基础分类必需输入 |
| 评论原声与已有研究 | 解释读者困难、需求、反馈及争议 | 保留评论与父笔记关系、说话人、范围和版本；按 D01=B 仅挂靠已有主题或支持具体选题，不独立提出方向 |
| 发布/互动数据 | 表现、时间和我方覆盖 | 不混入 Core 事实；数字变化不重跑正文理解 |

PR #572 的 `latest` 读取每次会复核当前来源，并只返回该 Core/领域下最新 Deep。图谱不能对数千篇逐个调用此接口并把返回的最新 Deep 拼作同一次研究。需要领域范围批量读取/快照能力，并显式绑定所消费版本；保存的历史 Deep 不等于当前读取已经提供多问题全量视图。

### 5.2 跨篇输出

一个候选方向至少要让人看懂：名称、定义、包括/不包括什么、支持作品及具体单元、差异或边界材料、为什么值得单独成方向、与现有方向的关系。不存在的反例留空，不强制模型编造。

归属结论需要能够区分：主要涉及、次要涉及、材料不足/不确定；实际枚举应与现有裁定合同对齐后确定，不为本手册另起冲突状态。不要把全文仅出现一次关键词视作明确归属。

目录继续使用既有主题身份与定义版本。系统自动发现新方向并归并材料，保留判断依据；用户可以纠正归属和调整命名。整棵树的批量重命名、合并和拆分属于结构调整，需单独明确影响与规则，不作为日常自动归并的审批门槛。

### 5.3 版本与增量

- 互动数字更新：刷新统计，不生成新 Core 或主题判断。
- 只有评论变化：更新评论研究/需求、已有方向的评论挂靠及选题材料，不重跑作者 Core，不触发新方向创建或作者内容归属重判。
- 材料内容或来源资格变化：先判断原 Core 是否仍合格；需要新理解的只处理受影响作品。不能显示已撤回的旧内容。
- 主题定义变化：按影响范围重新判断相关归属，不重做无变化的基础理解；保留历史与人工裁定来源。
- Core 更新：旧主题结果保留历史，但不能悄悄冒充新快照已覆盖。重算范围和未完成状态可见。
- 模型配置变化但方法未换：当前 L1 逻辑身份不保证自动重跑；实施时明确方法版本策略，不能靠改配置制造“最新理解”。

## 6. 页面能力与完整验收范围

| 表面 | 必须完成的用户行为 | 数据依赖 |
|---|---|---|
| 全域/主题概览 | 看范围、统计、研究覆盖和下一步；切换领域/筛选可恢复 | 全量统计与分页材料分离；未知不写零 |
| 主题目录 | 自动从无目录开始建立；查看归并依据、可选纠偏，合并拆分前看影响 | 跨篇候选、正式定义、材料归属与版本 |
| 材料与讨论 | 搜索/筛选/选中，阅读已有底稿与评论，理解当前研究状态 | Core/原材料/评论独立读取；不另存第二底稿 |
| 研究面板 | 显示准备度、明确选择范围、提交回执、进度、失败/未知恢复 | 既有 AI 执行器；消费规则及独立配置 |
| 内容格局 | 读到场景、问题、方法、讲法与差异，并能定位依据 | Core 各类知识单元；按需 Deep；不能硬映射未知讲法 |
| 来源与表现 | 比较来源、时间和单项互动；未知作者/粉丝明确 | 共享来源统计；规则与经营口径统一 |
| 五阶段旅程及矩阵 | 概览/主题交叉、阶段下钻；区分已分析、未分析、阶段不明 | 需要显式旅程判断；不能用 contentType 或标签字符串直接猜阶段 |
| 我方对照与再做 | 我方发布覆盖、外部近期参考、旧方向新切入 | 运营账号/发布事实与采集作品的映射；草稿不算发布 |
| 备选与选题交接 | 从有依据的角度进入运营，查看已创建选题与创作引用 | 运营选题实体、去重、来源快照和真实回执 |

原有页面审查的选材长列表、手动刷新链、关闭丢失请求身份、失败原因缺失、加载波动仍应修复。默认只验证桌面；不因为手册模板额外要求手机验收。

## 7. 开发顺序与可独立交付包

### 包 0：接入准备与依赖盘点

- 固定基线，确认 #572 实际部署与配置，读取目标领域 L0/Core/Deep 覆盖及失败原因，只读。
- 按已确认 D01=B 登记来源资格与版本消费方式；核对正在推进的统一理解分支，双方文件所有权不交叉覆盖。
- 将数据量、缺失分布、慢读取与现有用户路径形成一个可复查的截面。无需重跑二十篇或重开已冻结问题。

收口：实现团队知道“哪些材料有可用 Core、缺的是什么、如何读取、哪些字段能用”。没有新 Core 也不伪造，但可以使用已有冻结结果做隔离开发。

### 包 1：Core 消费与页面可操作性

- 提供图谱范围的合格 Core/知识单元读取与版本绑定；按需读取，避免每篇一个完整来源重建请求。
- 页面显示材料准备、已理解、已入图谱三个不同进度；补搜索分页选材、固定操作区与可恢复任务。
- 首屏统计、材料页、来源视图分开读取。先测失效与重建，再做有证据的优化，不新建一套缓存权威。

收口：已有 Core 在图谱被真实消费；引用能回同一底稿；缺失和失效不混成空库；不触发隐式模型调用。

### 包 2：自动主题发现与归属的纵向链路

- 用范围明确的现有 Core 召回和比较，产生少量方向候选及边界，沿现有主题定义/绑定/影响预览保存。
- 按 D01=B 只从作者内容 Core 提出方向，评论研究复用语料库结果；未匹配评论保留，不丢弃或硬归。验证仅评论提出的问题不会创建方向，也不会改变作者内容归属。
- 调整现有研究方法与输入，使跨篇比较承担图谱独有任务；避免继续执行同内容的第二次单篇基础理解。新旧方法版本、迁移读取和停止新旧重复任务需要专项验证。
- 跑完自动提出→目录显示→查看依据/可选修正→新材料自动归属的真实链路，不将人工审批插入日常处理。

收口：Mog 认可一组方向有意义、边界清楚，材料归属与遗漏可解释；不能只以 JSON 合法、任务成功或主题数达到 20 为通过。另验收评论挂靠有依据、未匹配评论可回看、评论选题来源保留，以及仅评论变化不会新增方向。

### 包 3：研究视图与经营交接

## 8. 核心质量怎么评价

最重要的是主题发现与归属效果；上游 L1 正确是必要基础，不能替代跨篇效果。

| 质量维度 | 验收对象 | 不能替代的证据 |
|---|---|---|
| 方向意义 | 整组候选是否能帮助选择长期经营方向 | 不能用名称好听、标签数多代替 |
| 区分与边界 | 相邻方向为何分开；代表材料和边界材料如何处理 | 不能仅抽查最容易匹配的正例 |
| 归属忠实 | 作品/单元/评论是否真支持对应方向 | 引用 ID 存在不等于语义支持 |
| 遗漏与覆盖 | 未归入的相关材料、长尾和新问题 | 不把低赞、无 Deep 或材料缺失排除后隐瞒 |
| 稳定与演化 | 增加新材料后是否保留合理目录；何时提出调整 | 不为保持稳定强行塞入旧主题 |
| 决策用途 | 能否从方向看到问题、已有回答、差异与下一步选题 | 不能把高赞统计当因果结论 |

抽样先说明总体、时间、领域、Core 覆盖和排除项。用随机材料判断普遍性，另用跨主题、仅评论需求、来源受限、低互动、图片主导、视频文字等难例做回归。不要只用原二十篇判断整个 ADHD 方向体系，也不机械要求固定准确率。

工程校验包括：跨篇局部 ID 不串用、重复请求、失效来源、历史读取、部分失败、关闭重开、取消、选题去重。重要内容错误先定位是 L1 遗漏、消费丢失、跨篇归并错误、归属错误还是展示问题；下游能修复的不默认重跑上游。
