## 1. 目标与已定决定

**终点**：所有正式网页由同一个 React + TypeScript 应用提供；仓库里不再有 Rust 拼接的页面 HTML 和原生页面脚本；迁移过程中，主线上任何页面都只有一套实现。

Mog 2026-10-15 的决定（长期部分见 DEC-0010）：

| 编号 | 决定 |
|---|---|
| D1 | 技术栈：React + TypeScript（`strict`）+ Vite，由 Axum 同源提供；不用 Next.js、服务端渲染框架、额外 Node 服务、BFF、微前端或 iframe |
| D2 | 现有 16 个页面全部迁移，包括采集、工位、运营台账、设置和登录；新页面一律用 React |
| D3 | 不留双轨：页面切换的同一 PR 删除旧实现；不设新旧开关；迁移期间旧页面冻结；终态由 CI 防止旧写法回流 |
| D4 | 开发期数据不构成迁移约束：可以调整接口与读模型，不做新旧逐项等价证明，也不做旧书签兼容；迁移本身不删数据 |
| D5 | 内容工作台（#425）的前端暂停，在本计划阶段 C 用 React 实现；后端照常推进 |
| D6 | UI 改版专项并入本计划；本计划是网页改版与迁移的唯一推进入口 |

不变的边界：业务判断、资格、授权、幂等和操作回执仍由 Rust/PostgreSQL 负责；浏览器插件与 Pi Adapter 不迁移；LIDS 仍是唯一设计标准。

## 2. 用户结果（来自 UI 改版专项）

主要使用者是 Mog，个人高频使用；运营团队现有能力继续保留。首批产品交付的主产出是图文笔记，效果看我方发布后的阅读量。

核心路径：**每日选题 → 研究与取材 → 正文创作 → 封面与内页制作 → 成品预览与导出 → 发布后复盘**。

- 每天至少获得 10 个可进入制作的完整选题方案：角度、依据、提纲和素材。相同角度只换标题不重复计数；供给不足时如实展示并指出缺口。
- 正文、封面与全部内页图片在 Intelligence 内完成，导出后即可发布。
- 创作过程沉浸、简洁、美观；有明确的编辑中心，辅助信息按需展开，保存、恢复与版本可靠。
- 较低频地完成下周选题规划，研究领域变化、新发现作者、高表现作品和用户讨论。
- 采集、语料、主题图谱流畅、严密，路径清楚。
- 核心方法、提示词和 Skill 可见、可迭代，有版本、比较和回退记录。
- 视觉、导航和工作流程允许重新梳理；新方向在代表页面验证后统一修订 LIDS，不另建并行设计标准。

**与 DEC-0009 的关系**：[DEC-0009](../../decisions/0009-stage-one-job-topic-pool.md) 的业务对象、我方/外部表现口径和既有运营数据责任继续作为基础。本专项扩展了 Mog 的个人每日使用与正文/封面/内页制作，取代 DEC-0009「本阶段不做写作与改编」对本专项的限制。每日 ≥10 个方案与运营团队产能不是同一计量范围。

**迁移与改版的关系**：每个页面在迁移那一次就按已确认的新设计实现，不先原样搬过去、再改一遍。尚未确认的产品改版（例如 2026-10-14 JTBD 讨论中的候选卡、讲法卡、月度简报）不由迁移替产品做决定；它们确定后直接在 React 上实现。

## 4. 目标技术架构

### 4.1 选型

| 层 | 选择 | 约束 |
|---|---|---|
| 应用 | React + TypeScript（`strict`） | 一个 React Root，按路由划分业务 |
| 构建 | Vite；Node 版本按根目录 `.nvmrc`（当前 24.13.0） | `npm ci` + lockfile；产物带内容 hash；具体依赖版本在阶段 B 实测后锁定 |
| 路由 | React Router | 路径沿用现有命名（没有理由不改名）；浏览器前进后退恢复真实状态 |
| 服务器数据 | TanStack Query | 读取、取消、刷新；切换范围时取消旧请求；缓存不当作新事实 |
| 局部状态 | React state、少量 Context | 不建全站万能 Store；出现第二个真实场景再评估 Zustand |
| 表格 | 语义 `<table>`；需要时 TanStack Table；长列表按需虚拟化 | 排序与分页以服务端完整范围为准 |
| 图形 | 现有主题图谱、Canvas、Three.js 绘制逻辑以适配器纳入 React 生命周期 | 不借迁移重写绘图算法 |
| 样式 | LIDS `--lgi-*` + CSS Modules | 不引入 Tailwind、第二套 Token 或 shadcn 视觉源 |
| 接口 | 现有 Rust/Axum `/api/*`；缺的补窄读接口 | 不把 SQL 搬到 TypeScript，不建 BFF |
| 测试 | `tsc` + Vitest + Playwright（真实 Axum + 隔离 PostgreSQL）+ 既有 Rust/PG 测试 | 针对旧 DOM 的测试随旧代码一起改写（R5） |

### 4.2 目录

只建真正用到的部分，不预建空组件、分层脚手架或独立 npm 包。`packages/ui` 在出现第二个正式消费应用之前不建。

```text
apps/web/
  package.json  package-lock.json  tsconfig.json  vite.config.ts  index.html
  src/
    main.tsx
    app/        App.tsx  routes.tsx  AppShell.tsx
    styles/     LIDS Token 的构建期副本（不可手改）
    ui/         经两个以上真实使用处验证的基础组件
    shared/     api.ts  navigation.ts  formatting.ts
    pages/      settings/ corpus/ ops/ topics/ collection/ workbench/ login/
    test/       fixtures/（合成或脱敏）  e2e/
```

### 4.3 Axum 与页面的分工

- Axum 只对已登记的页面路径返回 React 入口 HTML；`/api/*`、资源、下载和健康检查保持精确路由；未知路径继续 404；不使用全局兜底路由。
- React 静态产物用专用前缀（例如 `/ui-assets/`），与现有 `/assets/*` 和媒体端点分开。带 hash 的文件可以长缓存，入口 HTML 不缓存。
- 同源访问。开发时 Vite 代理到 Axum 只能放行本机可信代理，不为方便而放宽 Host/Origin 校验。

### 4.4 数据、状态与回执

- URL 只放标识和可公开的筛选值（领域、搜索、页码、选中对象引用），原声和研究正文不进 URL。
- 原声、作品、研究结果、采集状态以服务器为准。含原声的查询结果不写入 localStorage、IndexedDB 或 sessionStorage；切换领域时不拿上一个领域的数据占位。
- 写操作（研究启动与停止、采集启停、目标保存、作品保存等）只在服务器回执后显示成功。网络中断时先按原请求身份查询结果，再决定是否重试，不能产生第二次真实动作。不做乐观更新。
- 打开页面、Effect、预加载和重试都不得自动触发模型调用、平台采集或付费动作；React StrictMode 下重复执行的 Effect 不得产生重复命令。
- 不允许的状态偷换：unknown 不等于 0；partial 不等于 invalid；已提交不等于已接纳；批次完成不等于归并完成；来源受限不等于删除；人工填报的阅读量不等于平台核实数据。
- API 客户端只负责：同源请求、内容类型校验、取消、错误规范化、请求身份透传、分页游标编码、回执身份校验。禁止：把非 200 变成空数组；把 `null` 变成 0；POST 自动重试并换新幂等键；在客户端猜权限；出错时自选默认领域。
- 页面所需字段若只存在于旧的 Rust 拼接 HTML 中、没有 JSON 接口，在原 Rust 读所有者上补一个窄读投影，写明字段来源、`asOf` 与错误语义。

### 4.5 LIDS 与组件

- **Token 唯一数值源**：迁移期仍是 `apps/web/src/styles/lids_tokens.css`。React 构建时引用它的副本，CI 校验名称与数值一致。阶段 H 决定最终位置，并同步插件构建与 Rust Token 测试（插件的 `popup.html` 目前也加载它的构建副本）。
- **两层组件**：基础组件（`Button`、`StatusText`、`Dialog`、`Drawer`、`FilterBar`、`DataTable`、`Pagination`、`SearchField`、`EmptyState`、`Readout`、`EvidenceQuote`、`Surface`、`ActionFeedback`）新增前至少要有两个真实使用处；业务组件（`ProblemCard`、`WorkCoverCard`、`CreatorRow`、`StudyRunRow`、`StationStatus` 等）放在所属页面目录，不抽象成万能卡片。
- 每个组件连同交互状态、允许的 props、极端数据示例和测试一起交付。
- **表达规则**：Sans 用于系统语义；Mono 只用于 ID、数字和技术状态；Serif 只用于真实原声，AI 摘要不能装成带引号的原话。作品封面按 3:4 完整显示（contain），不裁切。状态用文字、符号和颜色共同表达。遵守 `prefers-reduced-motion`，不做 hover 上浮。
- **视口与可访问性**：1440、1024、390 像素和 200% 缩放；键盘操作、Esc、焦点恢复、读屏标签。

### 4.6 构建、部署与回退

- `scripts/runtime/sync.sh` 增加 Web 构建阶段：`npm ci`（锁定）→ 类型检查 → 构建。同一 revision 的 API 与前端产物一起切换；构建失败就拒绝切换，不能静默跳过。
- Node 定位沿用 `scripts/runtime/launch.sh` 的现有做法：按 `.nvmrc` 解析固定的 node 路径，不依赖 launchd 的 PATH；安装方式参照 `prepare-pi-adapter.sh`。Web 与 Pi Adapter 的依赖各用独立的 lockfile。
- 离线重启时直接复用已构建 revision 的产物，不要求每次联网安装。
- 产物位置登记到 [generated-artifacts-registry](../../governance/generated-artifacts-registry.md)，dist 不提交进 Git。
- 回退以整个 revision 为单位（API 与前端一起），不保留旧页面路由作为回退手段（D3）。
- `/health` 或现有诊断能读出前端产物对应的 revision，便于核对 UI 与 API 是否同版本。

### 4.7 安全与隐私

- 用户内容只通过 React 文本节点渲染，不对不可信内容使用 `dangerouslySetInnerHTML`。
- SQL、DSN、Cookie、模型凭据和未脱敏原文不进浏览器存储、控制台、测试快照或 CI 产物；测试与截图使用合成或脱敏数据。
- 保留现有 `Cache-Control`、`X-Content-Type-Options`、CSP 与 Origin 处理；为 SPA 调整 CSP 时只做必要的最小放开。
- `/login` 仍是开发入口，不创建会话；正式登录与权限另行立项，前端路由隐藏不能代替服务器授权。

## 5. 不留双轨的执行规则

| 编号 | 规则 |
|---|---|
| R1 冻结 | 本计划生效起，旧页面（Rust 拼接 HTML、原生 JS/CSS/HTML）只允许修复阻断使用的缺陷：不加功能、不改版、不新增原生页面文件。Rust 侧的接口与业务逻辑不受冻结影响 |
| R2 整页切换 | 一个页面（或共用状态的一组页面，如评论研究四视图）一次切换。React 版合入的同一 PR 删除旧实现：Rust 视图函数与页面路由处理、页面 `.html/.js/.css`、只服务旧页面的表单处理和旧 DOM 测试 |
| R3 不留开关 | 不设新旧切换开关、灰度参数或长期预览路由；开发期预览只存在于 PR 分支 |

**制作规则**：

- 正文：标题、提纲和连续正文是编辑中心，出处按需展开。引用原话与自己的表达保持不同身份。支持中文输入法、粘贴、撤销/重做、选段改写；不能用固定字符切片或整篇覆盖来实现采用。
- 封面：标题、副标题、模板、配色、主图、裁切和对齐可编辑；从正文标题带入时有预览和撤销，不强制长期同步；预览显示完整画幅和实际字形，不能静默缩字或裁掉文案。
- 内页：最小模板家族覆盖观点、原声、步骤三类，内容与版式分开保存；超长内容提示拆页，由作者确认；正文后来修改时只提示相关页，不自动覆盖。
- 图片资产：本机自有图片上传后登记哈希、尺寸和用途，可裁切、替换；阅读原图与作品图片分别登记用途。
- **渲染**（取代原 §10.6 的原生 JS 建议）：一个正式模板渲染模块同时服务预览与导出，按目标像素绘制，预览只缩放；字体与资源加载完成后再渲染；记录渲染器、模板和字体的版本。该模块是独立的 TypeScript 模块，由 React 组件调用。
- 导出：先等服务端保存回执并冻结快照，再渲染该快照；每页按页 ID 和哈希登记到导出记录，服务端核对数量、尺寸与完整性后打包。中断可以重试，已有正文和图页不回滚；成功的包可以再次下载；内容改动产生新版本，不覆盖已导出的旧文件。
- 默认发布包：`正文.txt`（标题、正文、作者确认的标签）、`01-封面.png`、按顺序命名的内页 PNG。来源清单、原声和模型上下文留在内部作品记录里，不混进默认发布文件。

## 9. 完成定义

- **架构**：所有正式页面由同一个 React Root 和统一路由提供；Axum 只提供接口、资源、下载和页面入口；未知路径 404。
- **干净**：`apps/api/src/local_web/` 下没有页面 `.html/.js/.css`；Rust 不输出业务页面 HTML；`shell.rs` 的页面输出已删除；CI 防回流检查生效；旧 UI 工作流与旧 DOM 测试已删除或改写。
- **能力**：每页迁移前登记的能力在新版都在，或经 Mog 明确删除并留有记录。
- **真实**：操作回执、部分结果、受限来源、未知与 0 的区分都在真实链路上验证过。
- **体验**：全站统一使用 LIDS；视口、键盘、焦点和减少动态效果都可用。
- **运行**：同 revision 构建、冷启动、离线重启、整版回退演练通过。
- **验收**：每个阶段都有 Mog 的业务验收，最后有全站验收。

- 每个阶段是一个交付包：Mog 派定 → Issue（可作为 #430 的子 Issue）→ Claim → `.worktrees/` 下的专属工作树 → PR → 由 Mog 指定审查 → Mog 授权合并与部署。默认串行；并行须由 Mog 派定，并指定集成负责人。
- **集成接缝**（同一时间只有一个负责人修改）：`apps/api/src/local_web.rs` 路由注册、`shell.rs`、`apps/web/src/app/*`、`apps/web/src/ui/*`、`apps/web/src/shared/api.ts`、`scripts/runtime/sync.sh`、`lids_tokens.css`。

## 11. 风险与停止条件

| 风险 | 应对 |
|---|---|
| launchd 环境找不到 Node，或离线无法安装依赖 | 沿用 Pi Adapter 的固定 Node 路径与本地安装方式；阶段 B 在真实 launchd 环境验证；失败时同步脚本拒绝切换 |
| 采集页面大量依赖 Rust 拼接与表单提交 | 阶段 G 先盘点全部表单与读取，逐个补 JSON 接口；涉及语义变化即停止并升级 |
| 主题图谱绘图复杂 | 以适配器纳入，不重写算法；做同场景性能对照 |
| 迁移期两套外壳观感不一致 | 按 R4 使用同一 Token 和同一导航结构；外壳视觉改版只在 React 一侧进行，并需 Mog 确认 |
| 迁移与改版边界不清，范围膨胀 | 只实现已确认的设计；未定的产品问题升级给 Mog |
| 并行工作冲突共享文件 | 集成接缝单一负责人；冲突时停止并报告 |
| 冻结期间有紧急界面需求 | 只修阻断缺陷；其余排进对应阶段，或由 Mog 决定提前迁移该页面 |

停止条件（任一出现即停止，并报告 Mog）：需要改变业务含义、权限或真实外部动作；需要删除数据；共享接缝出现他人未合入的冲突改动；产品设计未定。
