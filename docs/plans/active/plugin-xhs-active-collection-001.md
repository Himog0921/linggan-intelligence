## 用户结果与职责边界

插件收到明确采集目标后，负责在真实页面环境中主动加载、取得和保全目标范围内的公开数据；它不分析内容、不生成关键词/博主、不判断趋势，也不自行扩大对象范围。

事实回执不是替代执行的失败说明。它用于区分任务目标、实际取得、页面可见范围、停止原因、可恢复位置和 Linggan 接纳状态，使已取得材料不被未完成成员连坐，也不把未观察范围写成零或“平台没有”。

## 冻结范围

1. 以已有 DOM 读取与滚动基础实现目标驱动的搜索/主页发现，不调用旧工作台 endpoint、轮询、Cookie 或旧同步。
2. 保留标准详情的 `30` 条评论窗口，同时把单篇深采和批量评论作为独立、有明确目标与停止条件的执行能力。
3. 将详情、评论、媒体观察的交付状态聚合为用户可理解的结果；媒体原件仅在已请求的独立字节通道处理。
4. 为页面输入、采集包、媒体候选地址和 Linggan 专属本地暂存补齐最小安全边界。
5. 更新 focused tests、能力登记、插件说明、迁移说明、当前状态、文档索引、当月进度和可复现 ZIP。

## 明确不做

- 不操作真实账号、不读取 Cookie/令牌、不绕过验证码或安全限制。
- 不向真实 Linggan Evidence 链路交付真实页面原文，不进行真实页面回归、生产部署或业务验收。
- 不修改 Rust backend、数据库 migration、调度/租约、分析、OCR/ASR、抖音或其他平台。
- 不把页面自然到底等同于平台全量；不把最大配额反推为未采对象或完成百分比。

## 实施步骤

1. 冻结目标、执行、回执和安全边界的 focused 测试。
   - 验证: 目标 50/实际 27、标准 30 条窗口、深采不限于 30、批量空态成功、恶意页面消息和非法媒体地址均可证伪。
2. 连接目标驱动的 DOM 滚动发现与正确的 TaskSpec/回执。
   - 验证: 搜索任务保持原始请求数量，记录实际数、滚动轮次、停止原因与当前筛选，不宣称结果集完整。
3. 收口单篇深采、批量评论 checkpoint 及详情三路交付状态。
   - 验证: 每篇独立状态、暂停/恢复、已取得材料保留；只有请求部分均接纳才显示整体接纳。
4. 收紧本地数据/页面消息/媒体地址边界。
   - 验证: 旧库不进入当前 Linggan 暂存；无关联/超限输入和非平台 HTTPS 媒体地址被拒绝。
5. 更新文档、构建可复现 ZIP，进行分层验证与 Draft PR 交付。
   - 验证: package baseline、治理检查、ZIP/hash/reproducibility 均通过；真实页面、接纳、部署和 Mog 验收明确保留为未验证。
