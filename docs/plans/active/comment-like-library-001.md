## 用户结果与边界

运营的做法是"找到家长高赞评论，直接改写成帖子"。Mog 选择在既有「语料 → 评论研究 → 用户评论」列表上扩展，不新建页面或导航：

- 每条评论显示**自己的**点赞数与采集日期；未知显示 `—`，不得用作品点赞推算评论点赞（合同既有规定）。
- 排序：最新收到 / 点赞最多；点赞下限：不限 / 30 / 100 / 1000。界面默认排序由「最新收到」改为「点赞最多」（Mog 2026-10-14，CORPUS-COPY-001 / Issue #421）；接口合同中 `sort` 的服务端缺省仍为 `received_desc`，界面始终显式传递 `sort`，网址在默认值时省略该参数。
- 「已改成帖子」标记：可标记、可撤销，全团队共用，记录时间；筛选：全部 / 未改 / 已改。
- 原有原文、所属作品、九类研究标签、声音角色（默认排除作品作者本人）、研究状态、搜索与分页保持不变。

非目标：说话人身份标注、评论发布时间、选题池或运营模块、评论研究语义/归并/运行逻辑、其他页面与导航、视觉重设计。Mog 已于本轮明确授权：修复审核发现的三项问题、补反例、复审通过后合并 #401，执行 0122 与历史回填，再部署并刷新本机 3000；不包含模型调用、恢复研究、平台采集或插件重载。

## 已核实的数据事实（共享开发库只读，2026-10-12）

- `linggan_material_comment` 为 append-only（禁止 UPDATE/DELETE 的触发器），不能就地补列回填；点赞须进入新的 append-only 观测表。
- 13,106 条评论行都能由 `(package_ref, record_ordinal)` 精确定位原始记录，评论 ID 100% 一致，且都带数值 `likes`。
- 插件写法：页面显示「赞」表示 0；找不到点赞元素时 `likeText` 缺省为 `"0"`。分布：「赞」8,141、纯数字 4,926、「万」6、空 45、`"0"` 3。

## 点赞判定规则（`comment-like.v1`，回填 SQL 与入库代码同一口径）

| 原始写法 | 记录 |
|---|---|
| `likeText` 为「赞」 | 已知，0 |
| 数值 `likes` > 0 | 已知，取该值（插件已解析「万」） |
| 其余（`"0"`、空、缺失、非数值） | 未知（不写 0） |

列表展示的点赞数取该评论在 asOf 之前**最近一次已知**的观测；`likeCountAsOf` 为该次观测时间。排序时未知排在最后；设置点赞下限时未知不进入结果。

## UI 变更清单要点

- 分类：混合（展示 + 交互 + 行动）。最高风险为"行动"：改帖标记是持久化的人工记录，界面必须以服务端回执为准。
- 依据：评论研究接口合同 CommentItem 已定义可空 `likeCount/likeCountAsOf`；LIDS 数据边界四态（零值/未知/极大值/超长）；LANG-05 界面文案全部中文。
- 复用现有筛选表单、表格、徽标与链接按钮样式与 Token，不新增组件变体或页面结构；不触及 Token、材料、壳层与导航。
- 停止条件：需要新组件变体、新导航或改变既有研究状态含义时，停止并上报。
