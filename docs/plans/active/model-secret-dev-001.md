# MODEL-SECRET-DEV-001 · 开发期模型凭据单一路径

> 状态: 活跃计划
> 最后核对: 2026-09-30
> 适用范围: 本机模型连接凭据保存与 API/worker 读取
> 事实来源: Mog 当前请求、三批 Comment Study 调用账本、现行 SecretStore 与本机运行进程
> 冲突时以谁为准: 用户当前决定、真实运行回执、当前代码与权限检查

## 用户结果与边界

开发期重编译、刷新本机 3000 后，模型密钥无需反复点击 macOS Keychain 授权。API 保存与 worker 读取同一个本机文件 SecretStore；不引入 Keychain/文件双路回退，也不把凭据存入 Git、数据库、前端、日志或 `.env`。文件由当前用户持有，目录权限 0700、文件权限 0600；这是**未额外加密的本机文件**，需要按本机设备与账户安全策略保护。

不改变模型、研究 Run、预算、语义接纳或调用账本合同；不启动新批次、不重放旧失败批次、不调用真实 provider。

## 点时证据与恢复顺序

- 9 月 29 日 18:18、9 月 30 日 10:26 和 12:18 三个 Run 的失败调用均为 `model_secret_unavailable`、`callStarted=false`、计费 token 0；前一个成功 Run 使用同一连接版本。现有 Keychain 条目存在且交互式终端可读，worker 不能读取；具体底层 Keychain 错误类型未获日志证明。
- 以 `origin/main@1e94252a` 建专属 worktree。替换唯一运行时 SecretStore，删除 Keychain 依赖及测试；对私有目录/文件、跨实例读取、替换/删除及拒绝宽权限/符号链接作合成测试。
- 逐个把本机当前 DB 引用的旧 Keychain 凭据转入新文件，写后从新存储逐字校验；任一项失败即停止，不删除任何旧项。部署切换并验证 worker 可读后，逐项删除旧 Keychain 条目，不留下第二套存储。
- 使用受控 install 刷新本机三个服务，核对精确 revision、PID/cwd、健康接口及 worker 不再报密钥不可用。真实模型探针或新 Run 另需明确样本与预算授权；旧失败回执保持不可变。

## 停止与回退

若权限、迁移验证、仓库复审或受控安装失败，保持旧运行版本与 Keychain 条目；新文件不得被旧进程误读。切换后如需回退到旧代码，须先恢复其凭据读取资格，不能静默回退到 Keychain/文件双路。
