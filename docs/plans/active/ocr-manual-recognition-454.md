## 用户结果和边界

在证据库当前作品的“图组”旁发起一次手动 OCR。服务端先冻结已有本地图片、模型配置与许可，再以同一执行器按图序每张一次处理；首个失败停止后续派发。结果在同一检查器中按首图标题、内页正文、局部待核验和逐图原始回执显示。

该能力使用新任务键 `ocr_recognition`，与 `ocr_quality_audit` 分责。它不要求既有 Paddle 结果、42 探针或 adoption；不启动 worker，不自动重试、补采、换供应商或全库回填。保存模型配置不发送图片。真实供应商、共享数据库、现有服务、真实材料与部署都不在本包验证范围。

## 状态和进度合同

服务端持久化冻结集合的 `completed_images`、`total_images`、运行状态、逐图状态和版本化原始结果。用户可见进度仅显示 `floor(completed_images / total_images * 100)%`：排队为 0%，成功的最后一张完成且聚合结果已提交后才为 100%，失败/停止固定在已保存比例。客户端仅对后端确认的百分比做视觉平滑，永不按时间递增；页面与 aria 文本不得显示分数形式的完成计数。

`queued`、`running`、`finalizing`、`succeeded`、`stopped`、`unknown` 分别表达受理、实际执行、末张保存/聚合、可读结果、失败后停止和回执待核对。内容采用状态与任务完成状态分开：每个区块为 `adopted`、`pending` 或 `excluded`，原始 JSON 始终独立保留。

## 表面、依赖和验收

| 表面 | 变更 | 真实依赖 |
| --- | --- | --- |
| AI 设置 | “图片文字识别”任务和 OCR 模型选择 | 现有模型连接、能力、设置版本和开关 |
| 证据库图组 | 当前作品局部 M2 按钮、百分比进度 | workRef + runRef 的受限本地 API |
| 作品检查器 | 封面标题、逐图正文、局部待核验、受限原始回执 | 同一版本化 run 读取模型 |
| 执行器 | 冻结输入、顺序领取、一次调用、失败停止和幂等读取 | 既有 batch、admission、Pi 和账本 |

合成验证必须覆盖：无旧 OCR 的原图输入、重复 blob 去重和槽位别名、空/未知坐标保留、首图之外标题不升级为作品标题、局部 pending 不清空正文、首图失败停止、同一 command 幂等、回执未知不重发、跨作品结果隔离及刷新后读取。浏览器/API/owned PostgreSQL 证明只使用合成图片与保存 mock 响应。
