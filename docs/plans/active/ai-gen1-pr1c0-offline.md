## 用户结果与边界

在没有真实模型、共享数据库或服务、G4 的条件下，用固定合成材料查看输入包、mock结果及人工判断路径。mock不得冒充模型能力或正式分析。C1才接真实供应商/调用账/审批/生产调度，仍需A/B发布、#420/G4及相应真实启用授权。旧链退休另包，C0不删除任何旧链、表或业务页面。

## 实施顺序

1. 固化纯输入/输出合同，复用A的Material/Unicode片段坐标和版本身份；仅用合成测试。先实现结果闭集、版本隔离、相关/未知/不相关、方向成员、关键词字面证据、理由长度与清除。
2. 补方向清单两层/20–40方向/定义和2–3样例、固定样本编排与输入包，输出mock必须显式标记；默认输入沿既定五类，ASR不因A有该列就自动加入。
3. 准备方向/逐篇输入与输出/人工判定的具体只读主路径规格，按既有G1确认后做UI。未确认前不实现UI，但步骤1/2不因此暂停。
4. 相关合同/必要隔离DB测试，一个真实UI主路径（有UI时），一次收尾审查；同范围小修只定向验证，最后Draft/CI。无需新增原生缩放/故障注入/备份恢复包。

### 依赖、数据和行动后果

C0新增的唯一数据源为后端人工维护的合成fixture及纯合同模块；前端不得再写一份方向/样本真相。拟提供一个固定合成GET和有界、无状态的预演校验请求，使用当前React→Axum路径；请求只接合成成员/当前版本与裁定字段，由服务器纯函数验证。没有SQL、provider、worker、生产handler或正式serving写口。会话状态只记录在当前页面内存；返回的是本次预演计算结果，不能称落库回执。无任意文件上传、真实样本选择器、真实调用按钮、正式清单发布或导出原文。

专属文件将扩到本模块内部fixture/聚合/裁定、页面`topics/offline/`及其测试；必要共享接缝限App路由、TopicsPage的一处入口、API固定合成路由接线/响应、文档索引和设计采用记录。G1已确认且原C0 Claim已补这些具体边界，按此改对应代码；有真实并行冲突只暂停冲突接缝。AppShell/ActionButton本体、旧业务实现、设置、migration及数据库/运行脚本不改。

## 验证入口和限制

- `cargo test --locked -p linggan-intelligence --test note_interpretation_offline`：纯合同。
- `cargo test --locked -p linggan-api --bins -- local_web::offline_preview_tests local_web::web_app_tests`：无DB app及页面/源守卫；ignored浏览器不计普通套件通过。
- `npm --prefix apps/web run verify`：类型、lint、全部Web测试和构建。新增组件测试验证精确标签、清除理由与Unicode字数；旧focus测试保留原语义并等待effect，不更改采集实现。
- 构建成功后，设`C0_PREVIEW_NODE`为当前固定Node、`C0_PREVIEW_PROOF_DIR`为自有private目录，运行`cargo test --locked -p linggan-api --bins offline_preview_browser_main_path -- --ignored --nocapture`。监听127.0.0.1随机端口、app数据库NotConfigured，浏览器只允许该origin及固定预演POST，finally关闭浏览器，Rust退出前abort并等待自有server。5步为同一用户主路径，不是5轮验收。
- 过程中的Token、自有测试选项类型、标签定位及构建未就绪失败原件保留，不计成功。源码资格、相应测试、一次审查/最终提交/CI各自核实；不补全套故障/缩放/恢复包。具体最终数字和head集中本包PR，避免多份状态漂移。
