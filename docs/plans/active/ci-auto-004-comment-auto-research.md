## 2. 主线审查裁定

| 原讨论中容易误执行的地方 | 本轮执行裁定 |
|---|---|
| 所有计算写作“100% 本地”，其中含 Embedding | 清洗、调度、校验本地；Embedding 是独立语义计算，可本机或已配置外部接口，分别核算调用与资源。不能用词哈希伪装向量 |
| 自动回归被描述为准确率证明 | 自动检查证明结构、依据约束、稳定性和分布变化；模型复核也是派生判断，不把一致性当正确率，不建立人工标注流水线 |
| 所有版本变化都重研究 | 凭据轮换、点赞变化、改额度不失效；换模型默认只影响后续任务；有效输入/研究规则变化形成过期候选，按照已冻结重算政策和预算处理 |
| “低信息”可能重新回到界面 | 纯 emoji/mention/标点剔除研究层；短但有语义的原声保留。旧 low_information 只兼容历史，不新增低信息待办 |
| “无依据输出率”容易伪造语义真值 | 机器硬指标叫“引用/依据约束拒绝率”；语义评审单列方法、模型、样本与不确定性 |
| 只补失败就等于安全恢复 | 逐成员幂等；已接纳不再外发；未知用量不当作零费用，不无限重试。恢复策略一次配置，普通故障不要求逐条点批准 |
| 保留真实语料等于永久复制请求正文 | 回归长期保存来源引用、版本与摘要；内容读取仍服从当前来源资格，诊断正文继续最长 24 小时，不扩建第二原文库 |
| 自动命名问题簇等于正式 Topic 发布 | 评论研究问题对象自动组织；关联已有 Topic 时保留派生关系和出处，不自动修改正式领域定义或发布市场事实 |
| P5 必须前面稳定，容易被无限延期 | 本包实现 P5 查询/证据/变化资格路径及 UI，并验证合成正反例；真实质量与可比性未证明时明确受限，不以永久空页面冒充完成 |
| 每日最多 3000 与 10 万聚类似乎冲突 | 3000 是当前每日/定向研究预算边界；历史累计 10 万原子语义以分页、缓存与稀疏图处理，不构造 10 万平方相似度矩阵 |

## 6. 审查与防幻觉纪律

1. 根代理先核对本阶段需求、数据/API接缝和旧能力复用，再派实现；不能用整份聊天替代精确任务。
2. 实现者自检覆盖整类正常/空/部分/错误/来源受限情况后交回；根代理做一次集中审查。
3. 审查问题按正确性、数据/费用、用户路径、视觉、证明缺口一次列齐。修订后只复验问题及受影响邻域，不再无限拉起新 reviewer。
4. 新发现只有会破坏本交付既定结果才阻塞；相邻产品想法登记为不在本包，不扩大范围。
5. 来源不足保留 unknown。未跑真实模型就写未验证；不存在的列/API/能力先声明目标并实现，不能在UI伪造数据。
6. 文档状态、测试状态、Git发布、共享迁移、运行版本、真实模型语义质量、Mog验收分别记录。

## 7. 验证、切换与回退

- 单元：严格解析、清洗、指纹、优先级、时间、状态与统计公式。
- 真实 SDK + 本地供应商 fixture：HTTP/SSE请求/终止/部分输出/超时/诊断脱敏；不把模拟结果说成 DeepSeek 实测。
