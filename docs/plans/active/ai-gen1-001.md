## PR-1A 实施内容

1. 新详情同事务投影 hashtag；已有 detail 独立补投影，不依赖会跳过已投影包的旧通用 reproject，不重放其他 lane。
2. 统一底稿上的新适配合同：栏目原因、确定性内容指纹、真实作业状态与 24h 详情宽限、来源 manifest；旧消费者不切换。
3. 显式保存追加式快照/片段，不存第二份正文；同文不同来源及不同冻结时间各保留血缘。
4. 只读 plan + 显式 apply 的有界媒体重分层编排；逐篇 revision 校验、幂等/中断续跑、残留与失败可见；不 OCR/ASR/采集/模型。
5. 合成一次性 PG、纯规则/API/CLI、旧消费者和迁移证明；文档同步后一次独立收尾审查，处理发现并核对最终 head，交 Draft PR。

工程合同见 [note-material-input](../../data-contracts/note-material-input.md)。常规实现选择自主完成，文档/自测不各设 reviewer 或人工批准。共享冲突只暂停相关接缝。
