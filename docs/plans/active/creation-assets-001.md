## 3. 各片说明

### S0 成员登录与入口（DECISION_REQUIRED：C2、C3）

- **内容**：创作接口接入运营成员会话与角色判断；作品与资产记录创建人（现在固定写 `local_machine`）；运营左栏「创作」入口对所有成员开放；已有 3 篇测试作品保留并标注创建人未知。
- **验收**：不带会话不能读写创作接口；停用成员立即失效；成员只能看到被授权看的资产；写手、组长、管理员的权限各有正负例；真实浏览器链路从登录走到打开创作。
- **验证**：隔离 PostgreSQL + Axum 的合同测试，加真实浏览器链路。
- **授权**：Mog 决定入口与权限方案；邀请真实成员要写共享库，另行授权；成员名单不进 Git。
- **PR**：1 个后端（会话接入、创建人），1 个前端（入口与可见性）。
- **不能开工的条件**：C2、C3 未回答。

### S1a 资产与检查

- **内容**：账号身份（与机构关系、简介是否写明、背后有无真人及其角色，不写真名）；产品事实卡；衔接句库（入库检查、待审/可用/停用、审核）；稿件的衔接位与“这篇不植入”；三级检查（规格附录 A 的 R-M1–M6、R-W1–W3、R-W6–W9、R-I1–I2、R-L1–L7）；复制到小红书（A.4）；稿件状态“草稿中 / 已复制”。
- **规则只有一份实现**：检查在服务端（Rust）实现，前端防抖调用检查接口，不在前端再写一套；检查结果不通即不能复制（离线时不能复制）。复制回执记录规则集版本与产品事实卡版本。
- **验收**：规格场景 V1、V2；每条规则有正例、反例、边界例（合成数据）；产品事实卡改了，检查跟着变。
- **验证**：规则单元测试；隔离 PostgreSQL 的迁移与合同测试；真实浏览器场景；小样第 3 项的真机结果决定格式定稿。
- **授权**：跑迁移（共享库写入）要 Mog 授权；产品事实卡由机构确认；账号底细表至少填完 2–3 个试点号；合规书面意见，或 Mog 明确决定先在 1–2 个号上试。
- **PR**：1 个后端（迁移、领域、检查服务、API），1 个前端（资产库页、检查面板、复制）。
- **不能开工的条件**：见第 6 节开工条件的 1–4、7。

### S1b 个人经历资产（保护车道，敏感）

- **内容**：人设事实（含新旧冲突处理）；经历库（采集、本人确认、同意记录、讲过几次）；稿件里的经历位与经历来源标记；经历相关检查（R-M7、R-M8、R-W4、R-W5）；撤回时沿引用传播。
- **验收**：规格场景 V8；本人未确认的经历不能进稿件；别的账号的经历不挪用；撤回后稿件、样板和“AI 会看到的内容”里不再出现。
- **授权**：S0 完成；合规意见里的“提供经历的真人同意书要点”；保留期限由 Mog 决定。任何 Agent 都不读取真实经历。
- **PR**：1 个后端，1 个前端。
- **不能开工的条件**：S0 未完成；同意书与保留期限未定。

### S2 选题框与开稿（DECISION_REQUIRED：C4、C5、C6、C12）

- **内容**：选题框对象；材料卡（用途 7 选 1 + 思路 + 坐标）取代现有五列画布；材料桌（无限画布，纯 DOM，400 张以内）；“AI 会看到的内容”；开稿与一题多号（一次命令事务内创建多篇稿件）；按段落换个说法与采用（拦截条件改成目标段落级）；撤销改为按“一次采用 / 一次输入法提交”为单位；旧前端的七步流程在新界面上线的同一个 PR 里删除，不留开关。
- **验收**：规格场景 V3、V4、V5；A07–A09（打字期间结果返回、改目标后旧结果返回、改其他段后返回）在真实链路通过。
- **验证**：采用事务需真实 PostgreSQL 的正负例；输入法场景在真机复测（小样只用了模拟）；模型调用在授权前只用合成适配器。
- **授权**：模型、供应商、外发材料范围、每月预算（开工评审）；真实模型调用与真实材料另行授权。
- **PR**：①后端：选题框、材料卡、开稿命令（无模型）；②后端：段落级采用与撤销；③前端：材料桌与写稿区；④AI 接入（需外发授权）。
- **不能开工的条件**：S1a 未完成；C4–C6、C12 未回答。

## 5. PR 怎么拆

- 每片 2–4 个 PR，后端先于前端；每个 PR 小到能独立审阅。
- 本文档 PR 是第一个，只含文档；不合并，等 Mog 看。注意：合并任何 PR 都会让 `origin/main` 先于本机运行目录，之后任何服务重启都需要先部署（Mog 此前决定“不推文档”），所以文档 PR 的合并时机请 Mog 决定。
- 保护车道的每个 PR：关联 Issue 与 Claim、独立分支、真实链路验证、独立审阅（Mog 授权后），最终 head 单独授权合并。

## 7. 试用与可用性测试方案

含真人姓名的记录放 `artifacts/private/creation-prep/`，不进 Git。下面的表格是空白模板，可直接使用；可打印的副本也在私有目录。

### 7.1 Demo 可用性测试（现在就能做）

- **人**：1–2 位写手，每人 30 分钟，由 Mog 安排。
- **材料**：交互 Demo 第二版（只在测试者自己的电脑上打开）。Demo 里有 Mog 的真实打样稿和孩子的昵称，给写手看之前由 Mog 确认；如不愿给看，需要先做一份全合成的副本（待 Mog 回答）。
- **做法**：主持人念任务，不提示界面；记录他们卡在哪、跳过了什么；每个任务最多 5 分钟，超时就跳过并记下。

**任务卡**（由 Demo 的 8 步体验清单改写成真实任务）：

| 编号 | 任务（念给测试者听） | 对应规格场景 |
|---|---|---|
| T1 | “你接到一个账号的稿子，不确定这个号能不能提机构的产品。请弄清楚，并让稿子里出现合适的一句话，或者决定这篇不提。” | V1 |
| T2 | “这篇稿子准备发了。请把需要改的都改好，然后把它带到小红书。” | V2 |
| T3 | “你想知道系统为这篇稿子参考了哪些材料。请找到它们，再回到稿子。” | V3 |
| T4 | “挑一张材料，告诉系统你想怎么用它，再看看系统会读到什么。” | V4 |
| T5 | “同一个选题，要给两个账号各写一篇。请一次开出来，并检查两篇开头是不是不一样。” | V5 |
| T6 | “封面大字想换个说法。请换一批，选一个用上。” | V6 |
| T7 | “你在证据库看到一篇好笔记，想以后照它的写法起稿。请把它变成样板。” | V7 |
| T8 | “一个有真人的账号刚讲了一件新事。请把它记下来，并让本人确认。” | V8 |

**观察表**（每人每个任务一行）：

| 测试者代号 | 任务 | 完成（是 / 否 / 提示后完成） | 用时（分） | 卡住的地方（原话） | 跳过了什么 | 多余的点击或回退 | 他期望它在哪里 | 备注 |
|---|---|---|---|---|---|---|---|---|

**结束后问 5 个问题**：最容易的一步是哪个？最糊涂的是哪个？衔接那一块你会信它吗，为什么？哪个检查提示你觉得多余或不对？你现在做一篇稿子，哪一步最想让它帮你？

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

### 7.3 两周对照试用（拿到授权和基线后）

- **人与账号**：3 名熟练度不同的写手；每人固定账号；不要求全队切换。
- **设计**：同人同账号、近似题材、交错顺序，复用与试新分层；一周现法，一周新界面，或按日交替（开工评审时选定），避免“先后顺序”影响。
- **门槛**：写一篇的中位耗时下降 20%；衔接句可用率达到 80%（盲评：隐去来源，由运营负责人和另一位写手各自独立判断，分歧保留）；至少 2/3 的写手愿意继续用（试用结束时各自表态，不以被要求使用代替）。
- **不做的结论**：两周看不出爆款率有没有变化，不作为门槛，也不在结论里写“提高爆款率”。
- **允许不植入**：选择“这篇不植入”的稿子不计入衔接句可用率的分母，但计入耗时。
- **数据**：只汇总计数和中位数，写手代号对应关系放私有目录；发布沿用团队现有审批流程，不为试验增加刷量或重复发布。
- **结果怎么用**：达到门槛——继续做并延长观察；未达到——缩到最有效的一步，或停。
