## 1. 用户结果与范围

团队成员必须能在 Intelligence 内完成：接受内部邀请并登录；查看全队运营数据；在授权范围内维护当前负责账号、登记/维护发布、补阅读量、填写每日数据；对明确选中的已登记发布发起单条或当前页批量同步；追踪真实回填；交接资产或停用离职成员。管理员能纠错、管理成员和处理待接管账号；历史贡献保持可查。

已确认的产品规则为：仅内部邀请、全队数据可见、运营助理与运营同权、直接录入、当前责任与历史归属分离、XHS 与抖音均为发布同步的承诺平台。小红书最新有效手工阅读量 `>= 5000` 才是我方爆款；满七天尚未填阅读量为待补；抖音播放量选填且不判爆款。同步不得覆盖手工阅读量、日报、历史发布人、当前负责人或业务归属，也不得隐式启动研究、评论、OCR、ASR 或模型调用。

不在本包内：主页巡查或自动发现新帖、通用权限编辑器、第二套采集队列、旧内容工作台修改、真实邮件/真实平台采集/共享数据库写入、生产切换、合并、部署和团队签收。它们必须由独立授权和实际回执证明。

## 2. 旧规则裁定

`OPS-MIGRATION-001` 的 D1–D3 历史迁入及其历史数据语义继续有效；D4/D4b/D5/D6 的未来路线被本计划取代。尤其：

- 旧“迁入台账只读、工作台一直是唯一写入口”不再描述切换后的目标；历史导入来源仍不可伪造成原生记录。
- 旧“主页自动发现 / 立即检查主页”不再是本包同步的替代；本包只同步用户明确选择的已登记发布。
- 旧 localhost 守卫不是浏览器身份校验。正式会话同时保护业务页面、JSON 和受保护媒体；producer、工位和 worker 继续使用既有机器身份与租约协议。
- 所有新增写入都走一条原生业务模型，不做旧工作台双写、字段级 fallback 或伪造导入批次。

历史迁入的已知限制（旧日报的 `0` 与未填不可区分、来源人只保留旧名称/编号、迁入封面不可变）保留为历史事实，不被新模型静默改写。

## 3. 已采用的实现合同

### 3.1 权限和身份

角色只表达管理员、组长、运营三种操作权限；运营助理使用运营权限。浏览器不可自报 actor、角色、组或负责关系。读取全队运营数据，写入由当前权限、当前责任和对象状态在服务器逐条判定。管理员保留历史发布人/历史业务归属纠错的受限操作；组长只能在管理组内交接；最后有效管理员和负责人受事务保护。`0147_ops_team_responsibility` 已建立 Linggan 组、追加式成员组事件、账号当前负责人和责任变更回执的结构基础；服务端交接/停用/逐条授权仍未开放，详见 [OPS-TEAM-RESPONSIBILITY-001](../../data-contracts/ops-team-responsibility-001.md)。

邀请、会话、密码重设令牌只保存摘要；令牌单次、限时且可撤销。停用独立于资产交接：停用立即撤销会话，交接失败不得恢复访问。`0148_ops_first_admin_bootstrap` 与受控本地命令已建立一次性首位管理员的结构和 fail-closed 输入边界；它只创建待签收的管理员邀请，未写入任何真实名单、未发送邮件、未验证邮箱，也不等于真实环境完成。首次负责人不开放公共注册或“第一个注册者成为管理员”。真实名单、第一位负责人和邮件服务均为环境阶段的 `NOT VERIFIED` 输入，不得猜造。

### 3.2 原生运营事实

人员、账号、发布、阅读量修订、日报、账号责任变更和同步关联各自有稳定身份与版本。发布时人员/业务归属不可因后续账号交接漂移；当前账号责任可变。新日报的打开和加微可空，`null` 是未填、`0` 是明确填零；旧迁入值保持旧来源限制。写请求使用请求身份和必要的期望版本，批量请求逐条返回实际结果。`0149_ops_native_write_model` 已将历史/原生来源在同一正式账本中分开约束，并建立原生请求回执、日报修订与原生日报人日唯一性；`0150_ops_native_publication_date_precision` 进一步禁止把仅知发布日期伪造成时刻。当前单事实 API 已实际覆盖账号创建、发布登记、阅读量追加和本人日报创建/版本更新，按会话、当前责任和组长同组/管理员规则授权，并为重放、拒绝和陈旧版本留下回执；对应字段、回放和未交付边界见 [OPS-NATIVE-WRITE-001](../../data-contracts/ops-native-write-001.md)。它仍不是批量、编辑/撤销/归档/交接、代填、统一读投影、UI、导入停写或切换完成。

### 3.3 精确发布同步

同步只把冻结的、明确选中的发布连接到既有 `Acquisition Request → Admission → WorkOrder → Lease → Task/Attempt → Package/Receipt` 链；不会建第二套队列或由前端直调插件。`accepted`、`existing`、`blocked`、`forbidden`、`conflict`/`invalid` 是逐条决定；“已提交、执行结束、已接纳、已回填、媒体可用”永不互相替代。

尚无 material 的合法运营发布使用受约束的运营精确来源，不能插入假 discovery、假 package 或把内部 publication ID 当平台内容 ID。只有合格 record 和 receipt 可触发运营投影；投影失败重放合格回执而不重采。链接、账号、身份版本、作者 ID 和当前采用权限不一致时阻断投影。XHS 签名 URL 仅作短期执行输入；抖音须补全身份、导航、能力、可知性与回填闭环，不能仅改枚举。

## 6. 停止与升级

以下情况暂停受影响 lane 并报告：需要改变已确认的可见/编辑边界或平台范围；需要真实团队名单、负责人、邮件供应商或外部平台样本；需要共享数据库、生产切换、部署、合并或真实资源消耗；以及与已有工作包发生无法按当前合同裁定的共享文件冲突。当前包不由这些缺口倒推为完成，也不因真实环境尚未授权而停止可隔离验证的实现。
