> 适用范围: Issue #74 的最小真实小红书页面能力核实、受限探针刷新和字段登记；不进行真实材料接入或情报分析。
> 事实来源: Mog 于 2026-08-26 的明确授权、`AGENTS.md`、Issue #74、当前插件源码、内容工作台现行 XHS 采集策略与真实页面可观察结果。
> 冲突时以谁为准: 用户最新确认、`AGENTS.md`、真实页面可观察结果、当前插件源码；历史迁移材料仅作对照。
> 事项: GitHub Issue #74

## 用户可见结果

形成一份小红书页面字段与采集探针的唯一登记册，使后续每次平台变化或插件升级都能回答：页面现在展示什么、探针实际看到了什么、插件已经能交付什么、缺口是在页面、插件还是执行边界。

其中，一篇笔记的基础详情交付固定为：详情字段、内容媒体清单，以及平台当前展示顺序下**最多 30 条评论**。它们是一个逻辑任务的不同部分，不分裂成彼此独立的用户动作。

## 已冻结范围

### 允许

- 在当前已连接的 Chrome 中，使用最小页面样本检查小红书公开页面的可见状态：搜索上下文、搜索结果、笔记详情与作者主页。
- 使用项目现有的 XHS 读取逻辑和新的、无原文输出探针，核对字段存在性、显示顺序、数量、筛选状态、停止原因和字段来源类别。
- 对一篇由本次搜索面打开的笔记，检查详情、内容媒体和当前评论窗口，最多读至 30 条；只记录字段结构、数量和覆盖状态。
- 在 `docs/platforms/xiaohongshu/capture-capability-registry.md` 记录可公开复查的字段合同和本次匿名化结果。

### 明确不做

- 不向 Linggan 本机服务提交、保存或展示任何真实笔记、评论、作者资料、媒体字节或原始页面/API 输出。
- 不读取、复制或持久化 Cookie、local storage、登录令牌、账号资料或其他浏览器秘密。
- 不下载媒体，不调用 OCR/ASR，不做 Topic、VOC、趋势或任何内容分析。
- 不绕过登录、验证码、限流、安全挑战、平台页面限制；不新增插件权限、后台自动化或定时采集。
- 不把单次页面观察宣称为平台总体规律、稳定兼容性或真实 Evidence 接入成功。

## 执行与可证伪验收

1. **建立唯一登记册** → 验证：登记册具有状态头、字段来源、页面状态、探针、采集能力和证据/缺口列；不包含真实原文。
2. **刷新搜索上下文与结果探针** → 验证：记录当前可见筛选组、已选状态、下拉联想词的可见性、列表字段、加载数量和停止原因；不把前 20 条固定成永久规则。
3. **刷新笔记详情探针** → 验证：同一次逻辑探针输出详情、媒体槽位和当前评论窗口；评论目标为 `min(公开评论数, 30)`，同时报告实际获得数、排序/层级和缺口。
4. **刷新作者主页探针** → 验证：记录资料与作品列表的页面字段、加载边界和停止原因；不扩大到无界历史扫描。
5. **能力裁定** → 验证：每项登记明确为 `VERIFIED`、`PARTIAL`、`NOT_IMPLEMENTED`、`NOT_AVAILABLE`、`SOURCE_INCOMPLETE` 或 `UNKNOWN`，并把“平台未见”与“插件未交付”分开。
6. **自动与治理检查** → 验证：相关探针测试、插件 `npm run verify`、`./scripts/check-project-governance.sh` 和 `git diff --check` 通过；真实浏览器结论单列且不替代自动测试。

## 最小真实页面预算与停止点

- 使用一个与项目当前领域相关的搜索词、该搜索面中的一篇笔记及其作者页；若首篇笔记页面明确呈现零评论，才允许在同一搜索会话中补充一篇笔记验证正向评论窗口。搜索筛选仅覆盖当时可见的代表性状态，不批量翻页或无界滚动。
- 详情评论只观察到 30 条上限、页面自然结束、登录/安全限制或预设时间预算中的第一个停止点。
- 页面出现验证码、安全挑战、登录失效、明显限流，或完成核实必须读取浏览器秘密/隐藏账户数据时，立即停止，登记为 `BLOCKED` 或 `SOURCE_INCOMPLETE`。
- 若发现需要改动 Capture Package、TaskSpec、接入 API、数据模型、插件权限或真实数据处置合同，停止在探针报告层，另行请求产品与架构授权。
