## 1. 本次交付结果

在保留当前 clean Comment Study 引擎和全部合法历史的基础上，完成 **材料能查全、研究能说清、结果能回证**。用户入口固定为 **概览｜用户评论｜研究批次｜用户问题**。用户“研究批次”对应 `linggan_comment_study_run`；内部 `linggan_comment_study_batch` 仅是同篇评论的模型请求分组。

本轮文档不构成执行授权；本包生效后也不得援引过去 DEC-0006 再次 reset。源码上的机制存在，不等于本机模型效果、召回准确性或业务价值已验证。

## 2. 已收口的技术决定

| 编号 | 决定 | 取舍与禁止事项 |
|---|---|---|
| D01 | 保留 Rust / PostgreSQL / 现有 Axum 本地 Web / Pi adapter | 不迁回 Next.js，不新增服务、消息队列、通用工作流框架 |
| D02 | 原始评论身份继续为 `(content_public_ref, comment_external_id)` | `material_ref` 是一次材料版本；重新采集不产生第二位用户或第二条独立评论 |
| D03 | 现有 `policy` 扩展为不可变“研究方法版本” | 不再建 Method、PromptVersion、PipelineVersion 三套表；活动指针只决定默认方法 |
| D04 | 用户最终点击“开始研究”即授权冻结并入队 | 不存在名为 prepared 却偷偷执行的“待启动草稿”；预览只读，不产生 Run |
| D05 | 最终请求携带准确方法、范围与三项预算 | 不依赖另一个“保存设置”动作的先后；修改输入框不会悄悄使用旧预算 |
| D06 | 默认只选未处理材料；重研、输入变化、失败重试为显式模式 | 新方法成为默认，不自动重跑全库；下游召回重试不重做语义提取 |
| D07 | 使用数据库约束阻止跨 Run 的同评论同时执行 | 不用前端按钮禁用代替幂等；允许同评论先后重研，不重复计算独立依据 |
| D08 | 当前只新增三张物理表 | 清洗缓存、开始请求回执、模型请求快照；各自必要性见架构手册 |
| D09 | 输入、方法、请求三种哈希分工固定 | 比较内容是否变化与审计究竟发了什么不能混用一个 hash |
| D10 | 原声和依据仍由 Rust 校验，方法编辑不能修改证据约束 | 模型只能提取／比较／提出定义；不能直接写 Problem 或 membership |
| D11 | 部分有效结果立即可读；总量与分页分开聚合 | 不等待所有评论、所有向量或所有归并完成，不建立全局完整性门闸 |
| D12 | 下阶段自动化只增加定时发起者 | 复用本轮 `start_study_run`、预算与三阶段 Worker；不是另一个分析系统 |

上述细节是本包给出的明确目标，不冒充源码现状。Mog 批准本包开发后，Agent 按这些裁定实施；若真实迁移状态与基线不同，只调整受影响差异并报告，不能自行扩成重建。

## 3. 本轮必须完成与明确不做

**必须完成：**全库评论和作品分页检索、来源与清洗状态、跨批次历史和排重、幂等启动、方法版本可视化与受控复制、三阶段请求留痕与预算边界、局部故障恢复、当前有效依据去重、四 Tab 下钻、迁移和回滚验证。

**为自动化现在就实现：**统一内部启动函数；非 UI 的输入类型；持久幂等回执；原子预算预留；三阶段超时回收与有限尝试；暂停／停止执行边界；新增材料的确定性清洗；失效材料在读／发／收各处的限制传播。只在合成测试中调用自动发起者适配接口。

**下阶段才实现：**自动计划表、计划设置 UI、到期扫描、时间槽幂等、每日额度、跨日消费限制和开启自动运行。它们的具体合同在 [自动化衔接](comment-study-automation-002.md)，本轮不创建计划表、不配置真实时间、不打开定时外发。

**暂不做：**全原声向量检索、证据问答、冲突图谱、自动问题拆分合并、解决办法图谱、自动采集补证、A/B 实验平台、对外 MCP、全库模型重跑、云端 Embedding、更换数据库或前端框架。

## 4. 最小模块边界

以现有调用点为主，新增的本地模块只对应真实职责：清洗缓存、来源读取、研究选择、方法版本、请求快照与预算。它们仍在现有 `linggan-intelligence` crate 内，不是服务层级。公共函数由两处以上调用才抽出共享；不能为每个 DTO 创建 Manager、Service、Repository、Factory 四层封装。

完整文件地图在 [架构](../../architecture/comment-study-productization-001.md)。字段以 [数据库合同](../../data-contracts/comment-study-productization-001.md) 为唯一来源；HTTP 名称以 [接口合同](../../data-contracts/comment-study-http-001.md) 为唯一来源；其他文件引用而不重新发明字段。

## 5. 技术实施顺序，不等于自动派单

| 顺序 | 可验收结果 | 主要工作 | 合并或发布前的必要证明 |
|---|---|---|---|
| P0 | 确认不会损失历史 | 基线差异、数据库目录与旧队列只读盘点；登记本包和冲突裁定 | 原始材料与 clean-study 表清单；无 reset 操作 |
| P1 | 评论可查全、历史可查证 | 清洗缓存、全库读、作品分页、稳定身份与只读统计修复 | 搜索第 101 篇之后作品；300 条分页；限制传播 |
| P2 | 一次明确确认完成启动 | 方法版本、最终预算绑定、幂等请求、选择和并发约束 | 并发相同／不同 requestRef；预算未保存；有限重研 |
| P3 | 运行有界且可追溯 | 完整请求、严格 Schema、先验证后缓存、预算、三阶段恢复和公平调度 | 进程崩溃点、过期返回、上游失败不拖死其他队列 |
| P4 | 结果成为可持续知识 | 有效结果 head、Problem 依据与边界、概览下半区和四 Tab 联动 | 重研不增证；no_signal 不借旧结论填空；部分成果及时可读 |
| P5 | 形成可批准发布的包 | 数据保留证明、升级／空库安装证明、浏览器验证、运行手册 | 分层报告源码、隔离测试、真实模型、部署、业务验收 |

P1–P4 可拆成内部提交，但只有 Mog 决定 Issue、人员、并行和 exact-head 合并。不得自动创建子任务或启动额外 Agent。完整集成必须验证同一组用户路径；单个提交通过不是交付完成。

## 6. 风险与验证方式

| 项目 | 当前确定性 | 处理 |
|---|---|---|
| 字段和模块设计 | 本包已给出明确目标合同 | 不交给实现 Agent 猜 |
| 当前本机数据库的迁移、在途任务数量 | 本轮没有访问本机，未知 | P0 只读检查，不靠仓库文档猜现场 |
| 中文短词检索性能 | 未实测 | 1／2／3／长词与目标规模分别测；不把检索结果少当作准确 |
| WeMM 在用户 M4 16G 上与 OCR／ASR 争用 | 源码有让路机制，现场负载未知 | 保留现有资格探测；在授权的本机性能测试中测量 |
| 语义提取和归并准确率 | 合同校验不能证明 | 独立标注的固定样本，报告错误类别；不把模型自评当 Gold Set |
| 默认批量、tick 额度 | 工程初值，不是性能结论 | 使用手册固定初值，测试后以配置调整，不增架构层 |
| 历史方法的精确文本 | 旧记录未必存在 | 显示未记录；不倒填本次方法、不自动重跑 |

## 7. 执行禁区

本轮不得执行 `reset-local-comment-study.sh`、`comment-study-reset.sql`、TRUNCATE 当前研究表、删除原始材料、重写已应用 migration、复活旧 `linggan_comment_research_*` 路径。不得把真实评论放入 Git、把密码或 Keychain 引用内容写入方法快照、自动开启付费调用或真实平台访问。

升级会对旧未闭合执行采用显式安全停留，具体在运行手册；既有有效结果仍可读。升级不是对历史结果的否定，也不是第二次重建。
