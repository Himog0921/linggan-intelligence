## 战略转向

旧产品以采集、内容管理和内容生产为中心；新项目以感知世界、理解变化、发现信号、形成情报和指导行动为中心。

情报的工作定义：

```text
情报 = 变化 + 证据 + 判断 + 行动价值
```

## 已确认决定

- 新建独立项目，不继续把所有新能力堆入旧内容工作台。
- 后端和 worker 使用 Rust。
- 使用全新 PostgreSQL 数据库，不带旧表。
- 现役插件不盲目重写；保留运行、租约、队列、重试、死信和页面采集能力。
- Evidence First、不可变 Evidence、版本化 Observation、无 fallback 继续有效。
- 历史数据不批量伪装为 V2；高价值数据重新采集。
- 当前所有 Linggan Intelligence 讨论稿与 V2 交付资料作为项目历史上下文归档。
- ENV-001 之后不直接进入垂直切片或业务实现；先通过 DISC-001 从头梳理并确认产品、功能、领域、采集流程、数据库、架构和页面，完成一致性验收后再启动 SCOPE-001。
- 情报发现与决策闭环是完整产品中最复杂的核心引擎，但不是产品全部。语料库、主题词表、主题地图、市场洞察、选题库均为正式产品能力，必须纳入 DISC-001 的产品与架构设计。
- Linggan Intelligence 的稳定核心定义是“面向垂直领域的持续情报研究系统”。语料、主题地图、市场洞察、内容增长和 Agent 调用是共同内核面向不同任务的应用能力；深入讨论一个应用不能反向把产品重定义成评论数据库、内容工具或市场看板。
- 最终产品需要提供面向外部 Agent 的 CLI，使其可以在稳定合同、权限和证据追溯边界内调用数据与获准能力；CLI 不是临时运维脚本，也不得直接绕过产品合同访问数据库。
- 当前产品长期围绕一个一级 Domain：ADHD。`ADHD 数学`、`家庭干预`、`作业拖延`、`执行功能`等是 Domain 内不断演进的 Topic，不是平级 Domain；专题研究和采集计划均发生在 ADHD Domain 内，不会因此创建新 Domain。共同语言见 [`domain-language.md`](domain-language.md)。
- 第一阶段首要用户是产品负责人本人及其小团队，核心任务是围绕 ADHD 持续完成市场研究、内容判断和选题决策。外部客户、商业化账户和多租户产品能力不进入首期范围，不得为了未来可能性提前建设。
- 产品同时支持持续观察和主动研究：持续观察是默认日常主循环，负责积累资产和发现候选变化；主动研究由人的问题或经人确认的候选变化触发，负责复用已有资产并补齐证据。两者使用同一 Evidence、Observation、Coverage、语料和主题知识底座。目标“全量”不等于事实“已全量”；遗漏、受限、失败和未观察必须分别呈现。
- Linggan Intelligence 长期价值可以从世界事实、语料与表达、领域知识、市场与情报认知、行动与学习五类积累视角盘点。它们不是五种平级真相、五张表或五个模块；应用视图共享底层来源关系，重要判断能够向下追溯，行动结果能够向上校准，Outcome 不得改写过去事实或伪造因果关系。
- Gate 1 的产品成功不以每次都产生 Intelligence 或 Outcome 衡量，而以持续提高观察边界说明、资产复用、历史可比、未知发现、可追溯判断和现实学习能力衡量。不同能力可以停在不同层级；任务完成、数据量、聚类、评分、报告或 AI 输出都不能单独证明成功。证据不足却表现得高度确定属于核心质量事故。
- Gate 2 已确认受控渐进式采集的责任链：AI 提出证据缺口与候选获取方案；人批准目标、范围、成本、风险和允许策略；服务端在授权范围内拆解、调度和恢复有界任务；producer 只执行当前工作单元；Evidence 接入验证并保存实际结果、失败和分层 Coverage。授权范围内的机械步骤可以自动运行，越界扩张必须重新申请。
- 候选来源必须来自可追溯的真实发现，不会自动触发长期监控或深度采集。系统按当前问题选择内容、讨论串、作者等最小合适观察对象，并在每个阶段根据新增信息价值、证据充分性、成本和风险决定停止或加深；作者不是默认采集单位。
- Gate 2 已确认有限工位是系统事实，真实平台访问必须经过统一的采集准入和执行边界。AI、页面和研究能力只能提出证据需求，不能直接向插件下达无边界任务；服务端必须先检查 Evidence 复用、等价需求/在途执行、有意复观测、所需 Coverage 与新鲜度、授权、时间价值、工位/账号能力和风险预算，再决定复用、合并等待、延后、过期或产生有界工作。
- 需求判断、执行协调、producer 和 Evidence 接入必须分责：执行协调负责工位/账号匹配、领取、租约、恢复、重试与安全停止；producer 只报告实际结果；Evidence 接入独立验证哪些结果可以成为事实；任务终态不能替代 Evidence 验收。一次合格采集可以服务多个需求，但必须区分原始采集动机、发现路径和后续复用，不能因去重消灭有意复观测。
- “7 天”等平台生命周期经验只可作为带版本的平台资源策略，不能写成来源对象的永久事实。新鲜度是“对象 × 观察目的 × 当前时间”的使用价值；排队任务在领取前必须重新判断，市场变化只能基于明确时间窗口、观察条件和 Coverage 的可比样本。
- Gate 2 已确认持续观察的根本纪律：比较性观察负责测量变化，探索与调查观察负责理解和发现；两者共享 Evidence，但探索/调查材料不能未经明确可比性处理直接进入趋势基线。影响解释的观察方法变化与单轮 Coverage 不足必须分开记录，AI 可以提出调整尺子的建议但不能静默执行。
- 新的平台访问只允许因为三类持续价值发生：补齐已批准的信息缺口、完成有时间窗口的已批准观察、使用受控探索预算发现未知。时间敏感只提高已有目的的紧迫性，不能单独创造采集目的；没有持续价值或有效观察承诺时，默认不新增平台访问。
- 普通采集与复杂判断采用分级治理，但所有 Evidence 都必须满足统一最低底线：真实对象和来源、producer/版本、观察时间、实际结果、失败/缺失及运行时合同验证。只有形成市场变化、Signal 或 Intelligence 等复杂判断时，才进一步要求可比样本、反例、不确定性、方法和版本。
- 搜索入口的实际返回只能称为发现面或搜索结果观察，不能称为市场普查。系统可评估一个观察入口的新增率、发现延迟、重复、成本和后续资产贡献，但只能提出计划调整建议；观察效率优化与市场趋势测量必须隔离，避免系统用自己扩大的镜头证明自己的判断。
- Gate 2 已确认主动研究是问题驱动的有限闭环：从服务于具体判断或行动的有边界问题开始，先复用已有世界事实、语料、主题知识和历史认知；只有会影响当前判断的证据缺口或受预算约束的探索分支，才可以进入统一采集准入。完全不新增平台访问也可以形成成功研究。
- AI 可以修改假设、寻找反例和建议补证，但不能直接指挥插件或静默扩大问题、来源、成本、风险和比较性观察范围。研究以“当前已足够、假设未获支持或受到反证、证据不足、继续研究不再值得”等诚实语义结束，不把结束解释为永久真理。
- 主动研究保存问题与用途、使用证据、关键反例、证据缺口、补证理由、判断变化、限制和停止原因等结构化血缘；产出默认先成为候选，不能由一次研究自动更新正式 Topic、市场洞察、Intelligence、比较性观察或现实行动，也不要求保存模型完整内部推理。
- Gate 2-5 已确认资产流转是共享事实底座上的多条可追溯路径，不是所有材料必须逐层升级的流水线。Corpus 通过用途明确的选择与组织复用材料但不替代或复制 Evidence；主题词表与 Topic 关系形成版本化知识，Topic Map 是可浏览投影；市场洞察负责发现、验证和有边界地解释观察面变化；选题可以从原声、Topic、洞察或情报形成候选，Outcome 只校准后续判断。
- Topic 是连接用户原声、社交媒体内容叙事、长期市场记忆、近期变化、证据和下一步行动的共同探索入口。Topic 详情是组合现有资产的受控视图，不是新的事实来源；AI 可以聚合、对比、选择代表样本、找异常与反例，但所有聚类名称、内容角度和解释都必须能下钻至真实材料与 Evidence。
- Topic 探索必须区分：树形导航与真实知识关系、Topic/Term/采集关键词、用户表达与创作者叙事、Topic Map 与带时间的市场叠加、累计库存与可比趋势、市场观察历史与系统认知历史。爆款只表示特定观察范围内的内容表现，不单独证明需求、市场规模或机会。
- 市场洞察保留为正式产品能力，但不再等同于指标看板或 AI 总结。系统可以自动刷新合格事实投影、发现变化、检查 Coverage/观察方法/来源集中/规则版本和反例，并在授权内有限补证；解释和机会判断默认先成为候选，不能反向修改正式 Topic 或比较性观察形成自证循环。
- Gate 2-6 的组织方式已纠正：不再围绕 Corpus、Topic、洞察、Intelligence、选题和 Outcome 逐类建立状态机，而先区分发生记录、被接纳的来源材料、Observation、领域定义、可争论判断、提案/决定与应用视图，再按改变正式认知、观察方法、资源、敏感传播或现实行动等后果决定治理强度。
- 已建立跨 Gate 的 [`../product/domain-invariants.md`](../product/domain-invariants.md) 验收基线。案例持续攻击身份推断、Candidate Topic、Topic 拆分、假趋势、选择性证据、Agent 越权、Outcome 伪因果、对象身份错误、隐私处置、新模型重分类、无效零值、Evidence 跨用途误用、时间伪精确、发现历史丢失、发现自动深采、观察目的复制事实、知识关系偷换和 Outcome 直改知识；任何后续设计不得只靠类型、报告或页面证明通过。

## 2026-08-19 真相分层讨论的审查与收口

用户提交的外部讨论确认了“事实对象先稳定、业务理解后派生”的方向，与 V2 媒体资源架构的 Evidence/标准化/投影纪律一致；但对话编号、对象清单和所谓“最终模型”不自动进入项目。经当前共同语言和领域不变量审查后，收口如下：

> 后续修正（2026-08-20）：下面“暂称 Observation Intent”的表述只保留当时讨论轨迹，已被 Gate 3 的进一步决定取代。当前规则是持续观察目标与主动研究问题保持不同身份和生命周期，不建立统一 `Research Intent / Observation Intent` 父对象；“观察目的”仅是责任总称。

- 保留“持续观察目标与主动研究问题需要统一目的入口”的责任，项目暂称 Observation Intent。它只说明用途与授权，不拥有 Source Object、Evidence 或 Observation；同一次 Observation 可以服务多个意图。
- 保留 Source Object 作为稳定来源身份、Observation 作为版本化对象状态；拒绝“一份 Evidence 等于一份 Observation”和“一个 Research Intent 复制一份 Observation”的固定基数。
- Observation 只保留 Evidence 能直接支持的对象状态。Topic 分类、用户角色推断、医学解释、趋势和市场含义属于 Derived Analysis 或 Claim；`孩子坐着不动 → 执行功能障碍` 不得进入 Observation。
- 不采用 `Raw Evidence / Normalized Evidence` 两个平级真相层。原始采集包、被接纳 Evidence、来源状态 Observation 和可重算 Derived Analysis 按资格分责；“经过清洗”本身不决定身份。
- 修正“Topic 描述存在、Claim 描述发生”：Topic 定义系统当前采用的领域语言；Claim 对存在、关联、变化、需求、机会或行动价值提出可争论主张。人工确认授予当前发布/使用资格，不把候选变成现实真理。
- Topic 的定义性/知识性关系与数据共现、市场关联、因果假设分开。后者先是有输入与版本的 Derived Analysis 或 Claim，不能因为人工点击确认就写成正式父子关系。
- Corpus 不是复制的评论池，也不只是页面投影；可长期保存用途、选择规则和成员历史。Topic Map 是知识导航视图；CLI/Agent Interface 是受控服务入口，不把三者压成同一种 Projection。
- Decision、Action、Outcome Observation 和 Evaluation 分开。Outcome 只能通过新 Claim 或有记录的定义修订影响后续认知，不能直接“反向更新 Knowledge”。
- 当前唯一一级 Domain 仍为 ADHD，`家庭干预`是 Topic/研究范围。对话提出的第二 Domain、Domain Relationship、Domain Seed、万能 Knowledge Graph 和固定 10/12 个核心对象不进入当前首期模型。
- “Knowledge Layer First”可以描述重视长期知识资产，但不取代已确认的“领域情报研究系统”核心定义；外部 Agent 仍可以在隐私和用途授权下检索真实原声，不被强制只能读取已确认知识。
- 不新增 `Gate 3-A`。所谓“采集现实约束反向审查”属于 Gate 4 的 producer、Identity、Time、Coverage、工位和插件合同审计。
- 外部讨论使用的 `DEC-01`–`DEC-15` 只是该对话内部编号，与本项目活动计划中的 `DEC-01`–`DEC-05` 无关，不写入项目决定目录。

## 2026-08-19 DEC-01 真实材料隐私与传播边界

- 公开可见不等于允许无限制长期保存、逐字展示、批量导出、模型训练或外部传播。ADHD、儿童、家庭、医疗和可反向识别材料进入更严格的用途与访问边界。
- 原始 Evidence 可以按明确用途在内部受限区长期保存，但“长期”不是“永久”；固定期限、加密、角色、访问审计和法律适用性由 Gate 5–7 与必要的专业审查确定。
- 普通工作台默认显示脱敏片段。脱敏必须同时考虑直接身份字段、原话反向搜索和多个上下文线索组合识别，不能只删除昵称后继续逐字公开。
- 外部 Agent 默认只能读取聚合结果、脱敏片段和受控 Evidence 引用，不得批量读取原文。内部真实材料实验仍需逐次说明目的、最小样本、访问、输出与结束处置；第三方模型处理合同未确认前，不发送原文。
- 获准的删除、撤回、脱敏或访问限制必须传播到 Corpus 选择、全文索引、embedding/feature、摘要、引用、缓存和 Agent 输出。历史 Claim/Intelligence 不静默消失，而是标记来源资格变化并重新评估；仅保留不含原始敏感内容的最小处置审计痕迹。
- 平台页面消失或暂时不可访问只是一种来源状态，不自动等同于收到隐私撤回请求。两者必须分开记录，避免误删历史或继续传播已明确撤回的材料。
- 本决定不开放原文 CLI、不授权扩大真实材料采集，也不提前创建隐私表、固定权限等级或审批系统。

## 2026-08-19 DEC-02 第一阶段每日主任务

- 第一阶段用户每天进入 Linggan 后，先看到少量值得关注并需要判断是否深入的事项，而不是默认进入完整 Topic 目录、评论数据库或指标大盘。
- 每个事项必须说明为什么现在出现、当前观察范围、支持与反例/缺失、证据资格和决定后果；用户再选择暂不处理、继续观察、进入 Topic 深入研究或提出行动。
- Topic 是点击后的核心深入工作区，继续组织真实原声、创作者叙事、长期历史、近期观察、Coverage 和 Evidence。每日入口与 Topic 不是二选一，而是“发现重要事项 → 深入理解”的前后关系。
- 进入每日入口只代表值得注意，不把候选变化、证据缺口、观察异常或待授权事项统一升级成 Signal、Intelligence 或现实变化。
- 没有合格事项时显示“没有形成新的合格事项”；任务未运行、Coverage 不足或分析未完成时显示“观察不完整/无法判断”。不得为了保持每日内容量而生成假趋势、机会或空洞简报。
- 本决定只确认每日任务和信息顺序；首页名称、导航、卡片数量、评分、通知、按钮、物理 Inbox 对象和第一条实现切片仍分别由 Gate 7 与后续 SCOPE-001 决定。

## 2026-08-19 DEC-03 外部 Agent 委托深度

- 第一阶段外部 Agent 采用“可读、可分析、可建议、可申请，但未经人明确授权不能直接执行有后果动作”的边界。它不是共享全部权限的超级用户，也不能因代表 Mog 或团队就绕过产品合同。
- 每次调用必须能够回到具体调用者与委托范围：代表谁、目的、Domain、可读数据、允许动作、期限、资源边界和输出传播范围。同一个 Agent 在不同任务间不自动继承永久权限。
- 委托范围内可以读取聚合结果、脱敏片段和受控 Evidence 引用，运行可重算且不改变正式世界的分析，并提交带来源的候选建议、补证申请、知识修订申请或行动提案。
- 申请只是等待决定的请求。改变正式 Topic/Claim、长期观察方法、真实采集范围、受限材料传播或现实行动必须由人明确授权；批准也只表示允许后续系统尝试，不表示已经采集成功、知识已成立或行动产生结果。
- 获准后的真实采集仍经过 Evidence 复用、采集准入、工位/账号调度、producer 和 Evidence 接入；知识修订仍经过定义/判断治理；现实行动仍经过 Decision、Action、Outcome Observation 和 Evaluation。外部 Agent 不直接创建插件工作、直连数据库或把自己建议的扩采结果用于自证。
- 本决定不冻结角色表、权限等级、授权字段、预算模型、CLI 命令、MCP、审批页面或认证方案，也不授权现在实现 CLI、权限系统、Agent 内核或插件升级。

## 2026-08-19 DEC-04 第一阶段 Outcome 最低边界

- 第一阶段不把深度评论、私信、咨询、报名、销售、访谈或产品使用定义成自动主 Outcome：这些渠道当前没有打通，系统没有资格承诺能够稳定取得。
- 最低产品承诺改为 Decision 与 Action 可追溯、结果渠道可获得性可见，并只保存实际取得且来源明确的结果。未接入、未观察、观察窗口未结束或来源不合格必须保持未知，不能记为 0、失败或“没有结果”。
- 结果按来源资格分为：真实 producer 与运行时合同支持的系统观察；带提供者、时间、依据和精度边界的人工/外部陈述；当前不可观察。人工陈述只证明有人这样报告，不能自动成为平台、销售或用户行为事实。
- 公开点赞、收藏、评论数、分享和浏览等指标仍需证明我们的 Action 与真实平台对象稳定关联、producer 来源合格、观察时间和缺失可追踪。旧 schema 有字段、旧页面有数字或任务完成都不能替代这条证明。
- 第一阶段不承诺完整自动反馈闭环，不冻结主成功指标、渠道枚举、人工补录页面、同步频率、归因算法或 Outcome 表。Outcome Observation 与 Evaluation 继续分开，任何结果都不能直接证明原 Intelligence 正确。

## 2026-08-19 DEC-05 第一阶段趋势承诺边界

- 第一阶段不承诺“市场正在增长/下降”的正式趋势判断。跨账号、工位、时间、搜索入口、Coverage、平台排序、内容生命周期和分析版本的可比性尚未由真实实验建立，继续标记为 `SOURCE_INCOMPLETE`。
- 第一阶段可以展示“近期观察”：只描述明确时间范围和实际捕获面中看到了什么，并同时说明 Coverage、来源和分析版本；它不表示前后可比，也不外推平台总体或 ADHD 家庭总体。
- 系统可以形成“候选变化”：说明观察到什么差异、哪些条件可能解释该差异、有哪些反例或缺口，并用于继续观察、主动研究或用户决定；候选变化不能因为进入首页、Topic 页面或报告就升级为趋势。
- 正式趋势必须等待 Gate 4 的真实 producer/跨时间与账号可比性实验，以及 Gate 5 对单位、分母、时间、Coverage、版本和统计资格的设计通过。资格按被证明的具体范围逐项开放，不建立一个全局 `trend_ready` 开关。
- 本决定不删除长期趋势能力，也不授权当前实现趋势算法、阈值、数据库表、固定窗口、基线任务或趋势 Agent。

## 2026-08-19 Gate 3 搜索发现与详情采集边界

- 搜索、作者页和其他低成本发现与逐篇详情/评论采集正式分责。发现执行可以独立结束；发现 N 条不授权插件自动打开 N 篇详情，任何新增详情访问仍经过 Evidence 复用、去重、身份解析、授权、资源和风险准入。
- 搜索接口返回和页面实际可见是两个不同的来源陈述。发现面 Evidence 可以证明某个入口当时返回或展示了什么，但不能替代笔记正文、评论、精确发布时间或其他详情 Evidence，也不能直接成为 Topic、市场总体或趋势事实。
- 发现记录保留入口、查询/计划、时间、顺序/排名、观察身份和 Coverage。身份充分时可以据此建立或复用最小 Source Object；这只确认“它是谁”，不生成完整 Note Observation。身份有歧义或冲突时保留实际发现和影响，不勉强制造对象。
- 身份是否解析、语义是否相关、是否值得继续采集分别属于身份、分析和资源/行动问题，不采用混合三者的 `Candidate Source Object` 万能状态。搜索词只保留为发现路径，不自动成为 Topic 关联。
- 现役 V2 源码证明搜索 API 捕获、页面可见卡片读取、表层扫描和逐篇详情采集能力客观存在，但历史代码把表层记录写入旧 noteStore 的方式不构成新项目数据模型；具体字段、保留方式、批量大小、间隔和风险阈值继续标记为 Gate 4 `SOURCE_INCOMPLETE`。
- Gate 4 必须执行真实搜索页 producer 探查：对账 API 与页面可见、逐字段来源、身份、顺序/终止、Coverage、失败和风险；并用“返回 50、可见 35、只批准 5 条详情”的压力场景证明发现不会隐式放大成全量深采。单次未触发验证码不证明安全。

## 2026-08-19 Gate 3 Capture Package、Evidence 接受与 Observation 边界

- 采集发生记录、Capture Package、Evidence 接入、Accepted Evidence、Source Identity Resolution、Source Object/Observation 和 Derived Analysis 正式分责。包只是 producer 的交付，不因字段合法或任务成功自动成为 Evidence；Evidence 被接受也不证明来源内容真实、完整、有代表性或适合任何 Claim。
- Capture Package 可以包含头、零到多条来源 Record、Coverage/终态来源事实和按合同需要的 Artifact。V2 已存在 `platform_response`、`page_snapshot`、`dom_fragment`、`media_inventory`、`context` 等 Artifact 类型，因此不新增一个所有 producer 必经的独立 Raw Artifact 真相层；哪些材料必需和怎样保留等待 Gate 4–5。
- 包级 Evidence 接入采用原子边界并区分幂等重放与采集身份/hash 冲突；冲突必须隔离且不进入下游。包被接纳后，身份解析、对象归属和 Observation 形成按 Record / Source Object 隔离失败：单条坏记录不能让其他合格记录无故失效，也不能被整包成功掩盖。
- 无效包、目标错误、身份冲突、风险中断和解析失败必须留下安全发生/失败记录、终态、Coverage 与影响范围；但这不自动把无效包变成 Evidence，也不授权永久保存全部敏感原始载荷。完整无效载荷的隔离范围、访问与期限留给 Gate 4–5。
- 缺少稳定身份的评论文本不创建 `Expression Object`、Comment、Source Object 或 Observation 兜底；它只能保持未解析材料或受限 Corpus 片段候选，并保留原包位置、身份缺口和用途限制。V2 的 `noteId + commentId` 只是小红书评论身份的审计起点，不是未经探查的新项目最终合同。
- Observation 只表达 Evidence 能直接支持的来源对象状态。表达簇、作者一段时间的内容方向变化、Topic 关联、趋势和市场含义属于 Derived Analysis 或 Claim；来源字段解析/格式转换与 AI 语义解释不得合成万能 `Evidence Interpretation` 层。
- 正常复观测、parser 更正、同一时间不同来源陈述不一致、来源明确删除、本次不可访问和隐私处置是不同语义；不得通过一个 upsert、统一 `conflict` 或 Source Object 万能生命周期覆盖旧历史。Evidence 也不建立跨用途全局可信度分数。
- 本项确认当时仍未确定 Attempt/重试/分块/checkpoint 与 Package 关系；该最小语义关系后来已在 Gate 4 单独确认。无效原始载荷隔离期限、Comment/Metric/Media 完整合同、各类时间的真实 producer 来源与最终字段，以及 Current 的持久关系、事务和重算方式仍依次进入 Gate 4 producer 实验与 Gate 5 数据设计，不由本决定创建表。

## 2026-08-19 Gate 3 Observation 历史、来源差异与时间语义

- Observation 只追加：正常较晚复观测形成新 Observation；迟到材料保留原观察时间与较晚接收/接纳时间，不因较晚入库伪装成世界较晚变化，也不能让较新的 Current 倒退。
- 同一 Evidence 的 parser、字段来源或时间精度修正属于有血缘的 Interpretation Revision，不制造新世界 Observation。旧解析继续可追溯；依赖旧解析的 Current、Derived Analysis 或 Claim 可以被有记录地重新计算和评估。
- Source Discrepancy 与采集身份/hash 冲突、跨时间变化和 parser 错误分开。API/页面等合格来源在相近条件下给出不同值时必须并存；未完成真实来源优先审计前，第一阶段不取最大值、平均值或最后写入作为无条件真相，Current 允许未知或待裁定。
- Current Resolution 被确认为带来源、规则和理由的可重算读取责任，不是 Evidence、永久真相或第二事实源。任何当前值都必须能回到 Observation/来源陈述；部分 Observation 不能清空既有合格字段，也不能被无来源地拼成一次完整快照。整对象/字段级/混合物理方案留给 Gate 5。
- 时间责任分为 producer 执行、实际观察、服务端接收、Evidence 接纳、来源事件陈述和 parser/analysis 派生时间；它们不能互相替代。V2 已证明按 `observedAt` 防 Current 倒退和同时间歧义 fail closed，但当前 Ingress 未落实 schema 预留的客户端时钟偏差/时间来源字段，因此只继承不覆盖历史的原则，不照搬“最大 observedAt 决定全部 Current”。
- 小红书“1 个月前”等原始相对表达保持来源陈述；当前插件按固定天数推算的毫秒值不进入新项目精确事实。Gate 4 必须对照 API/页面字段、时钟偏差、相对时间精度、删除/不可访问来源和字段优先资格；Gate 5 决定持久关系、Current 事务、冲突/未知和值级来源。
- 来源明确删除、本次不可访问和获准隐私处置继续分责：不可访问首先影响本次执行与 Coverage；删除需要合格来源陈述；隐私处置沿血缘传播并不改写为来源生命周期。
- 本决定未创建业务代码、数据库模型、Current 服务、Resolution Engine、AI Agent 或插件升级，也不确认最终字段、状态枚举或来源优先级。

## 2026-08-20 Gate 3-4 正式领域语言确认

- Topic 被确认为长期 `Topic Identity` 与不可静默覆盖的 `Topic Definition Version` 两种责任：身份回答历史引用指向哪个概念，定义版本回答某个时期怎样命名、界定、包含和排除。保持同一身份会误导旧材料或旧判断时，必须创建新身份并保留血缘。
- `Domain Definition Release` 是某个时期正式采用的 Topic 定义、首选名称、Alias 和 Knowledge Relation 的可复现逻辑清单；“当前正式”来自明确发布决定，不由最后创建、最大版本或最后更新自动决定，也不要求 Gate 5 物理复制整套词表。
- 新定义发布与历史重分类、统计和页面投影就绪分开。发布后尚未重算时，页面和查询必须明确显示未就绪，或继续使用并标明旧定义/分类版本；禁止新定义标题搭配旧统计而不说明。
- Candidate Topic 被确认为一种 Knowledge Change Proposal，而不是半正式 Topic。聚类和模型产生的临时标签首先属于固定输入与实验词表快照的 Analysis Run；只有需要提交、比较、决定或长期追踪时才形成持久提案。
- 正式 Domain Definition Release 与 Experimental Analysis Vocabulary Snapshot 分开。Classification Run 必须固定实际输入集合、所用正式发布或实验词表快照、模型/规则/提示和运行版本；新运行不覆盖旧运行。
- Term 是语言表达，不等于 Topic。首选名称和 Alias 是 Term 在指定语言、语境和 Topic Definition Version 下的关系；同一 Term 可以多义。用户原话与 Collection Seed 分别保留来源表达和发现动机，不自动成为正式词表关系。
- Knowledge Relation、数据共现/相似/因果假设和 Map View 导航分开。正式层级关系在同一发布版本内不得自引用或成环；普通 related-to 可形成网络；导航移动只改变找路方式，不改变 Topic 定义或分类。
- Topic 的拼写修正、改名、边界修订、拆分、合并和导航移动分别治理。拆分通常产生多个新身份，合并通常产生新身份；旧 Claim、人工分类、模型分类和统计不自动继承给新 Topic。纯展示修正保留编辑记录，不制造语义版本或重审批。
- Human Adjudication 追加具体分类裁定、理由与依据，不覆盖机器输出，也不自动改变正式 Topic 定义。历史必须能比较固定数据下模型解释变化和固定模型下世界输入变化。
- Claim 被确认为有主张、范围、时间和当前依据的重要可争论判断，不是万能三元组，也不要求每个统计都持久化。支持、反例、评估、取代和撤回不能压成一个原地覆盖的 confidence；冲突 Claim 可以并存，“当前不采用”不等于已证明为假。
- 正式 Topic 定义与 Knowledge Relation 是当前采用的领域语言，不复制为 Claim。Claim 可以支持或挑战 Knowledge Change Proposal；人工发布语言或确认 Claim 都只授予当前使用资格，不制造现实真理。
- 会改变正式语义的知识提案必须由人决定，并显示准备改变什么、依据和反例、影响的分类/统计/页面、重算要求与可撤回性；页面采用、模型置信度或 AI 建议都不能自动发布。
- 本确认只收口候选设计 A。候选设计 B 与 C 在该时点均尚待确认，后于同日分别确认；A 的确认本身没有创建数据库表、知识图谱、统一 Claim 表、AI Agent 或插件升级。

## 2026-08-20 Gate 3-B 研究、采集权力与行动反馈确认

- 持续观察目标与主动 Research Question 被确认为两种不同责任，不建立万能 `Research Intent`。前者说明长期关注什么，后者说明本次要弄清什么；二者都不进入 Source Object、Evidence 或 Observation 身份，同一 Observation 可以被多个目的复用。
- 观察目标、Collection Plan 和实际运行分开。计划说明准备怎样观察；实质扩大问题、来源、时间、深度、成本、风险或比较口径必须形成新范围/新版本，不能静默修改原问题或借用旧授权。
- Research Project 只在跨多轮问题、多人协作、长期材料组织或多个决定需要连续性时作为工作容器；简单查询不必创建项目，也不由此创建万能研究对象或通用 Workflow。
- Information Need 说明当前判断还缺什么，不是插件命令。它可以由已有 Evidence、新 Analysis Run、人工/外部合格材料或新采集满足；材料取得、用途适用、信息足够和研究停止分别记录，任务完成不自动关闭 Need。Research、Claim、Need 与 Evidence 允许多对多关系。
- Acquisition Request、Acquisition Authorization、Acquisition Admission 和 Work Order 分别表达申请、人的许可边界、执行前最新准入判断和 producer 有界工作。排队、预留或早期准入不产生永久执行资格，开始前必须重查已有 Evidence、等价在途工作、Need/探索目的、时间价值、授权、工位、账号和风险。
- Acquisition Authorization、Evidence 读取/处理/传播许可和插件设备 `PluginAuthorization` 是不同权力。授权固定明确申请/计划版本、范围、期限、资源与风险，计划修改不能扩大旧授权；采集获准也不自动允许原文展示、第三方模型处理或外部传播。
- 多个申请可以共享一次必要平台访问，但只合并执行，不合并原始动机、字段/Coverage、新鲜度、用途权限、保留要求或各自满足评估。允许在独立、有限、已授权且有停止条件的探索预算中降低未知，但探索材料不得混入稳定比较面自证增长。
- Knowledge Change Proposal、Acquisition Request 和 Action Proposal 按实际后果分开，不建立一次批准多种权力的万能 Proposal。Decision 固定所决定的确切版本、当时依据与反例，可以批准、拒绝、缩小、附条件、延后、要求补证或撤回；批准不证明执行或结果成功。
- Action Proposal/Plan、Action Attempt/Occurrence 和已由合格来源证明的外部动作分别表达。采集 Work Order 不是业务 Action；计划获批、排期、点击发布或任务完成都不能冒充内容已发布、访谈已举行或实验已启动。
- Expected Outcome 必须在结果出现前固定对应 Action Plan 版本、观察窗口、预期方向和依据；行动后新增解释只能进入 Evaluation。Outcome Observation 只记录实际结果与观察条件；Evaluation 解释有限支持、挑战或未知，不直接改写 Topic、Claim、Observation Plan 或 Evidence。
- 研究退出至少区分已回答、未获支持/受到反证、证据不足、继续不值得、范围改变和暂时中止。授权、资源、平台风险或 producer 故障造成的中止不等于 Need 满足、研究完成或假设为假；恢复前必须重查范围、时效、授权、资源和新材料。
- V2 的 TaskDemand/Link/ExecutionJob、队列领取/开始和插件设备授权只提供局部设计参考；固定源码缺少部分 demand/planner/eligibility 实现，也未证明 Evidence 复用、人的业务采集授权、完整 Research/Decision/Outcome 运行链。新项目不得把 schema 意图、设备令牌或任务完成当成闭环证据。
- 本确认冻结产品责任、权力边界和失败语义，不确认数据库表、关系基数、固定状态枚举、统一评分、工作流引擎、服务拆分、API、UI、算法、批量或安全停止参数；没有启动业务代码、数据库架构、AI Agent 内核或插件升级。候选设计 C 在该时点仍待独立确认，后于同日完成确认。

## 2026-08-20：Gate 3-C 应用资产与发布视图确认

- Corpus 被确认是同一来源材料上的用途化选择，不是第二份评论数据库。精确片段固定来源版本、范围与 hash；脱敏、翻译、转写、摘要、改写和语义标注各自保留转换血缘，不能互相冒充。
- 历史 Corpus Selection 与当前使用资格分开。曾被选择或使用不代表永久可读、可展示、可交给模型或可外传；每次有后果的使用按调用者、目的、受众、隐私状态、传播范围和策略版本重新判断。
- Retrieval Run、固定 Material Pack 与真实 Material Usage 分责。零命中、未保存、未采用、Coverage 不完整和权限拦截不能混成一个结果；普通浏览不强制永久记录，产生 Agent、Decision、引用或传播后果时保留足够复现链。
- Signal 保存有来源、有范围、有 Analysis Run 版本的派生发现；Attention Handling 只管理是否值得继续关注。被人看到、进入首页、重复出现或关闭都不自动改变 Claim 资格，也不把异常升级成正式趋势、需求或机会。
- Market Insight 与 Intelligence Brief 被确认是组织 Claim、分析、反例、限制和行动选择的不同版本化发布物，不是第二套 Claim。历史版本固定当时引用，后续 Claim 修订或来源资格变化追加影响说明；发布 Brief 不等于建议获批或行动授权。
- Content Idea 是内容工作资产，不是 Domain Topic 或 Claim 的下一级状态。人工经验是合法来源；机器建议、保存版本、采用 Decision、成稿、Publication/Action、材料真实使用和 Outcome Observation 分开。
- “内容角度”采用多维派生分析，不使用一个万能角度标签。若用于长期检索或跨期统计，必须固定定义、输入和分析版本，不能把聚类标签升级成正式 Topic。
- Agent 临时回答不自动形成 Intelligence。只有保存、共享、用于 Decision 或需要追踪时，才冻结委托、输入、输出和引用版本；输入 Evidence 血缘不替新生成事实、诊断、承诺或因果背书，也不扩大 Agent 权限。
- 本确认不创建 `CorpusSelection`、`Signal`、`Publication`、`ContentIdea`、`AgentAnswer` 等物理表，不确认统一状态机、报告模板、检索算法、抽样数量、Signal 阈值、AI 模型、页面或 CLI 协议。上述问题分别进入 Gate 5–7。

## 2026-08-20：Gate 4 Attempt / Capture Package 最小关系确认

- 一个 Work Order 可以产生零到多次 Execution Attempt；每次 Attempt 使用服务端分配的独立 Capture Identity。正常租约续期不制造新 Attempt，重新准入、租约失效后重做或其他执行重试必须形成新 Attempt。
- 第一版一个 Attempt 最多提交一个终态 Capture Package；没有可交付结果时为零个。复杂采集通过多个有界 Work Order 拆分，不提前引入可变多包或流式分块协议。
- 同 Attempt、同 Capture Identity、相同内容的网络重传是 replay；相同身份、不同内容是冲突。网络 replay 与现实执行 retry 不是一回事。
- checkpoint 只是可变运行进度，不能充当 Evidence、Coverage、观察成员清单、Package 或来源耗尽证明。
- 新 Attempt 不得把旧 Attempt 尚未接纳的本地记录或 checkpoint 静默改挂到新身份。确需挽救旧材料时使用有独立来源的 recovery/import；已经接纳的 Evidence 按用途复用不属于这种挽救。
- Package 接入保持全包原子；接纳后的来源身份解析、Source Object 归属、Observation 与派生失败按 Record / Source Object 隔离。
- authority 有效性检查与 Evidence 写入必须共享事务 fence 或等价原子条件，不能先检查授权、再在授权可能变化后无条件写入。
- 本确认固定语义关系和实现硬约束，不创建物理表、字段、队列、服务拆分或事务代码；这些进入 Gate 5–6。

## 2026-08-19 中期对抗审查的核实结论

以下是对外部中期报告逐条回到仓库源码、fixture、测试和现行文档后的项目结论。外部报告本身不进入权威层级：

- 小红书 producer 的 `publishedAt` 可能由“今天/昨天/N 天前/N 月前”等相对表达在观察时刻推算；月份按近似天数处理，归一化记录不总能直接说明实际解析了哪个来源字段。新项目不得忠实移植这种语义，必须保留原始表达、来源、参照时间、解析版本、时区和精度。
- 搜索结果在不同账号、工位和时间下是否可比较尚无真实实验结论，标记为 `SOURCE_INCOMPLETE`。这限制趋势判断，不否定搜索结果作为发现面 Evidence 和发现记录的价值。
- producer 能证明的是多种 Coverage 来源事实，例如扫描位置、返回数量、cursor/`has_more`、终止状态和失败；“这些事实是否足以支持某个承诺或判断”是用途相关、可修订的后续评估，二者不能压成一个百分比。
- 稳定来源对象与每次发现必须同时保留：对象去重不能删除入口、查询、计划、时间、排名、执行身份和 Coverage，也不能把多个发现次数当成多个现实对象。
- 身份失败至少分为执行目标不匹配、来源记录内部身份不匹配、相同采集包身份/hash 冲突和媒体主体不匹配；它们不能共享一个不分后果的错误语义。
- 版本化分析除了模型/规则，还必须知道实际输入集合。否则无法区分世界变化、观察面变化和模型解释变化。
- 真实 ADHD、儿童和家庭评论实验在开始前必须先有实验级最小隐私与传播规则；“内部验证”不是跳过最小化、访问、保留和撤回传播的理由。
- 当前 Bootstrap Rust crate 名称只是放置护栏，不是已确认的最终模块边界；最终模块与插件升级合同留给 Gate 6。
- 历史针对性测试只能按实际结果陈述：已运行断言的测试通过，不把因归档快照缺少依赖而无法加载的文件报告为业务失败，也不宣称全部历史测试已在当前环境复现。
- 外部报告提出的对象数量上限、固定 4–6 周工期和“六加一”骨架不采纳为退出条件。Source Object、Discovery Finding / 发现记录、分析输入集合、外部 Agent、Outcome、AI 内核、插件升级和 Gate 7 不能因此被省略。

## 已被实践证明的教训

- `success` 只能表示完整事实链完成，不能仅表示某个接口返回成功。
- TypeScript/Rust 类型不等于运行时合同。
- 测试必须主动攻击部分成功、并发、replay、跨 workspace、旧版本迟到和边界伪造。
- 同一个物理媒体可以对应多个业务 slot，不能因去重丢失业务语义。
- “采集成功”“合同接受”“Projection 可见”“现实 active”是不同事实。
- 上线证明系统不能无限扩张；在核心证据安全成立后，应尽早用真实小流量发现产品问题。
