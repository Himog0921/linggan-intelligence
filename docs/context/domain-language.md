# 项目共同语言

> 状态: 权威当前
> 最后核对: 2026-08-20
> 适用范围: DISC-001 已确认的产品与领域术语
> 事实来源: 用户在 DISC-001 中的明确确认
> 冲突时以谁为准: 用户最新确认和 ACCEPTED ADR；实现事实以真实代码、合同和测试为准

本文件只记录已经确认的共同语言，不记录数据库字段、技术实现或尚未裁定的候选设计。

## Linggan Intelligence（领域情报研究系统）

面向垂直领域的持续情报研究系统。它长期、可追溯地观察现实世界材料，组织领域语言与历史认知，帮助人和 Agent 发现变化、形成有边界的判断，并支持内容、产品和商业行动。

它的核心定义不会因为语料、主题地图、市场洞察、内容增长或 Agent 调用中的某个应用被深入设计而改变。长期价值是不断提高对一个领域的可追溯、可挑战、可修订认知能力；这不授权创建一个包办所有含义的“领域认知模型”对象。

## 应用能力、应用视图与服务接口

围绕特定用户任务，选择、组织和展示共同底层记录、定义与判断的产品能力。语料库、主题地图、市场洞察、情报、选题库、工作台页面和 Agent 接口都属于这一层。

应用能力可以保存自身的选择、布局、查询和版本，但不得复制一套与来源脱节的事实，也不得因为前端存在一个模块就推导出同名数据库表、Rust crate 或独立服务。页面通常是视图；CLI/Agent Interface 是受控服务接口，可以读取、提交提案或发起获准动作，不能被简单等同为只读 Projection。

## Corpus（语料库）

面向用户语言、内容表达和研究复用任务，对可追溯材料进行选择、组织、检索、分类、聚类、标注和受控引用的应用能力。它帮助人和 Agent 理解“人们怎样表达、在什么场景表达、哪些模式反复出现”，但不是评论数据库的别名，也不是最终情报。

Corpus 不替代 Evidence。同一份来源材料可以因不同目的进入多个语料选择，选择关系与转换过程需要保留；是否适合趋势判断、公开引用、模型训练或外部 Agent 全文读取，必须按具体用途另行判断。

## 受限原始材料、脱敏片段与隐私处置（DEC-01 已确认）

ADHD、儿童、家庭、医疗或能够通过账号、头像、原话、地点、学校、年龄、时间线等线索反向识别个人的来源材料，属于受限原始材料。公开可见只描述来源当时的可访问状态，不自动授予长期保存、逐字展示、批量导出、模型训练或外部传播资格。

原始 Evidence 可以在内部受限区按明确用途长期保存，但“长期”不等于永久；具体期限和分级规则留到 Gate 5。普通工作台默认使用脱敏片段；脱敏不仅移除直接身份字段，也必须考虑原话搜索、组合线索和上下文造成的反向识别风险。外部 Agent 默认只能取得聚合结果、脱敏片段和受控 Evidence 引用，不得批量取得原文。

隐私处置是经过授权的删除、撤回、脱敏或访问限制行为，不等同于来源页面暂时不可访问或在平台消失。获准处置必须沿来源血缘传播，使 Corpus 选择、全文索引、embedding/feature、摘要、引用、缓存和 Agent 输出停止继续使用受影响内容；已有 Claim 或 Intelligence 标记证据资格变化并重新评估，不被静默删除或继续伪装成证据完整。系统只保留合规允许且不含原始敏感内容的最小处置审计痕迹。

本节确认产品责任，不确认数据库表、加密方案、脱敏算法、固定保留天数、权限角色或法律合规结论；这些分别进入 Gate 5–7 和必要的专业审查。

## Domain（领域）

系统长期、持续研究的一级认知边界。

当前产品已确认的一级 Domain 是 **ADHD**。Domain 不是关键词，也不负责表达领域内部的具体分类。它在当前阶段相对稳定，但不是永远不可修订的宇宙边界；任何范围变化必须有记录并重新判断历史适用性。

## Topic（主题）

Domain 内部不断生长、拆分、合并或重命名的概念与问题。Topic 提供系统在某个版本中使用的领域语言和边界，不因被正式采用就证明对应现象普遍存在、正在增长或构成机会。

`ADHD 数学`、`家庭干预`、`作业拖延`、`执行功能`等属于 ADHD Domain 内的 Topic，不是与 ADHD 平级的 Domain。

## Continuous Observation Objective（持续观察目标，Gate 3-B 已确认）

说明系统希望长期关注什么对象、范围或变化。它是持续责任，不等于某次实际运行，也不等于实现它的 Collection Plan；计划改变、某轮执行不足和目标本身变化必须分别记录。

持续观察目标可以长期复用同一批合格 Observation，也可以产生新的 Information Need。它不进入 Source Object、Evidence 或 Observation 的身份，不能因为目标仍有效就无限产生平台访问。

## Research Question（主动研究问题，Gate 3-B 已确认）

为了当前判断、决定或行动，希望在明确 Domain、范围和时间边界内弄清的问题。它先复用已有 Evidence、Observation、Corpus、领域定义和历史 Claim；只有剩余信息缺口或受控探索仍会影响判断时，才申请新的分析或平台访问。

对研究对象、人群、来源、时间、成本或主要判断方向的实质扩大形成新的问题范围，不能静默改写原问题。研究可以不新增采集，也可以以已回答、假设未获支持或受到反证、证据不足、继续研究不值得、范围改变或暂时中止等诚实方式结束；中止不等于完成或结论为假。

## Research Project（专题研究，Gate 3-B 已确认的有限责任）

当一个主动研究需要跨多轮问题、多人协作、长期材料组织或多个决定时，用于保持整体目标、范围和历史连续性的工作容器。一次简单查询或单个 Research Question 不必创建 Research Project。

Research Project 不创建新的 Domain，不拥有 Source Object、Evidence 或 Observation，也不自动生成万能 Workflow。是否需要独立持久身份由 Gate 5 根据真实生命周期决定，不能因为产品上存在“专题研究”就预设同名表、服务或状态机。

## Information Need（信息需要，Gate 3-B 已确认；物理模型待 Gate 5）

说明为了当前研究、Claim、Decision 或受控探索，仍缺少什么信息，以及什么条件下可以认为当前用途已经得到满足。它描述知识缺口，不描述调用哪个插件、打开哪个页面或执行哪个 Work Order。

Information Need 可以由已有 Evidence、新的 Analysis Run、人工或外部提供的合格材料、新的平台采集共同满足。同一份材料可以服务多个 Need，同一个 Need 也可以依赖多份材料；每个用途分别评估字段、时间、Coverage、来源资格和访问权限，不能因一个任务完成就自动关闭 Need。

材料已取得、材料适用于当前用途、信息已经足够和研究决定停止是四种不同事实。已有 Evidence 足够时不产生新平台访问；证据不足但继续获取已不值得时，可以诚实停止并保留未满足部分。

## 每日关注与决策（DEC-02 已确认，页面名称待 Gate 7）

第一阶段用户每天进入 Linggan 后的首要任务：从持续观察、正在进行的研究和既有判断中，看到少量值得关注的事项，理解它为什么现在出现，并决定是否继续观察、进入 Topic 深入研究、提出行动，或暂不处理。

“值得关注事项”是用户注意力入口，不是一种新的事实或统一领域对象。它可以引用候选变化、证据缺口、观察异常、待授权事项或已有判断的状态变化，但必须保留各自真实资格，不能因为进入每日入口就统一升级为 Signal、Intelligence 或已证明的现实变化。

Topic 探索是主要深入工作区：用户从每日事项进入相关 Topic 后，继续查看真实原声、创作者叙事、长期历史、近期观察、支持与反例、Coverage 和 Evidence，再决定下一步。若当天没有合格事项，系统只能说明“没有形成新的合格事项”；观察未完成时必须说明未知，不能表述为现实没有变化。

本词只确认每日产品任务和信息顺序，不授权创建 `DailyBrief` 表、统一收件箱对象、通知系统、固定卡片数量、评分公式或页面布局。

## 外部 Agent 与委托范围（DEC-03 已确认）

外部 Agent 是代表某个已知调用者、通过 Linggan 受控产品接口使用数据或能力的 Agent。它不同于系统内部可重算的分类、聚类或分析运行，也不是共享全部权限的“另一种用户”；同一个 Agent 在不同调用者、用途或期限下可以拥有不同委托范围。

委托范围说明这次代理关系允许谁为了什么目的，在什么 Domain 和时间内读取什么、分析什么、提交什么建议、申请什么动作，以及结果允许传播到哪里。第一阶段允许外部 Agent 在范围内读取聚合结果、脱敏片段和受控 Evidence 引用，运行不改变正式世界的分析，提交有来源的候选建议，并申请有边界的采集、知识修订或行动。

“申请”只产生等待决定的请求，不产生真实采集、正式知识或现实行动；“批准”只授予后续系统尝试执行的边界，也不证明执行或业务结果成功。改变正式 Topic/Claim、长期观察方法、真实平台访问或现实行动必须由人明确授权，获准后仍分别经过正式治理、采集准入与 producer/Evidence 链或 Decision/Action/Outcome 链。外部 Agent 不得直连数据库、直接指挥 producer、批量取得受限原文，或同时扩大观察并用新增数据自证。

本节确认产品权力边界，不冻结固定角色表、权限等级、授权字段、预算模型、CLI 命令、MCP 协议、审批页面或技术认证方案；这些在 Gate 3–7 根据真实调用方和合同继续设计。

## 观察目的（责任总称，不是万能 Research Intent）

持续观察目标和主动研究问题都可以解释“为什么关注或研究”，但二者具有不同生命周期和产品责任，不建立统一的 `Research Intent` 父对象或状态机。

观察目的不拥有 Source Object、Evidence 或 Observation 的身份。同一次合格 Observation 可以服务多个目标、问题和 Information Need，必须通过可追溯使用关系连接，而不是为每个目的复制一份对象状态。手工导入、失败执行或业务目的未知的发生记录也不能因此消失；其实际来源和未知目的必须如实保留。

## Collection Plan（观察/采集计划）

为了实现某个持续观察目标、研究问题或已授权探索，定义观察对象、入口、范围、频率、Coverage 目标和执行方法的版本化计划。它说明“准备怎样观察”，不同于目标本身和某次实际运行。

Collection Plan 不负责定义内容“属于什么 Topic”，也不因为获批就证明某次运行已发生。会实质扩大来源、深度、成本、风险或比较口径的计划修订必须形成新版本，并重新检查授权；不能通过修改当前计划扩大旧授权。

## Acquisition Request（采集申请，Gate 3-B 已确认；物理模型待 Gate 5）

提出一次新的真实平台访问为什么必要、准备取得什么、服务哪个 Information Need 或受控探索、范围和所需 Coverage 是什么，以及预计消耗和风险。申请不等于许可、排队、插件工作或采集成功。

多个申请可以共享一次平台访问，但各自的原始动机、字段/Coverage、新鲜度、用途权限、保留要求和满足评估不能被合并掉。执行去重不等于需求、授权或用途合并。

## Acquisition Authorization（采集授权，Gate 3-B 已确认；物理模型待 Gate 5–7）

人允许系统在明确目标、来源、计划版本、期限、资源和风险边界内尝试新的平台访问。授权固定批准时的申请或计划版本；后续扩大范围必须重新决定。授权过期、撤回或条件不再满足时，排队和执行前必须重新检查，执行中的安全停止方式由后续具体工作合同决定。

Acquisition Authorization 与 Evidence Access/Use Authorization、插件设备 `PluginAuthorization` 是三种不同权力。插件令牌有效只证明设备可以接入；材料读取/处理/传播许可只说明某种用途可以使用既有材料；两者都不能替代新增平台访问授权，采集获准也不自动允许展示原文、交给第三方模型或对外传播。

## Acquisition Admission（采集准入，Gate 3-B 已确认；物理模型待 Gate 5–6）

在新的真实平台访问进入执行队列之前，判断这次访问是否仍有必要、是否已获授权、是否值得占用有限工位的责任边界。

采集准入至少先判断：已有 Evidence 是否足够、等价需求或在途执行是否已满足目标、Information Need 或探索目的是否仍有效、是否属于有意复观测、所需 Coverage 与新鲜度、授权是否仍覆盖当前计划，以及时间价值、工位、账号和风险预算。排队、预留或较早准入不是永久许可，实际开始前必须按最新事实重评估。

准入结果不只有“创建任务”，也可以是复用已有 Evidence、共享一次必要访问、合并等待、延后、过期、拒绝或返回结构化原因。它是责任边界，不因此预设独立微服务、统一评分器或数据库表。

## Work Order（有界执行工作单元，Gate 3-B 已确认；producer 合同待 Gate 4）

服务端交给 producer 的最小、明确、有边界工作：目标、允许能力、输入、最大范围、停止条件和回执要求都已确定。Work Order 只负责“这一小步做什么”，不拥有研究意义，也不允许插件自行扩大到下一阶段。

作者索引、笔记详情、评论发现、回复分页和媒体处理可以按真实 producer 能力形成有依赖的多个 Work Order；具体拆分、批量、租约、checkpoint、重试和安全停止仍由 Gate 4–6 证明，不能在共同语言里拍脑袋固定。

## 受控探索（Gate 3-B 已确认）

当系统尚不知道具体 Claim 或 Information Need、但发现可能值得降低的未知时，可以在独立、有限且已授权的探索预算中申请平台访问。探索必须说明想降低哪类未知、来源/成本/时间边界、停止条件，以及为何已有 Evidence 不能回答。

探索不等于无目的扩采。探索所得材料不得未经可比性处理进入稳定观察分母，也不得因“发现更多相关内容”反向证明候选现象正在增长。

## 有意复观测

为了比较同一现实对象在不同时间的状态而进行的新一次观察。它与同一时间窗口内的重复请求不同，不能被普通去重消除。

同一对象被多个关键词或研究需求发现时，可以复用同一次合格采集结果；但原始采集动机、每条发现路径和后续复用关系必须分别保留。后来的复用不能倒写成当初的采集原因。

## Capture Occurrence（采集发生记录，责任已确认，最终 producer 术语待 Gate 4）

系统针对一个有边界工作实际尝试了什么、由哪个 producer/版本/工位/账号在何时执行、怎样结束、哪里失败以及对 Coverage 造成什么影响的安全记录。它证明“采集行为发生过”，不证明来源对象已经被有效观察，也不因为没有形成 Evidence 就消失。

无效包、目标错误、身份冲突、风控中断和解析失败至少都要留下足以解释发生、失败、终态与 Coverage 的记录。是否在受限隔离区暂存完整原始返回、保留多久、谁能访问以及怎样处置，必须由 Gate 4 的 producer 合同和 Gate 5 的隐私/生命周期规则共同决定；失败记录不等于 Accepted Evidence，也不授权永久保存全部原始字节。

## Execution Attempt（执行尝试，Gate 4 已确认；物理模型待 Gate 5）

producer 在一份 Work Order 和一次有效执行授权下实际开展的一次有身份尝试。一个 Work Order 可以有零到多次 Execution Attempt；每次 Attempt 使用服务端分配的独立 Capture Identity。正常租约续期不制造新 Attempt；租约失效、重新准入或重新执行必须形成新 Attempt，不能把任务 ID、插件本地 run ID 或 checkpoint 当成 Attempt 身份。

Execution Attempt 是运行与权限边界，Capture Occurrence 是对实际发生、停止、失败和 Coverage 的安全记录。二者在 Gate 5 可以有紧密关系，但现在不预设同表或一一物理实现。

## Capture Package（采集包，语义责任已确认，物理合同待 Gate 4–5）

producer 针对一次有边界采集提交的完整交付单元。它逻辑上可以包含执行头、零到多条来源记录、Coverage/终态来源事实，以及合同要求的原始响应、页面快照、媒体清单或上下文等 Artifact。Artifact 是采集包中的可选或按合同必需材料，不预设一个所有 producer 都必须经过的独立“Raw Capture Artifact”真相层或数据库表。

采集包只是 producer 的交卷，不自动成为 Evidence。接入必须校验来源权限、目标和身份、包自身一致性、运行时合同、checksum/canonical 及重放/冲突语义。包级接入采用原子边界：同一包不能只写入一半来源材料却宣称接纳成功；包被接纳以后，后续身份解析、对象归属和 Observation 生成按单条 Record / Source Object 隔离失败。违反包级最低合同的 Record 会使包接入失败；只有接入后才暴露的对象归属或解释问题才进入下游隔离，不能让其他合格记录无故失效。

第一版确认一个 Execution Attempt 最多提交一个终态 Capture Package；没有形成可提交交卷时为零个。第一版不引入可变多包或流式分块协议，复杂采集通过多个有界 Work Order 拆开。未来若真实成本要求部分交付，每个分块必须拥有独立服务端身份并冻结成员，不能反复改变同一 Capture Identity 的内容与 hash。

同 Attempt、同 Capture Identity、完全相同内容的网络重传是 replay，不产生新 Observation；相同身份、不同内容是显式冲突并停止接纳。新 Attempt 不得把旧 Attempt 尚未接纳的本地记录或 checkpoint 静默改挂到新身份；确需挽救时走独立 recovery/import 并保留原来源。已经接纳的 Evidence 可以按用途复用，这与复用未接纳本地材料不同。

checkpoint 只保存可变运行进度，不是 Evidence、Coverage、观察成员清单或 Capture Package。它可以帮助同一 Attempt 少做重复工作，但不能证明页面已经耗尽、目标集合完整或恢复前后的观察天然可比较。

## Evidence Ingress / Acceptance（Evidence 接入与接受，责任已确认，最终术语待 Gate 4–5）

判断 producer 交付是否有资格成为系统接纳的来源材料。通过接入只说明来源、身份关系、包一致性与最低合同达到当前标准，不证明来源陈述真实、完整、有代表性或适合某个具体 Claim。

接入结果至少要区分：同一采集身份与相同内容的幂等重放；同一采集身份却对应不同内容/hash 的采集身份冲突；因合同或权限问题未被接纳；以及成功接纳。采集身份冲突必须隔离且不能继续下游。未被接纳的包保留安全发生/失败记录，但完整原始载荷是否隔离保存仍受明确保留与隐私政策约束。

Execution Attempt 的 authority 有效性检查与 Evidence 写入必须处于同一事务 fence 或等价原子条件，不能“先查仍有效、稍后无条件写入”。Package 接入保持全包原子；接纳后的身份解析、来源对象归属和 Observation/派生失败按 Record / Source Object 隔离，物理事务与重试方式进入 Gate 5–6。

## Discovery Execution（发现执行，责任已确认，最终 producer 术语与物理模型待 Gate 4–5）

系统实际执行的一次搜索、作者页扫描、话题页扫描或其他低成本发现动作。它记录“系统尝试通过哪个入口观察什么”，并与后续逐篇详情、评论或回复采集分开；发现执行结束不授权自动打开所有已发现对象。

同一次发现执行可以同时产生接口返回、页面可见结果、失败和 Coverage 来源事实。接口返回与页面实际可见是不同的来源陈述：前者只能证明 producer 收到了什么响应，后者只能证明页面在当时实际展示了什么；没有真实合同和比对实验时不得互相代替。

## Discovery Surface Evidence（发现面 Evidence，责任已确认，最终物理合同待 Gate 4–5）

系统从搜索或其他发现入口实际接纳的来源材料，例如接口返回的卡片集合、页面可见卡片和相应的查询、筛选、顺序、时间与 Coverage。它属于 Evidence，能够证明“这个入口当时返回或展示了什么”，但不能证明笔记完整正文、评论、精确发布时间、Topic 归属、总体市场或相关性。

发现面 Evidence 与详情 Evidence 证明不同主张，不能用“只有打开详情才算 Evidence”抹除前者，也不能用搜索卡片替代详情观察。原始响应、页面级快照和单条规范化记录怎样组合与保留，由 Gate 4 producer 审计和 Gate 5 隐私、成本与生命周期设计决定。

## Discovery Finding（发现记录，原 `Discovery Event` 候选术语，责任已确认）

在一次发现执行中，某个来源身份于特定入口、查询/计划、顺序或排名、时间、观察身份和实际 Coverage 下被返回或展示的可追溯记录。同一来源对象可以被多个关键词、作者页、研究或比较性观察重复发现；这些记录不能因对象去重而消失。

发现记录只能说明“通过什么镜头看到了什么”，不等于新的对象版本、完整详情 Observation、正式 Topic 关联或市场趋势。搜索词是发现路径，不是内容语义。最终英文名称和物理合同由 Gate 4 真实 producer 能证明的字段决定。

## Source Identity Resolution（来源身份解析，责任已确认，规则待 Gate 4–5）

根据平台、对象类型、平台稳定 ID、链接和其他来源陈述，判断一个发现记录是否足以解析为某个稳定 Source Object。身份解析至少要区分“已解析、仍有歧义、来源冲突”，不能把相关性、采集优先级或 Topic 分类混进身份状态。

当搜索卡片具有通过合同验证的稳定平台身份时，系统可以建立或复用最小 Source Object；这只确认“它是谁”，不确认正文、评论或详情完整。身份不足或互相冲突时保留发现记录和失败影响，不勉强制造 Source Object。

## Source Object / Source Identity（来源对象与来源身份，语义责任已确认，具体身份键待 Gate 3–5）

来源平台中长期可识别的现实对象及其稳定身份，例如某个平台上的一篇笔记、一条评论或一个作者。它与“系统这次如何发现它”“系统何时观察它”“模型怎样解释它”不是一回事。

对象去重只合并对同一来源对象的重复身份表达，不删除每次发现、每次观察和每个用途的来源关系。身份是否解析、语义是否相关、是否值得继续详情采集是三个不同问题；不能用一个 `Candidate Source Object` 状态混在一起。来源对象的最终类型、身份键和跨平台语义留到 Gate 3–5；不能用万能 `Object` 表或页面内部 key 提前代替。

缺少稳定来源身份的文本不能为了进入语料库而被制造成 `Expression Object`、Comment 或 Observation。它可以在来源允许时作为未解析材料或 Corpus 片段候选保留，但必须带回原采集包/位置、身份缺口和用途限制。当前 V2 小红书评论合同要求 `noteId + commentId` 才能形成评论来源身份；这只能作为 Gate 4 审计起点，不能代替新项目真实 producer 合同。

## Source Time Assertion（来源时间陈述，语义责任已确认，物理合同待 Gate 4–5）

来源页面、接口或 producer 对“某个事件何时发生”的陈述。它可能是平台给出的绝对时间、相对时间文本、producer 根据观察时间推算的时间范围，或无法确定。

系统必须区分原始时间表达、字段/页面来源、参照观察时间、解析规则版本、时区、精度和可接受范围。producer 推算出的 `publishedAt` 不能自动升级为平台已证明的精确事件时间，也不能未经资格检查进入窄时间窗口趋势。类似“1 个月前”的来源陈述首先是带参照时间和精度边界的陈述，不是一个由 parser 制造、精确到毫秒的平台事实。

## Time Responsibilities（时间责任，语义责任已确认，最终字段待 Gate 4–5）

系统必须分开表达：producer 实际执行工作的开始/结束时间；producer 看到页面或接口结果的观察时间；服务端收到采集包的接收时间；交付通过接入并成为 Accepted Evidence 的接纳时间；来源声称发布、评论或其他事件发生的来源时间陈述；parser、模型或分析产生结果的派生时间。

这些时间不能互相代替。较晚接收不代表较晚观察，较晚派生不代表现实刚刚变化，来源发布时间也不决定哪次 Observation 更新。最终字段、可信时钟、时钟偏差处理和各 producer 能提供的精度必须由 Gate 4 真实合同与 Gate 5 数据设计确认，不能从 V2 的 `createdAt`、`observedAt` 或插件本地时间直接照搬。

## Coverage Source Facts / Coverage Assessment（Coverage 来源事实与用途评估）

Coverage 来源事实记录 producer 实际扫描到哪里、返回多少、是否还有下一页、因何停止、哪些步骤失败或未运行。它们是可追溯发生记录，不因后来用途改变而重写。

Coverage 用途评估回答这些来源事实是否足够支持某个采集承诺或具体判断。相同来源事实对“读取正文”可能足够，对“评论完整性”或“没有相关讨论”的判断可能不足；评估必须带用途和版本，不能只保存一个全局百分比。

## Identity Failure Family（身份失败族，最终错误码待 Gate 4）

至少需要分开审计四类失败：执行结果并非所请求目标、来源记录内部的身份字段互相冲突、相同采集包身份对应不同内容/hash、媒体结果指向错误主体。它们对重试、隔离、安全、Evidence 接受和 Coverage 的影响不同，不能被一个笼统的 `identity_conflict` 吞并。

还必须把采集身份冲突与来源陈述不一致分开：同一 `captureId` 对应不同 hash 是接入冲突；同一 Source Object 在 API 与页面、或同一时间的两个来源中出现不同值，是需要并存和解释的来源差异；同一对象在较晚时间发生指标或状态变化，是正常复观测。三者不能共用“冲突后覆盖旧值”的处理。

## Observation（观察，语义责任已确认，物理模型待 Gate 3–5）

基于合格 Evidence，对稳定 Source Object 在一次可说明观察条件下、能够由来源直接支持的状态所作的版本化结构表达。它可以表达当时看到的正文、作者关系、来源时间陈述、可见指标或删除状态，但不能把模型推断、医学判断、Topic 分类、趋势或市场含义伪装成对象自带状态。

Observation 与观察意图是多对多复用关系，不把“这次为什么研究”写进对象事实身份。一个 Capture Package 可以产生零个、一个或多个有效 Observation；一个 Observation 也可能引用多份互相补充的 Evidence。具体基数必须由 Gate 4 真实 producer 合同证明，不能现在固定为一对一。

Observation 只追加，不在原记录上“修正”。较晚时间看到同一对象的新状态形成新的 Observation；较早观察的材料迟到接纳时仍保留原观察时间和较晚接收/接纳时间，不因为较晚写入而伪装成较晚世界状态。同一 Evidence 因 parser 或来源字段解析错误被重新解释时，追加有血缘的解析/结构化版本，不制造一次现实并未发生的新 Observation，旧解释仍可追溯。

同一时间不同合格来源给出不同值时保留来源差异，Current 可以保持未知或待裁定。暂时无法访问只证明本次执行未取得对象，不自动形成“对象已删除”；来源明确显示删除也必须保留来源资格。隐私处置属于另一个有授权、有传播规则的治理行为。

Source Object 不拥有一条把 `Discovered → Resolved → Observed → Changed → Deleted → Unavailable` 混在一起的统一生命周期：发现属于 Discovery Finding，解析属于身份结果，观察属于 Observation，变化属于派生比较，删除需要来源支持，不可访问首先是本次采集结果。

## Interpretation Revision（来源解析修订，语义责任已确认，最终术语与物理模型待 Gate 5）

针对同一 Accepted Evidence 修正 parser、字段来源识别、时间精度或忠实结构化表达的可追溯新版本。它保留原 Evidence、原观察时间、旧解释、修订原因、规则/adapter 版本和修订发生时间；不会因为生成时间更晚就把来源事件改写成“刚刚发生”。

Interpretation Revision 只修正系统怎样忠实表达来源材料，不能混入 Topic 分类、用户角色推断、趋势或市场意义。后者仍属于 Derived Analysis 或 Claim。

## Source Discrepancy（来源差异，语义责任已确认，来源优先规则待 Gate 4–5）

同一 Source Object 在相近观察条件下，由两个或多个通过合同的来源对同一状态给出不同陈述，例如 API 与页面显示不同点赞数。它不同于采集身份/hash 冲突、正常跨时间变化和 parser 错误；各来源陈述必须并存并保留自己的 Evidence、观察时间和来源位置。

没有真实 producer 审计支持的来源优先规则时，系统不得取最大值、平均值或按最后写入静默选出“真相”。若以后形成字段级来源优先规则，该规则必须版本化、可解释，且被选择值不能使其他来源差异消失。

## Current Resolution（当前状态裁定，产品读取责任已确认，物理模型待 Gate 5）

系统按照当前有效且可追溯的选择规则，从合格 Observation、来源陈述和解析版本中组织的当前读取结果。Current 不是新的 Evidence，不是永久真相，也不能只由数据库最后写入、最大 `observedAt`、最大 `receivedAt` 或一个全局可信度分数决定。

Current 可以因迟到材料、解析修订、来源差异或选择规则变化而重新计算，但不得覆盖旧 Observation。任何被展示为当前的值都必须能回到实际 Evidence、Observation/来源陈述、选择规则和理由；来源仍冲突或资格不足时允许保持未知或待裁定。是否使用整对象指针、字段级来源或有限混合投影，以及事务、状态和值域，由 Gate 5 决定，本轮不创建同名表。

## Derived Analysis（派生分析，语义责任已确认，物理模块待 Gate 5–6）

对明确输入集合执行的可重算处理，包括分类、聚类、embedding、统计、语义解释和 Agent 分析。每次运行必须能够说明实际输入、定义/规则、模型/算法、提示版本、时间、输出和限制。表达簇、作者一段时间内的内容方向变化、Topic 关联和趋势都属于这里或后续 Claim，不是 Source Object 的 Observation。

来源字段解析、格式转换和身份归一化若只忠实表达 producer 可验证的来源状态，属于 Evidence 接入或 Observation 形成过程；不能因为也叫“归一化”就与 AI 语义分析混成一个通用 `Evidence Interpretation` 层。派生分析可以形成 Topic 关联候选、关系候选或判断候选，但不会因为自动运行、置信度高或人工看过就变成来源事实。`Normalized Evidence` 当前不作为独立权威术语；结构化结果究竟属于 Observation 还是 Derived Analysis，取决于它是否只是来源可验证状态，不能按“清洗过”三个字决定。

Evidence 不拥有一个跨用途的全局可信度或置信分数。同一 Evidence 对“这段文本曾被返回”可能适用，对“该表达正在增长”可能不适用；资格必须在具体 Claim、用途、Coverage 与观察条件下评估。

## Topic Identity（Topic 长期身份，Gate 3-4 已确认）

一个领域概念跨名称、定义版本和页面位置变化时的长期引用身份。Topic Identity 回答“历史材料和判断指向的是哪个概念”，不直接保存某次模型分类、市场表现或导航层级。

只有在保持同一身份不会误导用户理解历史材料和旧判断时，才延续 Topic Identity。改名或可解释的边界修订可以保持身份并发布新定义版本；拆分通常产生多个新身份，合并通常产生一个新身份，旧身份继续保留历史与血缘。页面导航移动不改变 Topic Identity。

## Topic Definition Version（Topic 定义版本，Gate 3-4 已确认）

某个时期对一个 Topic 的名称、含义、边界、包含与排除条件的不可静默覆盖表达。新版本不会改写旧版本，也不会自动把历史材料按新含义重新分类。

纯拼写、排版或不改变语义的展示修正保留编辑记录即可；名称改变、概念边界修订、拆分、合并和导航移动必须按各自后果处理，不能统一成普通更新。

## Term / Preferred Label / Alias（术语、首选名称与别名关系，Gate 3-4 已确认）

Term 是真实语言中的词或表达，不等于 Topic。某个 Term 在指定语言、语境和 Topic Definition Version 下，可以被采用为首选名称或 Alias；同一个 Term 在不同语境中可以指向不同 Topic，因此禁止建立脱离语境的全局同义等价。

用户表达和 Collection Seed 也不等于 Term 的正式知识角色。搜索词只说明系统怎样发现材料；评论原话只说明来源怎样表达；二者都不能因为重复出现而自动成为 Topic 名称或 Alias。

## Domain Definition Release（领域定义发布，Gate 3-4 已确认）

系统在某个时期正式采用的 Topic Definition Version、首选名称、Alias 关系和知识关系的可复现逻辑清单。它表达“当前用什么语言组织 ADHD”，不是把全部词表物理复制一份的实现要求，也不是现实真理、分类结果、市场变化或页面导航。

“当前正式发布”必须来自明确发布决定，不能由最后创建、最后更新或最大版本号自动决定。新定义可以已经发布，而历史重分类、统计和页面投影仍未准备好；此时必须明确显示尚未就绪，或继续使用并标明旧分析版本，禁止把新定义和旧分类结果混成一个当前答案。

## Knowledge Change Proposal / Candidate Topic（知识变更提案 / 候选 Topic，Gate 3-4 已确认）

对正式领域语言提出新增、改名、边界修订、拆分、合并或关系调整的待决定提案。Candidate Topic 不是半正式 Topic；聚类产生的临时名称首先只是 Analysis Run 输出，只有需要跨运行提交、比较、决定或追踪时，才形成持久的 Knowledge Change Proposal。

会改变正式语义的提案由人决定。决策包必须说明准备改变什么、为什么、影响哪些分类/统计/页面、是否需要重算以及能否撤回。批准只发布新的正式语言版本，不证明相应现象普遍存在。

## Experimental Analysis Vocabulary Snapshot（实验分析词表快照，Gate 3-4 已确认）

某次探索、分类或聚类实际使用的候选 Topic、临时标签及其定义快照。它与正式 Domain Definition Release 分开；模型可以使用实验词表寻找未知结构，但不能把实验标签静默写入正式词表、长期统计或 Topic Map。

## Knowledge Relation（知识关系，Gate 3-4 已确认）

正式领域语言中对 Topic 之间概念关系的版本化表达。层级关系如 broader/narrower 在同一 Domain Definition Release 中不得自引用或形成循环；普通 related-to 可以形成网络。

Knowledge Relation 与数据共现、语义相似、市场关联、因果假设以及 Map View 导航路径分开。前者是当前采用的领域知识；数据关系属于 Derived Analysis 或 Claim；导航只帮助用户找路，不能改变 Topic 定义或制造知识关系。

## Classification Run / Human Adjudication（分类运行 / 人工裁定，Gate 3-4 已确认）

Classification Run 对一个不可变输入集合，按固定的正式 Domain Definition Release 或 Experimental Analysis Vocabulary Snapshot，以及明确的模型、规则、提示和运行版本产生分类结果。更换词表、模型或输入集合必须形成新运行，不覆盖旧运行。

Human Adjudication 是人对具体分类结果作出的追加裁定，必须记录理由和依据；它不删除机器原始输出，也不自动改变 Topic 定义。Topic 拆分或合并后，旧分类、旧统计和旧 Claim 不自动继承给新 Topic，是否重算与怎样解释必须另行决定。

## Map View（主题导航视图，Gate 3-4 已确认）

面向具体产品场景组织 Topic 浏览路径的版本化视图。它可以把同一 Topic 放入多个导航路径，也可以只改变展示层级；Map View 不等于 Domain Definition，不决定分类，也不因为页面移动而触发概念版本变化。

## Claim（可争论判断，Gate 3-4 已确认；物理模型待 Gate 5）

对明确范围提出、可以被支持、挑战、修订、取代或撤回的重要主张。Claim 不只描述“发生了什么”，也可以主张某种表达存在、某种关系可能成立、某种变化正在发生、某类需求未被满足，或某项行动值得考虑；普通可重算统计和每个模型标签不必都持久化为 Claim。

需要长期保存的 Claim 至少说明主张内容、适用范围、时间边界和当前依据。不同强度的 Claim 需要不同资格：简单存在性判断不强制承担 Intelligence 级全部流程；趋势、需求、机会、因果和行动价值必须逐步增加时间、观察面、统计单位、Coverage、支持、反例、不确定性和可能推翻条件。

支持材料增加、反例出现或评估改变不能被一个原地覆盖的 `confidence` 字段吞掉；相互冲突的 Claim 可以并存。“被取代、被撤回、当前不再采用”是治理结论，不等于系统已经证明主张为假。人工确认只允许 Claim 成为当前发布判断或下游依据，不把它变成不可争论真理。

正式 Topic 定义和 Knowledge Relation 是当前采用的语言，不重复保存为 Claim。Claim 可以支持或挑战 Knowledge Change Proposal，但不能与正式定义形成两份互相竞争的“当前词表”。

## Proposal Family（提案族，Gate 3-B 已确认）

系统或人可以提出三类后果不同的提案：Knowledge Change Proposal 准备改变正式领域语言；Acquisition Request 准备消耗资源访问真实平台；Action Proposal 准备采取内容、研究、产品或商业行动。它们可以共享决策包的展示和审计模式，但不能压成一个万能 `Proposal` 状态机或一次批准多种权力。

临时聚类、可重算统计和未产生后果的机器建议不必全部持久化为提案。只有需要比较、决定、执行、共享或长期追踪时，才冻结具体内容、版本和依据。

## Decision（决定，Gate 3-B 已确认；物理模型待 Gate 5）

人对一个确切版本的提案、申请或行动计划作出的有记录选择。Decision 必须固定当时看到的对象版本、依据、反例、未知项、资源影响、权限边界和理由；后来修改提案或依据不能让旧决定看起来批准了新内容。

决定不只有批准/拒绝，也可以缩小范围、附加条件、延后、要求补证或撤回。批准表示允许下一责任继续，不证明知识已经真实、采集已经发生、内容已经发布或结果已经成功。

## Action Proposal / Action Plan（行动提案 / 行动计划，Gate 3-B 已确认）

Action Proposal 说明建议采取什么现实行动及其理由；经决定采用后，Action Plan 固定实际准备执行的版本、对象、范围、时间和责任。内容选题、发布、访谈、实验和产品调整可以共享这套责任模式，但不因此被塞进一个巨大 `Action + payload JSON` 对象。

采集 Work Order 是 producer 执行工作，不属于业务 Action。行动建议、已采用计划、排期或预约都不证明现实行动已经发生。

## Action Attempt / Action Occurrence（行动尝试 / 行动发生，Gate 3-B 已确认）

记录系统或人实际尝试做了什么、何时开始和结束、执行到哪里以及如何失败或完成。点击发布但失败、计划通过但未执行、发布成功、访谈实际举行和实验实际启动是不同事实。

只有合格外部来源、平台回执或带来源边界的人工记录能够证明相应现实动作已发生。Action Attempt 不能因失败而消失，也不能因流程状态为“完成”就自动升级为外部动作成立。

## Expected Outcome（行动前预期，Gate 3-B 已确认）

在行动结果出现前，固定对应 Action Plan 版本、期望观察到什么、观察窗口、预期方向和当时依据。行动前可以有记录地修订；行动发生后新增的解释只能进入 Evaluation，不能事后补写成“早就预料到”。

行动实质改变后，旧 Expected Outcome 仍指向旧计划，不能继续冒充对新行动的预测。Expected Outcome 是行动假设，不是承诺，也不证明结果一定可获取。

## Outcome Observation（结果观察，Gate 3-B 已确认）

记录行动之后通过合格来源实际观察到的指标、反馈、事件或缺失情况。它只说明看到了什么以及在什么条件下看到，不自动说明行动导致了结果，也不能遗漏未执行、失败、未知或未接通结果渠道的行动。

## Evaluation（评价，Gate 3-B 已确认）

解释一组 Outcome Observation、环境条件和缺失对原 Claim、Expected Outcome 或行动假设提供了什么有限支持、挑战或新未知。Evaluation 追加版本，不覆盖 Outcome Observation，也不直接改写 Topic、Claim、观察计划或 Evidence。

## Research Exit / Suspension（研究结束与中止，Gate 3-B 已确认）

研究可以以当前问题已得到足够回答、假设未获支持或受到反证、证据仍不足、继续研究不再值得、问题范围已改变等理由主动结束；也可以因授权撤回、资源暂缺、平台风险或 producer 故障暂时中止。

中止不等于 Information Need 已满足、研究完成或假设为假。恢复时必须重新检查问题范围、材料时效、授权、资源和期间新增的 Evidence。研究、Claim 和 Evidence 是多对多关系，一次研究结束不自动关闭所有相关 Claim 或 Need。

## Source Span / Material Transformation（来源片段 / 材料转换，Gate 3-C 已确认；物理模型待 Gate 5）

Source Span 是固定到某个来源内容版本、明确范围和内容 hash 的精确片段。它只证明这段文字或媒体范围来自哪一版材料，不自动证明作者身份、内容真实性、代表性或任何市场判断。

脱敏、翻译、转写、摘要和改写是从来源材料产生的不同表达，必须保留来源、转换方法、版本和限制。转换结果不能反向覆盖原文，也不能把翻译、摘要或改写新增的含义冒充来源原话。普通一次性分析输出不必都获得长期身份；只有需要稳定引用、重复选择、治理或形成长期血缘时，才成为可寻址材料。

## Corpus Selection（语料选择，Gate 3-C 已确认；物理模型待 Gate 5）

Corpus 不是第二份评论数据库。Corpus Selection 记录某份来源材料或精确片段曾因什么用途、按什么规则、以什么角色、在怎样的访问边界下被选择。原始材料仍只由 Evidence/Observation 链负责，选择不得复制或改写来源真相。

历史选择与当前使用资格分开：来源撤回、隐私处置、用途变化或授权过期后，过去确实发生的选择和使用记录继续存在，但新的检索、展示、模型调用和外部传播必须按当前调用者、目的、受众、隐私状态、传播范围与策略版本重新判断。不得用材料上的永久 `allowedUse`、`featured` 或“正式 Corpus”单值代替具体用途资格。

“典型、反例、多样性、高表现、边界样本”只是在指定输入集合、捕获面和选择规则下的材料角色，不代表平台用户、ADHD 家庭或总体市场。缺少稳定 Source Object 身份但仍有合格采集包和不可变来源位置的材料，只能在受限资格下被选择，不能为了进入 Corpus 伪造 Comment、Expression 或 Observation。

## Retrieval Run / Material Pack / Material Usage（检索运行 / 固定材料包 / 材料使用，Gate 3-C 已确认；最终名称待 Gate 5–7）

Retrieval Run 回答“当时用什么请求、输入范围、过滤、规则和版本得到哪些候选”；Material Pack 回答“为某个目的固定保存了哪些材料引用”；Material Usage 回答“哪些材料真实进入了 Agent 上下文、决策包、报告、选题或成稿”。三者不能由一个 `resultCount` 或 `used=true` 代替。

普通无后果浏览不要求把完整候选集合、Material Pack 或回答正文全部长期保存；这不免除受限材料读取和外部 Agent 调用本身的安全访问审计。当结果被交给 Agent、共享、引用、用于 Decision 或进入内容生产时，必须额外保存足够的委托、输入、选择、资格和实际使用血缘。零命中、未保存、未采用、Coverage 不完整和因权限被拦截是不同结果，任何一个都不能被解释成现实不存在。

## Signal / Attention Handling（信号 / 注意力处理，Gate 3-C 已确认；物理身份待 Gate 5）

Signal 是一个有来源、有范围、有 Analysis Run 版本和限制的派生发现，说明某种变化、结构、异常或风险可能值得注意。Detector Event、统计异常或聚类输出先属于 Analysis Run；只有结果值得被引用、继续观察或调查时，才需要形成可寻址的 Signal Candidate。

Signal 可以支持或挑战 Claim，但不复制 Claim 正文、证据关系或判断资格；人工查看、保留或放入每日入口不会把它升级为正式趋势、需求、机会或行动价值。同一现象在不同运行中再次出现，只能在检查输入可比性、来源分散和模型差异后形成新的复现/持续/合并/分裂分析，不能按标题相似或累计次数原地提高“置信度”。

是否进入每日入口、继续观察、降级或停止投入注意力属于 Attention Handling。关闭只表示当前不再投入注意力，不表示分析从未发生、Claim 已证伪或现实不存在。Coverage 异常、证据缺口、授权申请和 Claim 状态变化也可以进入每日入口，但它们不是 Signal，不能共享一个万能状态机。

## Market Insight / Intelligence Brief（市场洞察 / 情报简报，Gate 3-C 已确认；分析发布模型待 Gate 5–7）

Market Insight 面向市场结构、用户表达、内容供给或变化解释，组织一组 Claim、Analysis Run、反例、限制和适用范围。Intelligence Brief 面向具体目标或 Decision，在此基础上进一步组织证据缺口、不确定性、备选解释、行动选择和行动价值。页面即时小结和一次查询回答可以是明确标注的可重算表达，不自动成为长期发布物。

当一份输出需要保存、比较、订阅、共享、引用为 Decision 依据或长期追踪时，才冻结版本。历史版本固定当时引用的 Claim revision、分析运行、材料选择集合、输入边界和正文，不随当前 Claim 静默变脸；后来 Claim 修订、来源失效或隐私处置时追加影响评估和当前阅读警示，必要时停止原文访问并生成脱敏或受限后继版本。

这里的“发布物”是把一份分析表达冻结为可引用版本，暂称 Analysis Publication 责任；它不同于把内容实际发到小红书等外部平台的 Publication/Action。分析版本被冻结不证明外部内容已发布，外部发布成功也不能反向把分析判断升级为真理；两者不得共用一个巨大 Publication 状态机。

Claim 是可单独支持、挑战和修订的判断最小单位；Market Insight 与 Intelligence Brief 是组织这些判断的不同发布视图，不建立第二套 Claim 真相。发布一份 Brief 不等于批准其中建议，更不等于授权现实行动。会扩大人群、时间、平台、因果、确定性、资源选择或对外承诺的重要新断言，必须引用已有 Claim revision 或先成为待审查 Claim，不能藏在自然语言正文里。

## Content Idea（内容选题候选，Gate 3-C 已确认；物理模型待 Gate 5–7）

Content Idea 是可编辑、可比较、可采用或放弃的内容工作资产，不是 Domain Topic，也不是 Claim 的下一级状态。它可以来自人工经验、原声、Topic、Signal、Market Insight 或 Intelligence；没有系统 Evidence 时如实记录人工来源，不伪造机器上游。

未保存的机器建议可以保持短暂输出；需要编辑、比较、Decision 或多次执行时，才固定可寻址版本。Decision 固定被采用的 Idea 版本；实际 Brief、成稿、Publication/Action 和 Outcome Observation 分开。成稿对材料的引用、改写或未采用另记真实使用血缘，不能因 Idea 有 Evidence 来源就把整篇生成内容标记为有证据。

“内容角度”是包含用户问题、目标人群、叙事立场、内容承诺、表达形式、情绪入口、内容目的和解决方案类型等维度的派生分析，不是一个万能单值标签。若某套叙事分类用于长期检索或跨时间统计，必须固定定义、输入和分析版本，不能把一次聚类标签变成正式 Topic。

一个 Content Idea 可以在不同账号、形式和时间被多次执行；Outcome 首先关联实际发生的 Publication/Action。多个结果是否共同支持某个 Idea，需要另一次有范围的 Evaluation，不能回写一个覆盖失败和环境差异的总分。自有内容被平台再次发现仍可成为 Source Object/Discovery，但必须关联原 Action 并与稳定市场基线隔离。

## Agent Answer（Agent 回答，Gate 3-C 已确认；接口与权限待 Gate 6–7）

一次受控 Agent 查询可以返回带范围、时间、来源、缺失和限制的临时答案，不自动形成 Intelligence Brief。只有答案被保存、共享、作为 Decision 依据或需要后续追踪时，才冻结调用者委托、请求、输入、输出、使用资格和引用版本。

输入血缘只证明 Agent 参考过什么，不证明新输出正确。Agent 新增的事实、诊断、承诺或因果仍需逐项满足证据、隐私和用途边界；长期保存回答也不扩大 Agent 的读取、传播、采集或行动权限。

即使回答不被保存为长期分析资产，外部 Agent 的身份、委托、受限数据访问、策略结果、资源消耗和调用回执仍按安全审计规则留痕；“不冻结完整回答”不能成为绕过访问审计的途径。

## 结果可获得性（DEC-04 与 Gate 3-B 已确认；物理模型待 Gate 5）

说明某个 Action 在当前时间有哪些结果渠道已经接通并具有合格来源，哪些只能由人或外部系统提供，哪些尚未接入或无法观察。它描述系统是否有资格取得和评价结果，不是结果值，也不是 Action 成功或失败状态。

第一阶段最低承诺是让 Decision 与 Action 可追溯，并如实区分三类结果：通过真实 producer 和运行时合同取得的系统观察；带明确提供者、时间、依据与精度边界的人工/外部结果；当前未接入、未观察、窗口未结束或来源不合格的未知结果。人工提供的“收到咨询/销售”等陈述只证明有人这样报告，除非另有合格来源，不自动成为外部系统事实。

深度评论、私信、咨询、报名、销售、访谈与产品行为目前没有已证明的完整自动链；公开点赞、收藏、评论数、分享、浏览等指标也必须先完成行动与真实平台对象关联及 producer 来源审计。未接入不能写成 0，没有 Outcome Observation 不能写成行动失败。第一阶段不承诺完整自动反馈闭环，也不因此创建统一 Outcome 表、固定渠道枚举、人工补录页面或指标同步任务。

## 比较性观察（已确认产品含义，最终英文术语待 Gate 4–5）

为了判断现实是否随时间变化，而在足以解释前后差异的相近观察条件下重复进行的观察。它像一把“尺子”：观察入口、范围、频率、排序、producer 能力或停止方式发生影响解释的变化时，必须留下新的比较条件，不能把前后结果直接混成同一趋势。

计划中的观察方法发生变化，与某一轮因为工位、登录、访问或其他失败而 Coverage 不足，是两种不同事实。前者改变比较口径；后者不改变计划，只说明本轮没有完整执行。

## 探索与调查观察（已确认产品含义，最终执行拆分待 Gate 4–5）

为了发现未知结构、理解候选现象或补齐研究证据而进行的弹性观察。它像“放大镜”，可以在授权和有限探索预算内调整表达、来源和深化范围，但不能静默改变比较性观察的尺子，也不能把新增调查材料直接用作市场增长证明。

比较性观察与探索/调查观察是两种证据用途和解释边界，共享同一 Evidence 底座；本轮不据此创建两套数据库、两个服务或两个固定队列。持续监控、探索发现、主动调查和补采等执行分类留到 Gate 4。

## 发现面快照（产品可读视图候选）

系统基于一次或多次可追溯的发现执行、发现面 Evidence 和发现记录，向人或 Agent 展示某个搜索或发现入口在特定时间与实际 Coverage 下返回或展示了什么。它是产品读取视图候选，不新增一层真相，也不与笔记详情 Observation 共用含义。

发现面快照不能称为市场普查，也不能证明平台全部相关内容、总体分布或前后变化。API 返回与页面可见若未完成真实对照，必须分别呈现，不能合成一句“平台展示了这些内容”。

## 近期观察（DEC-05 已确认产品含义，最终术语待 Gate 5–7）

对明确时间范围和实际捕获面中所见材料的描述，例如“最近 30 天在当前捕获材料中观察到 38 条涉及任务启动的表达”。它必须说明时间、入口或对象范围、实际 Coverage、分析版本与已知缺失；它描述系统近期看到了什么，不主张前后可比，也不主张平台或总体市场正在增长、下降。

## 候选变化（DEC-05 已确认产品含义，最终术语待 Gate 5–7）

系统观察到前后差异，但可比性尚未完全成立、替代解释尚未排除或证据仍需补充时形成的可挑战分析。候选变化可以进入持续观察、主动研究或用户决策入口，但不得显示为正式趋势。账号、工位、入口、Coverage、内容年龄、平台排序、Topic/模型定义或分析输入变化都必须作为可能解释保留。

## 趋势判断（DEC-05 已确认资格边界，最终术语待 Gate 3–5）

关于某个明确对象、单位或结构在两个或多个时间窗口中发生方向性变化的 Claim。它至少需要版本化且可比较的观察面、明确单位与分母、合格时间、Coverage、来源集中检查、固定或可解释的定义/分析版本，以及支持、反例和无法排除的解释。第一阶段不承诺发布正式趋势；Gate 4–5 的真实可比性实验通过后，才能按被证明的范围逐项开放。即使成立，也不自动等同于平台总体、ADHD 家庭总体、需求增长或市场机会。

## 五类长期积累视角

以下五类用于说明产品长期复利来自哪里，不是五种平级数据库对象，也不表示语料库、主题地图、市场洞察、情报和选题库分别维护自己的真相。

### 世界事实资产

保存系统过去收到、接纳和形成的观察记录、观察边界与历史状态，包括采集记录、Evidence、来源对象、Observation 与 Coverage。它回答“系统在什么条件下看到了什么”，不证明来源内容必然真实、完整或代表现实总体，也不得被后来判断改写。

### 语料与表达资产

对正文、评论、回复、转录、用户原话和创作者表达进行的用途明确选择与组织。它回答“哪些语言材料因什么目的值得反复研究和引用”，必须保留来源、筛选与转换过程、版本、质量和访问边界；不得为了形成语料而复制第二份来源真相。

### 领域知识资产

用于共同理解 ADHD 的 Topic、Term、Alias、定义、分类和关系版本。它回答“我们在某个时期如何组织和解释这个领域”，必须区分人工定义、数据观察、模型分类和产品导航。主题地图是这些知识的导航视图，不是独立事实源。

### 市场与情报认知资产

在明确时间窗口、观察面、方法和证据边界下形成的候选变化、判断与 Intelligence 组织。它回答“当时有资格认为发生了什么、可能意味着什么”，必须保留支持、反例、不确定性、允许解释范围和版本；产品报告本身不能成为无法追溯的新事实源。

### 行动与学习资产

由提案、决定、人工修改、行动、发布、结果观察、评价和后续调整组成的学习记录。它回答“决定做什么、实际做了什么、后来观察到什么、如何评价”，但结果观察与评价必须分开，Outcome 不得改写过去事实或被自动解释为因果证明。

### Asset Lineage（资产来源与演进关系）

说明一项资产从哪些来源、选择、转换、判断或行动形成，以及它如何被后续结果校准。重要判断必须能够向下追溯，Outcome 必须能够向上校准；不同资产按自身性质保存来源和版本关系，不强制经过同一条流水线。

五类积累视角是产品价值分类，不是数据库表、万能对象、应用模块或技术模块的预先授权。其底层语义和长期对抗性案例见 [`../product/domain-invariants.md`](../product/domain-invariants.md)。

## 必须保持的区别

```text
Domain
≠ Topic
≠ Research Project
≠ Collection Plan
```

当前产品关系为：

```text
Domain：ADHD
├── Topic：ADHD 数学 / 家庭干预 / 作业拖延 / 执行功能 / ...
├── Research Project：发生在 ADHD 领域内的专题研究
└── Collection Plan：发生在 ADHD 领域内的持续或一次性采集工作
```

“领域工作空间”可以用于描述用户围绕一个领域完成连续工作的产品体验，但当前不把 `Workspace` 确认为独立领域术语、超级业务对象或数据库归属规则。
