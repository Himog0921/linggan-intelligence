# 首批媒体 Canary 生命周期合同

> 状态: 草案
> 最后核对: 2026-08-22
> 适用范围: ARC-001 `media-lifecycle-contract`；为 Mog 已确认的首批真实 producer Canary 方案 B 提供媒体责任、失败边界、验证门与待决策清单
> 事实来源: Mog 对方案 B 的明确确认、`AGENTS.md`、`docs/product/domain-invariants.md`、`docs/context/current-system-inventory.md`、ARC-001 决策图与固定 V2 历史参考；未访问真实平台、账号、插件、媒体、数据库或第三方处理服务
> 冲突时以谁为准: Mog 的后续明确选择、`AGENTS.md`、后续获准的真实 producer 合同/实验结果、ACCEPTED 决定与真实运行证据

## 0. 这份合同冻结什么，不冻结什么

Mog 已确认首批真实 producer Canary 选择 **B：同步纳入受限媒体**，因为旧项目长期没有收口媒体问题，Linggan 不能再把媒体留在正文之外。

本合同把这一选择落实为一个设计前置门：在任何真实媒体访问前，系统必须能够如实区分“看见了什么”“实际拿到了什么”“保存了什么”“谁能使用什么”“派生了什么”以及“哪里仍然不知道”。

它冻结的是**责任和可证伪边界**，不是数据库 schema、对象存储产品、OCR/转录模型或真实执行授权。它不授权：

- 访问真实平台、账号、插件工位、内容、评论、图片、视频或音频；
- 下载、保存、播放、转码、OCR、转录、嵌入或发送媒体给任何第三方；
- 选择存储供应商、保留期限、加密实现、访问角色、媒体格式白名单或敏感内容处置方案；
- 编写 Rust、SQL、API、Web、Plugin、Agent、对象存储或部署代码；
- 把一次 Canary 结果说成平台完整性、用户代表性、市场趋势、合规结论或可规模化方案。

本合同也不复制旧 `MediaAsset`、旧 URL fallback 或旧表。固定 V2 只提供问题和局部经验的历史证据，不是现行技术规格。

## 1. 旧问题 → 新不变量

| 旧问题或历史风险 | 新不变量 | 直接后果 |
|---|---|---|
| 一个 URL 字段同时被当作“页面看见”“已下载”“本地可读”“当前可用”的证据 | **页面可见地址、下载字节、存储副本与读取可用性是不同事实。** | 未下载地址不能显示为已保存媒体；读不到副本不能改写历史页面观察。 |
| 同一内容的媒体地址更新后，旧下载任务仍可能覆盖新地址或写入错误位置 | **来源地址是带观察时间和来源位置的断言，不是永远的媒体身份。** | 新地址形成新的来源断言/代次；旧任务必须用其预期来源版本校验，不能静默写到新版本。 |
| 缺文件、下载失败、未尝试、平台不可访问被折叠为一个“无媒体/失败”状态 | **未知、未尝试、来源明确无候选、下载失败、字节未验证、存储失败与读取不可用必须分责。** | 每一层只陈述自己知道的事实；不能用 `target - success` 伪造缺失对象或完成率。 |
| 仅凭 URL、role 或封面位置推断媒体属于哪个内容、什么用途 | **主体、slot、来源位置、用途与媒体字节身份分别证明。** | 错主体/错 slot 是独立错误；用途关系必须显式建立，不能由文件名或首图猜造。 |
| 旧媒体可读性、使用关系和派生关系没有统一血缘，撤回后仍可能从缓存或派生物返回 | **所有受限媒体及其派生物都必须有可追溯血缘与失效传播。** | 获准处置先阻断读取，再向副本、索引、转录、OCR、embedding、摘要、缓存与 Agent 输出传播。 |
| “同步媒体”被误解为“默认抓完、默认长期留存、默认送模型分析” | **方案 B 只要求媒体生命周期进入首批 Canary 的受控验证，不自动扩大媒体范围或处理方式。** | 真实 Canary 必须单独冻结媒体样本、允许类型、下载/处理范围、风险预算和处置计划。 |

## 2. 最小媒体事实链

下面不是一条万能状态机，而是六种不同问题的最小关系。每一层都可以存在失败、未知或不适用；后层成立不能回写前层，前层存在也不自动授权后层。

```text
内容/评论等来源主体
  ↓ 在某次 Observation 中
媒体候选来源断言（页面/接口实际可见）
  ↓ 经明确授权、准入和 Work Order
下载发生与取得的字节
  ↓ 经完整性验证
受限字节 Artifact
  ↓ 经保存回执
受限 Storage Replica
  ↓ 经明确转换运行
派生物（缩略图 / 转码 / OCR / 转录 / 特征等）
  ↓ 经用途化选择
内容、语料、研究或页面使用关系
```

### 2.1 媒体候选来源断言：当时看见了什么

**媒体候选来源断言**只陈述：在某个合格 Evidence / Observation 中，producer 在指定来源位置看到了一个可能的媒体入口。

它至少要能够回到：

- 外部主体：哪一篇内容、哪条评论或哪一个明确来源对象承载它；
- 来源位置与 slot：例如内容内第几个图片/视频位置、封面候选、正文嵌入位置；slot 只在其主体和本次来源断言的语境中有意义；
- 来源原始表示：平台实际给出的地址、ID、类型提示、封面提示或其他原始字段；
- 观察上下文：producer、合同版本、Attempt / Capture Identity、来源位置、实际 `observed_at` 与时间精度；
- 这一次的候选清单 Coverage：计划/实际看到了多少候选、何处终止、哪些位置无法解析或未知。

它**不能**单独证明：平台稳定媒体身份、地址仍有效、文件可下载、字节已取得、内容类型可靠、媒体可读、媒体属于另一个主体，或可以向工作台、外部 Agent、OCR/转录服务暴露。

若平台同时提供稳定媒体 ID，系统可以将其保存为来源陈述；是否足以形成独立 Media Identity，仍要与主体/slot 关系及后续合同一起判断。若没有稳定 ID，也不得用 URL、文件名、数组下标、内容标题或 AI 推断制造跨观察的永久身份。

### 2.2 下载发生：系统做了什么，不等于拿到了什么

**媒体下载发生**回答的是：在一个已经获准的媒体 lane 中，某工位是否在指定时间、以指定预期来源断言尝试取得字节。

它必须保留：

- 触发它的 Acquisition Authorization、Admission、Work Order、Attempt 与执行工位/账号上下文；
- 预期主体、slot 和来源断言/代次，而不是只写一个裸 URL；
- 下载开始、结束、实际响应或中断事实、风控/超时/权限/网络等停止原因；
- 本次请求的预算和边界，例如允许媒体种类、最大对象数、最大总字节、最大时长或明确风险停止条件；
- 这次下载 lane 自己的 Coverage，而不是沿用内容详情或评论 Coverage。

“尝试下载”不等于“下载成功”；“HTTP 返回”不等于“取得正确字节”；“插件任务结束”不等于“媒体全部可用”。重新尝试必须形成新的下载发生记录；不能把后一次网络结果覆盖第一次发生或篡改其 Coverage。

### 2.3 受限字节 Artifact：系统实际取得并验证了什么

只有在字节确实到达、其完整性可被指定规则验证，并能回到本次下载发生和预期主体/slot时，才可以形成**受限字节 Artifact**。

它最小需要保存或可验证地引用：

- 字节完整性依据：内容 hash、长度、验证规则/版本和验证时间；
- 取得来源：精确下载发生、预期来源断言、实际响应的最小非敏感元数据；
- 已知的内容描述：来源声明的 kind 与经验证后的格式/大小等必须分开，未知保持未知；
- 访问级别：它默认属于内部受限原料，不等于可在普通工作台、CLI 或模型上下文中读取；
- Artifact 与来源候选的多对多血缘：同一字节 hash 可以来自多个候选，但不能因此消灭各自的主体、slot、观察和下载历史。

不完整传输、内容 hash 缺失/不匹配、主体/slot 不匹配或无法安全确认的字节，不得被升级为“可用 Artifact”。它们保留为下载发生/验证失败的记录，并按后续最小化处置规则处理；不能被下游 OCR、转录、页面或 Agent 当成可读内容。

### 2.4 受限 Storage Replica：字节在哪里，而非字节是什么

**Storage Replica**记录某个已验证 Artifact 的一个实际保存副本。它必须与 Artifact 身份分开：同一字节可有多个副本；副本不可读、迁移或清理也不抹除历史 Artifact 或其他副本。

每个副本至少需要可审计地说明：

- 所属 Artifact、保存意图和保存回执；
- 存储域/路径范围/访问类别，而不是把可访问 URL 当作长期身份；
- 写入、最近验证读取、不可读或已处置的发生记录；
- 副本的完整性复核结果和时间；
- 与访问、删除、撤回和清理传播的关系。

对象存储写入和数据库接纳不是一个原子事务。后续实现必须明确两种失败均可恢复：先上传后数据库失败时形成可回收 orphan；先登记保存意图后上传失败时，不能把 Artifact 或副本标为可读。具体顺序、存储产品和清理机制由后续实现/安全设计决定。

### 2.5 派生物：由什么、按什么规则、何时生成

缩略图、转码文件、OCR 文本、转录、帧抽取、embedding、摘要或其他处理输出都是**派生物**，不是原始媒体本身。

每项派生物必须明确：

- 精确输入 Artifact / Replica 与其完整性身份；
- 转换或模型/规则版本、执行时间、操作者/服务边界和允许用途；
- 输出自身的受限程度、可用性和验证回执；
- 可重处理关系：输入、规则或模型变化应产生新派生版本，不覆盖旧输出；
- 因隐私/撤回/访问限制导致的失效关系。

OCR/转录尤其不能因“是分析”而绕过原料访问边界。未获得单独授权前，首批 Canary 可以记录“此 Artifact 具备未来派生可能”，但不能调用任何模型、服务或本地处理器。

### 2.6 内容用途：为什么此刻可以被谁怎样使用

**媒体用途关系**记录一个已获准的上下文选择，例如某个 Topic 深入页面使用一张脱敏缩略图、某个 Corpus 材料包引用一段转录片段、或某项研究将某 Artifact 作为受限证据引用。

用途不是 Artifact 的永久属性，也不因为“已下载”自动成立。每个用途关系至少需要：

- 使用者/上下文：页面、Corpus selection、Analysis Run、Claim basis、Agent delegation 等；
- 精确输入及版本：Artifact、Replica 或派生物，不能只写“这条笔记的媒体”；
- 已批准用途、访问范围、脱敏/呈现形式和有效期/失效条件；
- 实际使用发生与可撤销/失效回执。

普通工作台默认只能显示经用途化、最小化后的材料；外部 Agent 默认只可获得聚合结果、脱敏片段或受控引用。它不能直连副本、批量读取原始媒体，也不能凭分析请求启动下载或派生。

## 3. 身份、代次与关系的最小约束

### 3.1 何时可以说“是同一个媒体”

当前只冻结以下判别纪律，不预设物理表：

1. **同一来源候选**：必须来自同一主体、同一 slot/来源位置和可比较的来源断言；地址文本相同并不足够。
2. **同一稳定来源媒体身份**：必须有平台明确给出的稳定媒体标识，并通过后续 producer 合同证明其作用域和主体关系；URL 不是默认身份。
3. **同一字节 Artifact**：以经过验证的内容 hash 与完整性规则为准；相同字节不能抹掉不同内容、不同 slot 和不同观察路径。
4. **同一存储副本**：以同一 Artifact 与受控存储位置/回执为准；复制、迁移、重新验证或清理都要留下新发生记录。
5. **同一派生物**：以精确输入、转换规则/模型版本和输出完整性身份为准；相似文本或同名文件不是同一派生物。

任何无法满足的情况都保持 unresolved，而不创建一个“看起来方便”的全局 `mediaId`。

### 3.2 来源代次防止旧任务覆盖新观察

来源候选在 later Observation 中发生地址、slot、kind 提示或可见性变化时，必须追加新的来源断言/代次。新的断言可被分析为“可能变化”，但不覆盖旧观察。

后续下载工作必须带它预期的主体、slot 与来源断言/代次。执行和写回时若发现不匹配：

- 不能把得到的字节挂到新的来源断言；
- 不能用新地址覆盖旧下载发生；
- 必须记录媒体主体/slot/代次不匹配这一独立错误；
- 其对 Coverage、重试或人工处置的影响由实际合同说明。

这避免“来源更新 + 旧队列晚到”悄悄污染 Current 或媒体库。

### 3.3 关系而非字段

下列关系必须可单独查询与审计，不能压在一个 `media.url` 或 `media.status` 字段里：

```text
Source Object / Observation
  └─ observed media candidate assertion (subject, slot, source location)

candidate assertion
  └─ authorized download occurrence (expected candidate generation)

download occurrence
  └─ verified byte Artifact or verification failure

Artifact
  └─ Storage Replica(s)
  └─ Transformation Run(s) → derived output(s)
  └─ governed Use / selection relation(s)
  └─ privacy / withdrawal disposition and propagation receipt(s)
```

## 4. Coverage、失败与部分成功

媒体 Coverage 不是一个通用百分比。至少要分别表达来源候选、下载、Artifact 验证、副本写入和派生处理各自的单位、范围、终止与未知。

| 层 | 能如实报告什么 | 绝对不能推出什么 |
|---|---|---|
| 候选发现 | 在指定页面/API位置、观察时间和入口中，看到/未解析/未观察到多少候选；页面或接口明确给出时可报告无候选 | 平台无媒体、其他入口无媒体、候选总数已穷尽 |
| 下载发生 | 指定候选中已尝试、风险中断、失败、未尝试、尚未知多少 | 未尝试对象不存在；下载失败等于平台无媒体 |
| 字节/Artifact | 哪些请求实际取得字节、哪些通过/未通过完整性验证 | 验证失败就是内容无效；未验证字节可读或可用 |
| Replica | 哪些已验证 Artifact 有保存回执、哪些读取失败/未验证/已处置 | 有 Artifact 就一定有可读副本；一个副本失败代表所有副本失败 |
| 派生 | 哪些精确输入在何规则下已处理、失败、未开始或被策略阻断 | 未处理代表没有可派生内容；一个派生结果代表原件已被理解 |

例如一个获准的 10 个候选图片 Canary 可能如实结束为：

```text
候选观察: 10 个被页面明确列出
下载尝试: 6 个
其中取得字节: 4 个
完整性验证通过: 3 个
副本保存确认: 3 个
另 1 个风险中断、2 个网络失败、3 个未尝试
```

这批 3 个合格 Artifact 仍然有价值，不能因 10 个目标未完成而丢弃；但它也不能被写成“10 个媒体全部已采集”或“其余 7 个不存在”。补采必须是新的 Attempt / Capture Identity / 不可变 Package，而不能修改本轮记录。

媒体 lane 的终止还必须保留停止原因，例如明确来源结束、已授权预算到达、人工停止、风险中断、超时、权限/登录失效、网络异常或未知。启发式停止不能伪装为平台耗尽。

## 5. 调度、风控、预算与停止

媒体不是详情采集的一个无成本附件。每一项实际下载或派生都必须经过和其风险相称的 Admission，最小回答：

1. **信息缺口与用途：** 为什么需要该媒体，而不是只使用文本/页面候选断言？
2. **对象边界：** 哪些主体、slot、类型、数量与来源代次在许可内？
3. **时效与重复：** 已有合格 Artifact / Replica / 派生物是否足够？当前请求是否与进行中的等价工作重叠？
4. **资源与风险：** 将占用哪个平台、账号、工位、时间窗、网络/存储/处理预算？风险事件发生后停止什么？
5. **隐私与传播：** 原件是否需要、保存在哪里、谁可读、是否允许任何第三方处理、结束后怎样处置？

调度器只能把已经批准、已准入、边界明确的媒体需求拆成有界 Work Order。插件只执行一个有界工作单并如实回执，不能自行扩大为“同页所有媒体”“视频全部转录”或“发现一个新 URL 就追加下载”。

风险、验证码、登录/权限异常、站点响应异常、预算耗尽或人为停止必须结束或暂停当前 Attempt，并生成与实际取得材料匹配的终态 Package / Coverage。恢复不是修改旧 Attempt；是否能恢复、如何新建 Attempt 和能否复用已取得 Artifact 由 Capture Control Contract 进一步冻结。

## 6. 访问、撤回、删除与派生失效

### 6.1 默认访问边界

- 原始下载字节、原始视频/音频和未脱敏帧默认仅在内部受限区按明确用途保存；
- 普通工作台不能因为“媒体已存在”而展示原始文件；它只能通过已批准的用途关系显示最小必要形式；
- 外部 Agent 不能直连 Artifact/Replica，不得批量读取原始媒体、派生文本或来源地址；
- OCR、转录、embedding 和任何第三方处理都必须先取得独立的明确授权、输入范围和处置计划；
- 审计记录只保留最低必要的非敏感引用、hash、原因与传播回执，不能借审计永久复制媒体内容。

### 6.2 平台不可访问不等于隐私撤回

媒体在某次重新观察中不可访问，只能说明该次来源观察得到“不可访问”或未知，且影响 Coverage。只有平台来源明确给出删除状态时，才能形成带来源的删除断言；这也不等于用户向 Linggan 提出隐私撤回。

隐私撤回、获准删除、脱敏或访问限制是另一条高权限处置链。它不能通过普通业务更新静默完成。

### 6.3 获准处置的最小传播合同

当存在有效的处置决定时，后续实现必须：

1. 同步写入处置发生、范围、授权者和最小非敏感审计；
2. 同步切换权威访问阻断，使新的原件/派生读取立刻失败关闭；
3. 为所有已登记消费者写入可追踪传播工作：Replica、缩略图、转码、OCR、转录、全文索引、embedding/feature、摘要、缓存、用途选择、页面引用、Agent 输出或持久提示上下文；
4. 让每个消费者回写完成、失败、重试或必须人工处理的回执；
5. 保留历史 Claim / Brief 的非敏感“来源资格变化”说明，并要求重新评估，而不是静默删除历史判断。

只有全部强制消费者完成，或有明确人工例外处置，才可以说“传播完成”。一个 worker 的完成、一个副本删除或前端不再显示都不代表全链已经处置。

## 7. 方案 B 的最小 Canary 证明范围

当且仅当本合同、Capture Control Contract、具体授权和新的真实 Canary SCOPE 均已通过后，方案 B 的首批 Canary 才应当验证一个**受限的媒体链**：

```text
指定主体/slot 的媒体候选来源断言
→ 指定、限量、已准入的下载发生
→ 指定的字节完整性验证
→ 指定受限副本的保存与读取回执
→ 不执行或经另行许可后才执行的派生处理
→ 失败、部分成功、未知和处置传播的可追溯表达
```

它最多可以证明：在那个精确的平台、入口、账号镜头、时间、对象范围、处理边界与 Coverage 条件下，producer 实际看到了哪些候选，获准工作实际拿到了哪些字节，哪些副本/派生回执真实存在，以及失败是否被如实记录。

它不能证明：

- 平台全部内容、媒体全量、任意 URL 的长期有效性或跨账号可见性；
- 所有图片/视频/音频、评论附件或作者头像已经有 producer 合同；
- 下载或转录可以规模化、默认执行或具有固定安全频率；
- 媒体中人物、儿童、地点、声音、医学信息或版权的真实身份/授权；
- OCR/转录/模型输出正确、合规、可对外使用，或可以支撑趋势、需求、机会和因果结论；
- 旧 V2 `MediaAsset` 或任何历史存储路径可直接迁入 Linggan。

## 8. 可证伪测试目录

以下是后续真实合同、fixture、数据库与 worker 实现必须能够反驳的场景。它们不是当前已运行测试。

| 编号 | 场景 | 必须成立 | 一旦出现即失败 |
|---|---|---|---|
| MLC-01 | 页面观察到 3 个候选，只获准下载其中 1 个 | 3 个候选来源断言与 1 个下载发生各自可查；另 2 个为未尝试，不冒充不存在 | 页面候选自动变 3 个已保存媒体，或未尝试被记为失败/缺失 |
| MLC-02 | 同主体同 slot 后来出现新地址，旧下载任务晚到 | 新来源断言追加；旧任务因预期代次不匹配不写入新断言 | 旧下载覆盖新地址、更新 Current，或把新旧观察压成一条 URL |
| MLC-03 | 插件返回字节，但实际媒体主体/slot 与 Work Order 不一致 | 发生记录与独立媒体主体错误保留；不形成可用 Artifact | JSON/下载成功就挂到目标内容或封面位置 |
| MLC-04 | 下载到 4 个字节流，1 个 hash 校验失败，另 3 个成功 | 3 个合格 Artifact 可继续；失败项隔离并进入正确 Coverage | 整批 4 个都丢失，或失败字节进入页面/OCR/转录 |
| MLC-05 | Artifact 已验证，但对象存储写入回执失败 | Artifact 与保存失败各自留痕；不会显示为可读副本；可安全恢复/清理 | 仅因下载成功就标记媒体已存储可读 |
| MLC-06 | 同一字节由两个不同内容候选获得 | 字节可按 hash 去重，但两个主体、slot、来源和用途血缘均保留 | 去重后其中一个内容失去来源关系，或自动复制用途 |
| MLC-07 | 平台页面暂时不可访问，另一个 Artifact 收到获准隐私处置 | 前者只形成来源不可访问/Coverage；后者立即阻断读取并创建传播工作 | 两者都直接删除媒体，或不可访问被当作撤回 |
| MLC-08 | 已处置 Artifact 有缩略图、转录、embedding、缓存和 Agent 引用 | 新读取立即阻断；每个消费者有传播回执；历史判断标注资格变化 | 只删原件，派生物或 Agent 仍继续返回内容 |
| MLC-09 | Agent 提议“下载此视频并转录” | 系统只保存有委托范围的申请；没有人类授权与 Admission 就不产生 Work Order | Agent 直连副本、下载、转录或把申请显示为已完成 |
| MLC-10 | 目标 10 个候选，风险中断时 3 个 Artifact 合格 | 3 个合格 Artifact 入受限链，Coverage 如实表达中断/未尝试/失败 | 因未完成 10 个丢弃 3 个，或用 3/10 声称平台只存在 3 个 |
| MLC-11 | 同一输入 Artifact 以新 OCR/转录规则重处理 | 新派生物带新输入/规则版本，旧派生与实际使用历史不被覆盖 | 更新旧输出让历史页面/Claim 看似一直使用新结果 |

## 9. `DECISION_REQUIRED`：仍必须由 Mog 或明确授权负责人决定的事项

方案 B 已确认，但下面不是工程团队可以自行补全的默认值。每一项必须在真实 Canary SCOPE 前明确记录；没有决定就冻结受影响 lane。

| 决策 | 为什么不能推断 | 建议责任 |
|---|---|---|
| 首批 Canary 允许的媒体种类、主体范围与最大样本 | 内容图片、视频、音频、评论附件、作者头像的敏感度、producer 成熟度和风险不同；现有 V2 对评论/作者媒体仍 `SOURCE_INCOMPLETE` | Mog 确认产品/风险边界；工程团队给出可执行范围 |
| 是否实际下载、仅保存受限副本，还是还允许 OCR/转录/帧抽取 | “同步纳入媒体”不等于授权所有处理；每一步都扩大原料传播与风险 | Mog 或受授权隐私负责人 |
| 首批保存位置、访问角色、加密/审计要求、地域与成本上限 | 这些决定敏感原件的真实可见面、外部后果和支出 | Mog 与安全/隐私专业审查；工程团队实施 |
| 保存期限、删除/撤回受理方式、法务/平台条款适用性 | 内部受限保存不等于永久保存；当前没有可接受的默认天数或法律结论 | Mog 与专业审查 |
| 哪些派生物可生成、是否允许第三方模型处理及其输出处置 | 转录/OCR/embedding 会产生新的敏感副本和供应商边界 | Mog 与隐私/安全审查 |
| 普通工作台与外部 Agent 对媒体、转录和引用的具体读取权限 | “脱敏片段”不足以替代可见媒体、抽帧或完整转录的授权 | Mog |
| 风险预算、单次/每日上限、停止/冷却与人工恢复责任 | 固定 V2 参数没有真实平台实验资格；不能凭旧经验声称安全阈值 | Mog 确认风险容忍度；工程团队以真实 Canary 数据逐步建议 |

## 10. 进入真实媒体 Canary 前的退出门

以下全部满足前，方案 B 仍是一个已经确认的方向，而不是执行授权：

1. 本合同经独立审查并集成，且与 Capture Control Contract 没有冲突；
2. 上表所有影响首批样本的 `DECISION_REQUIRED` 已由 Mog 或明确授权负责人做出可追溯决定；
3. 新的真实 Canary SCOPE 明确目的、平台/入口、账号镜头、对象/媒体类型、最大范围、下载与处理许可、预算、停止条件、访问与处置计划；
4. producer 合同和测试 fixture 能表达候选、下载、Artifact、Replica、派生和 Coverage 的不同事实，而不是只交一个 URL/状态字段；
5. 真实环境已具备最小受限访问、回执、审计和处置传播能力；
6. 相关实施通过与风险相称的真实数据库/存储副作用验证；仅静态文档、类型、mock 或页面预览不能通过此门。

## 验证与未证明边界

- 本文仅完成文档层的责任收口，未产生真实媒体、Artifact、Replica、派生物、数据库行、对象存储对象、OCR/转录输出、Plugin 执行或平台副作用。
