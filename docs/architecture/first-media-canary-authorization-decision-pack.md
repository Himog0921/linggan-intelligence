## 先确认已经决定的事

Mog 已确认 **方案 B**：首批真实 producer Canary 要同步纳入媒体需要。原因是媒体不能再次被留在正文链路之外，成为旧项目那种长期没有闭合的问题。

这项确认只决定了媒体必须进入首批 Canary 的受控验证范围。它**没有**授权任何真实执行。当前仍未授权：

- 访问任何平台、账号、Cookie、插件工位、真实内容、评论或媒体；
- 下载、播放、保存、OCR、转录、抽帧、embedding、摘要或向第三方传输媒体；
- 选择真实样本、平台入口、账号、数量、速率、费用、存储供应商、保留期限或模型供应商；
- 修改数据库、插件、Web、Agent、对象存储、部署或外部权限；
- 将 Canary 的任何结果说成用户总体、平台全量、市场趋势、需求规模、合规结论或可规模化方案。

本包的作用是把上述尚未授权的现实选择压缩为四项。**四项全部由 Mog 明确确认后，仍必须另立一份具体的真实 Canary SCOPE/Issue，并按正常授权、准入、执行、接纳和验证责任链运行。** 本文与其模板都不是授权单。

### 决策 1：首批媒体对象与样本上限

**推荐选择：** 仅内容详情明确关联的主媒体。首个授权单必须在执行前选择一种目标语义，并写清边界：

1. **已知对象集合**：先列出具体、稳定且经过批准的内容对象和媒体 slot；每个成员可以如实标记已尝试、失败、未尝试或未知。
2. **最大配额**：只写“最多处理多少个”并配合停止条件；它不是平台中“还剩多少个”的陈述，也不能自动产生完成百分比。

两种方式都必须是小样本；本文不替 Mog 填入数量、对象或平台。推荐不含评论/回复媒体、作者头像、封面以外附件、自动相关素材和页面周边资源，因为这些会同时扩大敏感性、身份/主体关系和风控面，却不增加验证最小媒体链所必需的事实。

**可选扩张：** 内容多个附件、评论/回复媒体或其他媒体类别。只有当授权单能额外说明“为什么本轮必须看到它、它属于谁、最大数量/字节/时长、如何处置”时才可选择；否则保持 `NOT AUTHORIZED`。

**为什么这不是丢媒体：** 方案 B 的要求是媒体进入同一轮受控验证，而不是把所有可见文件都抓进来。一个明确的主媒体样本足以验证媒体候选、主体/slot、下载发生、Artifact、保存副本和 Coverage 是否被混淆。

### 决策 2：处理深度

**推荐选择：** 到“受控读取证明”为止。也就是先验证：

```text
内容详情中的媒体候选
→ 获准的一次下载尝试
→ 经完整性规则确认的受限字节
→ 有保存回执的受限副本
→ 仅核验人员在授权范围内的一次读取证明
```

这能直接检验“页面 URL 不等于已取得字节、已取得字节不等于任何人可读”的核心边界。

**可选扩张：** OCR、转录、抽帧、缩略图、embedding、摘要或其他转换。每一种都会形成新的材料、供应商/模型传播路径、失败类型和撤回传播责任；因此不能在“同步纳入媒体”的字面下自动发生。首个授权单若没有逐项勾选，默认不处理。

### 决策 3：内部保存、访问与处置

**推荐选择：** 内部受限保存，最小化读取，并在真实授权单中写明一个具体的处置触发与复核点。这里的“处置”至少要回答：谁可以读、为哪个目的读、何时复核是否继续保留、若停止或收到有效限制时如何阻断后续读取和派生。

这不是永久保存政策，也不是删除政策。它只避免两种不可逆错误：

- 为了验证保存而把媒体无边界留存；
- 为了谨慎而在没有审计的情况下丢失已经取得的媒体和其处置事实。

若主张更长的保留、更广的访问、正式对外展示、批量导出、训练或第三方处理，则本轮必须停止，等待相应的专业与正式政策审查。平台内容后来不可访问，不自动等于收到个人的删除或撤回请求。

### 决策 4：工位、账号、时间与风险停止预算

**推荐选择：** 一个已确认的观察身份与一个已确认的工位，在人明确指定的短时间窗口内，执行事前冻结的范围。授权单必须写出：触发即时停止的信号、到什么条件必须升级给人、已取得材料如何提交、哪些后续动作不能继续。

这里不提供“安全频率”“安全并发”或“合适时长”的假数字。没有真实 producer 证据时，任何此类数字都会把行业想象伪装成平台事实。首轮结束也不会证明这个账号、该工位或该平台可以在更大规模下安全运行。

## 给 Mog 的四句确认格式

Mog 不需要在这里决定数据库、对象存储产品、算法、模型或具体实现。若认可推荐路线，可以只按下面四项确认产品与现实资源边界；实际对象、数量、账号、时间和处置触发仍必须在下一份真实授权单中填写。

```text
1. 我确认首批只处理内容详情明确关联的主媒体；对象采用事前冻结的已知集合或最大配额，不扩大到评论/回复媒体、头像和页面周边资源。
2. 我确认首批只做到受限下载、完整性、受限保存和受控读取证明；OCR、转录、抽帧、embedding、摘要和第三方处理不进入首轮。
3. 我确认首批媒体仅内部受限、最小人员读取，并要求真实授权单写明复核与临时处置；不开放给普通工作台或外部 Agent，不作无限期保存。
4. 我确认首批使用单一获准观察身份和工位，在人工指定短窗口内运行；触发风险、身份变化、预算触顶或合同不满足即停止，不自动恢复。
```

若其中任一项需要扩张，应只修改对应一句并补充“为什么首轮必须扩大、最大边界和如何处置”。没有这三部分，工程团队应保持该 lane 未执行。

## 不能由工程或 Mog 单独拍板的部分

以下问题可能影响合法性、未成年人/敏感材料保护或第三方数据传播。它们不是工程师凭经验、也不是 Mog 单凭产品偏好就可以替代的结论：

| 边界 | 当前状态 | 正确下一步 |
|---|---|---|
| 平台规则、准入条件与可允许的访问方式 | `DECISION_REQUIRED`；本文没有核验任何具体平台规则。 | 在选择具体平台和入口后，取得适用的专业/合规审查或明确组织授权。 |
| ADHD、儿童、家庭、医疗和可反向识别媒体的最小化处理 | `DECISION_REQUIRED`；公开可见不等于可无限保存、展示或再利用。 | 在真实授权前确认最小目的、对象范围、访问者和处置责任；必要时进行隐私/法律审查。 |
| OCR、转录、模型、云服务或其他第三方处理 | `NOT AUTHORIZED`。 | 只有在单独确认处理目的、发送内容、供应商、输出、保存和撤回传播后，才可以提出新的受限范围。 |
| 正式保留、删除、撤回、加密、角色和审计政策 | `DECISION_REQUIRED`；不能由本次临时验证替代。 | 另行形成长期政策与专业审查；本轮只允许授权单中写明的最小临时处置。 |

## 获得 Mog 逐项选择以后，仍必须做什么

1. 由协调者把四项选择和授权单中的具体值写入一个**新的真实 Canary SCOPE/Issue**；不能复用本文当工作单。
2. 在不与 Draft 合同冲突的前提下，明确真实 producer 合同、对象/slot、Coverage、风险回执、受限保存与处置的可证伪验收。
3. 单独核验平台、敏感材料、第三方处理和长期保留中需要专业审查的部分；未完成即不运行对应 lane。
4. 经过 Acquisition Authorization → Admission → Work Order → Attempt/Lease → terminal Package/ACK → Evidence/Artifact → Observation 的受控责任链执行。
5. 结束时分开报告：实际发生、保存/处置、Coverage、失败、可证明范围与不可证明范围。成功、部分成功或没有结果都不能自动扩大下一轮。

## 这个决策包能证明什么，不能证明什么

- **未证明：** 任何真实平台、账号、插件、媒体下载/保存、隐私处置、第三方处理、数据库、Web、Agent、部署或业务价值已经成立。
