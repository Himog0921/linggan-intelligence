## 先确认已经决定的事

Mog 已确认 **方案 B**：首批真实 producer Canary 要同步纳入媒体需要。原因是媒体不能再次被留在正文链路之外，成为旧项目那种长期没有闭合的问题。Mog 随后确认：在取得合格媒体后的首轮处理架构中，异步图片 OCR 与异步视频语音转文字（ASR）也是必需的媒体信息恢复能力；视频抽帧 OCR 仍是有条件的独立 lane。

这项确认只决定了媒体必须进入首批 Canary 的受控验证范围。它**没有**授权任何真实执行。当前仍未授权：

- 访问任何平台、账号、Cookie、插件工位、真实内容、评论或媒体；
- 下载、播放、保存、本地或外部 OCR/ASR、抽帧、embedding、摘要或向第三方传输媒体；
- 选择真实样本、平台入口、账号、数量、速率、费用、存储供应商、保留期限或模型供应商；
- 修改数据库、插件、Web、Agent、对象存储、部署或外部权限；
- 将 Canary 的任何结果说成用户总体、平台全量、市场趋势、需求规模、合规结论或可规模化方案。

本包的作用是把上述尚未授权的现实选择压缩为四项。**四项全部由 Mog 明确确认后，仍必须另立一份具体的真实 Canary SCOPE/Issue，并按正常授权、准入、执行、接纳和验证责任链运行。** 本文与其模板都不是授权单。

### 决策 1：首批媒体对象与样本上限

**推荐选择：** 仅内容详情明确关联的主媒体。首个授权单必须在执行前选择一种目标语义，并写清边界：

1. **已知对象集合**：先列出具体、稳定且经过批准的内容对象和媒体 slot；每个成员可以如实标记已尝试、失败、未尝试或未知。
2. **最大配额**：只写“最多处理多少个”并配合停止条件；它不是平台中“还剩多少个”的陈述，也不能自动产生完成百分比。

两种方式都必须是小样本；本文不替 Mog 填入数量、对象或平台。推荐不含评论/回复媒体、作者头像、封面以外附件、自动相关素材和页面周边资源，因为这些会同时扩大敏感性、身份/主体关系和风控面，却不增加验证最小媒体链所必需的事实。

**可选扩张：** 内容多个附件、评论/回复媒体或其他媒体类别。只有当授权单能额外说明“为什么本轮必须看到它、它属于谁、最大数量/字节/时长、如何处置”时才可选择；否则保持 `NOT AUTHORIZED`。

**为什么这不是丢媒体：** 方案 B 的要求是媒体进入同一轮受控验证，而不是把所有可见文件都抓进来。一个明确的主媒体样本足以验证媒体候选、主体/slot、下载发生、Artifact、保存副本和 Coverage 是否被混淆。

### 决策 2：处理深度与独立处理 lane

**推荐选择：** 在同一个受限 Canary 中按以下顺序安排三个彼此独立的 lane。它们的异步性表示：采集/插件在完成有界原媒体工作后停止；后续处理只能由受控的处理责任运行，不能占用或偷偷延长 capture/plugin lane。

| Lane | 首轮目的 | 合格输入 | 受控输出 | 必须单独报告的 Coverage 与停止边界 |
|---|---|---|---|---|
| **M1：原媒体生命周期** | 证明页面候选、下载发生、字节完整性、受限副本与读取证明没有被混为一个事实。 | 仅授权单中冻结主体/slot/来源断言的媒体候选。 | 经完整性验证的受限 Artifact、Storage Replica 与最小读取回执。 | 候选、尝试、取得、验证、保存、可读、失败、未尝试、未知；风险、身份、预算或合同不满足即停止。 |
| **M2：异步图片 OCR** | 从合格图片 Artifact 恢复图片中可提取的文字表示。 | 明确允许且仍具访问资格的 M1 图片 Artifact / Replica。 | 带输入 Artifact、处理器/规则版本、时间、输出版本和失败事实的 OCR 派生表示。 | 被授权的图片输入数、实际开始/完成、成功/失败/未尝试/未知、输出资格和处理停止原因。 |
| **M3：异步视频 ASR** | 从合格视频 Artifact 恢复可提取的语音文字表示。 | 明确允许且仍具访问资格的 M1 视频 Artifact / Replica。 | 带输入 Artifact、处理器/规则版本、时间、输出版本和失败事实的 ASR 派生表示。 | 被授权的视频输入数、实际开始/完成、成功/失败/未尝试/未知、输出资格和处理停止原因。 |
| **M4：视频抽帧 OCR（条件 lane）** | 仅在视频中的可见文字对本轮已写明的目的不可替代时，恢复一个明确帧集合中的文字表示。 | 明确允许的视频 Artifact / Replica，且授权单已经写明目的、冻结的抽帧选择规则/边界和最大范围。 | 带输入视频、抽帧规则版本、实际帧集合、OCR 处理版本和失败事实的派生表示。 | 选择的帧、跳过帧、实际处理帧、成功/失败/未尝试/未知、预算与停止原因。 |

M2、M3 和 M4 的输出都是**版本化、可追溯的派生表示**。它们不是被接纳的原始 Evidence，不会自动形成 Observation，也不会自动变成 Topic、Claim、Intelligence、内容建议或任何 Agent 结论。若未来有人希望以其中的文字表达一个判断，仍必须按该判断的来源、用途、权限、范围、反例与资格另行治理。

**部分失败与重处理边界：** M1、M2、M3、M4 彼此不是一个总成功状态。一个合格图片 Artifact 的 OCR 失败不使该 Artifact 或同批视频 ASR 无效；一个视频 ASR 成功也不证明抽帧 OCR 已运行。每次重新处理必须形成新的处理发生、输入引用、处理器/规则版本、输出版本、Coverage 和失败/停止事实，不能覆盖历史输入、输出或原媒体观察。输入被限制、撤回、不可读或已失效时，后续处理必须停止并按血缘传播规则处理。

**处理器边界仍待决定：** 首轮未来使用本地受控处理器，还是让任何外部服务接收原媒体，仍是 `DECISION_REQUIRED`。本包不推断具体处理器、服务、供应商、权限、传输方式或合规结论。在这项选择被写入真实授权单前，M2/M3/M4 均不得实际运行。

**明确不进入首轮：** embedding、AI/视觉摘要、语义解释、自动分类、自动 Topic/Observation/Claim/Intelligence、外部 Agent 原媒体访问、训练/评测集、普通工作台原媒体展示，以及任何未获单独授权的第三方处理。

### 决策 3：内部保存、访问与处置

**推荐选择：** 内部受限保存，最小化读取，并在真实授权单中写明一个具体的处置触发与复核点。这里的“处置”至少要回答：谁可以读、为哪个目的读、何时复核是否继续保留、若停止或收到有效限制时如何阻断后续读取和派生。

这不是永久保存政策，也不是删除政策。它只避免两种不可逆错误：

- 为了验证保存而把媒体无边界留存；
- 为了谨慎而在没有审计的情况下丢失已经取得的媒体和其处置事实。

若主张更长的保留、更广的访问、正式对外展示、批量导出、训练或第三方处理，则本轮必须停止，等待相应的专业与正式政策审查。平台内容后来不可访问，不自动等于收到个人的删除或撤回请求。

### 决策 4：工位、账号、时间与风险停止预算

**推荐选择：** 一个已确认的观察身份与一个已确认的工位，在人明确指定的短时间窗口内，执行事前冻结的范围。授权单必须写出：触发即时停止的信号、到什么条件必须升级给人、已取得材料如何提交、哪些后续动作不能继续。

这里不提供“安全频率”“安全并发”或“合适时长”的假数字。没有真实 producer 证据时，任何此类数字都会把行业想象伪装成平台事实。首轮结束也不会证明这个账号、该工位或该平台可以在更大规模下安全运行。

## 给 Mog 的四句确认格式

Mog 不需要在这里决定数据库、对象存储产品、算法、模型或具体实现。若认可推荐路线，可以只按下面四项确认产品与现实资源边界；实际对象、数量、账号、时间和处置触发仍必须在下一份真实授权单中填写。

```text
1. 我确认首批只处理内容详情明确关联的主媒体；对象采用事前冻结的已知集合或最大配额，不扩大到评论/回复媒体、头像和页面周边资源。
2. 我确认首批以 M1 原媒体生命周期、M2 异步图片 OCR、M3 异步视频 ASR 三个独立 lane 验证；M4 视频抽帧 OCR 只有在授权单写明目的与冻结抽帧边界时才可进入。OCR/ASR 仅产生可追溯派生表示，不自动成为 Evidence、Observation、Topic、Claim、Intelligence 或 Agent 结论。
3. 我确认首批媒体仅内部受限、最小人员读取，并要求真实授权单写明复核与临时处置；不开放给普通工作台或外部 Agent，不作无限期保存。
4. 我确认首批使用单一获准观察身份和工位，在人工指定短窗口内运行；触发风险、身份变化、预算触顶或合同不满足即停止，不自动恢复。
```

若其中任一项需要扩张，应只修改对应一句并补充“为什么首轮必须扩大、最大边界和如何处置”。对于 M2/M3/M4 还必须写明“本地受控处理，还是任何外部服务会接收原媒体”。没有这些信息，工程团队应保持该 lane 未执行。
