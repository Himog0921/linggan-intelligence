# 首批真实 Producer Canary：文本优先与媒体边界决策包

> 状态: 草案
> 最后核对: 2026-08-22
> 适用范围: ARC-001 `first-producer-canary`；为 Mog 决定首批获授权真实 producer Canary 是否纳入媒体提供边界材料
> 事实来源: 已确认的领域不变量、ARC-001 决策图、当前 V2 媒体参考与采集架构草案；没有真实 producer、账号、媒体或运行证据
> 冲突时以谁为准: Mog 的明确选择；`AGENTS.md`、真实 producer 合同/实验结果与后续已接受决定

## 这份材料要决定什么

首批真实 producer Canary 的目标是验证：在一个经过明确授权、严格受限的真实观察中，Linggan 能否如实记录内容与评论材料的身份、时间、Coverage、失败和风控终止，并把合格材料送入后续受控链路。

Mog 需要决定该 Canary 的采集边界：

| 选项 | 首批受限范围 |
|---|---|
| **A. 文本与结构优先** | 内容身份、标题、正文、作者、时间表达、有限评论、发现/详情/评论的 Coverage 与终态；不下载图片或视频，不做 OCR、转录或媒体存储副本。 |
| **B. 同步纳入媒体** | 在 A 的范围之外，再下载或保存图片/视频，并可能执行 OCR、转录或其他媒体派生处理。 |

这不是“媒体长期是否重要”的选择。媒体仍是 Linggan 的后续能力；本票只决定它是否应当与第一批真实来源审计捆绑。

## 共同前提：两种选择都不自动授权什么

无论选择 A 或 B，在独立的真实 Canary 申请和后续 SCOPE 获批准前，以下事项仍然没有授权：

- 真实平台、账号、插件工位或任何来源材料访问；
- 真实原文、媒体或个人线索写入 Git、普通日志、无边界缓存或第三方模型；
- 以一轮 Canary 的结果宣称平台完整、用户具有代表性、市场正在增长，或策略已被验证；
- 生产部署、真实 Agent 调用、媒体数据库 schema、对象存储、OCR/转录技术选择，或固定保留期限；
- 因一次任务成功、部分成功或无结果，把未知变成完整、零或不存在。

真正启动时，仍需冻结目的、样本/对象、观察入口、账号镜头、允许字段、最大范围、停止条件、数据最小化、访问与处置边界，并走 Acquisition Authorization → Admission → Work Order → Attempt → terminal Package → Evidence Acceptance 的责任链。

## 选项对照

| 维度 | A. 文本与结构优先 | B. 同步纳入媒体 |
|---|---|---|
| 第一批业务价值 | 直接验证第一阶段最需要的“可解释材料”：内容如何表达、用户如何评论、对象/时间/Coverage 如何如实保留。它足以为后续用户原声、Topic 深入和有限内容叙事研究准备事实审计起点。 | 可同时检验视觉/视频是否对内容理解有决定性信息，并较早暴露媒体来源、体积和处理差异。 |
| 工位与风控 | 搜索发现、详情与有限评论仍须分段、限量、可停止；不再增加下载、播放、长时读取或媒体处理造成的额外页面行为与耗时。 | 一次 Canary 同时承担详情、评论、下载、可能的播放/转录与失败恢复；工位时长、访问频率、网络体积、风险暂停和恢复复杂度都会增加。 |
| 数据最小化与敏感材料 | 保留被明确批准的最小文本/结构材料，仍按受限原始 Evidence 与脱敏工作台边界处理。文本本身可能包含儿童、家庭、医疗和可反向识别线索。 | 额外增加人脸、儿童影像、家庭环境、学校/地点、语音和屏幕内容等敏感面；即使公开可见，也不自动获得下载、长期存储或第三方处理许可。 |
| 保留、删除与再处理 | 仍需在启动前决定受限文本原料的最小保存、访问和处置路径；本选项不要求先解决对象存储或媒体派生失效。 | 必须先明确原件与副本的身份、来源、存储位置、访问、保留、删除/撤回传播、重试/去重、转码/OCR/转录再处理和派生失效；这些都尚未由真实证据或正式合同关闭。 |
| 失败与 Coverage | 每个 lane 如实报告已发现、已尝试、已接纳、失败、未尝试和未知；有限评论不等于评论全量。成功取得的合格文本记录可保留，但不自动取得趋势或代表性资格。 | 除上述事实外，还必须分开表达“页面发现媒体候选”“成功下载”“字节/内容可用”“成功解析/转录”“缺失/不可访问/未尝试”。任何一个缺口都不能被压缩成“无媒体”或“媒体已完整”。 |
| 对 Capture contract 的影响 | 可先验证发现—详情—有限评论的最小 producer 合同与终态 Package/Coverage；媒体字段只可作为未经下载的候选来源陈述，不能被写成已获媒体事实。 | Capture contract 必须在首个真实运行前额外冻结媒体清单、主体/slot、下载身份、artifact 完整性、传输与重放、失败分类、Coverage 单位和受限原件处置。 |
| 对 Media V2 的影响 | 不否定 V2 的 `identity / origin / slot / usage` 分责经验；它把这些经验留给后续 `media-lifecycle-contract`，使该合同能用真实的“是否需要媒体、哪些媒体、体积与失败”证据设计。 | 迫使 `media-lifecycle-contract` 在 Canary 前解决。现役 V2 的媒体合同是参考，且其真实 producer inventory/Coverage/缺失事实尚未形成稳定全量闭环，不能直接照搬。 |
| 本选项具体授权 | 在后续 SCOPE 获批后，**可以申请**一个不含下载/转录的受限真实文本与结构 Canary；实际执行仍需单独授权、准入和验证。 | 在后续 SCOPE 获批后，**可以申请**一个含媒体的 Canary；但在额外的媒体/隐私/存储/处理合同通过前，不允许实际访问或保存媒体。 |
| 本选项不授权 | 不授权“以后永远不采媒体”，不授权趋势、自动化扩采、媒体缺失判断或对外传播。 | 不授权把媒体候选当作可下载资产，不授权默认下载全部附件，也不授权 OCR/转录供应商、媒体 schema、对象存储或固定保留期。 |

## 建议：选择 A，但把媒体作为紧随其后的独立 Gate

建议 Mog 选择 **A. 文本与结构优先**。理由不是媒体不重要，而是首批 Canary 需要先回答一个更基础、且可证伪的问题：在有限真实观察中，系统是否能如实接住内容/评论材料、对象身份、时间、Coverage、失败与风控终止。

将媒体与该问题捆绑，会把“来源事实是否可靠”“媒体是否可获得”“字节怎样保存”“是否能交给 OCR/转录”“如何撤回和失效”等多条未验证责任链混成一次试验。若 Canary 出现问题，团队无法判断是基础文本采集、插件行为、媒体下载、存储，还是派生处理造成的。

选择 A 的代价是第一轮不能用真实图片、视频、OCR 或转录来解释内容表现；对于依赖画面、口播或视频结构的内容研究，它仍然是未知。这一限制必须在所有用户界面、Agent 输出和后续决策中保留，不能因标题/封面 URL 或页面候选信息而假装已理解媒体。

## 选择后的直接工作顺序

### 若 Mog 选择 A

1. 以文本与结构为唯一 Canary 边界，形成一个新的、明确授权的真实 producer 申请；不复用本草案当作授权。
2. 先完成 `capture-control-contract`：把发现、详情、有限评论、终态 Package、部分结果、风险停止、Coverage 和恢复责任变成可证伪合同。
3. 运行最小真实 Canary 后，将真实字段来源、时间精度、账号/工位镜头、终止与失败事实记录为证据；不据此直接开放趋势或全量采集。
4. 仅当真实材料证明媒体是下一条用户任务不可替代的缺口时，启动 `media-lifecycle-contract` 并单独决定媒体访问、保留、派生和撤回边界。

### 若 Mog 选择 B

1. 在任何真实访问前，先把 `media-lifecycle-contract` 提到首批 Canary 的前置门：媒体来源/slot、下载/副本、访问、保存、删除传播、再处理、失败与 Coverage 必须形成可审查合同。
2. 由 Mog 或经 Mog 授权的负责人明确：最大媒体样本、是否允许图片/视频、是否允许下载、是否允许 OCR/转录、允许的保存位置和期间、第三方处理边界、风险停止和清理责任。
3. Capture control contract 必须增加媒体专属上限和回执，且将“候选、下载、可读、派生、缺失/未知”分开记录。
4. 只有上述门关闭后，才能另立真实 Canary SCOPE；这会延后第一批文本事实验证，但能避免以后以临时下载绕过媒体治理。

## 真实 Canary 可证明与不可证明的范围

| 经过批准且实际执行后，最多可验证 | 仍然不能由此证明 |
|---|---|
| 某个明确平台/入口/账号镜头/时间/范围内，producer 实际返回了哪些材料与失败/终止事实；指定字段能否按合同接入；Coverage 是否能如实表达；风险停止后合格材料是否不被连坐丢弃。 | 平台整体内容总量、用户总体、评论全量、市场趋势、需求规模、因果、内容机会已成立、固定安全频率、跨账号可比性，或任何尚未被来源合同覆盖的字段。 |
| 对 B 而言，最多再验证指定媒体样本在指定条件下的候选/下载/处理表现和处置路径；失败不能被解释为媒体不存在。 | 媒体方案可大规模推广、可以默认保存/转录所有内容、任何第三方处理已经合规，或旧 V2 媒体模型可原样迁入。 |
