# ADR-0002：评论采集完成、部分材料与重采语义

> 状态: 权威当前
> 最后核对: 2026-08-31
> 适用范围: 小红书笔记详情附带评论、单篇评论深采、批量评论采集，以及其 Producer Package、接纳和当前投影
> 事实来源: 用户在评论采集与调度恢复讨论中的明确确认；当前代码与自动验证
> 冲突时以谁为准: 用户最新确认；实现事实以当前合同、代码与测试为准

状态：ACCEPTED
确认日期：2026-08-30

## 决定

1. 评论采集的完成判断以当前页面的明确显示数量和本次 Attempt 的唯一采回数量为准：显示 `N`、采回 `N`，即为该次全量评论采集 `COMPLETE`；明确 `0/0` 亦为 `COMPLETE`。
2. 标准笔记详情固定附带最多 30 条评论。这是 `DETAIL_WINDOW`，窗口采满只表示窗口完成，不能被描述为该笔记全量评论完成。
3. 显示 `N`、采回少于 `N` 时为 `PARTIAL`。已采回材料正常接纳、检索、聚类和用于定性情报分析；任何需要完整分母、全量比例或“全部评论”表述的用途必须读取完成状态。
4. 每次新的深采 Attempt 都重新进入该笔记详情，从评论入口开始采集当前集合。不得从上次数量、页码、游标或本地 checkpoint 续采。
5. 服务端保留每次 Attempt 的不可变评论观察，并以稳定评论身份形成当前投影。重采的重复评论不会在当前检索和分析集合中重复计数；不同 Attempt 的数量不得相加证明完整性。
6. 批次 checkpoint 只可跳过已完成范围的笔记；对 `PARTIAL` 笔记恢复时，必须把整篇重新作为待采目标，而不是恢复其内部评论位置。

## 原因

产品需要完整拿回目标数据，但高互动笔记的采集不应因为一次未采满而丢失已经取得的真实材料。此前实现将“窗口达到 30 条”“单 lane 无错误”和“材料可用于分析”混为一体，又把本地批次进度当成可用于评论页续跑的位置，不能正确表达这一业务规则。

## 后果

- Producer、接纳与读取接口需要传递范围、页面显示数、唯一采回数、完成状态、停止原因和可用性。
- UI 必须可显示类似 `200 / 300，PARTIAL，已采回材料可用`，而不是只显示成功或失败。
- 原始 Attempt 观察保留，当前投影按评论稳定身份去重；历史不会因重采而删除。
- 不引入平台规避、验证码绕过或跨 Attempt 的评论分页续跑。
