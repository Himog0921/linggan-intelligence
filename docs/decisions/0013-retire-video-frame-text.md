# DEC-0013 · 视频画面文字下线，待专项重建

> 状态: 权威当前
> 最后核对: 2026-11-16
> 适用范围: 视频笔记的画面文字（抽帧 OCR，`video_frame_ocr` / `frame_ocr_text` / `video_frame` / `frame_text`）的生产、读取与消费；不涉及视频口播转写、图片识读和已删除的静态图片 OCR
> 事实来源: Mog 2026-11-16 指示与选择（“全删，旧结果失效后重跑”）；本机运行库只读核对；PR #595 的 L1 失败分析
> 冲突时以谁为准: Mog 最新明确决定；专项重建方案落定后由新决定替代本文

## 决定

视频笔记的画面文字从系统中下线，代码删除，留待以后单独立项重建。下线不是因为画面文字没有价值，而是现有做法质量不满意，又在拖累其他链路，不应成为阻碍。

## 原因（本机实测）

- 抽帧方式是“至少间隔 10 秒取一帧，每帧单独 OCR”。每一帧都带 bbox、识读问题、结构等元数据，发送给 L1 的材料里，文字只占 0.6%–3.4%。
- 画面文字片段超过 300 段的视频，平均输入约 23.9 万 tokens，8 次只成功 3 次；不足 100 段的平均约 2.2 万 tokens，77 次成功 61 次。
- 同一段画面文字在相邻帧重复出现，688 段里只有约一半不重复。

## 删除了什么

- **生产**：媒体处理器 `video_frame_ocr`、采集入库时的排队、补齐命令 `--missing-video-frames`、只为它存在的 PaddleOCR 桥接（`paddle_ocr.py`）、运行时准备脚本 `prepare-paddle-ocr.sh` 及对应证明用例。
- **读取**：研究底稿不再为视频生成画面文字材料，覆盖统计不再有 `videoFrames`，读本不再有“画面文字节选”，材料搜索不再匹配画面文字。
- **消费**：L0 视频就绪只看口播；L1、单篇分析、内容工作台不再读取画面文字；L1 提示词去掉画面文字说明，“画面原文「…」”按图片识读核对。
- **前端**：底稿解码、读本章节、AI 设置的可选材料列中去掉画面文字。

## 保留了什么

- 数据库里已有的画面文字作业、派生文本与读本原样保留，不删除、不迁移。数据库约束中的处理器名与材料种类保留。
- 读取历史记录所需的标识保留：Content Card 的 `includedKinds` 枚举、快照校验里的 `frame_text`、已保存 AI 配置里的 `frame_text` 材料列、内容工作台文档里的 `frame_text` 来源、评论研究与主题研究冻结输入中的 `frame_ocr_text`。它们只用于读取旧记录，系统不再产生新的值。

## 影响

- **旧 L1 结果失效**：材料快照身份包含全部文字，画面文字移出后，本机 85 份含画面文字的已保存 L1 结果不再是当前结果，底稿显示为未理解，需要重跑。Mog 已选择重跑；重跑需要单独授权模型调用。
- **无口播视频暂时无法理解**：没有口播的视频不再有可读文字，L0 会标为“当前没有可用的口播”。本机 107 份含画面文字的 L1 请求中有 6 份没有口播。
- **L2 V0.3**：规范里“已有画面文字”作为默认材料的部分随之作废，L2 视频只用口播。

## 以后重建时要回答的问题

1. 抽样方式：按场景切换取关键帧，还是固定间隔；相邻帧去重。
2. 发送给模型的形式：只发去重后的文字和时间，不发 bbox 等元数据。
3. 是否直接把关键帧作为图片交给模型识读，而不是先 OCR。
4. 与口播的关系：画面文字是补充，还是无口播视频的主要材料。
