# 研究自动化执行合同

> 状态: 代码事实优先
> 最后核对: 2026-11-19（评论研究 V2 切换候选）
> 适用范围: 评论研究、主题研究、创作者单篇与账号研究的当前候选
> 事实来源: ai_foundation 业务处理器、Axum 路由、迁移 0173–0179、0230–0232 与隔离 PostgreSQL/浏览器证明
> 冲突时以谁为准: 用户最新明确授权、当前代码和实际回执；候选不代表共享服务已发布

## 输入、版本与公共调用

创作者研究从 `research-dossier.v2` 取作品语境。评论研究 V2 使用同作品、同领域的 L1 Core。来源引用保留作品、来源版本、读本、块与 Unicode scalar 范围；图片缺页、未识读和未知页数随材料进入研究。评论原声与父评论分别有不可变来源，父评论和作品语境不能补成目标评论的原声证据。

每次提交原子冻结所有阶段 task config、提示词与 Skill；设置迭代只影响后续提交。提示词与 Skill 在 AI 设置直接编辑为不可变新版本，并可切换、回退；操作本身不派发模型。模型能力、输入额度、发送许可、用量及回执使用共享物理调用层，业务选择和接纳由各模块负责。

同一命令只重放原回执。确定拒绝后可修正条件；已经可能发送而缺少有效回执时记录 `ai_dispatch_unknown`，保留预留，不自动再发。同一冻结来源范围的未决请求阻止新命令重发。取消、暂停或撤销许可导致不能接纳结果，也不能将物理发送未知改成确定失败。

## 评论研究

评论目录在 `/api/local/comment-study`。它提供评论及作品目录、父评论、来源版本、索引覆盖和改帖标注。选择评论后使用 `/api/local/comment-research/v2`。

| 接口（省略前缀） | 行为 |
|---|---|
| `POST /preview`、`POST /runs` | 预览最多 1000 个明确选中的来源，按作品分研究单元。启动校验计划指纹和任务配置版本。缺 L1 时在预览提供现有 L1 的入口，由运营在 L1 完成后重新选择评论。 |
| `GET /runs`、`GET /runs/{batch}`、`POST /cancel` | 查看运行、单元和评论的回执。取消阻止后续派发和结果发布，已发出的调用仍结算用量。 |
| `GET /latest`、`GET /overview` | 读取单条当前结果、目录覆盖、信号和需求统计。返回的原声复核当前来源资格。 |
| `GET /problems`、`GET /problems/{problem}` | 查看需求、有效支持和重定向。至少两位不同的已知平台作者支持时，需求为正式。 |
| `POST /consolidation`、`POST /redirects/revoke` | 手动请求候选整理，或撤销同领域的合并重定向。 |

`comment_understanding` 每个单元调用一次，单元内每条评论分别保存结果。能确认来自创作者本人的评论排除，作品作者未知时仍可研究。只有目标原声可作为信号证据。运行的全部单元结束后，有新候选才排一次 `comment_problem_consolidation`。合并与撤销追加重定向或撤销记录。机会卡、研究概览与主题研究读取 V2 有效支持或结果。

迁移 `0232` 退役三个旧任务，关闭旧开关，取消尚未派发的项。迁移先确认三个旧阶段表为空，再移除它们。共享调用账本继续保留。旧写入口和三阶段处理器已从候选代码移除。V2 的任务设置仍由普通 AI 设置管理，迁移不设置启用、模型或预算。详细数据和输出规则见[评论理解合同](comment-understanding.md)。

## 主题研究

`POST /api/local/topic-research` 显式选择最多 10 篇作品、最多 50 个完整底稿/评论窗口。`GET /api/local/topic-research/runs?domainRef=...` 返回最近 30 个 run、窗口及实际阶段回执；summary 是当前领域完整研究历史的阶段合计。`POST /api/local/topic-research/cancel` 只取消精确 run 的余下阶段。

四阶段任务为 `topic_research`、`topic_research_extract_review`、`topic_research_resolve`、`topic_research_resolve_review`。引用精确、提炼校验、概念归属与独立核验全部通过后才接纳图谱；无信号只执行前两阶段，余下明确标为无需归属。词语或向量相似不能替代主题边界判断，未知不能强建主题。

归属候选是完整的当前合格定义集合；不以固定前 N 条截断来隐瞒范围。完整包超过配置额度时发送前拒绝，需在设置调整能力内额度。归属核验前及结果接纳前重查冻结候选的当前资格。定义依赖取实际 dispatch context 与 accepted core，比较邻居或父定义的来源撤回会沿依赖传播，失格定义不能再次成为模型候选。

图谱、人工结构操作和已保存备选仍使用现有 topic-map 接口；每次读取/保存/导出重新检查来源与定义资格。主题采集配置与研究执行分开，`linggan_topic_collection_policy` 只管既有采集意图，不保存模型配置或研究状态。旧 `/topic-map/research` 读写入口返回退役。

## 创作者研究

单篇 `GET /api/local/creator-research/preview`、`POST /api/local/creator-research`、`GET /api/local/creator-research/{requestRef}` 使用当前合格标准底稿，独立任务 `creator_research`。

账号对应 `creator-account-research` 三个接口及独立任务 `creator_account_research`。preview 明确固定选中的 1–30 篇合格作品及可用公开简介，start 核对精确列表及 fingerprint。抽样限制随 preview 和页面展示，不冒称账号全量画像；笔记材料与公开简介许可分别管理。研究结果动态复核来源，人工覆盖保存在独立当前表。

## L1 自动入队（0228）

`GET/POST /api/local/content-understanding/automation` 读取和切换按领域的开关，默认关闭，迁移不开启任何领域。读取返回 `configurationReady`（`content_understanding` 任务当前配置是否满足入队条件）和 `progress`（该领域已完成、排队中的作品数，以及按失败码统计的失败作品数）。

开启后，执行器每 5 秒扫描一页（10 篇）该领域的 `domain_research` 作品：只处理**从未发起过**当前方法版本 L1 的作品，先走与手动相同的 `preview` 与 `start`（批次类型 `automatic`），因此材料就绪、外发许可、模型探测、预算与任务开关都照常拦截。命令编号由领域、作品、输入哈希与方法版本确定，重启后重扫不会重复入队。排队中的自动请求达到 20 时原地暂停（不推进扫描位置，也不算扫完一轮）。扫完一轮且确实检查过作品后，等待 10 分钟再扫。

失败不自动重试：一篇作品只要有过请求（含失败），自动入队就不再碰它，避免持续的输出失败变成反复计费；失败由 `progress.failedByCode` 暴露，可在作品页手动重试。

## 数据库与历史边界

0173–0177 建立统一研究的请求、派发和结果账本；0178–0179 退役更早的独立研究表。评论研究由 0230–0231 建立 V2，0232 移除旧阶段表。历史迁移仍用于有序建库，重复迁移不重建已退役表。

实施与验证回执见[统一研究工作包](../plans/active/unified-research-automation-001.md)。真实证据笔记配合本机合成模型只能证明流程、来源及版本链；真实模型研究质量、发布和业务验收分别记录。

## 评论概览的只读投影与目录恢复

`GET /api/local/comment-research/v2/overview?domainRef=UUID` 使用当前来源目录、V2 研究请求和结果及派生的需求状态，返回 `comment-research.overview.v1`。原始可读评论、已索引可显示评论、可研究评论、已进入研究、语义阶段已有结果、当前有效信号和正式需求分别计数。概览不从最近100条研究记录推导全量统计；待索引不作为“全部没有可研究评论”。结果和原声预览仍重检精确来源资格，只返回少量预览；受限来源不显示旧原文。旧研究结果清理后，新结果为0并不影响保留材料的阅读。

观察图固定56个上海自然日，保留7/28/56切换；首次采集观察、进入研究和信号写入分别使用自己的事件时间。无评论采集覆盖记录不证明当日没有用户表达，显示未知；不从模型调用或索引处理制造平台观察覆盖。

确定性清洗缓存是可再生目录投影，依赖唯一 `comment_study_catalog::refresh_clean_cache`。单次工具 `linggan-comment-catalog --domain UUID` 只预览，追加 `--apply` 后有界重建缺失索引；它不组合巡查、采集、模型或权限开关，不恢复历史AI研究。巡查保持停用的升级环境应显式完成该索引重建并核对 `pendingCount=0`，不能把未重建的空缓存发布为“数据消失”。页面GET仍为只读。
