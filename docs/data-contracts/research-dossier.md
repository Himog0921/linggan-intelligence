## 底稿

底稿是同一稳定作品材料的派生读模型，JSON 表达，Markdown 用于导出及创作者任务材料区；评论/主题沿用其已冻结的 JSON 输入合同。平台标题、封面主文案、正文、标签、逐页图片正文、转写、评论、互动、覆盖和来源分别保留。没有正文与未取得正文不同；无 OCR 输出不证明图片没有字；平台评论数不证明已采全。

每片段包含稳定来源身份、版本与位置。原始 OCR 和正文不覆盖；底稿规则、输入范围和来源指纹可回查。评论可分页，正文不以 UI 展示截断作为完整来源。领域用途保留，跨领域不复制原文。受限/退役来源在每次读取/发送时检查。

## OCR rules-v3（保留 v1/v2 历史）

复用 Paddle 行、坐标、置信度；规则返回主文案、正文、待确认与排除行。多行主文案采用同尺度/对齐行组，字号中位数只是信号，不固定四行或单锚点小范围。常见文字卡片按连贯行组进入正文；背景/界面与角色不明的截图内容不自动当作者正文。

`PARTIAL` 可包含已经确定的主文案/正文；只读这些确定行，不把 raw 全部放开。正文和主文案由行重建；规则版本显式保存，旧结果保留。同一 layout/version 只生成一次，重新分层不重新 OCR/采集/调用模型。

详情可信标题优先；发现记录的纯数字标题若等于同次点赞数且没有详情标题，则标记疑似计数并排除，不断言平台无标题。其他数字标题保留。选择同一槽位的已取得且可读识别结果，考虑完整性和尺寸，固定 tie-break；不能拼接不同 layout 的行。当前规则选择明确，不把试验结果按时间自动升级为当前。

## 任务材料

统一材料准备由预览与调用方共享。创作者作品读取主体；作者级保持多作品与简介。评论研究读取实际选定评论、父评论与作品语境；主题研究保留原来源角色和输出合同。现有窗口/预算在兼容层保留，未启动新的方向算法。

底稿不因调用长度丢原文；任务按整体上限有界选取/分批。每段标片段 ID，输入清单保存原范围、已选/未选、规则和模型配置。父评论语境不重复计数，材料自身的指令不升级成系统指令。输入预览不调用模型。

默认人读预览每页 30 条评论，沿用受控评论通道的稳定来源引用排序；这是当前读取，不承诺冻结快照或平台展示顺序。真正任务按原有选择范围读取，不改 comment_budget 的计量单位。未知保持未知，缺一栏不阻塞整篇。

## 动作与界面

重建底稿只重读派生；重新分层只处理已有 OCR 行；重新识字复用既有媒体链。单篇与选定范围分别返回已处理、已是当前版本、需先识字、失败及剩余；请求受理不等于完成。

新接口沿用现有本地访问 guard；后台任务开关、暂停和额度不被此模块改变。原始来源只在既有许可范围展示/使用，不写进普通日志或 Git。本模块不扩张既有模型出站权限。原有评论清洗、父上下文、来源限制和任务输出合同继续生效；没有新增第三方处理通道。

## 当前适配边界

- 创作者：全量底稿先构建，搜索使用完整可用文字；单篇模型材料总计 4,000 字符，再由同一 `creator_discovery_input::prepare` 按配置额度压缩。预览返回实际准备请求及实际引用片段；原始来源映射不必在提示词内重复。作者级判断仍使用原有多作品和简介逻辑。
- 评论：P1 与 P2 均调用底稿来源映射；P2 的底稿读取与评论游标使用同一事务快照，启动使用 SERIALIZABLE 和原有有界重试，预览为 REPEATABLE READ READ ONLY。删去已被替代的 `comment_study_source/context.sql`，避免留下第二套分层准入。原评论/父回复选择与批次合同保留。
- 主题：复用完整底稿片段后，继续原有窗口、预算、复用与引用还原；`cover_headline` 是独立字段，未替换平台原标题。
- 页面中的评论预览明确是作品上下文，主题预览明确是分窗前单篇材料；两者不冒充整个多对象请求。历史实际请求仍从原研究记录查看。只有创作者提供当前配置下的完整请求准备预览。
- 片段在底稿中保留稳定逻辑 ID 与 sourceVersion；创作者适配为片段 ID 追加选中文字 hash，让原文变化时旧人工支持失效。自动指纹同时绑定当前引用 ID，防止同文案换媒体后沿用不存在的证据引用。
- `tags` 当前没有独立记录时标未知，正文里的标签原文保留；背景类型不凭 OCR 猜测。完整评论从受控分页通道读取，未复制进正文或单篇 JSON 导出。JSON 中的 comments 栏说明此边界。
- 重新分层只处理所选每篇当前可用的布局，单篇最多 100 个，列表批次最多 200 篇。批次范围与回执放当前浏览器 sessionStorage，逐篇提交，暂停发生在篇间；已完成分层在数据库保留。关闭浏览器不会让后台自动继续。
- 原图 URL 绑定所选 OCR job 的 blob 与具体 materialization，并沿用受限检查；没有可对应的帧图时不套用视频封面。源图片不可读取不阻止查看已取得的文字。

## 上线与恢复

无 schema migration、OCR 引擎版本升级或历史全量重处理。rules-v2 只追加，已有 layout/rules-v2 再次提交为已完成。页面读取/分层都不启动研究。创作者输入规则与指纹升级会使旧自动结果需要重新准备；如果日后恢复已启用的自动研究，原调度器会在原有额度内处理这些变化。发布时须保留现有暂停和 worker 停用状态，不能把更新代码当作恢复自动运行的授权。

## 真实验收修订约束

在同一张原图中按视觉行、行内从左到右读取，不以字符长度或每段至少三行丢掉连续正文的短尾行。对无法从 OCR 几何可靠确认用途的实物包装文字保持待确认。完整原始 OCR 留存。相同 blob、输入区域与处理种类的封面/首图材料只送一次，来源记录仍可查看。

平台标题必须来自可信标题字段；发现采集的数字计数冒充标题时，在派生读取中标明不可靠，禁止作为平台原标题送给研究。真实纯数字标题保留。缺少平台标题时允许封面大字用于展示，不伪造平台标题。

AI 阅读材料使用短来源编号；完整 UUID/hash、版本、字符范围放在后端来源映射或技术详情。需要引用定位的任务保留现有验证能力，不能为了简短丢失来源校验。

作品级创作者任务将短引用映射单独保存到本机调用账本 `citationMap`（引用 ID、来源、版本、实际字符范围，不复制原文）；预览在模型 `input` 外返回同一映射。输出只接受本次短编号，验证后还原长期引用。评论、主题及作者级 focus 的既有结构化引用合同保持原样。
