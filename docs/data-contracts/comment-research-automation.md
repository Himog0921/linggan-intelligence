# 评论研究自动化合同

最新目标入口：Mog 于2026-09-08采纳《重构评论研究流程》最后决策，明确取消日常人工判断/标注、要求自动研究与研究回归及规模化原子聚类。[CI-AUTO-004计划](../plans/active/ci-auto-004-comment-auto-research.md)逐项裁定与本合同的差异。下文继续记录CI-AUTO-003已实现基线，不得用其中“需要人工判断”、模型配置参与复用键或500对象召回上限限制新决定，也不能在新代码未验证前把目标写成已实现。

本合同替代 comment-intelligence-v1.md 中的100条手动范围、低信息保留、每日观察承载批次、人工确认普通候选等冲突部分；其余证据、权限、版本、LIDS与统计边界保留。

## 用户结果

主视图为概览、原声、用户问题、变化观察。运行记录是辅助入口，保留请求诊断、历史结果、重试与预算。用户设定研究范围/规则后，清洗、提取、复用、问题组织和增量更新自动执行；需要判断仅收真实歧义，不逐条审核普通候选。

## 清洗与分析

新规则用comment-clean.v2，旧v1不可重写。派生文本去emoji、可靠mention；无语义文字dropped，不进入当前原声/检索/词频/问题/代表统计。短语蹲、同问、求分享保留。anomaly不等于无价值。原始事实不删除，列表显示派生文本，详情可核对原文和位置映射。内部direct/context对应可分析/需上下文，low_information仅为旧记录兼容值。

Task A固定comment-research.v4提示词/Schema，逐评论提取需求、方案、经历、原文表达、问题和立场。explicit/context_resolved/uncertain有独立依据；context_resolved同时引用目标评论和实际输入辅助片段。模型只看相关上下文片段，不看点赞来决定语义。字段不合法仅拒独立字段；身份/截断/根结构失败仍不可接纳；全字段拒绝不冒充no_signal。分析合同升级不撤销已验证的模型调用能力；历史分析仍可读，既有授权不自动升级重算。MODEL-CALL-004以当前模型最后一次完整成功的调用回执作为配置/研究准入，评论格式校验仅为诊断，实际每次分析仍严格验证。

## 研究范围与复用

首版手动研究范围保护上限3000，与单次调用的1–30条内部上限分离。前后端读同一范围限制。预检显示范围总数、可复用、新增分析、已过滤、上下文待补、异常/不可读、既有失败及阻塞；分类互斥且总和一致。模型调用数与Token是注明方法的估算/上界，不能假装账单。准备只冻结；确认才创建一个批次并执行多个请求。

指纹包含原文、清洗、实际相关上下文、分析合同/Schema、模型语义配置。重复选择或点赞变化不重算。prepared范围及策略30分钟冻结，确认再核对，变化拒绝并要求重新预检。历史成功/no_signal按相同指纹复用，失败/可能计费状态不因重选绕过重试约束。

## 长期问题与变化

Task B独立召回与判断same/related/different/uncertain；只有same可自动入问题。无匹配表达仍需要新问题发现路径。问题candidate/emerging/stable规则必须有版本和真实校准边界，相似度不是正确率。人工边界决定追加记录并被后续匹配引用。处理一个表达只移除该表达的待判断状态，不能连坐同评论其他问题。若真实embedding未配置，明确记录能力未就绪，不造向量/概率/自动化结果。

变化观察分开首次采到、首次分析识别、可比窗口真实变化。历史补分析不制造新需求；无基线不标升温。共鸣/冲突由程序聚合且附依据，不由单条提取直接产生。

## 运行与验证

开启一次的每日23:00 Asia/Shanghai计划冻结[上次cutoff,本次cutoff)；预算/次数边界内运行。积压保留原观察时间，继续使用实际授权额度；未知费用不盲目自动重试。修改清洗/合同不自动扩大旧授权。原始事实/接纳分析/问题和人工版本长期保留，实际输入输出诊断正文按24小时策略清理。

验收必须覆盖噪声过滤与短语保留、300条范围及复用、字段部分成功、上下文不冒充评论、已解决表达去重、人工边界复用、跨23点和预算/重启/未知用量、历史补分析不造增长。合成测试、真实模型质量、共享部署、Mog验收分别报告。

## 代码接缝与边界

- `comment_cleaning.rs`、`comment_cleaning_noise.rs`：Unicode17.0 / unicode-properties0.1.4版本化处理；确定性分类与原文坐标映射分离。跨领域采用独立cross_industry_comment_clean，不能借同UUID本域分析。
- `comment_packet_context.rs`：comment-context.lexical-excerpts.v1，单条1200字预算，正文/OCR/ASR按字符二元词相关性选片；这是词法选择，可能遗漏相关内容，不能称为语义检索已经验证。父评论用稳定作品/外部评论身份保留出处。
- `comment_packet_result.rs`、`comment_packet_diagnostics.rs`：字段接纳、拒绝路径、uncertain解释；探针只有完整字段合同才取得v4资格。
- `comment_preflight.rs`、`comment_intelligence.rs`：3000范围保护和互斥计数；预检不外发。内容指纹包含原文以保护引用坐标；仅改emoji/mention也可能产生新版本，未经重映射不直接搬旧引用。
- `comment_problem_worker.rs`、`comment_problem_vectors.rs`：持久TaskB任务、定义版本、来源资格、同批额度、向量缓存和关系判断。关系结果与接纳回执同事务保存；记账前中断恢复已接纳结果并标用量待核对，不重复外发。相似度仅召回，same才入既有对象。自动首条对象为emerging；3条当前可用独立原声后可标stable，这只是暂定组织门槛，不是结论正确率；人工定义另记依据。
- `embedding_settings.rs`、`apps/pi-adapter/src/embeddings.mjs`：可配置本机或外部OpenAI兼容向量接口，复用Keychain连接。保存不发请求；独立合成探针合格后显式启用，授权在原研究额度内处理待归并表达。参考[官方Embeddings接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create)，最多2条、每条8000 UTF8字节，校验索引/维度/有限非零向量；缺少用量仍未知。兼容协议不等于所有供应商或模型都已通过真实测试。
- 当前向量召回以同域最多500个可读问题的精确余弦排序为首版边界；超出边界显示受限，不静默截断冒充全域召回。新表达依次比较既有对象，无same且无uncertain时建立emerging对象；尚未实现批量全局重聚类及自动重整问题树。
- `0050_comment_research_automation.sql`、`0051_comment_problem_vectors.sql`：追加新合同/队列/清洗派生/向量缓存；投影游标与词索引按领域及评论联合标识，迁移仅清空可重建游标使其重新投影，不删除原文/分析。部署暂停旧合同研究授权，恢复研究需显式设置；模型调用能力不因评论合同升级作废。批次切到新日只接续从未调用的积压，carried_forward保留出处，未知计费不随之转移。
